## 所見 1（記述の陳腐化）: 強制買戻しの発生回数の「現況」が古い

SC-03「表示項目の供給元」の表は、強制買戻しの発生回数の現況をこう書いている。

> ❌ **供給が無い。推定経路が未実装である。0 件と表示してはならない**

**推定経路は [#419](https://github.com/endazon/ai-stock-trading/issues/419) で実装済みである**
（ADR-0016 決定4 の 2026-08-06 改訂に追随。`IADR-0159`）。しかし**結論（供給が無い）は変わらない**——
理由が変わっただけである。

**新しい理由**: 推定台帳（`buy_in_inferences`）は**推定が起きたときにしか行を書かない**。

| 台帳の行数 0 の意味 | 運用上の性質 |
| --- | --- |
| ブローカ建玉の観測が一度も届いていない（OpenD 未常駐等） | **異常**（この統制はまったく働いていない） |
| 観測は届いたが強制買戻しは 1 件も無かった | 正常 |

**台帳はこの 2 つを区別する情報を持たない。** よって件数を数えて `Available` として返すと、
**「観測していない」が「0 件だった」として画面に出る**——決定15 が名指しで禁じた向きそのものである。
実装は結線せず `NotSupplied` を宣言し、その理由をコードのコメントとして値の隣に残した。

**依頼**: 供給元の表の「現況」欄を次の趣旨へ更新されたい（結論の変更ではなく理由の更新である）。

> ❌ **供給が無い。推定経路は実装済み（#419）だが、推定台帳は「観測が届いた事実」を記録しないため、
> 件数 0 が「観測していない」を意味し得る。0 件と表示してはならない。**
> 供給には**観測の到達を記録する経路**（最終観測時刻の永続化等）が別途要る。

**あわせて確認したい点**: 「観測が届いた事実」を記録する経路は**計画が要求する項目に入るか**。
入るなら要求として起こしていただきたい（実装側は `docs/blocked-tasks.md` へ残件として登録済み）。
入らないなら、**発生回数は当面恒久的に「取得できていません」と表示され続ける**ことになる。

## 所見 2（規約の片方向性）: 「正当な 0」を守る規律が明文化されていない

共通規約の 3 状態の表は「値が 0 ＝ 正当な測定結果として `0` を表示する」と定めている。
一方、規約の本文が禁じているのは**未供給を 0 や「—」で描くこと**だけである。

実装の過程で、**逆向きの誤り**が同じくらい起こりやすいことが分かった。

> 供給されている 0 を「たぶん未供給だろう」と描く（＝供給されているのに「取得できていません」と嘘をつく）

これは「クライアント側で 0 かどうかから供給有無を推測しない」という裁定の理由から**論理的に導ける**が、
**明文が無いため、テストを書くときに片方向だけ守って終わる**。実際、本実装の前は
「未供給を 0 に見せない」テストしか存在しなかった。

**害の所在**: 逆向きの誤りが積むと、「取得できていません」の表示が**当てにならない**と読まれ、
やがて未供給の警告そのものが無視される（統制の警告としての価値が失われる）。

**依頼**: 共通規約へ 1 文を追加されたい（意思決定の変更ではなく、既存の裁定の対偶の明文化である）。

> **逆向きも禁じる**——供給されている 0 を「取得できていません」と表示してはならない。
> 「0 かどうかから供給有無を推測しない」は**両方向**に効く規律である。

実装側は 3 状態を**両方向**に固定した（`IADR-0162` 決定1）。変異検査で、正当な 0 を未供給扱いへ
倒す変異・クライアントが 0 から供給有無を推測する変異のいずれもテストが赤くなることを実測している。

## 参考（実装側で採った扱い）

- 「—」は**対象なし専用の記号**とし、未供給は必ず文言で述べる（SC-02 の equity 実額併記を是正した）。
- 供給可否の宣言主体は原則サーバである。**例外は SC-01 §2 の収集間隔だけ**で、
  供給元となるエンドポイントも設定ストアも無く**宣言する主体が存在しない**（`IADR-0155` 決定5 の踏襲）。
- 維持率が **Stage 1 の全期間表示できない**旨（決定7 の 2026-08-07 追記）を画面とコードへ明記した
  ——「そのうち直る不具合」と読まれると、利用者は統制が無いまま待つためである。
