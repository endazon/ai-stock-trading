## 問題点 / あるべき姿（To-Be）

### 実装がそうなる理由（式）

実装（[IADR-0131](../docs/adr/IADR-0131_short-selling-controls-fail-closed.md) 決定5）は、計画の文言を
そのまま式にした。既存の空売り建玉を `S`、当該注文の名目額を `N`、建玉総額（ロング＋ショート）を `T`、
ロング建玉の総額を `L`（`T = L + S`）とすると、判定は次である。

```
S + N ≦ (T + N) × 0.50        …… 計画の文言そのまま（分母は「建玉総額」＝新規建て後の値）
```

これを整理すると **`S + N ≦ L`** と等価である。

```
S + N ≦ (L + S + N) × 0.5
2(S + N) ≦ L + (S + N)
S + N ≦ L
```

すなわち決定9 は、実効的には「**空売り建玉の合計は、ロング建玉の総額を超えない**」という規則である。
このとき **`L = 0`（ロング建玉が 1 件も無い）なら、`N > 0` のすべての空売り注文が拒否される**
（`N > 0 = L`）。1 件目の空売りは常に比率 100% になるためである。

### 含意（計画に書かれていないこと）

| # | 含意 | 根拠 |
| --- | --- | --- |
| 1 | **空売りは必ずロング建玉を持ってからでないと開始できない**（順序の制約） | `L = 0` なら任意の `N > 0` が拒否される |
| 2 | 空売りに使える金額は**ロング建玉の総額に上限づけられる**（equity ではない） | `S + N ≦ L`。equity $3,000・1 銘柄上限 $300 でも、`L = $100` なら空売りは $100 まで |
| 3 | **Stage 1（SIMULATE）で「空売りだけ」のシナリオを検証できない** | 検証には必ず先行してロング建玉を作る手順が要る。決定14 の「Stage 1 で検証できない統制」の表はこの制約に触れていない |
| 4 | ロングを全決済すると、残った空売り建玉は比率違反の状態で残る（新規は止まるが既存は残る） | 統制は**発注前**の判定であり、既存建玉を遡って是正しない。手仕舞いは止めないため解消手段はある（ADR-0009） |
| 5 | 「空売りをしたいのでロングを建てる」という**統制の意図と逆向きの誘因**が生じ得る | ロング建玉が空売り枠の前提になるため。決定9 の趣旨は方向性リスクの相殺であり、枠を作るためのロングはその趣旨に反する |

含意 1〜3 は**戦略の実行可能性**に関わる（「空売りは実装したが Stage 1 で単独検証できない」は、
決定8 が「Stage 1 の検証は資金水準に関わらず実施できる」と述べたこととの間に緊張がある）。
実装側で緩めてよい種類の判断ではないため、計画側の裁定を仰ぐ。

## 実装で判明した経緯

[#329](https://github.com/endazon/ai-stock-trading/issues/329) 第 2 段階（空売り統制 8 規則）で、否定形テスト
`ロング建玉が無ければ空売り比率の上限に掛かる`（T-10-171。迂回経路「ロング建玉が無いのに比率 50% を
対象外と読む」を塞ぐもの）を書いた際に、**塞いだ経路の裏返しとして**判明した。

実装は**文字どおりの読み**を採り（[IADR-0131](../docs/adr/IADR-0131_short-selling-controls-fail-closed.md)
決定5）、緩める解釈（建玉が無いときは対象外とする）を採らなかった。理由は、緩める解釈が
「1 件目の空売りは必ず無条件に通る」という穴を作り、決定9 の趣旨を空洞化するためである。
第 2 段階の[作業仕様書](../docs/specs/20260804_329_short-selling-controls.md) 未決事項 §3 に記録し、
第 3 段階で構造的含意として本書に環流する。

## 提案（計画への反映案）

- 反映先候補: **ADR-0016 決定9 の追補**（部分改定または追記）＋ 決定14 の表への 1 行追加 ＋
  05_trading-assumptions §5 「空売り比率の上限」行の備考更新
- 提案内容: 次の 3 択のいずれかを裁定し、あわせて**等価形（`空売り建玉 ≦ ロング建玉総額`）を明記**する

| 案 | 内容 | 得られるもの | 代償 |
| --- | --- | --- | --- |
| **A（現行実装）** | **文字どおり維持**する。決定9 の本文に等価形と「ロング建玉が無ければ空売りは開始できない」を明記し、決定14 の表へ「Stage 1 で空売りを検証するにはロング建玉を先に作る手順が要る」を追加する | 決定9 の趣旨（方向性リスクの相殺）を最も強く満たす。実装変更なし。統制に穴が開かない | Stage 1 の検証手順が空売り単独では組めない。含意 5（枠を作るためのロング）の誘因が残る |
| **B（建玉 0 件時の例外）** | 建玉総額が 0 のときに限り比率判定を適用しない（＝ 1 件目の空売りを許す） | Stage 1 で空売り単独の検証ができる。変更は 1 行 | **「1 件目は必ず 100% ショート」を許す**。露出は 1 銘柄上限（equity の 10%＝$300）に留まるが、決定9 が避けたかった「全建玉が空売り」の状態が建玉 1 件のときだけ成立する。判定が **0 件かどうかで不連続**になる（ロングを $1 持てば比率が効き、0 なら効かない）ため、境界の説明が難しい |
| **C（別の定式化）** | 分母を**建玉総額から equity へ**替える（`空売り建玉の合計 ≦ equity × 50%`） | 建玉構成に依存せず連続。Stage 1 で単独検証できる。他の統制（1 取引 1%・日次 2%・1 注文 25%・1 銘柄 10%）と**同じ土俵**（equity 基準）に揃う | **決定9 の趣旨を担保しない**（全建玉が空売りでも equity の 50% までなら通る）。値の意味が変わるため 50% という数字自体の再裁定が要る。ADR-0016 決定9 の理由（3 銘柄すべて空売りだと同時に損失を出す）は保有建玉数上限 3 との組で別途担保する必要がある |

> **不採用の案**: 分母から当該注文（自分自身）を除く読み（`S + N ≦ L × 0.5`）は、**さらに厳しくなる**だけで
> `L = 0` の問題は解消しない。計画の文言にも反する（[IADR-0131](../docs/adr/IADR-0131_short-selling-controls-fail-closed.md) 決定5）。

**実装の既定（案 A）で運用上の支障が出るのは Stage 1 の検証計画のみ**であり、実弾解禁（Stage 3・
自己資金 $5,000 以上）までに裁定されれば手戻りは生じない。緊急性は高くないが、**Stage 1 の検証計画
（決定14・#342 の PoC 項目）を組む前**に決まっている必要がある。
