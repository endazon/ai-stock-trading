# フィードバック: SC-03 の強制買戻し発生回数の「期間」が未定義


> ✅ **［2026-08-14］裁定済み。案 A（当月＝月初〜当日）が採用された**（[project-planning#328](https://github.com/endazon/project-planning/issues/328)。反映は planning #330・`130a109`）。
> **実装は既に案 A であり、コードの変更は不要であった。** 計画側の同記録も `status: accepted` である。

## 種別

**要求の不足**（判定に必要な入力が計画に無い）。

## 起点となる計画書

- 機能要求（FR）: **FR-21**（観測の到達の記録・2026-08-08 改定）／FR-10
- ユースケース（UC）: UC-06
- 画面（SC）: **SC-03**（統制状態参照画面・§供給が無い値の表示規約・§供給元の表）
- 関連 ADR: **ADR-0016 決定15**
- 計画書リンク: `projects/ai-stock-trading/02_requirements/01_requirements.md`（FR-21）／`projects/ai-stock-trading/05_screens/01_screens.md`（SC-03 供給元の表）

## 現状（計画書の記述 / As-Is）

FR-21 は 2026-08-08 の改定で、判定を**期間**で行うと定めた。

> **報告は期間に対して行われる**（日報＝当日・月報＝当月。ADR-0016 決定 15）ため、**判定も期間で行う**
> —— **報告期間が観測の届いた取引日で覆われている場合に限り、件数 0 を正当な 0 として供給する。**

05_screens の SC-03 供給元の表も同じ文言を引く。

> ［2026-08-08 改定］観測が届いた取引日の集合として保持し、**報告期間がそれに覆われている場合に限り供給する**

**しかし SC-03 は報告書ではなく現況画面であり、その「報告期間」に相当するものが計画のどこにも定義されていない。**
日報・月報については ADR-0016 決定15 が当日・当月を割り当てているが、**SC-03 の当該項目の期間は無指定である。**

## 問題点 / あるべき姿（To-Be）

**期間が決まらなければ被覆判定そのものが書けない**（`[from, to]` を与えられない）。
実装が期間を独自に決めると、**画面に出ている数字が何を指すのか計画から追えなくなる** ——
これは ADR-0027 が「表示されている数字が何を意味するか誰も答えられない状態」として塞いだ失敗と同型である。

**あるべき姿**: SC-03 の「強制買戻しの発生回数」について、**対象期間を計画が明示する**。

## 実装で判明した経緯

issue [#470](https://github.com/endazon/ai-stock-trading/issues/470)（IADR-0181 決定4 が名指しで約束した follow-up）で
SC-03 への結線を実装する際、被覆判定に渡す期間が決められないことで判明した。

なお **issue #470 の本文自体も 1 点が陳腐化していた**。起票（2026-08-08 05:30）時点では
「裁定前は最終観測時刻の存在のみで判定する」と書かれていたが、**同日中に [#292](https://github.com/endazon/project-planning/issues/292) の裁定が下り**、
FR-21 は取引日の集合＋期間被覆へ改定された。実装は改定後の FR-21 に従っている。

## 提案（計画への反映案）

- 反映先候補: **要求更新（FR-21 または 05_screens SC-03 供給元の表に 1 行）**
- 提案内容: 次の 3 案のいずれかを明示する。**実装は案 A で先行している**（下記「実装の現在の扱い」）。

| 案 | 期間 | 根拠 / 帰結 |
| --- | --- | --- |
| **A（実装が採用）** | **当月（月初〜当日）** | ADR-0016 決定15 が「**発生回数**」を月報（当月）へ、「**発生有無**」を日報（当日）へ割り当てている。SC-03 の当該項目の名称は**発生回数**であり、決定15 の語彙にそのまま対応する |
| B | 当日 | SC-03 は当日損益を持つため画面の枠としては自然。ただし決定15 で当日に割り当てられているのは**発生有無**であって回数ではない |
| C | 全期間 | 計画に定義が無い。観測は OpenD 常駐の開始後にしか届かないため**被覆が永久に成立せず恒久 `NotSupplied`** になる（#470 の目的を満たさない） |

**実装の現在の扱い**: 案 A を採用し、期間の決定を `ShortSellingStatusService.BuildBuyInCount()` の
**1 か所**に閉じた（[IADR-0186](../docs/adr/IADR-0186_sc03-buy-in-count-supply.md) 決定1）。
**裁定が案 B・C を指す場合、期間を組み立てる 2 行を差し替えるだけで追随できる。**

## 影響範囲

- **SC-03 の表示**（本項目のみ）。他の指標の供給可否には触れない（IADR-0154 残余リスク4 の規律）。
- 日報・月報側は影響を受けない（#463 / IADR-0181 で期間を呼び出し側が与える形になっており、当日・当月が決定15 で確定している）。
- **安全側の性質は案によらない** —— どの期間を採っても「覆えていなければ `NotSupplied`」であり、
  0 件を「起きていない」と誤読させる向きへは倒れない。案の違いは**いつ供給が始まるか**にのみ効く。
