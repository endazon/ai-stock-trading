# フィードバック: moomoo PoC の結果と、借株料統制の見直し

## 問題点 / あるべき姿

### 1. ADR-0016 決定 3 の「借株料 年率 20% 超を拒否」は発火しない

`TrdGetMarginRatio` で 8 銘柄を照会した結果である（実弾の信用口座）。

| 銘柄 | `IsShortPermit` | `ShortFeeRate` | `ShortPoolRemain` | `ImShortRatio` |
| --- | --- | --- | --- | --- |
| AAPL | True | **1.5** | 26,452,338 | 50 |
| MSFT | True | **1.5** | 16,655,203 | 50 |
| GME | True | **1.5** | 1,898,200 | 50 |
| MSTR | True | **1.5** | 3,443,217 | 50 |
| RIOT | True | **1.5** | 1,201,180 | 50 |
| AMC | **False** | 0 | **0** | **100** |
| SPCE | **False** | 0 | **0** | **100** |

**API は銘柄を明確に区別する**（AMC・SPCE は空売り不可）。**しかし借株在庫が 20 倍以上開いても料率は 1.5 のまま動かない。** 借株料は一律である公算が高い。

決定 3 は「借りにくい銘柄ほど借株料が高く、踏み上げリスクも高いため、**コストと危険度を同じ閾値で弾ける**」という理由で 20% を採った。**この前提が成り立たない。** 一律料率であれば閾値は永久に超えず、統制は何も弾かない。

**あるべき姿**: 決定 3 を「**照会できること**」と「**閾値で弾けること**」に分けて評価する。前者は成立し、後者は成立しない。実際に危険な銘柄を弾いているのは `IsShortPermit=False`（借株不可）であり、**一次ゲートをこちらに置くべきである**。

> **実装側の扱い**: 閾値判定そのものは実装し、**発火しないことを既知として記録する**（IADR-0144 決定 4）。落とすと、将来料率が銘柄別になったときに無防備になる。
> なお `1.5` の単位（年率 1.5% か否か）は未確定であり、確定するまで FR-17 の費用計算へ流し込まない。

### 2. 借株料・維持率の照会は実弾口座でしかできない — Stage 1 で統制を検証できない

`TrdGetMarginRatio` は **SIMULATE 口座では失敗する**（`Get Margin Trading Data does not support Stocks in US Market`）。**同じ市場・同じ銘柄が実弾口座では成功する。**

> **エラー文言が誤解を招く。** 市場を理由にしているが、実際の制約は口座環境にある。切り分けをせずこの文言を読むと「空売りは恒久的に不可」という誤った結論に至る。実際、本セッションでは一度その結論を記録し、切り分け後に撤回した。

ADR-0016 決定 14 は「Stage 1 で検証できない統制」の表で、決定 3 を「SIMULATE は年率 6% 固定のため 20% を超えない」＝**値は取れるが閾値に届かない**と説明している。**実測では値そのものが取れない。** 決定 7（維持率 40%）も同様で、SIMULATE の `Funds` は建玉があっても維持率フィールドが埋まらない。

**あるべき姿**: 決定 14 の表を実測に合わせて改める。「値は取れるが閾値に届かない」ではなく「**照会 API が SIMULATE で使えない**」である。

**実装への影響**: SIMULATE で発注しながら実弾口座のヘッダで照会する、**環境をまたぐ構成**になる。実弾ヘッダは読み取り専用に限る（IADR-0144 決定 3）。

### 3. 空売りと通常売却が API 上で区別されない

`TrdSide_SellShort` は**拒否される**。

```
Order side must be BUY or SELL.
A SELL order without holdings will open a short position.
A BUY order when short will close the short position.
```

**建玉を持たない `Sell` が新規ショートになる。** 手仕舞いのつもりの `Sell` が建玉を取り違えると**裸の新規ショート**になる。

これは実装側の [IADR-0119](https://github.com/endazon/ai-stock-trading/blob/develop/docs/adr/IADR-0119_decision-derived-close.md)（#298）が是正した問題そのものであり、**ブローカ側の実仕様として実在することが確認された**。計画側でも、空売りの前提条件として「発注前に建玉状態を確定させること」を明示する価値がある。

### 4. レート制限（30 秒あたり 10 回）

決定 3 は「発注前に借株料を照会する」ことを求めるが、`TrdGetMarginRatio` は **30 秒あたり 10 回**が上限である。**失敗した照会も枠を消費する**（実測: 失敗 3 回が同窓に入り 8 銘柄目が制限で落ちた）。監視銘柄数 × 判断頻度によっては設計上の制約になる。

### 5. 副産物 — 計画書に出所が無かった値を裏取りした

ADR-0016 決定 14 は証拠金条件を記載しながら根拠を示していなかった。実測で裏付けた。

- **実弾**: `ImShortRatio=50` / `MmShortRatio=30`（決定 14 の「ショート 初期 50% / 維持 30%」と一致）
- **SIMULATE**: `MaxSellShort = 自己資金 ÷ (株価 × 0.6)` が 3 銘柄で成立し、**初期証拠金 60%** が導かれる（決定 14 の「SIMULATE はショート 初期 60%」と一致）

決定 14 の「三者比較では SIMULATE だけが保守側の外れ値になる」という指摘が実測で裏付けられた。

## 実装で判明した経緯

実機確認セッション（2026-08-05）。#342 の PoC として、クラスタ内の使い捨て Pod から実 OpenD へ probe を当てた（`moomoo-rsa` Secret をマウントできるため秘密鍵をクラスタ外へ出さずに済む）。発注を伴う操作と実弾口座への照会は利用者が実行した。

**判定を 4 回訂正している。** 経緯は作業仕様書に残した（4 件目は「ADR-0019 決定 1 を 6 項目と誤読した」件。起案時の submodule が古い pin `df8bce5` で checkout されており、項目 7 の追補が入っていなかった）。とくに「SDK の型定義に列挙値があることは、ブローカがその値を受理することを意味しない」（`TrdSide_SellShort` の件）は方法論上の教訓として IADR-0144 に引いた。

## 提案（計画への反映案）

- 反映先候補: **新 ADR**（ADR-0016 の決定 3・決定 14 を部分改定）／ADR-0019 の Accepted 化判断
- 提案内容:
  1. **ADR-0019 の PoC 結果を本 ADR へ追記し、Accepted 化を判断する。** **項目 1・2・4・7 は成立**、項目 3 は条件付き成立、**項目 6 は部分**（単一ノードでの 7 日 20 時間の観測）、**項目 5 は未確認**（SIMULATE では原理的に発生しない）である。
     **不成立時の帰結が適用されるのは項目 3 の一部だけ**であり、他の項目は帰結の適用を要しない。**項目 7 の成立により [ADR-0005](https://github.com/endazon/project-planning/blob/main/projects/ai-stock-trading/07_adr/ADR-0005_paid-datasource-policy.md) の有料枠の検討は不要になる**（反映先は ADR-0023。別記録を参照）。
  2. **ADR-0016 決定 3 を改める。** 借株料の閾値は発火しない。一次ゲートを `IsShortPermit`（借株可否）へ移す。閾値判定は残置し「発火しない既知の統制」として記録する。
  3. **ADR-0016 決定 14 の表を実測に合わせる。** 決定 3・決定 7 は「値は取れるが閾値に届かない」ではなく「**照会 API が SIMULATE で使えない**」である。
  4. **借株料の照会が実弾口座を要することを計画に明記する。** 発注環境と照会環境が分かれることは統制の設計に影響する。
  5. **項目 5（強制買戻し）の扱いを決める。** SIMULATE では原理的に発生せず、専用 API も見当たらない。決定 4 の「30 日間の禁止銘柄自動追加」の供給元が無いままである。事後の突合で代替するか、決定 4 を保留するかの裁定が要る。
  6. **項目 6 の観測期間の限界を記録する。** 現時点で 7 日 20 時間・5 回の再起動であり、Stage 1 の 3 か月に対する外挿である。Hetzner 等へ移す場合は再測が要る。
