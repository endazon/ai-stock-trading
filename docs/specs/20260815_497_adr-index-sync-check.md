# 仕様書: ADR 索引行の追随を機械検査する

> 本仕様書は実装着手前に作成する。

## 起点

- 起点 issue: [#497](https://github.com/endazon/ai-stock-trading/issues/497)
- 起点 ID: **NFR**（工程の統制。計画側の非機能要件表に当たる番号が無いため無採番。planning#311 の 2）

## 事象（同型 2 回）

`docs/adr/` の ADR 本文を更新しながら、`docs/adr/README.md` の**当該 ADR の索引行を追随させない**事故が
**連続する 2 つの PR で起きた。** いずれも **AI レビューが検出**し、**CI は緑のまま通した。**

| # | PR | 何がずれたか |
| --- | --- | --- |
| 1 | [#491](https://github.com/endazon/ai-stock-trading/pull/491) | 本文・仕様書を「自己試験 **16 件**」へ更新したが、索引行は**「11 件」のまま** |
| 2 | [#495](https://github.com/endazon/ai-stock-trading/pull/495) | 本文を「遅れ **1** 件／双方向 **1** 件」へ訂正し残余リスクも「✅ 解消」へ書き換えたが、索引行は**「遅れ 2 件」「🔴 本 PR が初めての実測」のまま** |

> 🔴 **2 件目は、まさに「記述が実態と食い違う」ことを主題にした PR の中で起きた。**

`.claude/rules/traceability.md` の**規則 7**（「数値・名前を 1 つ直したら、その値を持つファイルを
全走査し直す」）が正面から当たるが、**規約として書かれていても守られなかった** ——
同ファイルの末尾が「**この規則を守っているかを見る機械は無い**」と自認しているとおりである。

運用標準は「**検査器・規約の追加は同型事故 2 回から**」（`planning/docs/ai-implementation-workflow-guide.md`）。**2 回に達した。**

## 🔴 なぜ実害があるか

**索引行は ADR 一覧を読む人が最初に見る要約である。** 本文が訂正されても索引が古いままだと、

- **解消済みの残余リスクが未解消の 🔴 として読まれる**（#495 の実例）
- **誤った件数・数値が「確定した実測」として引用される**（#491 の実例）

しかも `check-doc-links.js` は**リンク切れしか見ない**ため、**この種のずれは機械では一切拾えていなかった。**

## 決定

### 決定1: **構造で見る。内容の一致は見ない**

> **PR の差分に `docs/adr/IADR-XXXX_*.md` が含まれるなら、
> 同じ差分の `docs/adr/README.md` に `| IADR-XXXX |` で始まる行の変更があること。**

**索引行の「内容」が本文と一致しているかは機械では判定できない** —— 索引行は本文の**散文要約**であり、
文字列一致では意味を読めない。**人が読む前提である。**

#### 検討したが採らない案

| 案 | 採らない理由 |
| --- | --- |
| **索引行の数値と本文の数値を突き合わせる** | **対応関係が機械的に定まらない。偽陽性が大量に出て検査そのものが外される**（`check-cross-repo-refs.js` の `SELF_NAMES` 書き忘れで実測 22 件が上がった前例と同じ道） |
| **索引を本文から自動生成する** | 索引行は「**1 行に要約する**」という人間の判断そのものであり、生成できない。**生成すると要約の質が落ちる** |

### 決定2: **偽陽性へ倒す。ただし逃げ道は用意し、黙って素通りさせない**

本文の誤字修正だけなら索引の変更は要らないが、**それでも赤になる。**
**偽陰性より偽陽性へ倒す**のは [IADR-0190](../adr/IADR-0190_review-verdict-gate.md) と同じ判断である
—— **落ちれば人が気付くが、緑の素通りは誰も気付かない。**

**逃げ道**: コミット本文（または `PR_TITLE`）に **`[skip-adr-index]`** と書く。
**宣言すると `notice` が出る** —— **黙って素通りにはならない。**

### 決定3: **削除行も「索引を触った」と数える**

索引行の書き換えは diff 上「**削除＋追加**」として現れる。**追加行だけを見ると、
行を消しただけの変更（ADR の廃止等）を見逃す。** `+` と `-` の両方を見る。

### 🔴 決定4: CI は `fetch-depth: 0` を指定する

範囲（`origin/<base>..HEAD`）を解決するために全履歴が要る。
**浅いクローンでは範囲を決められず skip する** —— **指定を忘れると検査は永久に skip して緑を返し続ける**
（[IADR-0191](../adr/IADR-0191_kit-sync-classification.md) 決定3 と同じ型の穴）。**CI 設定側を回帰テストで固定する。**

## やらないこと

- **計画 ADR（`ADR-XXXX`）の検査** —— 別リポジトリにあり対象外。
- **索引行の内容の検査**（決定1）。
- **既存の索引行の一括点検** —— 現時点で **ADR 193 件・索引行 193 件で欠落ゼロ**を実測済み。
  **内容のずれは機械では見えない**ため、点検するなら人が読むしかない（本作業の範囲外）。

## テスト方針

| 何を守るか | どう守るか |
| --- | --- |
| 判定規則（索引を触ったか） | 自己試験 12 件（合成した差分） |
| **実データで捕まえられること** | **回帰テスト（#491 / #495 の実コミットを食わせる）** |
| **偽陽性を出さないこと** | 回帰テスト（是正コミットで緑） |
| **CI が skip して緑にならないこと** | 回帰テスト（`fetch-depth: 0` と自己試験の実行を固定） |

> **自己試験は「判定規則が正しいか」しか示さない。「実データで捕まえられるか」は別の問いである。**
> **過去の事故そのものを回帰に入れた**のはそのためである。

### 🔴 自分自身へ適用して欠陥を 1 件見つけた

**初版の逃げ道判定は `body.includes(SKIP_TOKEN)` であり、自己発火した。**
本検査器を導入したコミットのメッセージが**逃げ道を説明する文の中でトークンを書いており、
それが宣言とみなされた**（索引行を落としても緑になった）。

> **planning#319 知見3 と同型。** 本セッションで**同じ罠に落ちるのは 3 度目**である。
> **「新しい検査器は、まず自分自身に適用してみる」**——それをしなければ気付かなかった。

**是正**: トリムした行が完全に一致する場合のみ宣言とみなす。**自己試験を 2 件追加。**

## 残余リスク

- 🔴 **索引行を「触った」ことしか見ない。** **中身が本文と合っているかは見ない** ——
  **1 文字だけ変えれば通る。** 本検査が防ぐのは「**丸ごと忘れる**」ことだけである。
- **本文の誤字修正でも赤になる**（決定2 の意図的なトレードオフ）。
  **`[skip-adr-index]` が濫用されれば検査は形骸化する** —— notice は出るが、**読む人がいなければ同じである。**
- **浅いクローンでは skip する。** `fetch-depth: 0` を回帰テストで固定したが、
  **ワークフローを別ファイルへ移すなどすればテストの前提が外れる。**
