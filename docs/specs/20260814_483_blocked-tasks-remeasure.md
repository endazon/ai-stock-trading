## 実測1: A-6（Playwright E2E のローカル実走）—— **記述は成り立たない**

### 現在の記述

> **現況**: サンドボックスで**ブラウザ取得が失敗**する（`Failed to download Chrome for Testing`）。実走は **CI の `frontend-e2e`**。
> **なぜ AI にできないか**: 環境側の制約。CI では動くため、**運用としては「E2E は CI に委ねる」で成立している**

### 実測（2026-08-14）

| 測ったこと | 結果 |
| --- | --- |
| ブラウザの有無 | **既に導入済み**（`/opt/pw-browsers` に `chromium-1194` ほか）。**ダウンロードは発生しない** |
| 素で `npx playwright test` | **失敗**。`Executable doesn't exist at /opt/pw-browsers/chromium_headless_shell-1228/...` |
| 失敗の正体 | **バージョンの食い違い**。リポジトリが固定する `@playwright/test` **1.61.1** はブラウザビルド **`-1228`** を要求するが、導入済みは **`-1194`** |
| `executablePath` を明示して実走 | **60 tests passed（21.6 秒）** |

**「ブラウザ取得が失敗する環境側の制約」ではない。** 実際は
**pin したバージョンとプリインストール版のビルド番号がずれているだけ**であり、
**設定 1 つで解消する。**

> **#483 提案 4 の疑い（環境観測を恒久制約として書いている。MSP #617 と同型）は当たっていた。**

## 実測2: B-3（GitHub Secrets の登録）—— **「権限が無い」は 3 つの別物を混ぜている**

### 現在の記述

> **なぜ AI にできないか**: Secrets の読み書き権限が無い

### 分解して測る

| 分解 | 実測・根拠 | 種別 |
| --- | --- | --- |
| **(a) 値の読み取り** | **誰にもできない。** GitHub は登録済み Secret の値を**所有者にも返さない**（設計）。**AI の権限の問題ではない** | **恒久**（普遍） |
| **(b) 登録（書き込み）** | 権限としては **admin が要る**。B-2 の実測（2026-08-14・#473）で**本リポに `admin: true`** が確認されている。**能力の不在ではなく、規則による禁止**（リポジトリ設定の変更は利用者に留保）と読むべきである | **規則**（B-2 と同型） |
| **(c) 本セッションからの操作** | **できない。** Secrets を列挙・登録する MCP ツールが**本セッションのツール一覧に存在しない**（実測 2026-08-14）。`gh` CLI も本環境では使用できない | **能力**（この経路に限る） |
| **(d) 登録済みかどうか** | **登録済みと判断してよい。** AI レビュー（`claude-code-review.yml`）が**本日だけで 8 回以上、認証に成功して完走している**。認証情報が未登録なら起動時に失敗する | **観測** |

**「セッションからは確認できない」という現況記述は (d) の点で古い** —— **間接的には確認できている。**

## 実測3: ラベルの存在 —— **3 つとも存在する**

#483 は「これらのラベル自体が本リポジトリに存在するかどうかは `gh label list` が使用不可のため未確認」としていた。**API で実測した。**

| ラベル | 存在 | 説明 | 付与数 |
| --- | --- | --- | ---: |
| `blocked:env` | **有り** | （説明なし） | 2 |
| `blocked:decision` | **有り** | 裁定待ちでブロック中（**棚卸しごとに再検証する**） | **0** |
| `blocked:human` | **有り** | 人間の操作・権限が要りブロック中（**棚卸しごとに再検証する**） | **0** |

> 🔴 **`blocked:decision` / `blocked:human` は説明文に「棚卸しごとに再検証する」と書かれているのに、
> 付与が 0 件である。** **再検証すべき対象を 1 件も持たない運用標準**になっている。

## 決定

### 決定1: A-6 を実測で書き直す。**恒久制約の側から外す**

- 現況を**実測に置き換える**（ビルド番号のずれ・`executablePath` で実走・60 passed / 21.6 秒）。
- **「なぜ AI にできないか」の行を削る** —— **できる。**
- 代わりに**再現手順**を書く（次に誰かが測るときに同じ手順を踏めるように）。
- **B-2 と同型式**（最後に測った時点・再測定手順）を持たせる。

### 決定2: B-3 を (a)〜(d) に分けて書き直す

**「権限が無い」の一言に、性質の違う 4 つが混ざっていた。**
**混ぜたまま書くと、環境が変わっても誰も測り直さない**（B-2 の是正と同じ理由）。

### 決定3: A-7 を「解消し得る前半」と「恒久の後半」に分ける

- **前半（実 Discord サーバ・Bot トークンの用意）**: テスト用サーバとトークンの発行は**環境構築で解消し得る**。
- **後半（利用者本人による昇格承認）**: **設計上の要請であり恒久**（AI が自分に課す関門を自分で通さない）。

### 決定4: ラベルを付ける。**説明文の約束を実効させる**

`blocked:decision` / `blocked:human` が 0 件では、**「棚卸しごとに再検証する」対象が存在しない。**
該当する open issue へ付与する。

### 決定5: 受け皿の無い項目を起票する

**blocked-tasks.md に書いてあるが GitHub issue が無い**項目は、棚卸しの俎上に載らない。

## やらないこと

- **B-2 の記述の変更**（既に是正済みの手本である）。
- **`blocked:env` の説明文の追加**（ラベル説明の整備は本作業の範囲外。必要なら別途）。
- **A-1（Hetzner ToS）の再測定** —— 法的判断であり、測り直す対象ではない。
- **Secrets の実際の登録・変更**（規則による禁止。利用者の操作）。

## テスト方針

**本作業は文書と issue の整備であり、コードの変更を伴わない。**
機械検査は既存のもの（`check-doc-links.js`）で足り、**新しい検査器は追加しない**
（同型事故 2 回に達していない。運用標準「検査器の追加は同型事故 2 回から」）。

**ただし A-6 の実測は再現手順を書き残す** —— 次の棚卸しが**同じ手順で測り直せる**ことが、
IADR-0185 決定4 の実効性そのものである。
