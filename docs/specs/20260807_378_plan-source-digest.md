- ユースケース（UC）: なし

- 起点 issue: [#378](https://github.com/endazon/ai-stock-trading/issues/378)（発見の経緯は [#374](https://github.com/endazon/ai-stock-trading/issues/374) / PR #372）

## 目的・背景

`IADR-0127` の計画適合レジストリは `PlanRiskDefaults`（計画値）と `ActualDefaults`（実装値）の乖離を機械的に検出する。**しかし計画書そのものと `PlanRiskDefaults` の間は人手転記であり、無検査である。**

#374 の実測が穴を数字で示した——**submodule を更新しただけでは赤くならない**（Failed: 0）。赤が出たのは監査者が計画差分を読んだからであって、読まなければ検出されなかった。

## 対象範囲

### 対象

**計画書の該当節のダイジェスト（SHA-256）を実装側に保持し、節が変わったらテストを赤にする**（IADR-0166 決定1・案 C）。

| 追加物 | 役割 |
| --- | --- |
| `PlanSourceReader` | planning ルートの探索・**節の切り出し**・正規化・SHA-256 |
| `PlanSourceDigests` | 「節 → 最後に転記した時点のダイジェスト」の表（10 節） |
| `PlanSourceDigestTests` | 検査本体＋表の健全性＋正規化の否定形＋節切り出しの境界 |

対象の節（`PlanRiskDefaults` が引用する範囲）:

- `05_trading-assumptions.md` の **§1 / §3 / §4 / §5 / §6 / §6.1**
- `ADR-0008` / `ADR-0016` / `ADR-0018` / `ADR-0022` の **`## 決定` 節**

### 対象外（意図的にやらない）

- **計画書からの値の抽出**（IADR-0166 案 B の棄却）。抽出失敗が「緑」に見える形で壊れるため
- **計画側への機械可読ブロックの導入**（案 A の棄却）。計画書は人間が読む散文であり、実装都合で構造を強制しない
- **`ActualDefaults` の抽出候補配列の網羅性検査**（IADR-0166 決定5）。既存の検査2 が「計画キーに対応する実装値が解決できているか」を既に見ており、候補配列側の検査は #378 が挙げた 2 類型のうち 1 つにしか効かない
- **`PlanRiskDefaults` の中身の変更** —— 本作業は検知機構のみ。値の追随は担当 issue が行う

## 設計

### 節の切り出し

見出しを**前方一致**で探し（例 `### 5.`）、**同位以上の次の見出し**の直前までを 1 節とする。見出し行自体を節に含めるため、**表題の変更も検知される**。

**ファイル全体をハッシュしてはならない**（IADR-0166 決定2）。計画書には `## 変更履歴` が改訂のたびに追記されるため、全体ハッシュでは計画側のあらゆる更新で赤くなり、**「中身を読まずにダイジェストだけ更新する」運用へ堕ちる**。それは検査が無いより悪い。節単位なら `## 変更履歴` は別の `##` 節として自動的に対象外になる。

### 正規化

改行コード（CRLF→LF）と**行末空白**を落とし、末尾の空行を落とす。**これ以上は行わない**——全角/半角や表の整形まで正規化すると**内容の変化を吸収し得る**（＝検知漏れ）。

### submodule 未取得時

**skip する**（IADR-0166 決定4・fail-open）。ただし **skip したことを notice で出す**（`check-doc-links.js` と同じ規律。「緑だが検査されていない」を可視化する）。

## 受け入れ基準

- [x] 実装 ADR で抽出方式を決定し、**棄却案の理由を残す**（IADR-0166）
- [x] 計画書の該当節を変更すると **CI が赤になる**ことを実測で示す
- [x] **行末空白・改行コードだけの変更では赤くならない**ことを実測で示す（誤検知の抑制）
- [x] submodule が未取得の環境では **skip する**
- [x] 抽出候補配列の網羅性について**方針を決めた**（追加しない・IADR-0166 決定5 に理由）
- [x] `dotnet build` / `dotnet test` / `dotnet format` が緑

## テスト方針

| テスト | 内容 |
| --- | --- |
| `計画書の該当節が最後の転記時点から変わっていない` | 本体。submodule 未取得なら notice を出して skip |
| `ダイジェスト表に重複が無くパスと見出しが埋まっている` | 表の健全性（submodule 非依存） |
| `正規化は改行と行末空白だけを吸収し内容の差は吸収しない` | **否定形**。吸収しすぎ＝検知漏れを止める |
| `節は同位以上の見出しで打ち切り下位見出しは含める` | 境界。`## 変更履歴` を含めないことの担保 |

**実測での検証**（#378 の受け入れ基準が要求）: 計画書を実際に書き換えて赤／緑を確認する。

## 残余リスク

1. **ダイジェストだけを更新して緑に戻せる。** 本機構は「気づく機会を作る」ものであり、正しさを保証しない（IADR-0166 決定1 の位置づけの帰結）。**レビューで見るしかない。**
2. **submodule を取らないジョブでは効かない**（決定4 の fail-open）。notice で可視化するにとどまる。
3. **計画書の節構造に依存する。** 見出しの改名・再編で「節が見つからない」赤になる（安全側だが、計画側の正当な整理でも赤くなる）。この場合はハッシュ不一致とは**別の文言**で報告し、`HeadingPrefix` の追随を促す。
4. **ダイジェストの更新が計画追随 PR の作業として毎回発生する。** 意図した摩擦だが、摩擦である。
