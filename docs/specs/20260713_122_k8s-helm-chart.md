# 仕様書: AST k8s Helm chart（Issue #122）

## 起点となる計画書（トレーサビリティ）

- 機能要求（FR）: FR-02（取引サイクル。CronJob 化は #121）
- 関連 ADR: ADR-0006（Hetzner k3s・GitOps）／ADR-0001（platform 再利用・DB per service）
- 実装判断: [[IADR-0052]]（Helm chart・ExternalName で共有インフラ参照・CronJob 既定無効）
- Issue: #122（本 issue）／ #24（k3s デプロイ）／ #121（取引サイクル CronJob）／ #22（拡張規約準拠）

## 目的・背景

AST を MSP 連結のローカル k8s(k3d) dev 環境で稼働させるため、k8s デプロイ資産（Helm chart）を新設する。
AST には従来 compose しか無く（#24 が「デプロイ構成が存在しない」と明記）、これが #121 の CronJob 検証の前提。
共有インフラ（Postgres/RabbitMQ/Keycloak/otel）は MSP 側 `platform-infra`（IADR-0066）を参照する。

## 対象範囲

**対象（本 PR）**
- `deploy/helm/ai-stock-trading`: 10 Worker の Deployment/Service（同型テンプレート）・namespace・
  共有インフラ ExternalName エイリアス・#121 CronJob 骨子（既定無効）。
- `scripts/k8s-local-{images,deploy}.sh`: 10 イメージの build+import と helm 適用。
- 外部連携 env の fail-safe 既定（`ast-secrets` 空既定）。
- IADR-0052・本作業仕様書。

**対象外（後続）**
- #121 の run-once エンドポイント（`/internal/collection/run-once`）＋スケジューラモード切替の C# 実装（TDD）。
- 実外部接続（#13 moomoo 実弾 / #79 実 LLM / #81 実市場データ / #15 Discord）。
- #24 の Hetzner リージョン実測・Vault・実費用。

## 設計

- 10 Worker は全て Web SDK :8080（`/health/{live,ready}`）で同型 → `range .Values.services` でレンダリング。
- DB 保有サービスは `ConnectionStrings__DefaultConnection`（共有 Postgres・user=ai・専有 `*_svc`）を注入。
  認証保有サービスは `Auth__Authority=http://keycloak:8080/realms/ai-stock-trading` を注入。
- 素のサービス名（postgres 等）は AST namespace 内 ExternalName で `platform-infra` へ解決。
- 外部連携は `ast-secrets`（anthropic/finnhub/discord・空既定・`optional:true`）＋ `Broker__Provider=paper`。
- #121 CronJob（`trading-cycle-trigger`）は `tradingCycle.cronjob.enabled=false` 既定。有効化時は
  収集の run-once を curl で叩く。休場・費用停止は収集側でゲート（no-op）。

## 受け入れ基準

- [ ] `helm template` が 10 Deployment/Service ＋ 4 エイリアス ＋ namespace を生成（CronJob は enabled 時のみ）
- [ ] 既定で外部連携が fail-safe（no-op / paper）で起動する env になっている
- [ ] k3d 実クラスタで 10 Worker が Ready・共有インフラへ疎通・専有 DB へ接続（要ユーザ環境）
- [ ] CronJob は既定無効で在来 in-process を維持（#121 実装で有効化）

## テスト方針

- `helm template`（既定 / `--set tradingCycle.cronjob.enabled=true`）でレンダリング検証。
- 疎通は `kubectl -n ai-stock-trading get pods` と各 `/health/ready` で確認（k3d）。
- CronJob の起動は `kubectl create job --from=cronjob/trading-cycle-trigger`（#121 実装後）。

## 計画書との差異

  「k8s デプロイ構成が存在し適用できる」を先行実証）。/plan-feedback で #24 の分割を計画へ環流予定。
