## 目的・背景

計画大改定（project-planning PR #144）で段階ゲート（FR-20）の判定規則が数値まで確定した。実装は
[#20](https://github.com/endazon/ai-stock-trading/issues/20)（2026-07-17・IADR-0041/0070）の骨格のままであり、
確定した規則のほとんどを持たない。とりわけ次の 1 点は**統制の緩みとして現に危険**である。

> `Stage0GateCriteria.MaxDrawdownTolerance` は旧レンジ「10〜15%」の上限側を採って **0.15** である。しかし
> 運用の DD 停止ラインは **10%** であり、**Stage 0 は運用停止ラインより 5 ポイント緩い戦略を合格させ得る**。
> 検証で通した戦略が運用に載った瞬間に停止条件へ抵触し得るという、ゲートとして倒錯した状態である。
> （[ADR-0018](../../planning/projects/ai-stock-trading/07_adr/ADR-0018_risk-defaults-sync-and-stage0-dd.md) コンテキスト）

## 実装方針

### 1. Stage 1 期間カウント（IADR-0137）

- `Stage1TradingDayObservation(SessionDateEasternTime, RegularSessionMinutes, OperationalMinutes)` を
  **観測記録として受け取る**。**その日の通常取引時間の長さ（6.5h / 3.5h）を実装が導出しない。**
  計画は分母を「その日の**実際の**通常取引時間」と定めるだけで、**半日取引日カレンダーの出どころを述べていない**。
  発明せず観測値として受ける（[ADR-0022 決定3](../../planning/projects/ai-stock-trading/07_adr/ADR-0022_fx-rate-source-and-freshness.md)
  が別件で「営業日カレンダーを保持しない」と裁定した向きとも矛盾しない）。→ [feedback](../../feedback/20260804_fr20-stage1-session-calendar.md)
- 判定: `OperationalMinutes / RegularSessionMinutes >= 0.50` で 1 日。**ちょうど 50% は算入する**。
- 除外: `RegularSessionMinutes <= 0`（市場休場）は算入しない。OpenD 停止・ブローカー障害は
  `OperationalMinutes` の減少として自然に落ちる（別枠の除外フラグを設けない）。
- **日付は米国東部時間の取引日**（`SessionDateEasternTime`）で受ける。DST の切替は「その日の
  実際の通常取引時間」が観測値であることで吸収され、実装がタイムゾーン変換を行わない。

### 2. 昇格判定・打ち切り（IADR-0137）

`Stage1GateCriteria(TargetTradingDays: 60, MinimumTradeCount: 100, MaximumTradingDays: 120)` を
`StageGatePolicy` が保持する（テストは設定から引く。マジックナンバーを書かない）。

| 状態 | 条件 | 扱い |
| --- | --- | --- |
| `InProgress` | 営業日 < 60 | 昇格不可 |
| `Extended` | 営業日 ≥ 60 かつ 件数 < 100 かつ 営業日 < 120 | 昇格不可（**期間を延長する。件数は下げない**） |
| `Promotable` | 営業日 ≥ 60 かつ 件数 ≥ 100 | 他条件を満たせば昇格可 |
| `Exhausted` | 営業日 ≥ 120 かつ 件数 < 100 | **打ち切り**。撤退評価が Stage 0 差し戻しを提案する |

Stage 1→2 の未充足基準は `Stage1TradingDaysInsufficient` / `Stage1TradeCountInsufficient` /
`ControlViolationsPresent` / `Stage1ExtensionExhausted`。

### 3. 段階別の商品種別強制（IADR-0139）

`StageProductPolicy.Evaluate(stage, effectiveProductType, equity, release)` を `RiskEvaluator` の
**`isEntry` ブロック**から呼ぶ。手仕舞い・損切りは止めない（project-planning#179・ADR-0009・IADR-0132 決定4）。

| Stage | 現物 | 信用買い | 空売り |
| --- | --- | --- | --- |
| Stage 0 / Stage 1 | 許可 | 許可 | 許可（Stage 1 は 3 種すべて検証する） |
| Stage 2 | 許可 | **拒否** `StageProductTypeProhibited` | **拒否** `StageProductTypeProhibited` |
| Stage 3 | 許可 | 許可 | equity ≥ $5,000 **かつ** 空売りを含む戦略で Stage 0 再充足。いずれか欠けば `StageShortSellReleaseUnmet` |

### 4. Stage 2 の発注可能額（総資金比 0.30。IADR-0136）

`StageSettings(Stage, Mode, CapitalCapRatio)` へ改め、`OrderableCapFor(equity)` で解決する
（`RiskLimitSettings.MaxOrderAmountFor` と同じ規律。IADR-0130 決定1）。

## 実装したが発動しない部分（供給元・ドライバの不在）

**本作業で追加した判定は、いずれも入力の供給元が無いため実運用では発火しない。** 既定はすべて
fail-closed（昇格しない・発注しない）側であり、統制が緩む向きの不発は無い。

| 判定 | 不足している供給元 | 既定の振る舞い | 担当 |

1. **半日取引日カレンダーと DST の出どころが計画に無い。** §4.2 は分母を「その日の実際の通常取引時間
   （通常日 6.5 時間／半日取引日 3.5 時間）」「判定の基準時刻は米国東部時間」と定めるが、**その日が半日取引日か

   → [feedback/20260804_fr20-stage1-session-calendar.md](../../feedback/20260804_fr20-stage1-session-calendar.md)
2. **Stage 3 の空売り実弾解禁の第 2 条件（Stage 0 再充足）の verdict 形式が計画に無い。** 通常の Stage 0
   verdict と別立てにするのか、同じ verdict に「空売りを含む戦略か」の属性を持たせるのかが未定である。
   実装は fail-closed に倒し、`StageReleaseContext` を差し込み口として残した。
3. **equity の $5,000 判定は基準通貨（円）建てで行っている。** 計画（ADR-0016 決定6）は USD 建てを正とするが、

   `TradingDefaults.ReferenceUsdToJpyRate`（計画 §5 が明記した 163.7）による 1 点換算を用いた。
   実勢レートでの equity 評価は本 issue の範囲外である。
