# 仕様書: 統合 E2E 基盤 Slice B/C（issue #82・差分）

> Slice A（[作業仕様書](20260712_82_integration-e2e-foundation.md)・PR #114 マージ済み）の続き。
> Slice B（実 Keycloak トークンによる OwnerOnly 同期照会エンドポイント E2E）と Slice C（複数サービスを
> またぐイベント駆動パイプライン E2E）を追加する。設計判断は
> [IADR-0050](../adr/IADR-0050_e2e-multiservice-and-auth.md)。

## 起点となる計画書（トレーサビリティ）

- 起点: issue #82（Slice B/C）。基盤: IADR-0049（Slice A）
- 参照: IADR-0011（Keycloak OIDC/JWT・OwnerOnly）・platform ADR-0004（認証認可）
- **#76 依存分は分離**: 呼び出し側のサービストークン伝播（daily-policy/sizing-context/open-positions を
  呼ぶ側）は #76（OPEN）。本 PR は #76 に依存しない範囲（エンドポイント側 RBAC・イベント連鎖）に限定。

## 目的・背景

Slice A は発注執行 1 サービスの実基盤 E2E を確立した。本作業で (1) OwnerOnly エンドポイントを実 Keycloak
トークンで検証し、(2) 同期照会を経由しない複数サービスのイベント連鎖を通しで検証する。実接続・実発注・
実 LLM は引き続き既定 no-op（ペーパー）。

## 対象範囲（Slice B/C）

- 対象:
  - **Slice B（Keycloak OwnerOnly 認証 E2E）**: リスク管理 Worker を実 Keycloak＋実 PostgreSQL＋実 RabbitMQ へ
    結線。dev realm の ROPC で `trading-owner` トークンを取得し、`GET /risk-controls/open-positions`
    （#76 最優先エンドポイント）を検証。**トークンあり→200 / トークンなし→401**。実 OIDC 発見・JWKS 検証・
    realm ロール→OwnerOnly ポリシーを通しで確認。
  - **Slice C（マルチサービス イベント E2E）**: リスク管理＋発注執行の 2 Worker を共有 RabbitMQ／共有
    PostgreSQL へ結線。`TradeDecisionMade` を発行 → リスク管理スクリーニング（実台帳・既定資金
    `TradingDefaults.InitialCapital`）→ `OrderApproved` → 発注執行（ペーパー）→ 実 Postgres の
    `executed_orders` へ永続、を検証。
  - 統合テストプロジェクトへ `Testcontainers.Keycloak` とリスク管理 Worker 参照（extern alias）を追加。
- 対象外（#76 / #79 依存・後続）:
  - 呼び出し側（取引判断・市場監視）が同期照会へサービストークンを付与する経路（**#76**）。
  - 実 LLM を伴う「情報収集→取引判断」前段（**#79**）と、市場監視の保有取得（open-positions 同期照会・
    **#76**）を起点とする損切り検知パイプライン。

## 設計方針（要点。詳細は IADR-0050）

1. 複数 Worker 参照は **extern alias** で `Program` の曖昧を回避（発注執行=global・リスク管理=alias）。
2. マルチサービス E2E は**単一 PostgreSQL を共有**（テーブル非衝突）し、プロセスグローバルな環境変数の
   サービス別競合を回避。RabbitMQ も 1 つ共有。
3. 実 Keycloak トークンは dev realm の **ROPC** で取得し、`iss` と Worker の `Auth:Authority` を同一 base URL に
   揃えて JWT 検証を成立させる。
4. すべてペーパー（実弾なし・IADR-0016）。`Category=Integration` で既定 CI から分離（IADR-0049）。

## 受け入れ基準（issue #82 の受け入れ条件へ写像・Slice B/C 分）

- [x] サービス間同期照会エンドポイント（open-positions）を実 Keycloak トークンで検証（Slice B: 200/401）
  - daily-policy/sizing-context も同型で追加可能（本 PR は最優先の open-positions を代表実装）
  - **呼び出し側のトークン伝播（#76）は対象外**（明示分離）
- [x] 主要パイプラインの通し E2E（Slice C: TradeDecisionMade→承認→執行→永続の複数サービス連鎖）
- [x] 既定 CI から分離（`Category=Integration`）・実基盤 E2E は nightly（Slice A の integration.yml を踏襲）

## 検証方法

- ローカル（Docker）: `dotnet test --filter Category=Integration` で Slice B/C が緑（実 Keycloak/PG/MQ 起動）。
- 既定 CI: `--filter Category!=Integration` で全ユニット緑・E2E 非実行。
- `dotnet format --verify-no-changes` 緑。
