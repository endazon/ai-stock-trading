# 仕様書: 最小期待利益の計画追随

> 本仕様書は実装着手前に作成する。

## 起点となる計画書（トレーサビリティ）

- 一次情報: `planning/.../06_technical/05_trading-assumptions.md` **§4**（最小期待利益・利用者決定 2026-07-23）・**§1**（譲渡益税率 20.315%）
- 機能要求: **FR-17**（全体前提条件）・**FR-02**（取引判断サイクルのガードレールとして消費）
- 起点 issue: [#358](https://github.com/endazon/ai-stock-trading/issues/358)（`bug`。検知元は #343 / PR #350 の計画適合レジストリ拡張）
- 実装 ADR: **[IADR-0173](../adr/IADR-0173_minimum-expected-profit-tax-inclusive.md)（本作業で新設）**／既存: [IADR-0021](../adr/IADR-0021_trading-assumptions-configuration.md)（概算費用関数）・[IADR-0076](../adr/IADR-0076_trade-decision-profitability-gate.md)（採算ゲート）

## 目的・背景

**計画は 2026-07-23 に「往復費用＋税の 2 倍」で確定したが、実装は 2 点で乖離している。**

| | 実装 | 計画 §4 |
| --- | --- | --- |
| 倍率 | **1.5** | **2** |
| 基準 | **往復費用のみ**（税を含まない） | **往復費用＋税** |

経緯は #358 が特定済み —— 計画は `fbe162f` 時点では未確定の「&lt;1.5 倍&gt;」で、`4f594cb`（2026-07-23 利用者決定）で確定した。**2026-07-18 の実装は確定前の値のまま**である。

**本作業の着手時点で計画適合テストが緑なのは、値が一致しているからではない。** `KnownPlanDeviations` に #358 を担当とする登録行があるためである（IADR-0127 の運用）。**登録行の削除も本作業の範囲**であり、削除しないと以後は逸脱が「既知」のまま残り続ける。

## 設計上の要点 — **税をどう算入するかは計画に書かれていない**

計画 §4 は「往復費用＋税の 2 倍 を下回る取引は見送り」とだけ書き、**「税」が何に対する税かを定めていない**。#358 も「税の算入方法は §1 譲渡益税率 20.315% と整合させる。**設計判断は IADR に記録**」として実装側へ委ねている。

### なぜ自明でないか — **税は結果に依存する**

日本の譲渡益税は **譲渡益（＝ 売却額 − 取得費 − 費用）** に対して掛かる。つまり

```
税 = (期待利益 − 費用) × 税率
```

であり、**税を知るには利益を知る必要があるが、求めたいのはその利益のしきい値**である。素直に書くと循環する。

### 決定: **不動点として解く**（閉形式で求まる）

しきい値 `T`（＝ 最小の期待利益・**費用控除前**）が満たすべき式は

```
T = m × (C + (T − C) × r)
```

`m` = 最小期待利益倍率（2）・`C` = 費用（往復費用 ＋ 判断費用）・`r` = 譲渡益税率（0.20315）。整理すると

```
T = m × C × (1 − r) / (1 − m × r)
```

`m = 2` / `r = 0.20315` のとき **T ≈ 2.684 × C**（従来の 1.5 × C の約 1.79 倍）。

**この形は「税引後で見て費用の m 倍が残る」ことを意味しない。** 計画が書いているのは「利益が **費用と税の合計**の m 倍以上であること」であり、本式はそれをそのまま解いたものである。**計画の文言に忠実であることを、解釈で綺麗にすることより優先する。**

### 🔴 `m × r ≥ 1` は解が無い（fail-closed が必須）

分母 `1 − m × r` が 0 以下になると、**どれだけ利益が大きくても条件を満たせない**（利益を増やすと税も増え、要求が同じ速さで伸びる）。現在の値では `2 × 0.20315 = 0.4063` であり十分に離れているが、**設定は運用で変えられる**（倍率も税率も `TradingAssumptions` の可変フィールドである）。

**負のしきい値を返して全通過させることは絶対に避ける。** 該当時は `Indeterminate`（＝安全側 Hold）へ倒す。

## 対象範囲

### 対象

| # | 変更 | 内容 |
| --- | --- | --- |
| 1 | `TradingAssumptionsDefaults.MinimumExpectedProfitMultiple` | **1.5 → 2** |
| 2 | `ProfitabilityGate.Evaluate` | しきい値を**不動点の閉形式**へ。税率を引数に追加し、`m × r ≥ 1` を `Indeterminate` へ |
| 3 | `TradeCostAssessment` | **税率を運ぶ**（ゲートは Domain であり設定サービスに依存できない） |
| 4 | `CostCalculator.MinimumViableProfit` | 同じ閉形式へ。「税は後続」というコメントを解消 |
| 5 | `KnownPlanDeviations` | **#358 の登録行を削除**（IADR-0127 の機械的強制） |
| 6 | 文書 | `IADR-0021`・`docs/specs/20260718_trade-decision-profitability-gate.md`・`docs/data/trading-assumptions.md` の是正 |

### 対象外（意図的にやらない）

- **税の精緻化**（損益通算・繰越控除・NISA 区分・米国株配当の外国税額控除）。ゲートは**発注前の見積り**であり、年間の課税計算とは別物である。§1 の譲渡益税率 1 本で見積もる。
- **`ProfitabilityOptions.DecisionCostJpy` の扱いの変更**。判断費用は従来どおり費用 `C` に加算する。
- **スリッページの算入**。計画 §4 は最小期待利益の基準に含めていない（別行の「スリッページ想定 0.1%」は AI 判断の採算計算に使う値であり、本ゲートのしきい値式には現れない）。

## 受け入れ基準

- [ ] 税率 0 なら従来式 `m × C` に一致する（退化の確認）
- [ ] **ミューテーション**: 分母を `1` に固定（＝税を無視）するとテストが赤くなる

## テスト方針

**このゲートは「緩む方向に壊れる」と、発注が増えるだけで何も赤くならない。** したがって次を固定する。

1. **境界**: しきい値ちょうどは `Viable`（`>=`）、1 円下は `NotViable`
2. **退化**: `r = 0` で従来式と一致（式の書き換えが値を壊していないことの対照）
3. **fail-closed**: `m × r ≥ 1` で `Indeterminate`（**負のしきい値を返さない**）
4. **数値**: `m = 2` / `r = 0.20315` / `C = 1000` で T ≈ 2684.27

## 計画へ環流する（`/plan-feedback`）

**「税」の算入方法が計画に書かれていないことは、実装側の判断で埋めてよい範囲を超えている可能性がある。**

本作業は #358 の指示（「設計判断は IADR に記録」）に従って**不動点解**を採るが、**計画側に裁定を求める**。争点は次の 2 つである。

1. **「往復費用＋税の 2 倍」の「税」は、期待利益に対する譲渡益税か。** 本作業はそう読んだ（§1 と整合）。
2. **不動点で解く（実効 2.684 倍）ことが意図どおりか。** 「税引後の利益が費用の 2 倍」という別解釈なら実効倍率は変わる。

**この差は発注件数に直接効く**（1.5 倍 → 2.684 倍で、通過する取引が大きく減る）。実装の解釈で確定させるべきではない。

## 残余リスク

1. **実効倍率が 1.5 → 2.684 へ大きく上がる。** 通過する取引が減る方向であり**安全側**だが、**Stage 1 の最小取引件数（100 件）に到達しにくくなる**可能性がある。段階昇格の実績に影響し得る。
2. **税率が可変フィールドである。** 運用で `m × r ≥ 1` へ近づけると、しきい値が急激に発散する（`r = 0.49` で `m = 2` なら 51 倍）。**fail-closed は「解が無い」場合だけを捕まえ、「解はあるが極端」は捕まえない。**
3. **見積りの税は実際の課税と一致しない**（損益通算・繰越控除を無視するため）。**過大に見積もる方向であり安全側**である。
4. **計画の解釈が本作業の読みと違えば、実効倍率が変わる**（上記の環流待ち）。
