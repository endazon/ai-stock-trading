# 作業仕様書 #152: 取引の一時停止/再開（pause/resume）

## 起点・関連

- 対象 Issue: [#152](https://github.com/endazon/ai-stock-trading/issues/152)
- 計画書 ID: **FR-10**（リスク統制）、**FR-14**（Discord 操作）、UC-06 / UC-07、ADR-0003 / ADR-0009
- 計画裁定: **ADR-0009**（pause を日次損失ロックアウトと別状態とし、3統制の優先順位を定める・Accepted・PR endazon/project-planning#29）
- 前提 IADR: [IADR-0008](../adr/IADR-0008_daily-loss-limit-basis.md)（日次損失ロックアウト・**変更しない**）、
  [IADR-0062](../adr/IADR-0062_discord-bot-gateway-and-authorization.md)（Bot 基盤・多層認証・owner トークン）、
  [IADR-0051](../adr/IADR-0051_service-to-service-auth.md)（s2s 最小権限）
- 本作業の設計判断: [IADR-0075](../adr/IADR-0075_pause-resume-state.md)

## 背景と課題

詳細設計 07_discord-bot-design.md（fixed）は kill switch とは別に `/pause` / `/resume`（新規発注の一時停止・再開＝
「kill switch より軽い統制」）と `/status`（稼働状態の参照）を定めるが、#15（PR #148）ではスコープ外とした。理由は
**RiskManagementService に pause 相当の状態・API が無く、Bot から「呼ぶだけ」で済まなかった**ため。本作業はこの欠落を
埋める。計画側は #152 の指摘を受けて ADR-0009 で裁定済み（pause を別状態・優先順位確定）。

## 状態設計（ADR-0009 準拠）

3 統制はいずれも **新規建て（エントリー・`PositionEffect == Open`）のみを止め、手仕舞い（Close）・損切りは止めない**。
OR 条件（いずれか成立で新規建て停止）。優先順位（重い順）は表示にのみ用い、判定は OR。

| 統制 | 優先 | 発動 | 解除 | 実装経路 | ゲート位置 |
| --- | --- | --- | --- | --- | --- |
| kill switch（既存） | 1 | 利用者 | `/killswitch off`（フレーズ必須） | `PortfolioSnapshot.KillSwitchEngaged` | `RiskEvaluator` |
| 日次損失ロックアウト（既存） | 2 | システム自動 | 翌営業日（機械） | `ILockoutStore` | `OrderScreeningService` |
| 一時停止 pause（本作業・新設） | 3 | 利用者 | `/resume`（ボタンのみ） | `PortfolioSnapshot.TradingPaused` | `RiskEvaluator`（kill switch と同位置） |

pause は kill switch の完全ミラー経路（`IPauseStore` → `PortfolioSnapshotBuilder` → `RiskEvaluator`）。
lockout は `OrderScreeningService` に留め、`/resume` は pause のみ解除する（重い統制を軽い統制で解除させない）。

## スコープ

### Risk（RiskManagementService）

- `PauseState`（State/）、`IPauseStore`（Ports/）、`InMemoryPauseStore`（Adapters/）、`EfPauseStore` + `PauseRow` + Migration `AddTradingPause`。
- `PauseService`（Services/）: `GetState` / `Pause(actor,reason)` / `Resume(actor,reason)`。**冪等**（停止中の再 `Pause` は状態を返すのみ・記録もしない）。`ISettingsChangeLog` へ `TradingPaused` / `TradingResumed` を記録。
- `SettingsChangeType` に `TradingPaused` / `TradingResumed` を**追加**。
- `PortfolioSnapshot` に `TradingPaused`（bool）を**追加**。`PortfolioSnapshotBuilder` が `IPauseStore` から合成。
- `RiskEvaluator`: `isEntry && snapshot.TradingPaused` で `RejectionReason.TradingPaused` を追加（kill switch と同位置）。
- `RejectionReason.TradingPaused` を `Shared.Contracts` に**追加**（列挙追加1件のみ）。
- `RiskStatusService`（Services/）: kill switch / pause / lockout / stage / 当日損益 / 上限使用率 / ポジション と**優先中の統制**を集約。
- エンドポイント（owner サブグループ・親グループに認可を付けない）: `POST /risk-controls/pause`、`POST /risk-controls/resume`、`GET /risk-controls/pause`、`GET /risk-controls/status`。
- Program.cs DI: `IPauseStore`→`EfPauseStore`、`PauseService`、`RiskStatusService` を kill switch の隣接行へ登録。

### NotificationService（Discord Bot）

- `BotCommandKind` に `Pause` / `Resume` / `Status` を追加。`BotCommandParser` が `/pause`・`/resume`・`/status` を解析。
- `IPauseController` + `HttpPauseController`（owner マップ機密クライアント・`AddDiscordOwnerToken`）。`/status` 用の状態照会も持つ。
- `PauseCommandHandler`: 多層認証（`DiscordCommandAuthorizer` 再利用）→ 解析 → Risk 呼び出し。**確認フレーズは要求しない**（確認ボタンのみ）。
- `DiscordNetBotGateway`: `/pause`・`/resume`・`/status` を登録。pause/resume は確認ボタン→実行（モーダル無し）。`/status` は参照のみ（副作用なし）。
- Program.cs DI: `IPauseController`、`PauseCommandHandler` を kill switch の隣接行へ登録。

## 監査・イベントの設計判断（IADR-0075）

kill switch は MassTransit イベントを発行せず `ISettingsChangeLog`（`/settings/history`）で監査を満たしている。
pause/resume も**同経路で記録**するため、**新イベントは足さない・AuditService は無改修**。よって
`AuditConsumerCoverageTests` に影響なし。`Shared.Contracts` の変更は `RejectionReason.TradingPaused` のみ（追加）。

## 安全既定（fail-safe）

- 既定は**非 pause**。pause は**新規建てのみ**停止し、手仕舞い・損切りは継続。
- Bot は多層認証の設定が空なら全拒否（既存 `DiscordCommandAuthorizer`）。owner トークン未設定は 401/403＝操作失敗（成功に見せない）。
- pause 状態が不明（ストア障害等）でも「取引可能」側へ倒さない設計（EF 単一行・既定 NotPaused は明示的な行不在時のみ）。

## 受け入れ基準 → テスト対応

1. `/pause` で新規建てが停止し `/resume` で再開（往復） → `RiskEvaluatorTests`・`PauseServiceTests`
2. 停止中でも手仕舞い（Close）・損切りは止まらない → `RiskEvaluatorTests`（`PositionEffect.Close` は素通り）
3. pause/resume が冪等 → `PauseServiceTests`
4. 多層認証が kill switch と同水準（空なら全拒否） → `PauseCommandHandlerTests`（`DiscordCommandAuthorizer` 再利用）
5. OwnerOnly（trading-service は 403） → `RiskControlEndpointsTests`（pause/resume/status）
6. 監査ログに残る（アクター・理由・日時） → `PauseServiceTests`（`ISettingsChangeLog` 記録）
7. Discord `/pause`・`/resume` から駆動（確認ボタン2段階） → `PauseCommandHandlerTests`・`HttpPauseControllerTests`
8. `/status` で現在状態が表示（3統制の優先順位が明確） → `RiskStatusServiceTests`
9. `/status` は参照のみ → 設計上 GET のみ・Bot は状態変更経路を持たない
10. kill switch・ロックアウトに回帰なし → 既存テスト緑
11. 状態不明時に「取引可能」へ倒れない → `PauseServiceTests`・既定 NotPaused
