# 仕様書: キット追随の機械検査とドリフトの解消

> 本仕様書は実装着手前に作成する。

## 起点

- 起点 issue: [#492](https://github.com/endazon/ai-stock-trading/issues/492)
- 起点 ID: **NFR**（工程の統制であり計画側の非機能要件表に当たる番号が無いため無採番。planning#311 の 2）
- 先行実装: microservices-platform#734（同リポの IADR-0192）

## 事象（実測 2026-08-14）

`project-planning` の `tools/impl-handoff-kit/repo-template/`（**108 件**）に対し、
**本リポジトリの「バイト一致であるべき」ファイルが 5 件ドリフトしている。**

基盤実装リポ microservices-platform（以下 MSP）は同じ計測で **0 件**である。

| リポジトリ | vs pin (`130a109`) | vs planning 最新 (`3144424`) |
| --- | --- | --- |
| **ai-stock-trading** | 一致 60 / **差分 5** | 一致 60 / **差分 5** |
| microservices-platform | 一致 65 / 差分 0 | 一致 65 / 差分 0 |

**pin と最新で結果が同一である**ことを先に確かめた —— キット側は動いておらず、
**pin 遅れではなく本リポ側のドリフトである。**

### 🔴 差は仕組みの有無である

**MSP は `scripts/check-kit-sync.js` と `scripts/kit-sync-classification.json` を持ち、CI で機械検査している。**
**本リポジトリはどちらも持っていない。** 誰も見ていないので溜まった。

**これは本リポジトリが繰り返し扱ってきた「緑だが検査されていない」の一種である** ——
CI は緑であり続けたが、**キット追随という範囲がそもそも検査対象に入っていなかった。**

### 🔴 母集合の取り方で 1 度誤った（自戒・規則 2 の再発）

**最初の計測は planning の作業ツリー（`690b0c7`）に対して行い、`feedback/TEMPLATE.md` を
「両リポが進んでいてキットが古い」と読み違えた。** 実際は逆で、**手元のクローンが古かった**
（`130a109` は `690b0c7` の子孫であり、`git fetch` していなかった）。

**教訓: 比較の基準点そのものが古くないかを先に確かめる。**「差分がある」ことと
「どちらが古いか」は別の問いであり、後者は基準点の素性を確かめないと決まらない。
本仕様書の数値は **pin と最新の 2 点で測り直したもの**である。

## ドリフト 5 件と方向

**方向がばらばらであり、一律にキットで上書きしてはならない。**

| ファイル | 方向 | 中身 | 採る手 |
| --- | --- | --- | --- |
| `scripts/check-ai-workflow-config.js` | 🔴 **遅れている** | キット 723 行 / 本リポ 598 行。**キットが持つ検出（スタック別以外の Bash 指定の片落ちを ERROR にする）を丸ごと欠く** | **取り込む** |
| `scripts/commit-allowlist.json` | 🟡 **一部が遅れている** | `allow` の実エントリは正当（配布時は空）。**`_note` / 分類 `B` の方針文が改訂前のまま** | **方針文だけ揃え、分類 B へ** |
| `.claude/hooks/check-impl.js` | 🟢 **進んでいる** | フロントマター免除を名前付き集合へ切り出し、`blocked-tasks.md` を追加 | **環流し、分類 B へ** |
| `scripts/check-permission-denials.js` | 🟢 **進んでいる** | 引用符内の `\|` を判定する `hasQuotedPipe()` を追加 | **環流し、分類 B へ** |
| `.editorconfig` | ⚪ **正当なデルタ** | xUnit1051 の抑止は C#/xUnit v3 固有（[#352](https://github.com/endazon/ai-stock-trading/issues/352)） | **分類 B-2 へ（分類が誤っていた）** |

## 決定

### 決定1: 分類表を本リポ向けに作る

MSP の分類（A/B/C/対象外）を土台にする。**キット 108 件すべてが MSP の表に載っている**ことを
実測で確かめたため、**構造をそのまま借りられる**。本リポの実態に合わせて上表の 5 件を移す。

### 決定2: `check-kit-sync.js` を配備する。**ただしバイト一致の複製はしない**

**MSP 版のコメントは MSP の issue 番号を裸で引用している**（`#713` 等）。
**そのまま複製すると、本リポジトリの issue を指す誤リンクになる**（`.claude/rules/traceability.md`
「クロスリポジトリの issue / PR 番号の修飾」）。**修飾した形で書き直す。**

> **本ファイルはまだキットに無い**ため、**分類 C（本リポの中身）として置く**。
> キットが採用したら分類 A へ移す。**その時点で初めてバイト一致が要求される。**

### 決定3: 0 件走査で緑にしない門を置く

キットが未 populate なら skip（fail-open。既存の検査器と同じ規律）。
**ただし populate されているのに対象が 0 件なら fail する。**
**skip と「見たが 0 件」を混同しない。**

### 決定4: 進んでいる 2 件は環流する。**キットの内容で上書きしない**

上書きは改善を捨てることになる。**環流が反映されるまでは分類 B（X. 4 種に当たらない・環流候補）**
として、**追跡先の issue 番号を表へ必ず書く**（MSP の表と同じ規律）。

## やらないこと

- **分類 B / C の内容の同期。** B は「キット土台＋固有デルタ」、C は本リポの中身そのものであり、
  バイト一致は要求されない。
- **分類 B のデルタの妥当性の判定。** 文字列一致では意味を読めない。**人が判断する。**
- **`check-cross-repo-refs.js` の置換点の設定**（[#487](https://github.com/endazon/ai-stock-trading/issues/487) の範囲。本作業では触らない）。

## 受け入れ基準

- [ ] `scripts/check-kit-sync.js` と `scripts/kit-sync-classification.json` が置かれている
- [ ] CI ジョブ `kit-sync` が配線され、緑である
- [ ] 分類 A のドリフトが 0 件である（残す差分は分類表に理由と追跡先付きで宣言されている）
- [ ] `check-ai-workflow-config.js` の欠けていた検出が入り、**本リポの設定で実走して緑**である
- [ ] 進んでいる 2 件が計画側へ環流されている（issue 番号を分類表へ記載）
- [ ] **0 件走査で緑にならないことを対照実験で実測している**

## テスト方針

| 何を守るか | どう守るか |
| --- | --- |
| 分類 A が 1 件でもずれれば赤 | 対照実験（分類 A のファイルを 1 バイト変えて赤を確認） |
| **キットに増えたファイルを黙って見逃さない** | 対照実験（表から 1 件落として赤を確認） |
| **0 件走査で緑にしない** | 対照実験（キットを空に見せて赤を確認） |
| 未 populate なら skip | 対照実験（パスを外して exit 0 を確認） |

**対照実験は「壊して赤を実測する」形で行う。** 緑のまま「効いているはず」と書かない
（本セッションで 1 度、companion を実行しない経路で測って「赤 0」を誤って得た前例がある）。
