# テスト仕様書: 段階ゲートと発注先の 2 軸分離 — FR-20

> 全面再実装（[#344](https://github.com/endazon/ai-stock-trading/issues/344)）に合わせた再作成。
> ADR-0016（空売りの段階解禁）・ADR-0018（Stage 0 の DD ≤ 10%）・利用者裁定 2026-08-02（2 軸分離）を反映する。

## 起点となる計画書（トレーサビリティ）

- 機能要求（FR）: FR-20（段階ゲート）。関連: FR-12（内蔵 `paper`）・FR-13（設定変更）・FR-15（バックテスト＝Stage 0）
- ユースケース（UC）: UC-06（段階遷移の承認・設定変更）
- 受け入れ基準の所在: `02_requirements/01_requirements.md` FR-20、`06_daytrading-review.md` §4.1 / §4.2、
  `05_trading-assumptions.md` §5
- 関連 ADR: ADR-0008（段階ゲート）・ADR-0016 決定8/14（段階別の商品種別・実弾解禁）・ADR-0018（Stage 0 合格基準）

## 本改定で変わった前提（テストの意味が変わる箇所）

| 論点 | 改定前 | **改定後（計画確定）** |
| --- | --- | --- |
| Stage 1 | ペーパー | **moomoo `SIMULATE`（デモ取引・3 か月）** |
| 段階と動作モード | 段階が動作モードを決める | **段階（Stage）と発注先（Broker Provider）は独立した 2 軸**。段階が定めるのは既定の組み合わせにとどまる |
| Stage 2 の資金上限 | 固定額 | **総資金の 30%（$900）を発注可能額としてシステム側で制限**（口座への入金額は制限しない） |
| 段階別の商品種別 | 規定なし | **Stage 1＝3 種すべて／Stage 2＝現物のみ／Stage 3＝信用買い・空売り解禁** |
| Stage 0 の合格基準 DD | 10〜15% のレンジ | **10%（確定単一値。ADR-0018）** |
| 空売りの実弾解禁 | 規定なし | **Stage 3 かつ equity $5,000 以上**（＝1 銘柄あたり上限 $500 以上）かつ空売りを含む戦略で Stage 0 の 7 条件を再充足 |

## テスト対象・範囲

- 対象: 段階の定義と遷移（昇格・差し戻し）、段階別の資金上限・商品種別の強制、発注先の選択・切替と警告、
  Stage 1 の合格判定（期間・件数・統制違反件数）、Stage 0 の合格基準。
- 対象外: バックテストの実行エンジン本体（FR-15。`FR-15_backtest-tests.md`）、画面の実装（#340）、
  moomoo `SIMULATE` への実発注（#342 の PoC 完了後・`Category=Integration`）。

## テスト観点

正常系（規定の遷移）／異常系（条件未充足の昇格拒否）／**境界値**（合格条件のちょうど・直下・直上）／
**プロパティベース**（段階制約と統制上限の同時充足＝厳しい方が効く）／**否定形**（段階を飛ばせない・
`paper` の実績で昇格できない）。

## テストデータ

- 営業日カレンダー・現在時刻・equity はすべて注入可能にし、実時刻・実口座に依存させない。
- 閾値（100 件・60 営業日・120 営業日・30%・$5,000・DD 10%）は**マジックナンバーで書かず設定から引く**。
  設定値そのものの計画適合は `AiStockTrading.PlanConformance.Tests` が別途保証する（責務を分ける）。
