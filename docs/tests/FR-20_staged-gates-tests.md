## 本書が受け持つ範囲

- 機能要求: 段階ゲート。関連するのはペーパートレード（内蔵 `paper`）・画面からの設定変更・バックテスト（Stage 0）である。
- ユースケース: 設定変更（段階遷移の承認・設定変更）。
- 受け入れ基準の所在: 計画リポジトリの要求定義（段階ゲート）、デイトレード方針レビュー §4.1 / §4.2、
  全体前提条件 §5。
- 関連する計画 ADR: 段階ゲート運用／空売りの段階解禁（決定 8・14＝段階別の商品種別・実弾解禁）／リスク統制既定値（Stage 0 合格基準）

## 本改定で変わった前提（テストの意味が変わる箇所）

| 論点 | 改定前 | **改定後（計画確定）** |
| --- | --- | --- |
| Stage 1 | ペーパー | **moomoo `SIMULATE`（デモ取引・3 か月）** |
| 段階と動作モード | 段階が動作モードを決める | **段階（Stage）と発注先（Broker Provider）は独立した 2 軸**。段階が定めるのは既定の組み合わせにとどまる |
| Stage 2 の資金上限 | 固定額 | **総資金の 30%（$900）を発注可能額としてシステム側で制限**（口座への入金額は制限しない） |
| 段階別の商品種別 | 規定なし | **Stage 1＝3 種すべて／Stage 2＝現物のみ／Stage 3＝信用買い・空売り解禁** |
| Stage 0 の合格基準 DD | 10〜15% のレンジ | **10%（確定単一値。リスク統制既定値の計画 ADR）** |
| 空売りの実弾解禁 | 規定なし | **Stage 3 かつ equity $5,000 以上**（＝1 銘柄あたり上限 $500 以上）かつ空売りを含む戦略で Stage 0 の 7 条件を再充足 |

## テスト対象・範囲

- 対象: 段階の定義と遷移（昇格・差し戻し）、段階別の資金上限・商品種別の強制、発注先の選択・切替と警告、
  Stage 1 の合格判定（期間・件数・統制違反件数）、Stage 0 の合格基準。
- 対象外: バックテストの実行エンジン本体（`FR-15_backtest-tests.md` が扱う）、画面の実装、
  moomoo `SIMULATE` への実発注（#342 の PoC 完了後・`Category=Integration`）。

## テスト観点

正常系（規定の遷移）／異常系（条件未充足の昇格拒否）／**境界値**（合格条件のちょうど・直下・直上）／
**プロパティベース**（段階制約と統制上限の同時充足＝厳しい方が効く）／**否定形**（段階を飛ばせない・
`paper` の実績で昇格できない）。
