# live の E2E の実行手順と実行記録

稼働中の PoC へ当てる Playwright の E2E（読み取り層 `ro` と取引影響層 `trading`）を、**手元で**流す手順と、その実行記録の表を置く。
層の意味・送らない操作・閉場後だけ書く規則は [テスト戦略](README.md) の「フロント Playwright E2E」の節が持つ。ここへ複写しない。

> **CI のジョブでは流さない（実行場所は未決）。** 当たる先はオーナーの手元の常設 PoC で、GitHub のランナーからは届かない。
> 本リポジトリは公開リポジトリなので、PoC のホストに self-hosted のランナーを置くと、外部の変更が稼働環境で走り得る。
> 実行場所はオーナーが決める（#1506）。決まるまでは、取引オーナーの storageState を持つ手元の端末から、下の手順で流す。

## 流し方

### 前提

1. 基盤リポジトリの live の setup を、取引オーナーのセッションを残す設定で先に流す。取引オーナーの storageState（`trading-owner.json`）が書かれる。
2. その置き場を `E2E_AUTH_DIR` に入れる。到達先は既定で `https://localhost`（違うときは `E2E_EDGE_URL`）。
3. 取引影響層（`trading`）は、**米国市場が閉場していて次の開場まで 60 分以上ある**こと、**未約定の新規建て・処理中の決済が無い**ことを門が確かめる。目安の実行帯は日本時間の 7:00〜15:00（日報の生成と重ならない）。

### コマンド

```bash
cd frontend
# 読み取り層だけ（既定）
E2E_AUTH_DIR=<storageState の置き場> npm run e2e:live
# 取引影響層（閉場後だけ）。読み取り層と一緒に流すなら --layer ro,trading
E2E_AUTH_DIR=<storageState の置き場> npm run e2e:live -- --layer trading
```

- 層に `trading` があれば、Playwright を起動する**前に**市場の閉場の門（`scripts/e2e-market-closed.js`）を確かめる。開場中・まもなく開場なら、Playwright を起動せずに終える。
- runId は `E2E_RUN_ID`（英数字とハイフン 40 字以内）で固定できる。無ければ時刻から作る。設定の変更の理由欄と履歴の行には `[e2e <runId>]` が付く。

### 終了の読み方

| 結果 | 意味 | 終了コード |
| --- | --- | --- |
| 成功 | 流した test がすべて通り、未復元が無い | 0 |
| 前提未整備 | 門が通らなかった（storageState が無い・失効・開場中・まもなく開場・in-flight の注文がある・照会の失敗）。**test は 1 本も流れていない** | 0（🔴 **赤にしない**。成功とも失敗とも区別して記録する） |
| 失敗 | test が落ちた、または取引影響層の復元の後に差分が残った | 1 |

### 未復元一覧の出し方

- 取引影響層は、各 test の後と実行の終わりに、事前のスナップショットと突合して設定を戻す。戻せなかった項目は、終わりに `::error::` の行と未復元一覧として出る。
- 中身（変える前と今の値）は `frontend/test-results/trading-restore-<runId>.json` にある。スナップショットは同じ場所の `trading-snapshot-<runId>.json` である。
- 発注先・損切りの実行機構・全体前提条件などは、自動では戻さない。未復元一覧に出たら、設定画面とリスク設定画面から手で戻す。
- 実行が途中で止まって（kill）突合が走らなかったときは、リポジトリの直下で次を流す（`--live` を付けないと突合して差分を出すだけ）。

```bash
E2E_AUTH_DIR=<storageState の置き場> node scripts/e2e-trading-restore.js --snapshot frontend/test-results/trading-snapshot-<runId>.json --live
```

## 初回の live 実行で確かめる項目

取引影響層は、門（閉場・in-flight なし）と in-flight の照会の配備を要するため、まだ live で流していない。初回に次を確かめ、結果を下の表の行と、必要なら起票で残す。

- [ ] 門が働く: 開場中は「前提未整備」で、閉場で in-flight が無ければ通る。in-flight の照会が配備されている（照会の失敗で「前提未整備」にならない）。
- [ ] 各 test の後と実行の終わりの突合で、未復元一覧が「なし」になる。
- [ ] リスク上限の 1 項目の変更（保有建玉数上限）: 上限が 1 の環境では 1 上げる（緩める向き）。その向きでも保存でき、test の後に元へ戻ることを確かめる。
- [ ] 変動閾値・クールダウン・最小取引件数などの同値の保存: 監視の設定の履歴が自分の行で +2、リスク設定の履歴が +1（閉場前の統制・テーマを保存したときはその数を足す）になる前提が、実環境の履歴の書き方と合っている。
- [ ] 監視銘柄の追加: 監視銘柄に空きがあり（巡回の時間の検査で拒否されない）、試験銘柄の追加と削除が通る。
