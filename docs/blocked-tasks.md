# 実機確認・権限が必要で AI が完了できない作業の一覧

- 作成日: 2026-08-05
- 作成者: Claude Code（監査セッション）
- 対象: `endazon/ai-stock-trading`（計画 submodule `d980a01` 時点・develop `256e357` 時点）

## この文書の目的

AI（Claude Code）と CI だけでは**原理的に完了できない**作業を洗い出す。以下の 2 種類に分ける。

- **A. 実機・実環境が要るもの** — 実口座・実ブローカー・外部サイト・本番相当のデータ量が必要
- **B. 権限・人間の判断が要るもの** — GitHub の設定権限、資金の移動、計画側の裁定

**「実装が終わっていない」だけの作業は含めない**（それらは通常の issue で追える）。ここに挙げるのは、**誰かが実物に触るまで永久に終わらない**ものだけである。

> ⚠️ **重要な前提**: 現時点で**実弾の発注は 1 件も行われない**。`LiveTradingGate.LiveTradingReleased = false`（定数）が閂として効いており、解禁は 1 ファイルの変更に集約されている。本一覧の A 群が未了である限り、この閂を開けてはならない。

## B. 権限・人間の判断が要るもの

### B-1. 🔴 `CODEOWNERS` の設定 — **AI のレビュー関門が形骸化している**

| 項目 | 内容 |
| --- | --- |
| 現況 | **`.github/CODEOWNERS.example` のまま**。`CODEOWNERS` は存在しない（実測） |
| なぜ重大か | `AI_SETUP.md` 共通セットアップ 4 の原文: 「**AI が実装し AI がレビューする運用では、必須レビュアが不在だと『AI の実装を AI が承認して同一人物がマージする』ループになり、人間のレビュー関門が形骸化する**」 |
| 実際に起きていること | **本セッションで私は #392 と #390 を自分でマージした。** 実装も監査も AI であり、人間のレビューは介在していない |
| なぜ AI にできないか | ファイルのリネーム自体は可能だが、**レビュアに誰を指名するかは利用者の決定**であり、ブランチ保護での必須化には管理者権限が要る |

**B 群の中で最優先。** 資金を扱うシステムで、AI が書いた統制コードを AI が承認してマージしている状態です。
