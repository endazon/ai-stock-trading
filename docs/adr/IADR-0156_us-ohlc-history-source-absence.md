## コンテキストと課題

[IADR-0105](./IADR-0105_backtest-historical-bar-source.md) 決定2 は「安全既定は no-op（provider 明示指定でのみ外部へ接続する）」
と定め、`NoOpHistoricalBarSource` に**差し替え漏れ検知の警告**を置いた。当時の前提は明快である——
**差し替え先（Stooq）は存在し、`Backtest:BarData:Provider=stooq` と設定すれば使える。** 既定 `none` は
「まだ設定していない」という**一時的な状態**を意味していた。

**この前提は 2026-08-04 に崩れた。** 計画 ADR-0023 が次を決めた。

| 決定 | 内容 |
| --- | --- |
| 決定1 | **Stooq は取得不能として扱う。** JavaScript proof-of-work のボット検知チャレンジを**回避する実装は書かない**（提供側が明示的に自動取得を排除している以上、回避は規約リスクを負う。ADR-0004 が yfinance を不採用とした判断と一貫しない）。**区分としては検証用途のまま残す**（提供側の仕様が戻れば再び使える可能性があるため候補一覧からは削除しない） |
| 決定2 | 米国株の日足 OHLC 履歴源が未確定であることを計画側で追跡可能にする。**本件が解消するまでは Stage 0 の合格判定を実施できない** |
| 決定3 | moomoo OpenAPI の履歴取得検証を ADR-0019 の **PoC 項目 7** として追加（品質の評価観点 6 点） |
| 決定4 | 検証の期限は「基盤・可変機能ユニット双方の実装完了（**go-live 相当**）を起算日とし 1 か月以内」。超過時は ADR-0005 の有料枠の検討へ自動的に移る |

**実装は壊れていない。** 既定が no-op であるため誤ったデータで昇格することはなく、IADR-0105 の設計どおり
「バーが取れなければ Stage 0 は不合格になり昇格が止まる」に倒れている。**問題は、その安全側の縮退が
「一時的な設定漏れ」ではなく「恒久的な状態」になったことが実装側のどこにも書かれていないこと**である。
現行のコメントは Stooq を有効な選択肢として説明しており、読んだ人は「設定すれば使える」と受け取る。

これは [#330](https://github.com/endazon/ai-stock-trading/issues/330) /
[#374](https://github.com/endazon/ai-stock-trading/issues/374) と同じ「**実装した ≠ 効いている**」の型である。

### さらに、起票時点の記述はすでに古い（本 IADR の書き分けの核心）

issue #382 は「**使える履歴源が無く** Stage 0 の合格判定を実施できない」と書くことを求めているが、
起票（2026-08-04）の翌日に **moomoo が代替源になり得ることが実測された**
（[#342](https://github.com/endazon/ai-stock-trading/issues/342) の PoC 項目 7。
[作業仕様書 20260805_342](../specs/20260805_342_moomoo-poc-plan.md) §項目 7・[IADR-0144](./IADR-0144_moomoo-short-selling-poc-outcomes.md) 決定6）。

- `QotRequestHistoryKL` で米国株の日足 OHLCV が取れる（`KLType_Day` / `RehabType_Forward`）
- AAPL で **2006-07-24 まで**（約 20 年）遡れる。1 リクエスト 1,000 件・`NextReqKey` でページング
- **追加費用なし**（既に接続している OpenD で取得できるため ADR-0005 の有料情報源プロセスに乗せる必要が無い）

**したがって「使える履歴源が無い」と単純化して書くと、実測で判明した事実を否定する誤った記述になる。**
一方で「moomoo で解決した」と書けば、**裁定も実装も無いのに解決したように読める**。
ADR-0023 は代替源を定めておらず、moomoo の採用には**計画側の改定裁定**が要る
（環流済み・[blocked-tasks](../blocked-tasks.md) B-4）。

## 検討した選択肢

| 案 | 内容 | 評価 |
| --- | --- | --- |
| A | 何もしない（コードは正しく安全側に倒れているのだから触らない） | **棄却** |
| B | Stooq のボット検知チャレンジを回避する実装を書く | **棄却（計画が明示的に禁じた）** |
| C | Stooq を候補から削除し、コードとテストを消す | **棄却** |
| D | moomoo アダプタを実装して解決する | **棄却（本 PR では。裁定待ち）** |
| **E** | **構造は変えず、現況を記録・コメント・テストとして残す** | **採用** |

### A（何もしない）の棄却理由

**「実装済みだが一度も発火しない統制」を黙って持つことが、本リポジトリで繰り返し起きた失敗である。**
`ControlViolationCount` の既定 0 が「違反なし」に見えた [#403](https://github.com/endazon/ai-stock-trading/issues/403)、
維持率が無いまま「0.0%」と描かれかけた [IADR-0154](./IADR-0154_supply-availability-declared-by-server.md) と同型である。
コードが安全側に倒れていることと、**その事実が読める形で残っていること**は別の要求である。

### C（Stooq を削除する）の棄却理由

**ADR-0023 決定1 が「候補一覧からは削除しない」と明記している**（提供側の仕様が戻れば再び使える可能性がある）。
加えて、パーサ・シンボル写像・欠測記録のテストは**提供側の仕様が戻った場合に価値を保つ**（#382 の受け入れ基準にも明記）。
削除は「消したものを後から同じ品質で書き直せる」という根拠のない楽観に依存する。

### D（moomoo アダプタを実装する）の棄却理由

**ADR-0023 は代替源を定めていない。** 実測は「使える」ことを示したが、**どの情報源を採るかは計画側の決定**であり、
実装が先に既成事実を作れば計画と実装の乖離になる（計画リポ `.claude/rules/adr.md`「計画書は絶対的な正である」）。
未確定事項も 2 つ残る——**取得枠（`remainQuota: 300`）の単位と回復周期**、および
**前復権の調整方式がバックテストの費用モデル（ADR-0016 決定14 の借株料・配当相当額）と二重計上／欠落を起こさないか**。

## 決定

**案 E を採る。** `IHistoricalBarSource` の構造・provider 選択規則・安全既定はいずれも変えず
（[IADR-0105](./IADR-0105_backtest-historical-bar-source.md) 決定1〜7 はすべて有効）、**その既定 no-op が何を意味するかの
読み替え**と、**現況の 4 点**を実装側の記録として固定する。**実行時の振る舞いは 1 バイトも変わらない。**

### 決定1: 既定 `none` の意味を「差し替え漏れ」から「差し替え先の不在」へ読み替える

[IADR-0105](./IADR-0105_backtest-historical-bar-source.md) 決定2 の**構造**（provider 明示指定でのみ外部へ接続する・
構成不備は起動を落とさず警告して no-op へ倒す）は有効なまま残す。改めるのは**その前提**だけである。

| | IADR-0105（2026-07-26） | 本 IADR（2026-08-06） |
| --- | --- | --- |
| 既定 `none` の意味 | **差し替え漏れ**（設定すれば Stooq が使える） | **差し替え先の不在**（設定できる先が無い） |
| 解消の手段 | 構成を書く | **計画側の改定裁定＋アダプタの実装** |
| 期間 | 一時的 | **恒久**（上記が解けるまで） |

`NoOpHistoricalBarSource` の警告は残す（有効化したつもりで効いていない構成不備は依然として起こり得る）が、
**警告文とコメントを現況に合わせる**。運用時に読む唯一の signal がここだからである。

### 決定2: 現況は次の 4 点を**同時に**書く。1 点でも落とすと誤読になる

**本 IADR の中核である。** コード・機能仕様書・テスト仕様書・`blocked-tasks`・PR 本文のすべてで
同じ 4 点を用い、要約して 1 点に畳まない。

1. **実装済みの履歴源は Stooq のみであり、その Stooq は取得不能である**
   （ADR-0023 決定1 が回避実装を禁じたため、実装側で取得可能にする手段は無い）。
2. **既定は `none`（no-op）であり、バーが 1 本も取れなければ Stage 0 は不合格へ倒れる**
   （安全側の縮退。誤ったデータで昇格することはない）。
3. **moomoo が代替源の候補として実測されたが、採用には ADR-0023 の改定裁定と実装の両方が要る**（いずれも未了）。
4. したがって **Stage 0 の合格判定は現時点で一度も発火し得ない**。これは**恒久の状態**である。

**落としてはならない理由**（それぞれ、落とすと生じる誤読）。

| 落とす点 | 生じる誤読 |
| --- | --- |
| 1 | 「設定すれば Stooq が使える」——現行コメントが実際にそう読める。回避実装に手を出す動機にもなる |
| 2 | 「データが無いまま Stage 0 が合格し得る」——実際は fail-safe であり、そこは壊れていない |
| 3 | **「使える履歴源が無い」＝実測で判明した事実の否定**。逆に 3 だけを書けば「moomoo で解決済み」に読める |
| 4 | 「いずれ動く機能」に見え、`Stage 0 合格判定は実装済み` という記述だけが残る |

### 決定3: Stooq の実装・テストは削除しない。回避実装も書かない

ADR-0023 決定1 への追随である。`StooqHistoricalBarSource` / `StooqDailyCsvParser` / `StooqSymbolMapper` と
その全テスト（ボット検知チャレンジ応答を解析失敗として扱う `T-15-62` を含む）を維持する。
**チャレンジを解く実装は書かない。** 「無料だから」を理由に規約リスクを負うことは、
ADR-0004 が yfinance を不採用とした判断（規約グレーを避ける）と一貫しない。

### 決定4: 「未採用である」ことをテストで固定する

「実装したが効いていない」の逆——**「まだ実装していない」ことが黙って変わる**のを防ぐ。
[IADR-0154](./IADR-0154_supply-availability-declared-by-server.md) 決定7 と同じ形である。

| 固定する事実 | 落ちる変異 |
| --- | --- |
| 構成を何も与えなければ実効 provider は `none`（`BarDataOptions` の**既定値そのもの**を使う） | `Provider` の既定を `"stooq"` 等へ変える |
| `null` / 空 / 空白 / `none` / 未知の値はすべて実効 `none`（`ResolveProvider` と `Create` の両方で） | 選択規則を緩める |
| **未採用の代替源 `moomoo` を指定しても no-op へ倒れる** | **裁定前に moomoo アダプタを結線する** |

3 行目は**わざと落ちるように置いた関門**である。moomoo の採用が裁定された日、このテストが赤くなり、
本 IADR・FR-15 の仕様書・`blocked-tasks` の追随が強制される。**緑のまま採用が入ることはない。**

### 決定5: ADR-0019 の PoC 項目 7 は、**期限の起算が他の 6 項目と異なる**まま扱う

ADR-0019 決定2 は工程 ⑤（項目 7）を **①→④ の連鎖に含めない**と明記している。

| 項目 | 期限 |
| --- | --- |
| PoC 項目 **1〜6**（工程 ②） | **2026-08-31**（① Hetzner ToS → ② PoC → ③ 増資 → ④ Stage 1 開始 の連鎖の一部） |
| PoC 項目 **7**（工程 ⑤） | **go-live 相当（基盤・可変機能ユニット双方の実装完了）を起算日とし 1 か月以内**。**連鎖の続きではない** |

**この非対称を「PoC の期限は 8/31」へ畳まない。** 理由は ADR-0019 が明記している——履歴データの品質は
バックテスト機構（FR-15）が動いて実際に流してみて初めて判定できるため、実装完了前に急いでも使い道がない。
畳むと、**期限を過ぎたという誤った切迫**（実際には起算すらしていない）か、逆に
**go-live 後の 1 か月という期限の消失**のどちらかが起きる。

### 決定6: 本 IADR は moomoo の採用を決めない

範囲外である。採用は ADR-0023 の改定裁定を要する（[blocked-tasks](../blocked-tasks.md) B-4・環流済み）。
**実装側の記録に「moomoo を履歴源とする」と読める記述を置かない。**

## 理由

- **安全側に倒れていることと、その事実が読めることは別の要求である。** 前者は IADR-0105 が達成済みであり、
  本 IADR が足すのは後者だけである。コードの振る舞いを変えないのはそのためである。
- **4 点を同時に書くという制約は、実際に誤りやすいから明文化した。** issue #382 の受け入れ基準（「使える履歴源が無い」）
  をそのまま転記すると、翌日の実測を否定する記述になる。**起票時点で正しかった文言が、1 日で不正確になった実例**である。
- **未採用をテストで固定するのは、本リポジトリで既に確立した規律の適用である**（IADR-0154 決定7）。
  文書だけの禁止は、次に触る人が文書を読まなければ効かない。

## 結果

- 良い影響:
  - 「Stooq を設定すれば使える」という誤読の経路が、コード・仕様書の双方から消える。
  - 「Stage 0 の合格判定は実装済み」という記述だけが残る事態を防ぐ（#330 / #374 と同型の失敗の予防）。
  - moomoo の採用が裁定なしに入ることが、テストで機械的に止まる。
- 悪い影響 / トレードオフ:
  - **問題そのものは解消しない。** 本 IADR は現況の可視化であり、Stage 0 は依然として発火し得ない。
  - 同じ 4 点が複数の文書に重複して現れる（コード・IADR・機能/テスト仕様書・`blocked-tasks`）。
    **意図した重複**である——どこか 1 か所だけを読んだ人が誤読しないことを優先した。ただし
    **採用が決まった日に追随すべき箇所が 4 か所以上ある**というコストを負う（決定4 のテストが起点になる）。
- **残余リスク（明記）**:
  1. **moomoo 未採用の関門は「provider 名 `moomoo`」という文字列に依存する。** 別名（例 `futu`・`opend`）で
     アダプタを足せばテストは緑のまま通る。網羅的な禁止ではなく、**最も自然な名前に置いた 1 本の関門**である。
  2. **`Stage 0 は一度も発火し得ない` という事実自体はテストで固定していない。** 固定しているのは
     「実データ未供給ならバー 0 本→不合格」（既存 `T-15-50`）と provider 選択だけであり、
     「使える履歴源が実在しない」ことはコードから機械的に判定できない（外部サイトの状態であるため）。
     **文書と本 IADR がその記録である。**
  3. **ADR-0023 は `Proposed` である。** ただし計画リポ `.claude/rules/adr.md` が
     「`Proposed` は決定の効力を停止しない」と定めており、決定1〜4 は計画側の現行値として追随した。
     `/sync-impl` の突合（GitHub API 401 で未了）の結果によっては見直しがあり得る。
  4. **go-live の判定そのものが実装側に無い。** 項目 7 の期限は「実装完了を起算日とし 1 か月」であるが、
     「実装完了」を宣言する仕組みは無く、**起算日が来たことに誰も気づかない**経路が残る（計画側の追跡に依存する）。
