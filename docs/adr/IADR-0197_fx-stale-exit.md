# IADR-0197: 鮮度切れでも手仕舞いを止めない

> 実装リポジトリ内の意思決定記録（Implementation ADR）。1 ファイル = 1 意思決定。

- 状態: Accepted
- 日付: 2026-08-15
- 決定者: Claude Code（計画 ADR-0022 決定5 との乖離の是正）

## 起点・関連

- 計画書 ID: **FR-10**（リスク統制）・**FR-11**（監査）
- 計画 ADR: [ADR-0022](../../planning/projects/ai-stock-trading/07_adr/ADR-0022_fx-rate-source-and-freshness.md) **決定5**
- 対象 Issue: [#506](https://github.com/endazon/ai-stock-trading/issues/506)（発見元 [#381](https://github.com/endazon/ai-stock-trading/issues/381)・[PR #507](https://github.com/endazon/ai-stock-trading/pull/507) で実測）
- 作業仕様書: [20260815_506](../specs/20260815_506_fx-stale-exit.md)

## コンテキストと課題

計画は**入口と出口を分けている。実装は同じゲートで塞いでいた。**

| 状態 | 計画（ADR-0022 決定5） | 実装（実測） |
| --- | --- | --- |
| 5 日超〜30 日以下 | 直近レートで続行・警告。新規建ては止めない | ✅ 一致 |
| **30 日超** | **新規建てを停止。手仕舞い・損切りは止めない** | 🔴 **手仕舞いも止まる** |

換算レートのゲートが**建玉効果（Open / Close）を決めるより前**にあり、
**建玉効果が分かるのは LLM の判断後**であるため、**出口が入口と同じゲートで塞がれていた。**

> 🔴 **「止められない」より「閉じられない」ほうが危険である。**
> 新規建ての停止は安全側だが、**損失を抱えた建玉から出られないのは安全側ではない。**

鮮度切れは「レート無し（`null`）」へ潰されるため、**30 日超だけでなく未結線・取得失敗でも同じく手仕舞いが止まる。**

## 決定

### 決定1: **案 B を採る —— 値は失わせず、判断だけを変える**

**計画の語がそう読める。** ADR-0022 決定5 は「**直近レートで続行する**」と書いており、
**値が失われるのではなく判断が変わる**構造を想定している。

| 案 | 採否 | 理由 |
| --- | --- | --- |
| A: `FxRateToBase` を nullable 化 | ❌ | **永続化（EF マイグレーション）と統制側の読み手すべてへ波及する** |
| **B: 値＋鮮度の判定を返す** | ✅ | 計画の語に最も近く、波及が FX 経路に閉じる |
| C: 決済に限り最後に成功したレートを使う | ❌ | キャッシュ保持方針の変更が要り、**「いつのレートか」が見えなくなる** |

### 決定2: **鮮度を判定するのは最外の装飾だけ。他の源は「判定しない」と表明する**

`IFxRateSource` / `IFxRateProvider` に `GetReadingAsync` を**既定実装つき**で追加した。
既定は `FxRateFreshness.Unknown` を返し、**`CachingFxRateSource` だけが実際の齢から判定する。**

> 🔴 **`Unknown` を `Fresh` と書かない。** 生アダプタ（日銀・FRED）は**鮮度を判定していない**のであって、
> **新鮮だと確かめたわけではない。** ここで `Fresh` と嘘をつくと、**装飾を外した構成で
> 鮮度判定が消えたことに誰も気づかない** —— 本リポジトリが繰り返している「緑だが検査されていない」型である。

### 決定3: **`GetRateToBaseAsync` は `GetReadingAsync` から導く**

鮮度判定を二本立てにすると、**片方だけ直して静かにずれる。** 判定規則（`Classify`）は 1 箇所だけに置いた。

### 決定4: 🔴 **決済には実レートを載せる。`1m` は載せない**

`OrderIntent.FxRateToBase` は**非 nullable の `decimal`・既定 `1m`**。既定のまま載せると
`NotionalInBase = Quantity × Price × 1` となり、**JPY 建ての約定金額が USD として台帳へ記録され、
7 年保持の監査台帳（FR-11）の金額が約 150 倍ずれる。**

> **古いレートで換算した金額は不正確だが、`1m` で換算した金額は端的に誤りである。**
> **前者は桁が合っている（実勢からの乖離）。後者は通貨を取り違えており、約 150 倍ずれる。**
> **黙って `1m` を載せるのは、止めることより悪い。**

> 🔴 **【訂正・AI レビューの指摘 2026-08-15】初版はここに「前者は `AsOf` が残るので事後に判別できる」と書いていた。事実と異なる。**
> **監査台帳の行（`ApprovedOrderRow`）は `FxRateToBase`（数値）だけを持ち、観測日（`AsOf`）の列が無い。**
> したがって**「いつのレートで決済したか」は台帳から復元できない。**
> **決定4 の結論は変わらない**（桁が合う値と通貨を取り違えた値の比較である）が、
> **根拠から「`AsOf` が残る」を取り下げる。**

**値がまったく取得できない場合は決済も出さない**（載せる換算率が無いため）。

### 決定5: **入口しかあり得ない場合は LLM を呼ぶ前に見送る（費用の据え置き）**

ゲートを後ろへ動かすと鮮度切れでも LLM 費用が出る（[IADR-0107](IADR-0107_base-currency-conversion.md) 決定2 が避けていた形）。
**保有が無ければ建玉効果は `Open` にしかならない**ため、**鮮度切れかつ保有なしのときだけ**保有数を先読みして即座に見送る。

- **正常時の経路は変えない**（先読みは鮮度切れのときだけ）
- 先読みした保有数は**後段で再利用する**（ブローカ照会を二重に打たない）

## 対照実験（変異試験・実走した実測）

| # | 変異 | 落ちたテスト |
| ---: | --- | --- |
| 1 | **入口の停止を潰す**（鮮度切れでも新規建てが通る） | 「鮮度切れの新規建ては保有があっても止まる」 |
| 2 | **決済へ `1m` を載せる** | 「実レートが載る・1m を載せない」ほか **4 件** |
| 3 | **保有なしの早期見送りを潰す** | 「保有なしなら LLM を呼ばずに見送る」 |

### 🔴 変異試験でまた 1 つ学んだ —— **コンパイルできない変異は「殺された変異」と見分けがつかない**

**変異 3 の初版は `if (false)` へ置き換えたが、パターン変数 `held` が束縛されなくなり
コンパイルエラーになった。** `dotnet test` は **exit 1** を返すため、
**テストが落ちたのと同じ見え方になる。**

> **[#507](https://github.com/endazon/ai-stock-trading/pull/507) は「弱い変異」、[#509](https://github.com/endazon/ai-stock-trading/pull/509) は「当たらない変異」、本 PR は「ビルドが壊れた変異」。**
> **3 つとも exit コードだけを見ると『効いた』と読める。**
>
> **是正**: 変異の実行後に **`error CS` の件数を数え、0 であることを確かめてから**判定する。
> 変異 3 は**コンパイルが通る形**（条件を恒偽にする）へ書き直し、**期待どおり 1 件だけが落ちる**ことを確認した。

## 影響

- 肯定的:
  - **計画（ADR-0022 決定5）との乖離が解消し、出口が塞がらなくなった。**
  - **「レートが無い」と「古いレートがある」を呼び出し側が区別できるようになった** ——
    #381 の停止側の可視化は、この区別の上に載せられる。
  - **台帳の金額が守られた**（`1m` を載せない）。
- 否定的 / トレードオフ:
  - **ポートに既定実装つきのメソッドが 1 つ増えた**（`IFxRateSource` / `IFxRateProvider`）。
  - **鮮度切れかつ保有ありの経路では LLM 費用が出る。** 出口を通すための代償であり、
    **保有なしの経路（大多数）では従来どおり呼ばない。**
  - **古いレートで換算した決済金額は不正確である。** ただし `AsOf` が残るため**事後に判別できる。**

## 残余リスク

- 🔴 **「鮮度切れのまま決済した」事実は、どこにも永続化されていない**（AI レビューが実測して指摘）。
  | 経路 | `Expired` で決済したことが残るか |
  | --- | --- |
  | 監査台帳（`ApprovedOrderRow`・7 年保持） | ❌ `FxRateToBase` の数値のみ。**`AsOf` の列が無い** |
  | 監査イベント / Discord / 日報（IADR-0196） | ❌ **`NotifyStaleAsync` は `Warning` 分岐でしか呼ばれない** |
  | アプリケーションログ | ⚠️ `LogWarning` は出るが**7 年保持の対象外** |

  **つまり本 PR は「出口を開けた」が、「古いレートで出た」ことの記録は残していない。**
  **これは初版の記述より悪い状態である**（初版は台帳から読めると書いていたが、読めない）。
  [#381](https://github.com/endazon/ai-stock-trading/issues/381) の停止側の可視化で**必ず塞ぐこと**——
  **同時に設計するのが筋**である（別々に作ると同じ事象で 2 種類の通知が飛ぶ）。
- **`Unknown` は新規建てに使える扱いである。** 鮮度装飾を外した構成では**判定が働かない**。
  `FxRateSourceFactory` が最外に装飾を置くことを保証しているが、**それを機械が検査してはいない。**
- **損切りは本経路を通らない**（[#331](https://github.com/endazon/ai-stock-trading/issues/331) のブローカー側逆指値への一本化）。
  本 ADR が守るのは**判断由来の決済**（IADR-0119）だけである。
