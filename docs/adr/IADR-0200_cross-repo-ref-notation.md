# IADR-0200: 他リポジトリ issue / PR 番号の表記を短縮形へ確定する

> 実装リポジトリ内の意思決定記録（Implementation ADR）。1 ファイル = 1 意思決定。

- 状態: Accepted
- 日付: 2026-08-15
- 決定者: 利用者裁定（2026-08-15）＋ Claude Code（実装）

## 起点・関連

- 計画書 ID: **NFR**（無採番。工程の統制であり計画側の非機能要件表に当たる番号が無い／環流しない）
- 対象 Issue: [#487](https://github.com/endazon/ai-stock-trading/issues/487)
- 作業仕様書: [20260815_487](../specs/20260815_487_cross-repo-ref-notation.md)
- 規約: `.claude/rules/traceability.md`／新設した companion `.claude/rules/traceability.repo.md`

## コンテキストと課題

キット規約は「**プロジェクト内で短縮形とフルパス形式のどちらに寄せるかを最初に決め、混在させない**」と
定めるが、**本リポジトリはその決定をしていなかった。** 実測（`develop` = `9624160`）で **294 件**の違反があり、
検査器 `check-cross-repo-refs.js` は[#477](https://github.com/endazon/ai-stock-trading/issues/477) で
取り込まれたものの **CI へ配線されていなかった**（[IADR-0189](IADR-0189_plan-id-qualification-and-traceability-kit-sync.md) 決定4）。

## 決定

### 決定1: **短縮形を正とする**（`planning#NNN` / `MSP#NNN`）

利用者裁定（2026-08-15）。**フルパス形式は例外として許す**（`.md` で自動リンクになるのはこの形だけのため）。

> 🔴 **裁定の前に、選択肢の一方が実測で消えた。**
> 「長い表記（`project-planning#NNN`）へ寄せる」は**検査器が構造的に表現できない。**
> 短縮名にリポジトリ名そのものを与えて実走したところ、検査器は依然として型 1 として検出し、
> **`project-planning#329 → project-planning#329` と自分自身への置換を提案した**
> （設計が「短縮形へ寄せ、フルパス形式だけを例外として許す」であり、**リポジトリ名の裸書きは
> 定義上つねに違反**だからである）。長い表記を採るには**キット改修の環流**が要る。
> **「多数派だから長い表記」は、実装可能性を確かめる前の判断だった。**

### 決定2: **point-in-time 記録は是正の対象に含めない**

`docs/specs/`（作業仕様書）と `feedback/`（環流記録）を除外する（利用者裁定）。
**後から表記だけ直すと当時の記述と食い違う**ためであり、姉妹検査器
`check-plan-id-qualification.js` が同じ理由で既定除外しているのに揃える。

**これで母集合は 294 → 128 になった**（除外 166 件。引き算が合うことを確認した）。

### 決定3: **キット配布物の違反は手元で直さず環流する**

`.claude/rules/traceability.md:153` の `planning issue #202`（空白区切り）は**分類 A** であり、
直すとバイト一致が崩れてキット同期のたびに手動マージが要る。**除外に入れて planning#349 へ環流した。**

> 🔴 **規約が書いてある当のファイル自身が、その規約に違反していた。**
> 検査器のヘッダは「**その規約が書いてある当のファイルを編集する PR が同じ違反を犯して
> CI を green で通過した**」（microservices-platform の実測）を作られた理由として挙げているが、
> **今回はその 1 段深い版である。**

### 決定4: **`CHANGELOG.md` は除外しない。生成物の側を是正する**

コミット件名は書き換えない（履歴不変・force push 禁止）。
`changelog-overrides.json` の `remap` で **`desc` のみ**を是正し（`594deed`）、
生成済みの行も同じ文字列へ揃えて**再生成しても同じ結果になる**状態にした。
**除外して見なかったことにはしない。**

### 決定5: **配線は `scripts.repo.test.js` から。置換点は環境変数で自前で与える**

`.github/workflows/` は GitHub App 権限で編集できないため、既存の呼び出し口へ相乗りする
（IADR-0140／IADR-0189 決定2・決定6 と同じ形）。

🔴 **テストが自分で環境変数を与えることが要点である。** CI 側の env を消しても、こちらが赤くなる。

## 🔴 対照実験でわかった、この配線の本当の価値

**env を落とすと検査は「緑のまま素通り」する**（fail-open）。これを実測で示した。

| 実験 | 操作 | 結果 |
| --- | --- | --- |
| 1 | 実データへ違反を 1 件注入（`planning#205` → `project-planning#205`） | ✅ **リポテストが赤**（exit=1） |
| 2 | `CROSS_REPO_SELF_NAMES` を落とす | ⚠️ **緑のまま**（現ツリーには該当が 0 件） |
| 3 | `CROSS_REPO_NAMES` を落とす（キット既定のプレースホルダのまま） | ⚠️ **緑のまま**（違反 0 件） |
| 4 | **MSP 参照を 1 件だけ長い表記へ戻したうえで**、(a) env 無しの素の検査／(b) 配線したリポテスト | 🔴 **(a) exit=0（素通り）／(b) exit=1（検出）** |

**実験 4 が受け入れ基準そのものである。** キットの既定マップは `project-planning` しか持たないため、
**`microservices-platform#123` と書いても素の検査は緑になる。**
**配線したテストが env を自前で与えているからこそ赤くなる。**

> **実験 2 は正直に記録しておく。** `SELF_NAMES` は**現ツリーでは 1 件も守っていない**。
> それでも設定する——**「AST #123」と書かれた瞬間に効く**設定であり、
> [IADR-0199](IADR-0199_fx-status-supply-wiring.md) が削った「振る舞いを 1 ミリも変えない防御」とは違う
> （あちらは**論理的にあり得ない分岐**、こちらは**まだ起きていないだけの実在する入力**）。
> **ただし「守っている」と書かない。守るのは書かれたときからである。**

## 影響

- **良い影響**: 表記が 1 つに定まり、機械的突合が安定する。**検査器が初めて実効する**
  （取り込みから配線まで開いていた穴を塞いだ）。除外の理由が companion に全数残った。
- **悪い影響**: `docs/specs/` `feedback/` は**表記が混在したまま**である（裁定どおりだが、
  「揃っている」とは言えない状態が残る）。キット改修が入るまで除外を 1 件抱える。

## 残余リスク

- 🔴 **配線したのは `.md` の面だけである。実害の大きい面は未配線のまま残る**（AI レビューの指摘・実測で追認）。
  規約は面によって壊れ方が違うと明記している——**issue / PR / コミットメッセージでは裸の `#NNN` が
  本リポジトリへ自動リンクし「誤リンク」という実害が出る**のに対し、**`.md` は表記ゆれに留まる**。
  そして規約は「**優先して直すのは issue / PR / コミットメッセージ側**」と定めている。
  **本 ADR が配線したのは、優先度の低いほうである。**
  - さらに `check-cross-repo-refs.js` の docstring は「`scripts/check-commit-messages.js` から
    件名・本文・PR タイトル」も検査すると書いているが、**実際には呼ばれていない**
    （`grep -c 'cross-repo\|CROSS_REPO' scripts/check-commit-messages.js` → **0**）。
    🔴 **キットのコメントが、存在しない担保を書いている**——[IADR-0198](IADR-0198_fx-expired-visibility.md) で
    実測した「**維持されない記述はあるだけ有害**」と同じ形である。
  - **#487 の受け入れ基準の範囲外**であるため本 ADR では配線しないが、**別 issue として起票した**（[#515](https://github.com/endazon/ai-stock-trading/issues/515)）。
    範囲外を理由に**記録せずに閉じない**（それが「見落とされる」形そのものである）。
- 🔴 **`docs/specs/` `feedback/` は永続的に対象外である。** 新規に書く分は規約に従うべきだが、
  **機械は見ていない**。人のレビューに依存する。
- **キット配布物の除外は暫定である。** planning#349 が是正されたら**除外を外すこと**
  （外し忘れると、キットが直った後も検査が 1 件甘いままになる）。
- **`SELF_NAMES` は現ツリーで 0 件しか守っていない**（上記実験 2）。将来の入力に対する備えである。
- **フルパス形式を例外として許すため、表記は完全には 1 つに定まらない**（リンクさせたい箇所で使う）。
  機械的突合はどちらの形も許すため、**「混在」ではなく「2 形の使い分け」として運用する**。
