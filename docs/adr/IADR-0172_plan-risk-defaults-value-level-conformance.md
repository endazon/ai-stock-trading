# IADR-0172: 計画適合検査の値レベルへの引き上げ

- 状態: Accepted
- 日付: 2026-08-07
- 決定者: 実装（Claude Code）／ 起点 [#445](https://github.com/endazon/ai-stock-trading/issues/445)
- 作業仕様書: [20260807_445_plan-risk-defaults-recheck](../specs/20260807_445_plan-risk-defaults-recheck.md)

## コンテキストと課題

**#445 は「1 件の誤転記の後始末」として起票された。実際に見つかったのは、それより重い構造的な穴であった。**

起票の経緯は [IADR-0166](./IADR-0166_plan-source-digest.md) の残余リスクである —— 計画書 → `PlanRiskDefaults` の人手転記を検知する仕組みを入れたが、**ベースラインを「現在の計画書」で取るため、導入時点で既に転記を誤っていれば誤りごと固定される**。実際 `Fx.StaleRateWarningDays` は 3 日のままで、計画は 2026-08-07 に 5 日へ改訂済みであった（PR #444 で修正）。「残り 33 項目にも同じ誤りが潜んでいないか」が #445 の問いである。

### 結論1: **値の誤転記は 1 件も残っていなかった**

全 34 項目を計画書の現行版（submodule `a4616a8`）と 1 件ずつ突き合わせた。**#444 で直した 1 件以外に誤りは無かった。**

**この結論はそのまま記録する。**「全部見たが問題は無かった」は、見ていないことと区別して書かれなければならない。

### 結論2: 🔴 **`ShortSell.Limits` は型の形しか見ておらず、7 値が一度も比較されていなかった**

抽出側は `DescribeTypeWithMembers` を使っており、返すのは**プロパティ名の一覧だけ**である。

```csharp
var members = type.GetProperties(BindingFlags.Public | BindingFlags.Instance).Select(p => p.Name);
return $"type {typeName} with members: {Sorted(members)}";   // ← 値は一度も読まれない
```

**実測**: `PerSymbolCapRatio` を **0.10 → 0.50**（1 銘柄あたりの空売り上限を equity の 1 割から 5 割へ）に変えても、`PlanConformanceTests` は **16 件すべて緑**であった。

| 無検査だった値 | 実装 | 計画 |
| --- | --- | --- |
| `PerSymbolCapRatio` | 0.10 | equity の 10%（ADR-0016 決定2(a)） |
| `BorrowRateCapAnnual` | 0.20 | 年率 20%（決定3） |
| `MaintenanceMarginThreshold` | 0.40 | 40%（決定7） |
| `MaintenanceRecoveryTargetOffset` | 0.05 | +5 ポイント（§5） |
| `PriceFloorUsd` | 5.00 | $5.00（決定7） |
| `ExposureRatioCap` | 0.50 | 建玉総額の 50%（決定9） |
| `BuyInBanDurationDays` | 30 | 30 日（決定4） |

**7 値とも現在は計画どおりである。**「間違っていた」のではなく**「間違っても気付けなかった」**——[IADR-0166](./IADR-0166_plan-source-digest.md) が名付けた「緑だが検査されていない」そのものが、その ADR を書いた仕組みの内側にあった。

### 結論3: 🟡 **計画が確定した 4 値が表に無い**（いずれも実装済み）

規制側の維持率下限 **30%**・固定額 **$5.00/株**・信用買いの規制維持率 **時価の 25%**・空売り実弾解禁の自己資金 **$5,000**。

うち **25% は 2026-08-07 に確定した値**（利用者裁定 質問票 第 13 回 Q4-3）であり、**確定から本作業まで一度も検査されていなかった**。

### 結論4: 🟡 **`Guard.PreventSameDayReentry` の出典注記が計画より古い**

注記は「適用範囲は日本株現物」だが、計画 §5 は 2026-08-06 に `現物 && （日本市場 ‖ 現金口座）` へ改められている（ADR-0021 決定4-1）。**値は正しく、注記だけが古い。**

## 決定

### 決定1: **型の形の検査と値の検査を併存させる**

`ShortSell.Limits`（メンバ名の一覧）は**残し**、値の 7 行を**追加**する。

役割が違う —— 前者は**メンバの増減**を、後者は**値の逸脱**を捕まえる。片方では他方を代替できない。とくに前者を消すと、`ShortSellingLimits` にメンバが増えたことを誰も検知しなくなる。

### 決定2: **`ShortSell.PriceFloorUsd` と `Regulatory.FixedMaintenancePerShare` は別の行として持つ**

**どちらも $5.00 だが別の概念である** —— 前者は「空売り対象の株価下限」、後者は「規制の固定維持証拠金（`max($5.00 ÷ 株価, 30%)` の分子）」。

**値が同じだからまとめる、をしてはならない。** まとめると、片方が変わったときにもう片方の検査が黙って消える。**同値であることは偶然であり、統制としては無関係な 2 つである。**

### 決定3: **規制側の値も表に入れる**

自前の閾値（40%）と規制側（`max($5.00 ÷ 株価, 30%)`・信用買い 25%）は**別の情報源**であり、「厳しい方を採る」という規則の 2 つの入力である。

**自前だけを検査すると、規制側を緩めても気付けない。** 実効値は「厳しい方」であるため、規制側を下げても多くの株価帯では結果が変わらず、**テストも実挙動も何も言わない**。

### 決定4: **抽出はすべて実装から機械的に導出する**

追加した 11 件はいずれも `TradingDefaults.CreateShortSellSettings().Limits` / `ShortSellingLimits` の定数 / `StageProductPolicy` の定数から読む。**リテラルを手写ししない** —— 手写しすると `PlanRiskDefaults` と同じ紙の上の一致になり、既知逸脱の陳腐化検知（[IADR-0127](./IADR-0127_plan-conformance-known-deviation-registry.md) 検査3）が働かなくなる。

### 決定5: **値は単位つきで正規化する**

`equity ratio 0.10` / `annual rate 0.20` / `gross position ratio 0.50` / `USD 5.00` / `30 days`。

**同じ 0.50 でも「equity 比」と「建玉総額比」では意味する上限額がまったく違う。** 基準を表現に含めれば、基準を取り違えた実装が値の一致だけで素通りすることを防げる（既存の `Fx.*` / `EquityRatioPerDay` と同じ作法）。

## 理由

- **決定1〜3 はいずれも「検査の粒度を、統制の粒度に合わせる」という一つのことを言っている。** 統制は値の単位で効くのに、検査が型の単位でしか行われていなければ、緑は統制の健全性を意味しない。
- **決定4 は本方式の生命線である。** 計画側の表と実装側の抽出が**両方とも人手**になった瞬間、この仕組みは「2 つの紙が一致していること」しか言わなくなる。

## 結果

- **空売り統制の 7 値が、初めて計画と機械的に突き合わされる。**
- **規制側の 3 値と解禁資金 1 値が検査対象に入る**（うち 25% は確定から本作業まで無検査だった）。
- 表は **34 → 45 項目**になった。

### 悪い影響（記録する）

- **本表は「実装が持っている値」しか検査できない。** 計画が確定していても実装に無い値（§1 の配当課税 20.315%・米国株配当の源泉 10%、§4 のスリッページ 0.1%）は表に入れられない —— 入れると `ActualDefaults` へ書き写す以外に手が無く、決定4 が禁じた「紙の上の一致」になる。**実装されるまで無検査のままである。**
- **型の形の検査は、メンバが増えたときに落ちる。** 増やした本人が値の行も足すとは限らず、**型の行だけ直せば緑になる**ため「メンバだけ増えて値が無検査」という状態は依然として作れる。**本作業が塞いだのは既存 7 値であって、この経路そのものではない。**
- **注記（`Citation`）は機械検査されない。** 今回直した `Guard.PreventSameDayReentry` と同じ陳腐化は他の行でも起こり得る。`PlanSourceDigestTests` が計画本文の変更を捉えるため気付く経路はあるが、**注記を直すかどうかは人の判断に残る。**
- **本作業は 2026-08-07 時点の計画（`a4616a8`）に対する照合である。** 計画が動けば再照合が要る。それを自動で気付かせるのが `PlanSourceDigestTests` であり、**本作業はその前提となるベースラインを正しくする作業**である。
- **`Guard.PreventSameDayReentry` は注記だけを直し、実装の適用範囲には触れていない**（→ [#380](https://github.com/endazon/ai-stock-trading/issues/380)）。**注記が計画に追いついたことで、実装が追いついていない可能性がむしろ見えやすくなった。**
