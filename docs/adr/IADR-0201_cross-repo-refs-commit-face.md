# IADR-0201: コミット件名・本文・PR タイトルでクロスリポ参照を検査する

> 実装リポジトリ内の意思決定記録（Implementation ADR）。1 ファイル = 1 意思決定。

- 状態: Accepted
- 日付: 2026-08-15
- 決定者: Claude Code（[IADR-0200](IADR-0200_cross-repo-ref-notation.md) が残した残余リスクの解消）

## 起点・関連

- 計画書 ID: **NFR**（無採番。工程の統制であり計画側の非機能要件表に当たる番号が無い／環流しない）
- 対象 Issue: [#515](https://github.com/endazon/ai-stock-trading/issues/515)（[#487](https://github.com/endazon/ai-stock-trading/issues/487) / [PR #514](https://github.com/endazon/ai-stock-trading/pull/514) から分離）
- 作業仕様書: [20260815_515](../specs/20260815_515_cross-repo-refs-commit-face.md)

## コンテキストと課題 — **配線したのは、実害の小さいほうだった**

規約は**面によって壊れ方が違う**と定める。

| 面 | 裸の `#NNN` | 実害 | [IADR-0200](IADR-0200_cross-repo-ref-notation.md) |
| --- | --- | --- | --- |
| **コミット / issue / PR 本文** | **本リポの issue へ自動リンク** | 🔴 **誤リンク** | ❌ 未配線 |
| `.md` | リンクにならない | 表記ゆれ | ✅ 配線済み |

そのうえで規約は「**優先して直すのは issue / PR / コミットメッセージ側**」と明記している。
**IADR-0200 が配線したのは、規約が「後回しでよい」と言っているほうであった。**

### 🔴 さらに、検査器の docstring が「配線済み」と書いていた

```
 *   - scripts/check-commit-messages.js から件名・本文・PR タイトル（ci.yml の commit-messages / pr-title.yml）
```

実測 `grep -c 'cross-repo\|CROSS_REPO' scripts/check-commit-messages.js` → **0**。呼ばれていない。

> **[IADR-0198](IADR-0198_fx-expired-visibility.md) で実測した「維持されない記述は、あるだけ有害である」と同型である**
> （`Program.cs` が「10 種が扱われることはテストが固定する」と書きながら該当テストが 0 件だった）。
> **同じ型を 2 度実測した。**

## 決定

### 決定1: **`check-commit-messages.js` から検査器を呼ぶ。キット配布物には触れない**

`check-cross-repo-refs.js` が公開する `createChecker` / `findViolations` / `parseNameMap` / `splitList` を使う。
**同ファイルは分類 A（キットとバイト一致）であり、手元で編集しない。**

### 決定2: 🔴 **置換点は `check-commit-messages.js` へ直書きする**（env ではなく）

**`.github/workflows/` を GitHub App 権限で編集できない**（IADR-0140）ため、
既存の `commit-messages` / `pr-title` ジョブへ env を足せない。

`check-commit-messages.js` は**キット同期の分類 C**＝「本リポの中身そのもの（**置換点を持つ配布物**）。
同期しない」であり、**各リポが自分の値を埋める前提**である（`kit-sync-classification.json` の `$comment`）。
**したがって直書きが素直であり、ワークフローを触らずに既存ジョブが新しい検査を拾う。**

> **IADR-0200 決定5（env をテストから注入）とは形が違う。**
> あちらは呼び出し口が**リポ固有のテスト**だったので env で渡せた。
> こちらは呼び出し口が**分類 C のスクリプト自身**である。**同じ問題に同じ答えを機械的に当てない。**

**env でも上書きできる**ようにしてある（試験のため）。値は
`.claude/rules/traceability.repo.md`（#487 の利用者裁定）と同じものである。

### 決定3: **検査するのは PR 範囲のコミット（件名＋本文）と PR タイトル**

**既存履歴は検査しない**（`base..HEAD` のみ。履歴不変・force push 禁止）。
`check-commit-messages.js` の既存方針「**再発防止のみを目的とする**」をそのまま継ぐ。

🔴 **本文も見るのが要点である。** 規約が名指しした実害例は **footer の `Refs #NNN`** であり、
**件名だけ見ていては構造的に取りこぼす。** そのため `collectCommits` が `%B` も取るようにした
（`%B` は改行を含むため**フォーマットの最後に置く**——区切りで分割したときに後続を飲み込まない）。

### 決定4: **`markdown: true` で呼ぶ**

コミット本文はバックティックでコードを引用する（本リポの環流コミットが実際に `grep -c '...'` を書いている）。
**literal な引用は表記規約の対象外**という検査器の定義に合わせる。

### 決定5: **除外は既存の仕組みへ相乗りする**

bot 著者・`Revert`・`[skip ci]`・allowlist は**既存の判定をそのまま使う**。**新しい除外規則を作らない。**

## 対照実験（実走した実測）

| # | 操作 | 結果 |
| --- | --- | --- |
| 1 | 違反する PR タイトル 4 形（長い表記 2 / 空白区切り / 列挙形） | ✅ **4 件とも exit=1** |
| 2 | **否定形**: 正当な 5 形（短縮形 2 / 裸の自リポ `#487` / 末尾 `(#514)` / インラインコードの誤例） | ✅ **5 件とも exit=0** |
| 3 | **件名は適合・本文だけに違反**を置いた空コミット | ✅ **exit=1**（本文の面が効いている） |
| 4 | `checkSingleTitle` に**クロスリポ違反だけ**の件名を渡す | ✅ **1 を返す**（配線前なら 0 だった） |

**実験 3 が本 ADR の核心である。** 件名だけを見る実装では取りこぼす形を、実際に作って確かめた。
**実験 4 は「検査器を呼んでいること」そのものの対照実験**であり、配線が外れれば赤くなる。

## 影響

- **良い影響**: **規約が「優先して直す」と定める面が初めて検査される。** 誤リンクする件名が
  **マージ前に止まる**（スカッシュ後は履歴不変で二度と直せない面である）。
  検査器の docstring の主張に実装が追いついた。
- **悪い影響**: `check-commit-messages.js` の分類 C デルタが増える（キット追随時の手動マージが少し重くなる）。
  コミット本文まで見るため、**本文へ意図的に誤例を書くときはインラインコードへ入れる**必要がある。

## 残余リスク

- **キット配布物の docstring は直していない**（分類 A）。**実装が主張に追いついた**ため食い違いは解消したが、
  **キット側の他リポでは依然として「書いてあるだけ」の可能性がある**——環流の要否は planning#349 の
  「配布物全体を検査器にかける」提案と合わせて計画側が判断する。
- **`.md` 面と置換点が二重に存在する**（`scripts.repo.test.js` の env と本ファイルの直書き）。
  **裁定が変わったら 2 箇所を直す必要がある**——`.claude/rules/traceability.repo.md` を単一の参照先とし、
  両方がそこを指すようにコメントで結んである。**機械は同期を見ていない。**
- **PR 本文（description）は検査していない。** 規約は本文も対象と定めるが、
  `pr-title.yml` はタイトルしか渡さない。**本文は誤リンクが起きる面である**ため穴が残る
  （ワークフローを編集できないため、渡す口が無い）。
