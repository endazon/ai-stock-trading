# IADR-0171: MCP 非公開の維持

- 状態: Accepted
- 日付: 2026-08-07
- 決定者: 実装（Claude Code）／ 起点 [#348](https://github.com/endazon/ai-stock-trading/issues/348)
- 作業仕様書: [20260807_348_mcp-non-exposure](../specs/20260807_348_mcp-non-exposure.md)

## 起点・関連

- 計画 ADR: **ADR-0012**（Accepted・2026-07-23。取引報告書・判断根拠・収集情報を MCP 公開許可リストに含めない）
- 基盤 ADR: platform ADR-0024（MCP サーバー統合。**既定非公開＝許可リスト方式**）／platform ADR-0004（ABAC）
- 計画要求: **FR-08**（KB 保存）・**FR-14**（Discord）・非機能要件（発注機能へのアクセスは本人のみ）
- 関連する実装 ADR: [IADR-0164](./IADR-0164_stage1-trade-count-setting-and-monitor-parameter-relocation.md) 決定1（**変更経路が無いことを構造で固定する**先例）／[IADR-0166](./IADR-0166_plan-source-digest.md)（**「緑だが検査されていない」を作らない**規律）

## コンテキストと課題

**ADR-0012 の統制は、現時点で「何もしない」ことによって守られている。**

基盤の MCP サーバーは既定非公開（許可リスト方式）であり、**本ユニットが自分を登録しない限り公開されない**。ADR-0012 はその既定を維持すると決めた。したがって実装として足すべきコードは無い。

**問題はここにある —— 統制がコード上のどこにも書かれていない。**

着手前の実測（2026-08-07）:

```
$ grep -rniE 'mcp' backend deploy | grep -v '/bin/\|/obj/'
（0 件）
```

対象は `backend/`（`*.cs` 1092 件・`appsettings*.json` 22 件・`*.csproj` / `*.props`）と `deploy/`（`*.yaml` 19 件ほか）。**大文字小文字を問わず、部分一致でも 0 件**であった。

次に構成を触る者から見れば、**MCP 公開は「まだ作っていない機能」と区別が付かない**。基盤 MCP は microservices-platform#445 で作り直される途中であり、その際に「ついでに繋いでおく」ことは自然な発想である。

さらに #348 が求めた 3 点のうち、**AST 側で完結するのは 1 点だけ**であった。

| #348 のスコープ | AST 側の実情 |
| --- | --- |
| MCP 公開許可リストからの除外構成 | **構成そのものが存在しない。** 「除外を書く」対象が無い |
| 漏えいの否定形（結合）テスト | **基盤 MCP が未再実装**（platform#445）。**相手が存在せず書けない** |
| 将来公開する手続きの明文化 | **できる**（`docs/security/security.md` に MCP の言及はゼロだった） |

## 検討した選択肢

| 論点 | 案 | 評価 |
| --- | --- | --- |
| 担保の方法 | A: 何もしない（基盤が既定非公開なので安全） | **棄却** |
| | B: `scripts/check-*.js` ＋ 専用 CI ジョブ | 棄却 |
| | **C: `AiStockTrading.Architecture.Tests` の構造テスト** | **採用** |
| 検出の粒度 | D: 想定されるキー名（`mcp.exposure` 等）を列挙する | **棄却** |
| | **E: `mcp` の出現そのものを検出する** | **採用** |
| 結合確認の扱い | F: #348 のスコープから黙って落とす | **棄却** |
| | **G: `docs/blocked-tasks.md` へ登録して明示的に残す** | **採用** |

### A（何もしない）の棄却理由

**基盤の既定が非公開であることは、AST が公開しないことを保証しない。** 許可リスト方式は「登録しない限り公開されない」という意味であり、**登録する側は AST である**。ADR-0012 §結果 のフォローアップも「実装時、MCP 公開構成に本ユニットの文書コレクション・retrieval スコープが含まれないことを**確認する**」と書いている。**確認を人の記憶に委ねるなら、それは担保ではない。**

### D（キー名の列挙）の棄却理由

**宣言がどういう形で書かれるかは未知である。** platform#445 が構成を作り直す途中であり、`McpExposureOptions` かもしれず `mcp-server:` かもしれず `"mcpServers": {}` かもしれない。**列挙は、想定と違う形で書かれた瞬間に黙って素通りする**——それは検査が無いより悪い（緑であることの意味が失われる。[IADR-0166] 決定2 と同じ構図）。

## 決定

### 決定1: **MCP 公開の宣言が存在しないこと**を構造テストで固定する

`backend/Tests/AiStockTrading.Architecture.Tests/McpExposureNotDeclaredTests.cs` が `backend/` と `deploy/` を走査し、**`mcp` の出現があればテストを落とす**。

**「実装していない」と「実装してはならない」は別である**（[IADR-0164] 決定1 と同じ論法）。ADR-0012 が述べているのは後者であり、**後者はコードに書かれない限り誰も守れない**。

失敗メッセージには **ADR-0012 の要件（新 ADR で 4 点を定める）と `docs/security/security.md` の該当節**を書く。テストが落ちた者が、そこから統制の理由へ辿れるようにする。

### 決定2: 検出は **最も粗い照合（大文字小文字を問わない部分一致）** で行う

**現在 0 件だからこそ、最も粗い照合が最も強い。** 誤検出の代償は「テストが落ちたので人が読む」だけであり、**本テストが求めているのはまさにそれ**である。

対象を `backend/` と `deploy/` に限る。リポジトリ全体を対象にすると `.github/workflows/` の `mcp__github__*`（AI のツール許可リスト。**MCP 公開とは無関係**）を除外する必要が生じ、除外規則が育つ。**除外が育ったぶんだけ検査は弱くなる。**

#### 走査するファイルは **拒否リスト**で決める（PR #451 レビューによる修正）

**当初は走査する拡張子の許可リスト（`.cs` `.json` `.yaml` …）で書いていた。これは誤りであった。**

`Dockerfile` は `Path.GetExtension` が空文字列を返すため、**`backend/Dockerfile` と `deploy/opend/Dockerfile` の 2 件が黙って走査から漏れていた**。Dockerfile は `RUN` / `ENV` で **MCP サイドカーやクライアントの導入を書き得る場所**であり、決定2 が拠って立つ「粗い照合の強さ」を部分的に無効化していた。

**より重い問題は、それが「除外」として見えなかったことである。** 本 ADR は当初「除外は 1 件（本テスト自身）で済む」と書いていたが、**許可リストそのものが 2 種類目の除外として働いていた**。除外が明示的なら数えられるが、**許可リストの裏側にある除外は数えられない。**

したがって**拒否リストへ反転した**。除外は**意図的に 1 種類だけ**である。

| 除外 | 理由 |
| --- | --- |
| `.md` | **設計文書は「MCP へは公開しない」と書くこと自体が正しい場所**である（本 ADR・作業仕様書がそうである） |
| `McpExposureNotDeclaredTests.cs` | 本テスト自身（説明のために `mcp` を含む） |

**新しい種類のファイルは既定で走査対象になる。** 拒否リストを足すときは本 ADR に理由を書くこと。

### 決定3: **空振りしないことを対照（肯定形）で固定する**

否定形テストは「効かない方向」に壊れると**緑のまま統制だけが消える**——走査対象が 0 件になっても「違反 0 件」で緑になる。したがって次の 2 つを別テストで固定する。

1. **走査対象が痩せていないこと**（下限 900 件。着手時点の実測は 1100 件超）
2. **照合器そのものが効くこと**（`mcp` / `MCP` / `"mcpServers"` / `McpExposureOptions` / `mcp-server:` / `Exposure:Mcp:Enabled` を検出し、無関係な文字列は検出しない）
3. **拡張子を持たない構成ファイルが走査対象に入っていること**（`backend/Dockerfile` / `deploy/opend/Dockerfile` を名指しで確認する）
4. **Markdown が意図的に外れていること**（「うっかり外れている」のか「外してある」のかを区別できるようにする）

**3 は上記の修正への回帰テストである。** Dockerfile が漏れていたとき、**そのことは失敗メッセージにも件数にも現れなかった**——「違反 0 件」が「Dockerfile を読んでいない」を隠していた。**同じ隠れ方をもう一度させないために、名指しで固定する。**

**「0 件でした」が「1 件も読んでいません」と区別できない形にはしない**（[IADR-0166] と同じ規律）。

### 決定4: **閉じているのが MCP という経路だけであること**を明記する

`docs/security/security.md` に、**利用者本人による基盤チャット UI・RAG 検索（FR-08）・Discord からの参照（FR-14）は従来どおり可能**であることを経路の表で書く。

**これを落とすと逆向きの害が出る。** 「MCP 非公開」を「AST のデータは誰も検索できない」と読み違えると、FR-08 / FR-14 の実装が萎縮する。ADR-0012 §決定 の 2 点目が明示しているのはまさにこの区別である。

### 決定5: **結合確認は `docs/blocked-tasks.md` へ登録して明示的に残す**

#348 が求めた結合テスト（MCP ツール一覧・検索・文書取得のいずれの経路でも AST のデータが返らないこと）は **platform#445 が完了するまで書けない**。

**これを黙って落とすと、#348 をクローズした時点で「確認した」ことになってしまう。** A-10 として登録し、何を待っているか・解消後に何を確認するかを書く。

## 理由

- **決定1 と決定2 は同じことを別の角度から言っている** —— 守りたいのは「MCP という語が本ユニットの構成に現れないこと」そのものである。**意味を解釈しようとするほど、解釈から漏れた形が素通りする。**
- **決定3 が無ければ決定1 は自己満足である。** 否定形テストは、対象を取り違えても・照合器が壊れても緑になる。**緑が何を意味するかを、緑のときに確かめられる形にした。**
- **決定5 は「やっていないことを、やったことにしない」という規律である。** #348 のスコープは 3 点あり、実施したのは 2 点である。

## 結果

- **MCP 公開が「未実装の機能」として素直に足される経路が塞がれる。** 足そうとすればテストが落ち、落ちた者は ADR-0012 と手続きへ辿り着く。
- **セキュリティ仕様書に、実装側の読者が読む形で統制と手続きが載る。**
- **未了の結合確認が、待っている相手つきで見える。**

### 悪い影響（記録する）

- **本テストは本リポジトリ内しか見ない。** 基盤側の許可リストへ**基盤側の PR で**追加された場合、**AST の CI は緑のまま統制が破れる**。これが決定5 の結合確認が必要な理由そのものである。ADR-0012 §結果 が挙げるドリフト検出（構成情報 API / SC-11）は**まだ実装されていない**。
- **照合が粗い。** MCP 公開を意味しない記述でも落ちる。**誤検出は安全側**だが、頻発すれば拒否リストが育ち、育った分だけ検査は弱くなる。**除外を足すときは本 ADR に理由を残すこと。**
- **Markdown は走査対象外である**（`docs/` および `deploy/**/*.md`）。設計文書に MCP 公開を書いても検出しない（意図的——本 ADR 自身が `mcp` を多数含む）。**宣言が入るのは構成とコードであり、そこを見ている。**
- **許可リストで書いた当初版は、Dockerfile 2 件を黙って落としていた**（PR #451 レビュー指摘）。拒否リストへ反転して解消したが、**この失敗の本質は「除外が除外に見えなかったこと」**である。同種の隠れ方——走査条件の副作用としての除外——は今後も起こり得る。**下限件数と名指しの対照テストが唯一の防壁である。**
- **ADR-0012 が Superseded された後も本テストは残る。** 公開を決めた新 ADR の実装時に**明示的に外す**必要がある。**外す作業そのものがレビューの契機になるため、これは意図した設計である。**
- **`docs/security/security.md` は本節以外がまだ雛形のままである。** 実態の横断調査を要するため本作業では埋めず、[#450](https://github.com/endazon/ai-stock-trading/issues/450) として起票した。**書かれていないことを「対策が無い」と読まないよう、本文冒頭に注意書きを置いた。**
