# IADR-0196: 為替の情報源の状態を 3 経路へ可視化する

> 実装リポジトリ内の意思決定記録（Implementation ADR）。1 ファイル = 1 意思決定。

- 状態: Accepted
- 日付: 2026-08-15

## 起点・関連

- 計画 ADR: [ADR-0022](../../planning/projects/ai-stock-trading/07_adr/ADR-0022_fx-rate-source-and-freshness.md) **決定1**（クレジット表記）・**決定2**（切替の記録・通知と**期間**）・**決定5**（警告の宛先）

## コンテキストと課題

第 1 層で情報源は二段になり、鮮度の 3 段縮退も効くようになった。**しかし出力先はログだけであった。**

第 1 層の自分のコメントがそれを認めている。

```csharp
// **本 PR ではログのみであり、3 経路への配線は #381 の第 2 層（次 PR）で行う**
// ログに留まる間は、**切り替わった事実は運用者が能動的に見に行かないと分からない。**
```

> 🔴 **「黙って劣化させない」（ADR-0022 決定2）は統制の要件であって、ログの要件ではない。**
> **能動的に見に行かないと分からないものは、黙っているのと区別がつかない。**

## 決定

### 決定1: **状態の遷移で発行する。呼び出しごとには発行しない**

レート源は **watchlist の銘柄ごと・巡回ごと**に呼ばれる。呼び出しごとに発行すると **1 巡回で N 件**出る。

| 遷移 | イベント |
| --- | --- |
| 第一が使えている → **使えない** | `FxRateSourceFellBack` |
| 使えない → **回復した** | `FxRateSourcePrimaryRestored` |

> **遷移で発行すると、決定2 が求める「切り替わっていた期間」が自然に得られる。**
> 回復イベントが `FellBackAt` を持つため、**期間は受け手が引き算するのではなく発行側が事実として渡す** ——
> 受け手が引き算する形にすると、**片方を取りこぼしたとき期間が黙って狂う。**

**鮮度警告は遷移ではなく状態である**（数日続く）。こちらは [IADR-0096](IADR-0096_notify-daily-policy-unconfirmed.md) 決定4 と同じ
**暦日単位の抑止**とし、**日をまたげば再通知する**（1 度出して終わりでは気づけない）。

**判定はメッセージバスから切り離した**（`FxSourceStatusTracker`）。一体にすると、
**最も壊れやすい部分（遷移の判定）を試すのに Wolverine のホストを起こす必要が生じる。**

### 決定2: **押す経路と引く経路を、サービスごとの既存の作りに合わせる**

| 宛先 | 経路 | 根拠 |
| --- | --- | --- |
| 監査ログ | **push** | `AuditConsumerCoverageTests` が**網羅を強制する既存機構**に乗る |
| Discord | **push** | `NotificationService` の既存の作り |
| 日報 | **pull**（供給ポート） | `ReportService` は期間を指定して引く（`IPeriodFillSource` 等）。イベントを購読していない |

**無理に統一すると ReportService にイベント永続化層を新設することになる**（過剰）。

### 決定3: 🔴 **日報の供給不達を「切替なし」へ倒さない**

`IFxSourceStatusSource` は取得不能のとき **`null`** を返す（空列ではない）。
[IADR-0133](IADR-0133_maintenance-margin-auto-reduce.md) 決定7 と同じ判断である。

> **「照会できなかった」を「切替は無かった」と書くことは、劣化を隠したのと同じ結果になる。**
> **それは決定2 が禁じていることそのものである。**

### 決定4: **クレジット表記の literal は契約に 1 つだけ置く**

`FxSourceCredits.Boj`（`Shared.Contracts`）を唯一の実体とし、取得側（`BojFxRateSource.Credit`）も
表示側（`ReportRenderer`）もそこを引く。

**書き写すと、利用条件が変わったときに片方だけ古くなり、しかも誰も気づかない**
——**表示だけが古い＝出典の記載が事実と違う**という、最も気づきにくい壊れ方をする。

**日銀を実際に使った期間だけ出す。** FRED フォールバック中に日銀のクレジットを出すのは**事実に反する**。

### 決定5: **可視化の失敗で取引判断を止めない。ただし黙って飲み込まない**

通知経路の障害を理由にレートを捨てると、**警告が停止へ化ける**（ADR-0022 決定5 は「値は返す」と決めている）。
例外は飲み込むが、**飲み込んだ事実をログへ残す** —— 黙らせると「通知が来ない＝正常」と読めてしまう。

`OperationCanceledException` は伝播させる（取り消しは失敗ではない）。

## 対照実験（変異試験・実走した実測）

**5 通りの変異を当て、いずれも「変異が実際に適用されたこと」を diff で確認してから実行した。**

| # | 変異 | 落ちたテスト |
| ---: | --- | --- |
| 1 | **遷移判定を潰す**（毎回 `FellBack` を返す＝洪水） | 「フォールバックが続いている間は再発行しない」 |
| 2 | **暦日の抑止を潰す**（鮮度警告が毎回出る） | 「同じ日に 1 回だけ」ほか 2 件 |
| 3 | **監査ハンドラを 1 本消す** | `AuditConsumerCoverageTests`（`FxRateStale` を名指しで報告） |
| 4 | **報告書のクレジット出力を消す** | 「日銀を使った期間はクレジット表記を出す」 |
| 5 | **照会不能を「劣化なし」へ潰す**（決定3 を破る） | 「切替なしとは書かず要確認と明記する」 |

### 🔴 変異試験そのものでもう 1 つ学んだ —— **当たらなかった変異は「生き残った変異」と見分けがつかない**

**変異 4 は最初の実行で「生き残った」（exit 0・147 passed）。** 実際には
**シェルの引用符の都合で置換が 1 件も一致せず、変異が適用されていなかった。**

> 🔴 **[#507](https://github.com/endazon/ai-stock-trading/pull/507) では「弱い変異」が生き残った。今回は「当たらない変異」であった。**
> **どちらも「変異試験をした」という報告だけを見れば区別がつかない。**
>
> **是正**: 置換前に一致件数を検査して**一致 0 なら中止**し、適用後に **`git diff --numstat` で実際に変わったことを確認**してから実行する。

### 🔴 加えて、変異試験の手順そのもので作業を破壊した

**`git checkout --` で変異を戻したところ、同じファイルの未コミットの実装ごと消えた**
（`ReportRenderer.cs` の為替欄と `AuditEventHandlers.cs` の監査ハンドラ 3 本）。

**追跡済みファイルに対する `git checkout --` は「変異だけ」ではなく「HEAD との差分すべて」を捨てる。**

**是正**: **変異試験の前に必ずコミットする。** 本 ADR の実装はコミット後に変異試験をやり直した。

## 影響

- 肯定的:
  - **計画が 3 回求めている可視化（決定1・2・5）が、初めて実際に 3 経路へ届く。**
  - **期間がイベント自身に載る**ため、受け手の引き算ミスで期間が狂わない。
  - **監査の網羅は既存の強制機構に乗せた** —— 次にイベントを足す人にも自動で効く。
- 否定的 / トレードオフ:
  - **イベントが 3 つ増え、キューも 3 つ増える**（監査・通知それぞれ）。
  - **状態は in-memory（singleton）である。** 再起動すると「フォールバック中」の記憶が消え、
    **復帰イベントが 1 回失われる**（次にフォールバックしたとき改めて発行される）。
    永続化は過剰と判断した（IADR-0096 決定4 と同じ整理）。
  - **日報の供給ポートは未結線である**（既定は取得不能＝ `null`）。
    **配線するまで日報には「照会できませんでした（要確認）」と出る** —— **「切替なし」と嘘をつくよりよい**（決定3）。

## 残余リスク

- 🔴 **日報の供給ポートが未結線である。** 権威源（監査台帳の照会 API）への結線は別作業になる。
  **それまで日報の当該節は毎回「要確認」と出る** —— 正直ではあるが、**慣れると読み飛ばされる**。
  `IMarginReductionRecordSource` が同じ状態で先行しており、**同じ経路でまとめて結線するのが筋である。**
- **再起動でフォールバック状態が失われる**（上記）。**劣化中の再起動では復帰通知が出ない。**
- **通知の重複抑止は通貨ごと・プロセスごとである。** 複数インスタンスで動かすと**インスタンス数だけ通知が出る**。
  現構成は単一インスタンスであり実害は無いが、**水平展開すると顕在化する。**
- **鮮度警告の暦日は UTC である**（JST 営業日ではない）。`IADR-0096` 決定4 と同じ慣行に揃えたが、
  **JST の日付境界とはずれる**。
