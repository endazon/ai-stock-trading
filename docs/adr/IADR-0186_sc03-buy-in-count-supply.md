## コンテキストと課題

計画 FR-21 の受け入れ基準は**両方向に効く**。

> **供給されている 0 が「取得できていません」と表示されない**（FR-21・05_screens §供給が無い値の表示規約）。
> **規約は両方向に効く** —— 未供給を 0 に見せないことと、**正当な 0 を未供給に見せない**ことの**両方**をテストで固定する

`ShortSellingStatusService` は `BuyInCountAvailability: NotSupplied` を**無条件で**返しており、
そのコメントは「記録経路が要る」と述べていたが、**その経路は #463 / IADR-0181 で入っている**（コメントが stale）。

**現時点では観測が 1 件も到達していないため表示は事実として正しい。しかし観測が流れ始めた日に、
SC-03 は「正当な 0 を未供給に見せる」側の規約違反へ黙って転じる。** 供給が入った日は誰も画面を見直さない。

### 🔴 issue #470 の本文は 1 点が陳腐化していた

issue は受け入れ基準に「**裁定前は最終観測時刻の存在のみで判定する**」と書いていたが、
**その裁定（[project-planning#292](https://github.com/endazon/project-planning/issues/292)）は起票と同日中に下りた**。
FR-21 は「観測が届いた取引日の集合」＋「期間被覆」へ改定され、実装も #469 で追随済みで、
`observationArrivedAt`（最終観測時刻）という API はもう存在しない。**本 IADR は改定後の FR-21 に従う。**

### 決めるべきこと: SC-03 の「期間」が計画に無い

FR-21 は「**報告期間**が覆われている場合に限り供給する」と定めるが、**SC-03 は報告書ではなく現況画面**であり、
その期間を計画は明示していない。**被覆判定は `[from, to]` を与えられなければ書けない。**

## 検討した選択肢

| 案 | 期間 | 評価 |
| --- | --- | --- |
| **A** | **当月（月初〜当日）** | **ADR-0016 決定15 は「発生回数」を月報（当月）へ、「発生有無」を日報（当日）へ割り当てている。** SC-03 の当該項目の名称は**発生回数**であり、決定15 の語彙にそのまま対応する。**発明ではなく導出である** |
| B | 当日 | SC-03 は当日損益を持つため画面の枠としては自然だが、決定15 で当日に割り当てられているのは**発生有無**であって回数ではない |
| C | 全期間 | 計画に定義が無い。観測は OpenD 常駐の開始後にしか届かないため**被覆が永久に成立せず恒久 `NotSupplied`** になり、#470 の目的を満たさない |

## 決定

### 決定1: 期間は**当月（月初〜当日）**とし、被覆判定は `ObservationCoverage.Covers` を通す（案 A）

- **判定規則を再実装しない。** 照会 API（#469）と**同じ純関数**を使う —— 規則が 2 か所に分かれると必ず食い違う。
- **1 日でも欠ければ `NotSupplied`。** 部分被覆を「覆っている」と扱うと、観測が止まっていた日の推定 0 件が
  正当な 0 として画面に出る（FR-21 の失敗モード 2）。
- **期間の決定を 1 か所（`BuildBuyInCount`）に閉じた。** 裁定が案 B・C を指すなら 2 行の差し替えで追随できる。
- **計画へ環流済みである**（`feedback/20260813_sc03-buy-in-count-period-undefined.md`）。
  **どの案でも安全側の性質は変わらない** —— 覆えていなければ未供給であり、案の違いは*いつ供給が始まるか*にのみ効く。

### 決定2: 被覆が成立したときに限り `Available` ＋ 推定件数を返す

- **被覆を見ずに `CountInferredBetween` だけを結線しない**（issue の禁止事項）。IADR-0162 決定2 が塞いだ fail-open が戻る。
- 被覆が成立していれば**推定 0 件でも `Available` かつ 0** を返す。**これが本 issue の主目的である。**

### 決定3: **他の指標の供給状態を条件に混ぜない**（IADR-0154 残余リスク4）

本項の入力は**観測の到達と推定台帳だけ**である。維持率・現在値・空売り比率の供給が入った日に、
本項の可否が黙って変わってはならない。**両方向で固定する**（他が供給されても未供給のまま／他が未供給でも供給する）。

### 決定4: 結線は**必須依存**にする（省略可能引数にしない）

省略可能にすると**配線を落としても既定値で緑のまま通る**（「緑だが検査されていない」）。
`ICurrentPriceSource` は**省略可能のまま**残す —— 現在値の供給が無いことは正当な状態であり `null` の意味が違う。

### 決定5: SC-03 に操作を足さない（参照専用）

issue の禁止事項。BFF・フロントへも経路を足さない（`BffPassThroughTests` の網羅突合が既に守っている）。

## 対照実験（実走した実測）

| 壊した箇所 | 赤くなったテスト |
| --- | --- |
| **被覆判定を外し件数だけを結線**する（issue が名指しで禁じた fail-open） | **6 件**（T-10-257 / T-10-258 / T-10-259 / T-10-280 / T-10-281 / T-10-282） |
| **部分被覆を「覆っている」と扱う**（観測が 1 日でもあれば供給） | **1 件**（T-10-281 `当月の営業日が一日でも欠ければ未供給へ倒す`） |

> 2 件目が **1 件しか赤くならないこと自体が情報である** —— 部分被覆の禁止を覆っているのは T-10-281 だけであり、
> **この 1 本を消すと FR-21 の失敗モード 2 が無検査になる。**

## 影響

- 肯定的:
  - **観測が流れ始めた日に、SC-03 が自動的に正当な 0 を供給する。** 画面を見直す人手を必要としない。
  - 判定規則が照会 API と**単一の純関数**に集約され、画面と報告書で食い違わない。
  - stale なコメント（「記録経路が要る」）が事実へ是正された。
- 否定的 / トレードオフ:
  - **SC-03 の期間が裁定待ちである**（決定1）。裁定が案 B・C を指せば差し替えが要る。
  - **観測そのものはまだ届かない**（OpenD 常駐は A-1 / A-2）。本 PR で画面の表示は変わらない ——
    変わるのは**観測が届き始めた日**である。

## 残余リスク

- 🔴 **祝日の扱いは「暦がまだ無い」のではなく「持たないと裁定済み」である。**
  [#407](https://github.com/endazon/ai-stock-trading/issues/407) の裁定（2026-08-07・質問票 第13回 Q3 案2。
  計画 06_daytrading-review §4.2）は **「祝日は判別しない。除外しない」**と定め、
  **祝日判定・休場日リスト・外部カレンダーを入れること自体を禁じている**。
  したがって本項の祝日の扱いは **#407 の完了で解消される類の制約ではなく、現行設計の恒久の性質である**
  （「暦が入れば直る」と書くと、後から祝日カレンダーを足す動機になり裁定違反を招く）。
  **帰結は観測側の挙動に依存する** —— 観測が祝日にも届くなら被覆は成立し供給される。
  届かないなら**その月は未供給へ倒れる**（安全側だが供給が始まらない）。
  🔴 **米国市場の祝日は年 9〜10 日あり月をまたいで散在するため、後者なら「ほとんどの月で供給されない」ことになり得る。**
  **観測が実際に届き始めた時点で実測し、供給が始まらないなら期間の定義（決定1）とともに裁定を仰ぐ**
  ——本 IADR では観測実績が無いため**どちらに倒れるか実測できていない**。
- **月初は被覆が成立しやすい**（月初 1 営業日だけなら 1 日観測すれば覆える）。月をまたいだ瞬間に
  `NotSupplied` → `Available` へ変わり得るが、**これは期間の定義（決定1）の帰結であって欠陥ではない**。
  裁定で案 B（当日）が選ばれれば同じ性質がより短い周期で現れる。
- **推定台帳の件数そのものの正しさは本 IADR の範囲外**（IADR-0159 の推定に依存する）。
