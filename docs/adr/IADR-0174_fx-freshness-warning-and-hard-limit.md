# IADR-0174: 為替レートの鮮度 — 警告と停止の分離

- 状態: Accepted
- 日付: 2026-08-07
- 決定者: 実装（Claude Code）／ 起点 [#381](https://github.com/endazon/ai-stock-trading/issues/381)
- 作業仕様書: [20260807_381_fx-freshness-degradation](../specs/20260807_381_fx-freshness-degradation.md)

## コンテキストと課題

計画 ADR-0022 決定4・5（および §5「為替レートの鮮度による縮退」）は、鮮度の縮退を **3 段**で定めている。

| 齢 | 動作 |
| --- | --- |
| **5 日以下** | 通常運用 |
| **5 日超〜30 日以下** | **直近レートで続行し、警告を出す**（新規建ては止めない） |
| **30 日超** | **新規建てを停止**（**手仕舞い・損切りは止めない**） |

**実装は上限だけを持っており、この 3 段が 2 段に潰れていた。** 超えたら即「レート無し」＝停止であり、**気づくための警告が存在しなかった**。

### 🔴 実測で見つかった追加の問題 — **構成クランプが計画の絶対上限を超えていた**

`FxOptions.MaxAllowedRateAgeDays = 31` は、**計画が「絶対上限」と呼ぶ 30 日を上回っていた**。

つまり `Fx:MaxRateAgeDays: 31` と構成すれば、**計画が「新規建てを停止する」と定めた 30 日超の観測で発注できた**。クランプは「設定で guard を無効化させない」ために置かれた仕組み（[IADR-0112](./IADR-0112_fx-rate-freshness-publication-cadence.md) 決定2）だが、**その上限自体が計画より緩かった**。

31 は FRED の週次公表から逆算した当時の実装都合であり、**根拠が計画へ移った今は 30 が正しい**。

### 本 ADR の範囲 — **#381 の 3 分の 2**

`KnownPlanDeviations` の #381 担当は 3 件ある。**日銀アダプタの新設は別 PR にした**（外部 HTTP アダプタ・フォールバックの調停・通知・監査ログを含み、本作業とは壊れ方も試し方も違う）。

| 登録行 | 本 ADR |
| --- | --- |
| `Fx.StaleRateWarningDays`（定数が存在しない） | ✅ 解消 |
| `Fx.MaxRateAgeDays`（14 日） | ✅ 解消 |
| `Fx.RateSourceProviders`（FRED 単独） | ❌ **#381 に残す** |

## 決定

### 決定1: **警告と停止を分離する**

`FxOptions.DefaultStaleRateWarningDays = 5` を新設し、`CachingFxRateSource` が**警告域では値を返しつつ警告ログを出す**。

**警告と停止は役割が違う** —— 前者は**気づくため**、後者は**統制が意味を失った状態で発注しないため**である。同じ値に潰すと、**劣化が始まったことに気づく機会が消える**。

### 決定2: **構成クランプを 31 → 30 へ下げる**

計画の絶対上限と一致させ、**構成で計画を超えられない**ようにする。

### 決定3: **警告しきい値も上限でクランプする**

`min(warning, max)` で正規化する。**警告が上限を超えると、警告が一度も出ないまま停止する** —— 統制自体は残るが、**劣化に気づけなくなる**。決定1 の目的がそのまま消える。

## 理由

- **決定1〜3 はいずれも「気づけること」を守っている。** 統制（止めること）は元から効いていた。本 ADR が足したのは**その手前で気づく段**であり、決定3 はそれが消えないための保険である。
- **決定2 は「クランプの上限が計画より緩い」という、クランプの意味を無効化する状態の是正である。** 歯止めを置いたつもりで、歯止めの位置が守るべき線の外側にあった。

## 結果

- **縮退が計画どおり 3 段になる。**
- **構成で計画の絶対上限（30 日）を超えられなくなる。**
- `KnownPlanDeviations` から #381 の 2 行が消える（残り 1 行は日銀アダプタ）。

### 悪い影響（記録する）

- 🔴 **既定の鮮度上限が 14 → 30 日になり、「週次リリース 1 回の丸ごと欠落」（17.84 日）を棄却しなくなった。**
  旧実装は [IADR-0112](./IADR-0112_fx-rate-freshness-publication-cadence.md) 決定1 の逆算（≒12.84 日 ＋ 余裕）で 14 日を採り、**これを「系列側の異常」として止めていた**。計画が 30 日を絶対上限としたため、**この保護は失われる**（警告は出るが発注は続く）。
  **これは計画が選んだ緩和である** —— §5 は「5 日超〜30 日以下＝直近レートで続行し警告」と定めており、17.84 日はその範囲に入る。**実装の判断で計画より厳しくすることはしない**（計画書は絶対的な正）。既存テストの期待値もこの判定変更に合わせて更新し、**変わった事実をテストのコメントに残した**。
- 🔴 **日銀アダプタが無い限り、警告は常時鳴る可能性が高い。** FRED 単独では最新観測の齢が最大 12.84 日まで積み上がるため、**5 日超の警告域に常駐する**。**常時鳴る警告は無視される警告**であり、**本 ADR の決定1 は日銀アダプタ（#381 の残り）が入って初めて実効する**。分割の帰結として明示する。
- **警告の宛先はログのみである。** 計画は日報・監査ログ・Discord 通知も求めるが、それは**フォールバック切替の通知と同じ経路**であり #381 の残りの担当とした。
- **30 日超で「新規建てだけを止める」ことは本作業では検証していない。** 現在の実装は鮮度切れを「レート無し」として返し、呼び出し側が非基準通貨の新規建てを見送る。手仕舞いは為替レートを必要としないため止まらない —— **既存の構造であり本作業で挙動は変えていない**が、その一致を確かめてはいない。
