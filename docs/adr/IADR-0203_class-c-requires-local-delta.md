# IADR-0203: 分類 C は固有デルタを持つ。持たないなら A である

> 実装リポジトリ内の意思決定記録（Implementation ADR）。1 ファイル = 1 意思決定。

- 状態: Accepted
- 日付: 2026-08-15
- 決定者: Claude Code（[IADR-0202](IADR-0202_traceability-md-classification.md) が残した残余リスクの実測）

## 起点・関連

- 計画書 ID: **NFR**（無採番。工程の統制であり計画側の非機能要件表に当たる番号が無い／環流しない）
- 対象 Issue: [#521](https://github.com/endazon/ai-stock-trading/issues/521)
- 作業仕様書: [20260815_521](../specs/20260815_521_kit-sync-and-class-c-audit.md)

## コンテキストと課題 — **残余リスクが、翌 PR で現実になった**

[IADR-0202](IADR-0202_traceability-md-classification.md) は残余リスクにこう書いた。

> 🔴 **分類の誤りを検出する機械は無い。** … **今回は違反 1 件が偶然この矛盾を暴いたのであって、
> 構造的に見つけたのではない。残る C 16 件について同種の取り違えが無いとは言えない。**

**全数を走査したら、2 件あった。**

| ファイル | 実測 | なぜ固有デルタが 0 なのか |
| --- | --- | --- |
| `scripts/check-plan-id-qualification.js` | **キットとバイト一致** | 置換点 `PROJECT_PREFIXES` は**空**。本リポは他プロジェクトの計画書を参照せず、**空が正常な状態**である（検査は skip する）。埋める理由が無い |
| `scripts/check-cross-repo-refs.js` | 差分 13 行だが、**13 行すべてがキット側の是正** | 置換点は `<sibling-repo-name>` 等の**プレースホルダのまま**。[IADR-0200](IADR-0200_cross-repo-ref-notation.md) 決定5 で **env 注入を選んだ**ため埋めていない |

🔴 **後者は実害が出ていた。** キット側が planning#354 を受けて是正した後も、本リポの写しは
**`IADR-0140` の誤引用**（**本リポが環流した当のもの**）と、
「**ワークフローを編集できない**」という**実測で否定済みの前提**を保持し続けていた。

### 定義の読み違い

分類表の C は「本リポの中身そのもの（雛形から書き起こした実体、または**置換点を持つ配布物**）。同期しない」である。

| | 読み方 |
| --- | --- |
| ❌ 従前 | 置換点を**「持つ」**なら C |
| ✅ 是正 | 本リポが置換点を**「埋めている」**なら C |

**埋めていないなら固有デルタは 0 であり、「各リポが自分の値を埋める前提」という C の根拠が
そもそも成り立たない。** 根拠の無い C は「同期しない」だけが残り、**キット側の是正を永久に遮断する。**

## 決定

### 決定1: **分類 C は固有デルタを持つ。持たないなら A である**

`check-cross-repo-refs.js` と `check-plan-id-qualification.js` を **C → A** へ移す（A 81 → 83 / C 16 → 14）。

**`check-commit-messages.js` は C のままである** —— 同ファイルは**置換点を実際に埋めている**
（[IADR-0201](IADR-0201_cross-repo-refs-commit-face.md) 決定2 の直書き）。**同じ「置換点を持つ配布物」でも、
埋めているかどうかで分類が割れる。それが本 ADR の要点である。**

### 決定2: 🔴 **再発を機械で止める（同型 2 回に達した）**

運用標準は「**検査器・規約の追加は同型事故 2 回から**」と定める。**達した。**

| # | 事故 | 発見 |
| --- | --- | --- |
| 1 | `.claude/rules/traceability.md`（[#517](https://github.com/endazon/ai-stock-trading/issues/517)） | **人**（違反 1 件が偶然暴いた） |
| 2 | `check-cross-repo-refs.js`（本件） | **人**（残余リスクを追って全数走査した） |

**1 回目も 2 回目も人が気づいた。3 回目は機械が止める。**

`scripts.repo.test.js` に、分類 C の各エントリを 2 つの信号で検査するテストを置く。

| 信号 | 意味 |
| --- | --- |
| **キットとバイト一致** | 固有デルタが 0。C の根拠が無い |
| **置換点のプレースホルダが残っている** | 埋めていない。C の根拠が無い |

**キットに対応物が無いファイルは対象外**（本リポ固有の実体であり、C で正しい）。

### 決定3: **配線先は `scripts.repo.test.js` とする。`check-kit-sync.js` へは足さない**

`check-kit-sync.js` は**分類 B**（本リポが進んでおり、環流済み・追跡中）である。
**ここへ足すと B のデルタがさらに増え、キット追随時の手動マージが重くなる。**
リポ固有の検査は `scripts.repo.test.js` へ置くのが本リポの既定（IADR-0189 決定2・IADR-0200 決定5）。

### 決定4: **planning#355 の誤配線は「該当しない」ことを記録に残す**

計画側は「`check-review-verdict.js` を `prompt:` を持たないワークフローへ配線すると、
**正常完了した実装タスクでも恒常的に赤くなる**」と伝えてきた。**本リポは該当しない**（実測）。

- 配線は `claude-code-review.yml` の **1 箇所のみ**（同ファイルは `prompt:` を持つ）
- `claude-coding.yml` へは配線されていない

🔴 **「該当しなかった」を黙って通さない。** 確かめた事実を残さないと、
**次に同じ通知が来たとき、また同じ確認をやり直すことになる**（あるいはやり直さずに見逃す）。

## 対照実験（変異試験。実走した実測）

| # | 変異 | 期待する枝 | 結果 |
| --- | --- | --- | --- |
| A | `check-cross-repo-refs.js`（**同期後**）を C へ戻す | バイト一致 | ✅ **赤** |
| B | `check-plan-id-qualification.js` を C へ戻す | バイト一致 | ✅ **赤** |
| C | `check-cross-repo-refs.js` を**同期前の版に戻して** C へ置く | **置換点の未記入** | ✅ **赤** |

> 🔴 **変異 C を足したのは、A と B が両方とも「バイト一致」の枝でしか赤くならなかったからである。**
> **枝が 2 つあるのに 1 つしか試していない状態は「検査したつもり」である**
> —— **本 ADR が扱っている課題（固有デルタ 0 を C に置くと検査が止まる）とまったく同じ形**を、
> **自分の追加したテストで繰り返すところだった。**

### 🔴 初版のテストは偽陽性を出した（本 ADR の索引行に当たった）

置換点の目印を**文字列としてだけ引いた**ため、**`docs/adr/README.md` の IADR-0203 索引行**
——「置換点は `<sibling-repo-name>` 等のプレースホルダのまま」という**引用**——を違反として上げた。

**規則 2「あり得る形をすべて列挙してから引く」の裏返しである。**
目印は「置換点そのもの」と「置換点を語る引用」を区別しない。
**キット版が `【置換点】` を宣言しているファイルに限定して**解いた
（`docs/adr/README.md` は宣言を持たないため対象外になる）。

> **これで 2 度目である。** [#517](https://github.com/endazon/ai-stock-trading/issues/517) のコミット本文でも、
> **違反例を素で書いたことで自分の配線した検査に止められた**。
> **規約を書く作業は、その規約の検査対象に自分が入る作業でもある**（母集合の規則 8 と同じ構造）。

## 影響

- **良い影響**: 環流の**復路が 2 本ぶん開いた**。取り違えの families が**機械で止まる**ようになり、
  IADR-0202 が「構造的に見つけたのではない」と書いた穴が塞がった。
  **分類の判定基準が「持つ」から「埋めている」へ明確になった。**
- **悪い影響**: A が 2 件増えたぶん、キットが変わると**本リポの CI が赤くなる頻度が上がる**。
  **設計どおりの痛み**である（[IADR-0202](IADR-0202_traceability-md-classification.md) と同じ判断）。

## 残余リスク

- 🔴 **置換点の目印は決め打ちである。** テストが見るのは
  `<sibling-repo-name>` / `<SHORT>` / `<SELF_SHORT>` / `<self-repo-name>` の 4 つであり、
  **キットが別の形の置換点を導入したら検出しない**。バイト一致の信号は形に依らないため、
  **「キット側が変更していない間」は依然として捕まる**が、両方をすり抜ける形はあり得る。
- ~~🔴 **必読規約の総量が予算の 91.5%（45,760 / 50,000）に達した。**~~
  🔴 **【訂正・2026-08-15／[#519](https://github.com/endazon/ai-stock-trading/issues/519)・[IADR-0204](IADR-0204_reading-budget-mother-set.md)】この値は誤りであった。**
  `AGENTS.md`（4,434 バイト）は「**Claude 以外の AI エージェント**が読み込む共通指示」（同ファイル冒頭）であり
  **Claude は読まない**。**異なるエージェントの集合を足していた。**
  正しくは **41,326 バイト（82.7%）** であり、**#519 の着手条件 90% は満たされていなかった。**
  🔴 **母集合を取り違えると、「いつ動くか」の判断まで狂う** —— 本 ADR が扱った「分類の取り違えが
  検出機構ごと無効化する」と同じ構造を、**残余リスクを書く自分の手で繰り返していた。**
  以下は訂正前の記述である（増加の事実自体は正しい）。
  本 PR の追随で `traceability.md` が 20,912 → 21,590 バイトへ増えたためである。
  [#519](https://github.com/endazon/ai-stock-trading/issues/519) に書いた着手条件（90%）を超えた
  —— **本 ADR の範囲外として次の PR で着手する**（母集合の定義は計画側への環流が要る）。
  **条件を書いて超えたのに黙って通さない。**
- **分類 B の妥当性は検査していない。** B は「固有デルタがある」ことが前提であり、
  デルタが解消された（キットが追いついた）場合に **B のまま残る**形は検出しない。
  **同型事故はまだ 0 回**であるため作らない。
