# IADR-0204: 必読規約の総量予算の母集合を定義し、機械で測る

> 実装リポジトリ内の意思決定記録（Implementation ADR）。1 ファイル = 1 意思決定。

- 状態: Accepted
- 日付: 2026-08-15
- 決定者: Claude Code（[#519](https://github.com/endazon/ai-stock-trading/issues/519) の解消）

## 起点・関連

- 計画書 ID: **NFR**（無採番。工程の統制であり計画側の非機能要件表に当たる番号が無い）
- 対象 Issue: [#519](https://github.com/endazon/ai-stock-trading/issues/519)
- 作業仕様書: [20260815_519](../specs/20260815_519_reading-budget-checker.md)

## コンテキストと課題 — 🔴 **自分の書いた数値が 2 回とも誤りだった**

運用標準は「**毎セッション必読の規約は総量 50KB の予算内に収める**」と定めるが、
**母集合の定義も検査器も無かった。**

| # | どこ | 書いた値 | 実際 |
| --- | --- | --- | --- |
| 1 | [PR #518](https://github.com/endazon/ai-stock-trading/pull/518)・作業仕様書 20260815_517 | 45,082（90.2%） | **40,648（81.3%）** |
| 2 | [PR #522](https://github.com/endazon/ai-stock-trading/pull/522)・[IADR-0203](IADR-0203_class-c-requires-local-delta.md)・#519 | 45,760（91.5%） | **41,326（82.7%）** |

**どちらも `AGENTS.md`（4,434 バイト）を足していた。** 同ファイルの冒頭はこう書いている ——

> このファイルは、**Claude 以外の AI エージェント**（Cursor / Codex / Aider 等）や、
> `AGENTS.md` 規約に対応するツールが読み込む共通指示である。

**Claude は読まない。** 逆に `AGENTS.md` を読むツールは `.claude/rules/` を読まない。
**1 つのセッションが両方を背負うことはない。異なるエージェントの集合を足していた。**

### 🔴 誤りは「判断」にまで及んでいた

#519 は「**90% を超えたら着手する**」という着手条件を書いており、
**誤った 91.5% がその条件を満たしたことにしていた。正しくは 82.7% で、条件は満たされていない。**

> **母集合を取り違えると、数値が狂うだけでなく「いつ動くか」の判断まで狂う。**
> [IADR-0203](IADR-0203_class-c-requires-local-delta.md) が扱った
> 「**分類の取り違えは、検出機構ごと無効化する**」と同じ構造を、
> **その残余リスクを書く自分の手で繰り返していた。**

### AI レビューの警戒が正しかった

> 必読規約の**総量予算 45,082 バイト**という合計値は、対象ファイル集合を定義する自動検査器が
> 見当たらず、手動集計は規約が戒める「**母集合の取り違え**」のリスクがあるため追試しなかった。

**追試を断った理由が、そのまま誤りの原因だった。**

## 決定

### 決定1: 🔴 **予算はエージェントごとに判定する。集合を足さない**

制約は**セッション 1 本が背負う量**に掛かる。**合算は、誰も背負わない量を作る。**

| エージェント | 集合 | 根拠 | 実測 |
| --- | --- | --- | --- |
| **Claude Code** | `CLAUDE.md` ＋ `.claude/rules/*.md` | `CLAUDE.md`「Claude はこのファイルを毎セッション読み込む」／`traceability.md`「同ディレクトリの `*.md` は自動適用される」 | **41,326**（82.7%） |
| **`AGENTS.md` 対応** | `AGENTS.md` | 同ファイル冒頭「Claude 以外の AI エージェント…が読み込む」 | **4,434**（8.9%） |
| **GitHub Copilot** | `.github/copilot-instructions.md` | `CLAUDE.md`「Copilot 固有の運用は…」 | **2,850**（5.7%） |

**拘束するのは最大の集合＝Claude Code の 41,326 バイトである。**

### 決定2: **`.claude/rules/` は列挙せず走査する**

同ディレクトリの `*.md` は**自動適用**であり、**ファイルを 1 つ置いただけで予算が動く。**
列挙にすると**足したファイルが母集合から漏れる**——「緑だが検査されていない」の再生産である。

### 決定3: **超過で fail・接近（90%）で warn**

**超えてから気づくと、減量を迫られる場面で減らせるものが残っていない。**

### 決定4: **欠落したファイルを黙って 0 として扱わない**

集合のファイルが消えたとき、**合計だけ見ると「予算に収まった」ように見える。**
`missing` として出力に出す。

### 決定5: **母集合の定義と根拠を検査器の中に置く**

定義を別ファイルへ置くと、**定義と実装がずれても誰も気づかない**（本リポで繰り返している型）。

### 決定6: **既存の誤った数値は消さずに訂正として残す**

該当 4 箇所（作業仕様書 2・ADR 本文 1・ADR 索引行 1）に**取り消し線と訂正**を付けた。
**「間違えた」ことが消えると、次に同じ間違いをする。**

## 対照実験（実走した実測）

| # | 変異 | 結果 |
| --- | --- | --- |
| A | **`AGENTS.md` を Claude Code の集合へ足す**（2 回の誤りの再現） | ✅ **赤**（自己試験と専用テストの**両方**が独立に検出） |
| B | 予算を 1,000 バイトへ縮める | ✅ **赤**（`over`） |
| C | 予算を 45,000 バイトへ縮める（82.7% → 91.8%） | ✅ **warn**（exit 0。**枝が分かれていることの実測**） |

> 🔴 **変異 B が「否定形」である。** これが無いと、
> **「たまたま余裕があるから緑」と「母集合を 1 件も見ていないから緑」を区別できない**
> ——[IADR-0200](IADR-0200_cross-repo-ref-notation.md) の対照実験 2 / 3 が「緑のまま」で終わった形と同じである。
>
> **変異 A は両方の経路で赤くなることを個別に確かめた。** 最初の実行では
> **自己試験が先に落ちてプロセスが止まった**ため、専用テストが効いているかは分からなかった
> ——`resolveSet` を直接呼んで**独立に確認した**。
> **「赤くなった」だけでは、どの検査が効いたかは分からない。**

## 影響

- **良い影響**: 予算が**初めて機械で測られる**。母集合が定義され、**追試できる**ようになった
  （AI レビューが「未検証」とした唯一の項目が解消される）。
  `.claude/rules/` へファイルを足しても**自動で母集合に入る**。
- **悪い影響**: 集合が 3 つに分かれるため、**「総量」を 1 つの数で語れなくなった**。
  ただしこれは**正確さの代償として妥当**である——1 つの数は誰も背負っていなかった。

## 残余リスク

- 🔴 **母集合は「本リポの記述」を根拠に決めた実測であり、ハーネスの実装を読んで確かめたものではない。**
  Claude Code が将来 `.claude/agents/` や `.claude/commands/` を毎セッション読み込むようになれば、
  **母集合は静かにずれる**（検査器は緑のまま）。**記述と実装の一致を見る機械は無い。**
- **予算値 50,000 は計画側の運用標準に由来するが、本検査器が持っているのは複製である。**
  計画側が予算を変えても**自動では追随しない**（環流の対象。planning#364）。
- **`planning/CLAUDE.md`（submodule）は母集合に入れていない。** submodule 配下で作業するときだけ
  読み込まれるものであり「毎セッション」ではない、という判断である。**この判断を機械は検査しない。**
