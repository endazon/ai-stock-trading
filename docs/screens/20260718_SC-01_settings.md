## 画面の位置づけ

platform SPA の認証済みレイアウト配下に、本ユニットの feature `sc01-settings` としてマウントされる（ルート `settings`・
共通ナビ「設定」）。**本画面は §1 全体前提条件（FR-17・ConfigurationService `/assumptions` 由来）のみからなる。**

**リスク上限・監視銘柄・市場監視パラメータ（変動閾値・クールダウン）・Stage 1 の最小取引件数は本画面の範囲外**である
（RiskManagementService / MarketMonitorService 由来のため [SC-02](20260718_SC-02_risk-settings.md)。planning#33 の責務分界）。

## `paper` 稼働中の警告バナー（FR-12・#334）

本画面は発注先の表示・変更を持たないが、内蔵 `paper` 稼働中は画面上部に警告バナーを常時表示する
（必須 2 文言。05_screens「表示規約（共通）」）。`paper` 稼働中であることを**どの画面からでも**把握できるようにするため
である。発注先が判らない場合はバナーを出さない（判らないことを断定に変えない）。

## アクセス制御

- 表示・変更とも **利用者（`trading-owner`）限定**。`RequireRole anyOf=['trading-owner']` でラップし、権限外は `NotFound` を描画
  して画面の存在を示さない（存在秘匿。IADR-0009 と整合）。権限外では構成 API を呼ばない。
- 実効認可はサーバ側（`GET /assumptions`=OwnerOrService、`PUT`・`/history`=OwnerOnly）。フロントは表示制御のみ。

## 構成要素

1. **現在の前提条件（参照）**: バージョン、譲渡益税率、日本株/米国株の手数料体系（Rate/Minimum/Cap）、為替スプレッド率、
   最小期待利益倍率、月次費用上限（総額・LLM・インフラ・データ）を表示する。未解決（`isResolved=false`）時はその旨を明示。
2. **変更フォーム（利用者のみ）**: 上記の各数値を編集し、**理由（必須）** を添えて保存する。保存は楽観排他で、取得時の
   `version` を `expectedVersion` として送る。理由未入力時は保存不可（送信ボタン無効）。
3. **変更履歴**: `actor`・`reason`・`changedAt`・`version` を新しい順に一覧する。取得失敗時はその領域のみ縮退表示する。
4. **収集間隔についての注記（#423・[IADR-0165] 決定1）**: 「収集間隔は本画面からも API からも変更しない。
   起動時の構成値として運用する」旨を常時表示する（`role="note"`。`alert` にはしない ——
   常時表示の静的な注記を他の警告と同じ緊急度で読ませると、警告全体が軽くなる）。
   **入力欄は作らない。** 入力欄を消すだけだと「未実装の項目」に見え、次に画面を触る者が善意で実装してしまう。
5. **SC-02 への導線**: リスク上限・監視銘柄・市場監視パラメータは「リスク設定」画面（SC-02）で扱う旨を案内する。

## データ取得・更新（BFF `/bff/*` 経由・`apiFetch`）

| 操作 | 呼び出し | 応答/エラー |
| --- | --- | --- |
| 初期表示 | `GET /assumptions` | `VersionedAssumptions`。404=存在秘匿と整合（縮退）、その他失敗=エラー表示 |
| 履歴 | `GET /assumptions/history` | `AssumptionsChangeEntry[]`。失敗時は履歴領域のみ縮退 |
| 保存 | `PUT /assumptions`（`{assumptions, expectedVersion, reason}`） | 成功=再取得。400=検証メッセージ、409=競合メッセージ＋再取得を促す |

> **本画面は `/monitor/*` を 1 度も呼ばない**（#423）。呼んでいれば、節を隠しただけで実体が残っていることになる。

## 振る舞い（安全既定）

- **入力検証**: 空欄・非数値の財務パラメータ（税率・手数料・費用上限等）がある間は保存を無効化し、該当項目を警告表示する。
  黙って `0` として送信しない（誤更新防止・安全既定）。実効な範囲検証はサーバ側 400 が担う。
- 保存成功後は現在値・履歴を再取得して表示を最新化する。
- 409（競合）・400（検証）では**破壊的な自動再試行をしない**。競合時は「最新を取得して再試行」を促す。
- 取得不能・権限外は安全側（縮退・存在秘匿）へ倒す。秘匿情報は画面に載せない。

> 実装状況: §1（FR-17）は実装済み（#106 / PR #185）。**§2 は 2026-08-07 の裁定により廃止した（#423）。**
