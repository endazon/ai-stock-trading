# 設定画面（全体前提条件の閲覧/変更）

> 起点は**設定変更・一時停止・緊急停止のユースケース**（専用「設定画面」が明記された唯一のユースケース）と、
> **全体前提条件の要求**（バージョン管理・利用者のみ変更）である。

> **［2026-08-07 改定・#423］§2「収集パラメータ」は廃止した。本画面は §1（全体前提条件）のみの画面である。**
> 利用者裁定（質問票 第 13 回 Q11・Q12）が計画の画面設計へ反映された。
>
> | 旧 §2 の項目 | 2026-08-07 以降 |
> | --- | --- |
> | **収集間隔** | **画面から変更しない。起動時構成とする**（Q11・案 A） |
> | **変動閾値・クールダウン** | **[リスク設定画面](20260718_SC-02_risk-settings.md) へ移管**（Q12・案 B。権威は MarketMonitorService であり監視銘柄と同じ由来である） |
>
> **本画面に収集パラメータの入力欄を戻してはならない。戻すこと自体が裁定に反する。**
> 旧 §2 の実装記録は「収集パラメータ（変動閾値・収集間隔）の実装方針」を定めた実装 ADR に残る
> （同 ADR の決定 5・決定 6 は「Stage 1 最小取引件数の設定化と市場監視パラメータのリスク設定画面への移管」が置き換えた）。

## 画面の位置づけ

platform SPA の認証済みレイアウト配下に、本ユニットの feature `sc01-settings` としてマウントされる（ルート `settings`・
共通ナビ「設定」）。**本画面は §1 全体前提条件（ConfigurationService `/assumptions` 由来）のみからなる。**

**リスク上限・監視銘柄・市場監視パラメータ（変動閾値・クールダウン）・Stage 1 の最小取引件数は本画面の範囲外**である
（RiskManagementService / MarketMonitorService 由来のため [リスク設定画面](20260718_SC-02_risk-settings.md) が扱う。計画側で確定した責務分界による）。

## `paper` 稼働中の警告バナー（ペーパートレード・#334）

本画面は発注先の表示・変更を持たないが、内蔵 `paper` 稼働中は画面上部に警告バナーを常時表示する
（必須 2 文言。計画の画面設計「表示規約（共通）」）。`paper` 稼働中であることを**どの画面からでも**把握できるようにするため
である。発注先が判らない場合はバナーを出さない（判らないことを断定に変えない）。

## アクセス制御

- 表示・変更とも **利用者（`trading-owner`）限定**。`RequireRole anyOf=['trading-owner']` でラップし、権限外は `NotFound` を描画
  して画面の存在を示さない（存在秘匿）。権限外では構成 API を呼ばない。
- 実効認可はサーバ側（`GET /assumptions`=OwnerOrService、`PUT`・`/history`=OwnerOnly）。フロントは表示制御のみ。

## 構成要素

0. **供給が無い値の表示規約（全画面共通・2026-08-07 追加）** —— 計画の画面設計の共通規約を
   本画面にも適用する。3 状態を**両方向**に守る。

   | 状態 | 表示 | 本画面の例 |
   | --- | --- | --- |
   | **供給が無い** | **「取得できていません（供給元がありません）」** | §1 が未解決（`isResolved=false`）のとき／§1 の取得失敗 |
   | **対象なし** | 「—」 | 履歴 0 件などの「該当が無い」表示 |
   | **値が 0** | **「0」**（正常値として表示する） | 費用上限のデータ配分 0 円のような正当な 0 |

   - **供給可否はサーバが宣言する**（未供給表示規約の決定 4）。§1 は `VersionedAssumptions.IsResolved`（＝`Version > 0`）が
     サーバの宣言であり、画面は値の中身から推測しない。
   - **［2026-08-07・#423］本画面に「宣言する主体が存在しない」例外は無くなった。** 同決定 4 が唯一の例外として
     挙げていた旧 §2 の収集間隔は、§2 の廃止により**表示対象そのものが消滅した**（値を出さないのだから未供給とも書かない）。
     収集間隔については「供給が無い」ではなく「**本画面からも API からも変更しない**」と述べる（構成要素 4・移管の決定 1）。
     **両者を混同しないこと**——前者は「そのうち供給されるかもしれない」と読め、後者は「実装してはならない」である。

1. **現在の前提条件（参照）**: バージョン、譲渡益税率、日本株/米国株の手数料体系（Rate/Minimum/Cap）、為替スプレッド率、
   最小期待利益倍率、月次費用上限（総額・LLM・インフラ・データ）を表示する。
   **未解決（`isResolved=false`）のときは「取得できていません（供給元がありません）」と明示し、
   表示中の値が「組み込みの既定値であって実際に適用されている値ではない」ことを述べる**（#424・未供給表示規約の決定 4）。
   入力欄の数値そのものは既定値のまま残す（置き換えると保存操作が成立しない。同 ADR の残余リスク 3）。
2. **変更フォーム（利用者のみ）**: 上記の各数値を編集し、**理由（必須）** を添えて保存する。保存は楽観排他で、取得時の
   `version` を `expectedVersion` として送る。理由未入力時は保存不可（送信ボタン無効）。
3. **変更履歴**: `actor`・`reason`・`changedAt`・`version` を新しい順に一覧する。取得失敗時はその領域のみ縮退表示する。
4. **収集間隔についての注記（#423・移管の決定 1）**: 「収集間隔は本画面からも API からも変更しない。
   起動時の構成値として運用する」旨を常時表示する（`role="note"`。`alert` にはしない ——
   常時表示の静的な注記を他の警告と同じ緊急度で読ませると、警告全体が軽くなる）。
   **入力欄は作らない。** 入力欄を消すだけだと「未実装の項目」に見え、次に画面を触る者が善意で実装してしまう。
5. **リスク設定画面への導線**: リスク上限・監視銘柄・市場監視パラメータは「リスク設定」画面で扱う旨を案内する。

## データ取得・更新（BFF `/bff/*` 経由・`apiFetch`）

| 操作 | 呼び出し | 応答/エラー |
| --- | --- | --- |
| 初期表示 | `GET /assumptions` | `VersionedAssumptions`。404=存在秘匿と整合（縮退）、その他失敗=エラー表示 |
| 履歴 | `GET /assumptions/history` | `AssumptionsChangeEntry[]`。失敗時は履歴領域のみ縮退 |
| 保存 | `PUT /assumptions`（`{assumptions, expectedVersion, reason}`） | 成功=再取得。400=検証メッセージ、409=競合メッセージ＋再取得を促す |

> **本画面は `/monitor/*` を 1 度も呼ばない**。呼んでいれば、節を隠しただけで実体が残っていることになる。

## 振る舞い（安全既定）

- **入力検証**: 空欄・非数値の財務パラメータ（税率・手数料・費用上限等）がある間は保存を無効化し、該当項目を警告表示する。
  黙って `0` として送信しない（誤更新防止・安全既定）。実効な範囲検証はサーバ側 400 が担う。
- 保存成功後は現在値・履歴を再取得して表示を最新化する。
- 409（競合）・400（検証）では**破壊的な自動再試行をしない**。競合時は「最新を取得して再試行」を促す。
- 取得不能・権限外は安全側（縮退・存在秘匿）へ倒す。秘匿情報は画面に載せない。

> 実装状況: §1は実装済み（#106 / PR #185）。**§2 は 2026-08-07 の裁定により廃止した。**
