# SC-01 設定画面（全体前提条件の閲覧/変更）

> 起点: **UC-06**（設定変更・一時停止・緊急停止。専用「設定画面」が明記された唯一のユースケース）、**FR-17**（全体前提条件の
> バージョン管理・利用者のみ変更）、FR-13（利用者が設定を変更できる）。計画リポジトリ `05_screens/` は空のため、SC-01 の確定は
> `/plan-feedback`（`draft/feedback/20260718_ai-stock-trading-sc01-settings-screen.md`）で提案中。本書は実装側の詳細化。

## 画面の位置づけ

platform SPA の認証済みレイアウト配下に、本ユニットの feature `sc01-settings` としてマウントされる（ルート `settings`・
共通ナビ「設定」）。本画面は 2 節からなる。

- **§1 全体前提条件（FR-17）** —— ConfigurationService `/assumptions` 由来。
- **§2 収集パラメータ（FR-13・#340）** —— **MarketMonitorService `/monitor/settings` 由来**。

**リスク上限・監視銘柄は本画面の範囲外**である（RiskManagementService 由来のため SC-02。planning#33 の責務分界）。

> **由来サービスの差異（[IADR-0155] 決定6）**: 計画（05_screens SC-01 §2）は収集パラメータを
> 「**ConfigurationService 由来**」と書いているが、実装の権威は **MarketMonitorService** である
> （`MarketMonitorSettings.MovementThresholdRatio`）。**黙って合わせず**、画面は 2 サービスを消費する構造とし、
> §2 は §1 の取得可否に**連動させず独立して縮退**する（片方の障害・BFF 未結線を巻き込まない・fail-safe）。
> 差異は環流記録 [`feedback/20260806_sc01-sc03-unsupplied-screen-items.md`](../../feedback/20260806_sc01-sc03-unsupplied-screen-items.md) で計画へ返した。

## `paper` 稼働中の警告バナー（FR-12・#334）

本画面は発注先の表示・変更を持たないが、内蔵 `paper` 稼働中は画面上部に警告バナーを常時表示する
（必須 2 文言。05_screens「表示規約（共通）」）。`paper` 稼働中であることを**どの画面からでも**把握できるようにするため
である。発注先が判らない場合はバナーを出さない（判らないことを断定に変えない）。

## アクセス制御

- 表示・変更とも **利用者（`trading-owner`）限定**。`RequireRole anyOf=['trading-owner']` でラップし、権限外は `NotFound` を描画
  して画面の存在を示さない（存在秘匿。IADR-0009 と整合）。権限外では構成 API を呼ばない。
- 実効認可はサーバ側（`GET /assumptions`=OwnerOrService、`PUT`・`/history`=OwnerOnly）。フロントは表示制御のみ。

## 構成要素

1. **現在の前提条件（参照）**: バージョン、譲渡益税率、日本株/米国株の手数料体系（Rate/Minimum/Cap）、為替スプレッド率、
   最小期待利益倍率、月次費用上限（総額・LLM・インフラ・データ）を表示する。未解決（`isResolved=false`）時はその旨を明示。
2. **変更フォーム（利用者のみ）**: 上記の各数値を編集し、**理由（必須）** を添えて保存する。保存は楽観排他で、取得時の
   `version` を `expectedVersion` として送る。理由未入力時は保存不可（送信ボタン無効）。
3. **変更履歴**: `actor`・`reason`・`changedAt`・`version` を新しい順に一覧する。取得失敗時はその領域のみ縮退表示する。

### §2 収集パラメータ（FR-13・#340・[IADR-0155]）

4. **変動閾値（変更可）**: 現在値を**百分率**で表示・入力する（ワイヤは比率。`0.03` ⇄ `3 %`。[IADR-0151] 決定1）。
   **理由必須**・**値域検証**（0 超 50 以下 %）・**変更履歴へ記録**。
   保存は**項目単位の部分更新** `PUT /monitor/settings/movement-threshold` であり、クールダウンと監視銘柄を巻き込まない
   （全置換 `PUT /monitor/settings` を画面から使うと**送り漏らしで監視銘柄が消える**）。
   **空欄・非数値を黙って 0 として送らない**（0 は「すべての変動で発火する」危険側の設定である）。
5. **収集間隔（変更不可・表示のみ）**: **供給が無い。** 現在の実装では起動時構成
   （`Collection:PollIntervalSeconds` / `Monitor:PollIntervalSeconds`）であり、読み書きする経路が存在しない。
   **入力欄を作らず**、「収集間隔は本画面から閲覧・変更できません」と明示する（[IADR-0155] 決定5）。
   動かない入力欄は「変更できたつもり」を生み、統制設定では「設定したはずの値と実際の値が違う」ことが最も危険である。
6. **収集パラメータの変更履歴**: 種別（変動閾値 / クールダウン）・変更前後・変更者・理由・日時を新しい順に一覧する。
   監視銘柄の変更（SC-02 の関心）は本節に出さない（同じ台帳を種別で絞る）。

## データ取得・更新（BFF `/bff/*` 経由・`apiFetch`）

| 操作 | 呼び出し | 応答/エラー |
| --- | --- | --- |
| 初期表示 | `GET /assumptions` | `VersionedAssumptions`。404=存在秘匿と整合（縮退）、その他失敗=エラー表示 |
| 履歴 | `GET /assumptions/history` | `AssumptionsChangeEntry[]`。失敗時は履歴領域のみ縮退 |
| 保存 | `PUT /assumptions`（`{assumptions, expectedVersion, reason}`） | 成功=再取得。400=検証メッセージ、409=競合メッセージ＋再取得を促す |
| §2 収集パラメータ | `GET /monitor/settings` | `MarketMonitorSettings`（`movementThresholdRatio` / `cooldown` / `monitoredSymbols`）。失敗時はその領域のみ縮退 |
| §2 履歴 | `GET /monitor/settings/history` | `MonitorSettingsChangeEntry[]` を種別 2（変動閾値）・3（クールダウン）で絞る |
| §2 保存 | `PUT /monitor/settings/movement-threshold`（`{movementThresholdRatio, reason}`） | 成功=再取得。400=値域/理由の検証メッセージ、409=競合メッセージ＋再取得を促す |

## 振る舞い（安全既定）

- **入力検証**: 空欄・非数値の財務パラメータ（税率・手数料・費用上限等）がある間は保存を無効化し、該当項目を警告表示する。
  黙って `0` として送信しない（誤更新防止・安全既定）。実効な範囲検証はサーバ側 400 が担う。
- 保存成功後は現在値・履歴を再取得して表示を最新化する。
- 409（競合）・400（検証）では**破壊的な自動再試行をしない**。競合時は「最新を取得して再試行」を促す。
- 取得不能・権限外は安全側（縮退・存在秘匿）へ倒す。秘匿情報は画面に載せない。

> 実装状況: §1（FR-17）は実装済み（#106 / PR #185）。**§2 収集パラメータのうち変動閾値は #340 で実装済み**。
> **収集間隔は供給が無く実装できない**（表示のみ。環流済み）。
