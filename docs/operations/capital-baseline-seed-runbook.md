# Runbook: 基準資金が供給されず新規建てが止まるとき

> リポジトリ単位の運用 Runbook。起点は [#869](https://github.com/endazon/ai-stock-trading/issues/869) と、
> 「判定に用いる自己資金の供給元はブローカーの口座照会とする／照会できないときは新規建てを拒否する」を
> 定めた計画 ADR（2026-09-19 の利用者裁定）である。

## 症状 — **新規建てだけが一切通らない**

発注審査がすべて次の理由で拒否される。手仕舞い（Close）と損切りは**通る**。

```
拒否理由: CapitalBaselineUnavailable
```

`/status`（統制状態）と設定画面の実額併記は、資金と各上限を「取得できていません（供給元がありません）」と表示する。

**これは不具合ではない。設計どおりの fail-closed である**（分母が分からないまま比率の上限を判定すると、
統制が掛かっているように見えて実際には何も制限していない状態になる）。

## なぜ起きるか — 供給の条件

判定に使う自己資金は、**ブローカーの口座照会の観測を取引日ごとに畳んだ行**のうち
**「当日より前の取引日で最新のもの」**である。取引日は**米国東部時間の暦日**で数える。
したがって次の 2 つを同時に満たしていないと供給されない。

1. **当日より前の取引日の行が存在する**（＝その日のうちに口座照会が最低 1 回成功している）
2. **その行の観測時刻が `Risk:CapitalBaseline:MaxAge`（既定 4 日）以内**

🔴 **巡回に市場カレンダーのゲートは無く、暦日で数えるため土日にも行が作られる。** これは
「週末に稼働していれば月曜の朝から供給される」という**良い方向**にも働くが、裏返すと次のようになる。

| 状況 | 結果 |
| --- | --- |
| **週末（米国東部の土日）に最低 1 回でも口座照会が成功している** | 月曜の寄り付きから供給される |
| **月曜の朝（寄り付き前を含む）に初めて観測した** | 🔴 **月曜は一日中 `CapitalBaselineUnavailable`**（当日の行は判定に使わないため） |
| 金曜 23:55 ET に観測 → 月曜の寄り付き 09:30 ET | 供給される（経過およそ **2.40 日** < 4 日） |
| 三連休（金曜 23:55 ET に観測 → 火曜の寄り付き 09:30 ET） | 供給される（経過およそ **3.40 日** < 4 日） |
| 木曜 23:55 ET に観測したのが最後 → 火曜の寄り付き 09:30 ET | 🔴 供給されない（経過およそ **4.40 日** > 4 日＝鮮度切れ） |

🔴 **残高が 0 になっても自動では止まらない**（[#889](https://github.com/endazon/ai-stock-trading/issues/889)）。
口座照会が 0 を返した日は**行が 1 行も書かれない**ため、判定は**前取引日の正の行**をそのまま使い続け、
**鮮度（既定 4 日）が切れるまで新規建てが通る**。
🔴 **人手で 0 を 1 行入れた場合は逆に止まる**（下の埋め合わせの表は「最新行が 0 なら未供給」として扱う）。
**残高が尽きたことに気づいたら、0 を 1 行入れるか新規発注の一時停止（pause）で止めること。**

- **配備のとき**: 平日の日中に配備すると、その日は一日中新規建てが止まる（前取引日の行がまだ無い）。
  **週末に配備し、米国東部の土日のうちに巡回を 1 周以上回しておけば、月曜の寄り付きから供給される。**
- 🔴 **土日の行が基準になり得ることの帰結**: 月曜の基準資金は「**金曜の終値**」ではなく「**日曜の観測**」の行である。
  土日に入出金・ブローカー側の調整があると、営業日ではない日の評価額が当日の統制の分母になる。

## 埋め合わせ（1 行を投入する）

**自動で埋める手段は実装に無い**（値を構成から注入する口は、統制の分母に任意の金額を入れられる経路を作らないため意図的に置いていない）。
急ぐ場合は、リスク管理サービスの専有 DB へ**手で 1 行入れる**。

> 🔴 **これは統制の分母を人が与える操作である。** 値はブローカーのアプリ・Web で**実際に確認した
> 前営業日終値時点の USD 評価額**をそのまま入れること。**推定値・初期資金・買付余力を入れない**
> （分母を騙ると統制が黙って緩む。買付余力は信用でおよそ 2 倍になる）。

🔴 **テーブル名は snake_case だが列名は PascalCase であり、Postgres では二重引用符が要る**
（本リポジトリの EF 設定は `ToTable` だけを指定し、列名の命名規約を置いていない）。

```sql
-- "TradingDay"    … 「前営業日」の米国東部時間の暦日（当日を入れても判定には使われない）
-- "EquityInBase"  … ブローカーで確認した USD 評価額（含み損益を含む）
-- "ObservedAtUtc" … 確認した時刻（鮮度の起点。未来時刻を入れない）
INSERT INTO account_equity_days ("TradingDay", "EquityInBase", "ObservedAtUtc", "UpdatedAt")
VALUES (DATE '2026-09-18', 3000.00, TIMESTAMPTZ '2026-09-19T03:55:00Z', now())
ON CONFLICT ("TradingDay") DO UPDATE
    SET "EquityInBase"  = EXCLUDED."EquityInBase",
        "ObservedAtUtc" = EXCLUDED."ObservedAtUtc",
        "UpdatedAt"     = now();
```

投入したら次を確かめる。

1. `/status` の資金が「取得できていません」から実額へ変わる。
2. 新規建ての審査で `CapitalBaselineUnavailable` が出なくなる。
3. **次の巡回で行が上書きされる**（同じ取引日なら、より新しい観測が勝つ）。

## 恒久の直し方

**手で入れた行は次の取引日には要らなくなる。** 恒久的に必要なのは次の 2 つだけである。

- **巡回が生きていること**（口座照会が成功していること）。失敗しているならログ
  （`口座照会の応答に資産純値（TotalAssets）がありません` ／ `口座照会の応答通貨が USD ではありません` ／
  `口座照会の資産純値が 0 以下です`。いずれも警告）を確認し、OpenD の接続・口座の状態を直す。
  🔴 **`口座照会の応答が通貨を明示していないため、要求した通貨（…）を前提として基準資金を採ります（近似）`
  は失敗ではない。** これは情報の水準で出る**正常な見え方**であり、この行が出ているときは基準資金は
  **供給されている**。**警告として扱って接続設定をいじらないこと。**
  理由: 要求した通貨は**汎用証券口座・先物口座にしか効かず、単一市場口座では無視される**（提供元の公式資料）。
  応答の通貨欄も同じ条件でしか載らないため、**欄が無いこと自体が「この口座は単一市場口座である」という
  documented なシグナル**であり、そのとき資産純値は**口座自身の基準通貨**で返る。本系の照会先は
  **米国単一市場の口座**であり、その基準通貨は米ドルである。
  🔴 **したがって、この行を消すために接続や版を上げても無駄である**（欄の有無は口座種別で決まる）。
  **口座を追加した・種別を変えた・取扱市場を変えたときだけ、この前提を確認し直すこと。**
  🔴 **米国株を扱える非米国の単一市場口座を足すと、資産純値が別通貨で返ったまま米ドルとして採られる**
  （統制上限が桁で緩む）。その場合はこの Runbook ではなく実装側の対処が要る（`#899`）。
- **鮮度**（既定 4 日）を延ばすのは最後の手段である。`Risk:CapitalBaseline:MaxAge` を大きくすると、
  **巡回が死んでいることに気づけないまま古い分母で発注し続ける**。

### 🔴 「止まっていないのに壊れている」状態の気づき方（`#889`）

**基準資金が供給されていても、それが最新とは限らない。** 口座照会が値を返せない日
（残高 0・照会障害・プロセス停止）はその取引日の行が**1 行も書かれない**ため、判定は
**前取引日の正の値を鮮度が切れるまで返し続ける** —— 発注は通り続け、**他のどの指標にも異常は現れない**。

気づく手段は 2 つある。

| 手段 | 見るもの |
| --- | --- |
| 指標 | `ast_risk_capital_baseline_reads_total{outcome="SuppliedWithGap"}`（業務ダッシュボードの「基準資金を読んだ帰結の内訳」）。**0 でなければ、直前の取引日の観測が届いていない** |
| ログ | 警告 `基準資金は直前の取引日の観測ではありません …`（リスク管理）／警告 `口座照会が評価額を返さなかったため、この取引日の基準資金の行は書きません …`（同上・観測が届いた瞬間） |

- 🔴 **手で 1 行入れる前に、まず巡回が値を取れているかを確かめること。** 上の警告が出ているなら、
  埋め合わせではなく**照会側の是正**が要る（人手投入は当日をしのぐだけで、翌日また同じ状態になる）。
- 🔴 **残高が本当に 0 のときにどうするかは未裁定である**（`#889`）。現状は「ブローカーの 0 では止まらない／
  人手で 0 を 1 行入れれば止まる」という**非対称**であり、**止めたいなら人手で 0 を 1 行入れる**のが
  現時点の手段である。選択肢と害は実装 ADR に整理してある。

## やってはいけないこと

- **行を消す**（`DELETE`）。過去の行は現在の判定に使われないが、履歴として残す。
- **未来の `"TradingDay"` を入れる**。判定は「当日より前の取引日」で選ぶため効かず、翌日以降に古い値が選ばれる。
- **鮮度切れを避けるために `"ObservedAtUtc"` だけを前へ動かす**。
  🔴 **観測していない時刻を観測したことにする操作であり、鮮度の検査そのものを無効化する。**
