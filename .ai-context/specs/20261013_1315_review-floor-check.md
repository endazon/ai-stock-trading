# 仕様書: AI レビューの検証の下限を Check review verdict で機械的に検査する（#1315 是正 (b)）

> 本仕様書は実装着手前に作成した（着手 2026-10-13）。基点は AST `origin/develop` `14880c02`。

## 起点となる計画書（トレーサビリティ）

- 起点 ID: **`NFR`（無採番）**。CI の AI レビューの運用というメタ作業で、製品の要求には触れない。
- 起票: #1315。前段は 20261012_1315_review-depth-floor（プロンプトへ【検証の下限】節を置いた。#1318）。
- 関連 IADR: IADR-0190（判定の有無をジョブの結論へ結び付ける。`check-review-verdict.js` の起点）。
  新しい IADR は起こさず、IADR-0190 に日付つき追記（決定 7）を足す —— 同じ検査器・同じステップの射程の拡張であり、
  「判定の有無」と「判定の前提（下限）の有無」は同じ「緑だが検査されていない」の穴である。

## 問題（#1315 の最後の 2 コメントの要約）

#1318 で入れた【検証の下限】は、マージ後の抜き取りで 2 本の違反が出た。

| PR | 違反 |
| --- | --- |
| #1324 | `deploy/helm` と `.github/` の差分があるのに `helm lint` / `helm template` と `scripts.test.js` を走らせていない |
| #1336 | 32 ファイル中 18 ファイルしか読まず、本文に「下限（全ファイルを読む）は満たしていません」と自己申告した |

種別は違うが、どちらも「検証の下限」への違反として同型に数える。規約「同型 2 回で検査器」に従い、機械検査を入れる。

## 実在する申告の書式（母集合。#1318〜#1336 のレビューコメント 40 本ほどを gh api で採取）

| 書式（実文） | PR | 期待 |
| --- | --- | --- |
| `変更 9 ファイル中 9 ファイルを読んだ(生成物の除外なし)。`（半角括弧） | #1333 / #1335 | 緑 |
| `変更 9 ファイル中 9 ファイルを読んだ（生成物の除外なし）。`（全角括弧） | #1335 | 緑 |
| `変更 14 ファイル中 14 ファイルの差分を読んだ` | #1324 | 緑 |
| `変更 15 ファイル中 15 ファイルの差分を確認した` | #1326 | 緑 |
| `変更 32 ファイル中、生成物の除外なし。**全文または差分を読んだのは 18 ファイル**です。` | #1336 | 赤（18 < 32） |
| `変更 38 ファイル中、実装 15 ファイル（…）の差分を読みました` | #1325 | 赤（15 < 38） |
| `変更 38 ファイル中、実装 15 ファイルは差分を読みました（…）` | #1325 | 赤 |
| `変更 38 ファイルのうち、実装ファイル（…）の差分を読んだ`（M が無い） | #1325 | 赤（申告なし） |
| `変更 30 ファイル中、実装・テスト・仕様の主要ファイルは全文または差分で読んだ`（M が無い） | #1329 | 赤（申告なし） |
| `変更 21 ファイル中、生成物の … を除く 19 ファイルを対象にした`（「読んだ」が無い） | #1329 | 赤（申告なし） |

- 数字は全角・半角の両方を許す（NFKC で正規化してから読む）。単位は「ファイル」と「件」を許す。
- 生成物の除外は、プロンプトが許している（`CHANGELOG.md` 等）。除外数を本文から読めないと M < N で偽陽性になるため、
  **書式を 1 つ定める**: `（生成物 K ファイルを除外: …）`。検査器は **M + K ≥ N** で判定する。
  プロンプトの【検証の下限】節にこの書式を書き足す。

## やること

1. `scripts/check-review-verdict.js` に下限の判定を足す（既存の判定〔判定の見出し 3 種〕の挙動は変えない）。
   - 対象の本文: 実行ログから集めた候補（コメント投稿ツールの入力・assistant の text・result）のうち、
     **判定の見出しを含む最後のもの**。無ければ集めた全文。途中の独り言（「下限を満たしていないので読み足す」等）で
     赤くしないため。
   - (a) `変更 N ファイル中 M ファイルを読んだ` 形の申告を読む。申告が無ければ失敗。M + K < N なら失敗。
   - (b) 同じ行に「下限」と「満たして(い)ない」「満たさない」があれば失敗。
     ただし「満たしていない項目は無い」等の否定の否定は除く。
   - (c) 変更ファイル一覧（env `CHANGED_FILES`、改行区切り）に `deploy/helm/**` があるのに本文に `helm lint` と
     `helm template` の両方が無ければ失敗。`scripts/**` か `.github/**` があるのに `scripts.test.js` が無ければ失敗。
     ［2026-10-13 追記 / #1337 の AI レビュー 🟡］「在る」は**「確認できたこと」の節にコマンド名が在ること**で読む。
     「🔍 実行できなかったこと」の節に在るだけなら無いとみなす。行内の否定語（「拒否」「省略」等）で読む初版は、
     「`scripts.test.js` 全件成功（権限拒否なし）」を未実行と読む偽陽性があったため改めた。見出しの母集合は
     #1318〜#1336 の 32 本（全本に「確認できたこと」と「🔍 実行できなかったこと」が 1 つずつ在った）。
     あわせて申告は冒頭（最初の判定の見出しより前）だけから読み、「変更 N ファイル中／のうち」の形を優先する（同 🟢）。
     `CHANGED_FILES` が未設定・空のときは (c) だけを skip し、warn で明示する（fail-open。(a)(b) は走る）。
   - 失敗は `::error` で 1 違反 1 行ずつ出す。
2. `scripts/scripts.test.js` の check-review-verdict の節に単体試験を足す（陽性・陰性の両側）。
   #1336 の実文は赤、#1333 の実文（9/9）は緑で固定する。自己試験（`--self-test`）にも代表例を足す。
3. `.github/workflows/claude-code-review.yml`:
   - 「Check review verdict」ステップで `git diff --name-only BASE...HEAD` を計算し `CHANGED_FILES` で渡す。
   - プロンプトの【検証の下限】節に、申告の書式（生成物の除外数）と「この申告と下限の結果は検査器が読む」を書き足す。
   - 起動条件（`on:`）・ジョブ名・ステップ名・`--allowedTools` は変えない。
4. IADR-0190 に決定 7 を日付つき追記で足す。

## やらないこと

- 申告の N を実際の変更ファイル数と突き合わせること（レビュー側の diff の取り方〔`HEAD~1` 代用など〕と食い違い、偽陽性になる。残余リスク）。
- backend の `dotnet test` / `dotnet format` の実走の検査（今回の 2 違反の型ではない。3 回目が出たら足す）。
- 緊急避難用の環境変数の新設（必要になったら足す）。
