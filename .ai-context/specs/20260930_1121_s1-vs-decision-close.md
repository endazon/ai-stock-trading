# S1 の決済と判断の手仕舞い（#1121）

## 起点

- planning#704 の裁定（計画 ADR-0050・2026-09-30。ADR-0040 決定 4 の部分改定）。
  - 決定 1: 判断の手仕舞いは残りだけを送る（IADR-0461 の追認）。🔴 **S1 の決済は、判断の手仕舞いが処理中であることを理由に止めてはならない。**
  - 決定 2: 「損切りライン到達を理由とする手仕舞い」の案内は、機械的な損切りの無い構成（S2）に限る。方針に基づく手仕舞いはどの構成でも選べる。
  - 決定 3: ブローカーの逆指値が売れる数量を押さえるかを、実弾解禁前の確認に加える。受理されないなら保護レグを取り消す経路が要る（本 ADR は定めない）。
- 実装側の残作業（裁定コメント）: `StopLossLineIsRiskConstraintRule` を S2 に限る・`DescribeProtection` の古い S1 の案内を直す・逆向きを確かめて止まり得るなら直す・実弾の確認項目を運用文書へ。

## やること

1. 判断のプロンプトの「損切りライン到達で手仕舞いを選べる」案内（本判断の `StopLossLineIsRiskConstraintRule`、一次の `ScreeningHeldRule` の後半）を、
   機械的な損切りの無い構成でだけ出す。S0・S1・S3 では出さず、代わりに「損切りは機械的に執行される。損切りライン到達だけを理由に手仕舞いを選ばない
   （方針に出口の基準があればそれに従う手仕舞いは選べる）」と 1 行述べる。方針に基づく手仕舞い（`ExitFollowsPolicyRule`）は全構成で残す。
2. `DescribeProtection` の S1 の文言「未実装のため S0 と同じ扱い」を、実装済み（IADR-0344）の実態へ直す。
3. 逆向き（判断の手仕舞いが先に処理中のところへ S1 が発動する）を確かめ、止まり得るので直す（下の「逆向きの調査」「設計」）。IADR-0466。
4. ADR-0050 決定 3 の確認項目を、実弾解禁の確認表（運用仕様書の前提条件の表・実弾解禁 Runbook のチェックリスト）へ足す。

## 逆向きの調査（origin/develop 79abb596 で確認）

| # | 事実 | 場所 |
| --- | --- | --- |

**結論: 止まり得る**（無音ではないが、損切りが判断の手仕舞いの処理中を理由に実質止まる。ADR-0050 決定 1 の後段に反する）。直す。

## 設計（IADR-0466）

S1 の決済を送る直前（数量・待ち時間が決まった後、予約の前）に、**同じ建玉を売る判断の手仕舞い**を取り消してから送る。

- 対象: 発注執行の非終端の Close の記録（`IExecutedOrderStore.FindPendingCloses`。銘柄・市場・決済の方向が同じ）から、**保護の機構が出したもの**を除いた残り。
  - 除くもの（機械的な決済・保護レグ）: 同じ銘柄・市場・方向の保護記録（**状態を問わない**。新設 `IProtectiveStopOrderStore.FindRecentFor`）について、
    記録の `StopDecisionId`・`StopOrderId`、および試行 1..`Attempt`+1 の `ProtectiveStopIds.StopDecisionId` / `CloseDecisionId` / `SoftwareCloseDecisionId`。
  - 残るもの＝判断の手仕舞い・利用者の手仕舞い・維持率割れの自動縮小（いずれも承認〔`OrderApproved`〕の経路）。
- 手順（候補ごと）:
  1. `GetOrderAsync` で確かめる。**null・例外（確かめられない）→ 何もしない**（是正前と同じく送る。環境の違う記録で永遠に待たない）。
  2. 終端 → 取り消さない。約定数が記録より進んでいたら「変化あり」。
  3. 非終端 → `CancelOrderAsync`（例外は警告して続ける）→ もう一度 `GetOrderAsync`。終端なら「変化あり」。非終端・null・例外なら「取消待ち」。
- 結果:
  - 候補なし／変化なし → 従来どおり送る。
  - **取消待ちが 1 件でもある → 据え置く**（送らない・失敗に数えない・待ち時間を置かない）。次の巡回（ガード 30 秒）・次の到達で取り消し直す。
    据え置きが 15 分を超えれば既存の据え置き継続の Critical が出る。
  - 変化あり（取り消せた・約定が進んでいた） → **建玉を照会し直して、同じ試行を 1 回だけやり直す**（この段は通さない）。判断の手仕舞いが一部約定していれば
    建玉の減少は既存の外部要因の観測（その巡回の上限を即座に縮める）が扱い、二重に売らない。
- 取り消した判断の手仕舞いの記録・台帳の押さえは、約定追跡（30 秒）が終端（`Cancelled`・約定数）を観測して `OrderExecuted` を出す**既存の経路**で片付く
  （この段は記録を書かない＝書き手を 1 つに保つ）。**出し直さない**（IADR-0211 決定3。判断の意図の残りは次の判断から）。
- Warning ログに取り消した注文（DecisionId・OrderId・数量）を残す。

### 窓（規則 11）

窓 = S1 が判断の手仕舞いを確かめてから、S1 の決済がブローカーに処理されるまで。

プローブ（試験で実測する。T-10-1814）:

- **増える側**: 窓の中で判断の手仕舞い（全量・指値）が新たに板に載る（S1 の記録はまだ保存されていないので、判断側の IADR-0461 は S1 を引けない）。
- **減る側**: 判断の手仕舞いが先に板にあり、窓の中で終わる（取消が効く／約定する）。

形（窓のどちらの端で判断の手仕舞いを見るか）:

- 前の端だけ = 送る**前**に取り消す（候補 (a)）。
- 後の端だけ = 送った**後**、拒否を見てから取り消して 1 回出し直す（候補 (b)）。
- 両端 = (a) と (b) の両方。

| 形 | 増える側 | 減る側（先に板にある） | 減る側（取消の最中に約定） |
| --- | --- | --- | --- |
| 前の端だけ＝**採用** | △ 1 回拒否される。次の撃ち直し（待ち時間 30 秒＋ガード）で前の端が取り消して通る（止まらない） | ✓ 取り消してから送る。拒否されない | ✓ 建玉を照会し直し、減った分を売らない |
| 後の端だけ | ✓ 拒否の直後に取り消して出し直す | ✗ 必ず 1 回拒否を経る。🔴 **売れる数量を押さえない証券会社（実弾は未確認＝決定 3）では拒否されずに受理され、判断の手仕舞いも約定すれば二重に売る** | ✗ 同上 |
| 両端 | ✓ | ✓ | ✓ |

- 両端は増える側の遅れ（1 回の待ち時間）だけを縮めるが、(b) には次の費用がある: ① 拒否の理由を区別できない（`PlaceMarketOrderAsync` は理由を返さない）ので、
  **理由を問わず拒否のたびに判断の手仕舞いを取り消す** ② 1 回の呼び出しで 2 本の成行を送る経路（試行番号・予約・記録・通知を 2 回分）を足す。
- 増える側は前の端だけでも**止まらない**（既存の撃ち直しが次の試行で前の端を通る）。遅れの上限は 1 回の待ち時間（30 秒）＋ガードの間隔。さらに判断側の IADR-0461 は、
  S1 の記録が保存された後に来る判断の手仕舞いを残りだけに縮めるため、増える側の窓は「S1 の送信の往復」の間だけである。
- よって**前の端だけを採る**。両端の (b) は、決定 3 の確認（実弾で売れる数量を押さえるか）で押さえないと分かったときに改めて検討する（残余リスク）。

取消の確認（取消が確定する前に送るか待つか）:

| 形 | 売れる数量を押さえる証券会社（SIMULATE の実測） | 押さえない証券会社 |
| --- | --- | --- |
| 確定前に送る | ✗ 拒否され、失敗に数えて待ち時間が伸びる | ✗ 取消が効かず判断の手仕舞いが約定すると二重に売る |
| **確定を待つ（据え置き・次の巡回で確かめ直す）＝採用** | ✓ 次の巡回で送る | ✓ 二重に売らない |

エントリーの未終端の取消（`ResolveEntryAsync`）と同じ倒し方である。

## 母集合（規則 9: 誤りの側の文字列で引いた）

### プロンプト（`StopLossLineIsRiskConstraintRule|ScreeningHeldRule|DescribeProtection|未実装のため` で全文を走査）

🔴 **手法が不明（未供給・未知の値）のときは案内を出す。** ADR-0050 決定 2 は「S0・S1・S3 では案内しない」と構成で定めており、不明はそのどれでもない。
不明のもとで案内を消すと、実際は S2（機械的な損切りが無い）だった建玉の出口を塞ぐ（FR-10）。出したときの悪い側は判断と機械的な損切りの重なりで、
決定 1（IADR-0461）と本件（IADR-0466）が二重に売らないようにしている。保護の状態の文言も不明では「自動の損切りが効く前提に立ちません」と述べており、揃う。

### S1 の決済を送る経路（`PlaceMarketOrderAsync|TryCloseAsync|OnTriggeredAsync` で走査）

| 経路 | 本件の段を通るか |
| --- | --- |
| 到達の購読 → `OnTriggeredAsync` → `TryCloseAsync` | 通る |
| 常駐ガード → `TryCloseAsync`（巡回のスナップショットを渡す） | 通る（取り消したらスナップショットを捨てて照会し直す） |
| 失効した S0 の成行手仕舞い（`ProtectiveStopGuard`・`CloseDecisionId`） | **通らない**（範囲外。S0 は SIMULATE では建玉を持たない。IADR-0461 の残余のまま） |
| 保護逆指値が成立しないときの建玉解消（`CloseUnprotectedPositionAsync`） | 通らない（同上） |

### 取り消す／取り消さない決済（1105 の作業仕様書の「決済を発注する経路」の表から）

| 経路 | DecisionId | 取り消すか |
| --- | --- | --- |
| 判断の決済・利用者の手仕舞い・維持率割れの自動縮小（承認の経路） | 承認の DecisionId（リスク管理・判断が `Guid.NewGuid()` で採る） | **取り消す**（利用者の成行の手仕舞い〔UC-06〕・自動縮小は、発注の記録に出どころの列が無く DecisionId も無作為なので見分けられない。残余） |
| S1 の成行決済（他の記録のものを含む） | `SoftwareCloseDecisionId(entry, n)` | 取り消さない |
| 失効した S0 の成行手仕舞い | `CloseDecisionId(entry, n)` | 取り消さない |
| 保護逆指値が成立しないときの建玉解消 | `CloseDecisionId(entry, 1)` | 取り消さない（保護記録が残っていれば保護記録から、**残っていなくても新規建ての記録から**同じ導出で見分ける。PR #1123 の監査 🟡-1） |
| S0 / S3 の保護レグ（同時発注・張り直し） | `StopDecisionId(entry, n)`・記録の `StopOrderId` | 🔴 取り消さない |

## 残余リスク

- 増える側（S1 の送信の往復の間に判断の手仕舞いが載る）は 1 回拒否され、待ち時間 30 秒＋ガードの間隔だけ遅れる（止まりはしない）。
- 取消が確定しないあいだは据え置く。証券会社が取消を受け付けないまま生きていると答え続けると、据え置き継続の Critical（15 分）で人手へ回る。
- 確かめられない判断の手仕舞い（照会 null・例外）は取り消さない＝是正前と同じく拒否され得る（撃ち直しは続く）。
- 取り消した判断の手仕舞いは出し直さない。判断の意図の残り（S1 が守っていない株数の手仕舞い）は次の判断からになる。取消の理由は Warning ログにだけ残る（監査台帳は約定追跡の `OrderExecuted`〔取消〕として残るが、理由は載らない）。
- 保護逆指値を張れなかった建玉の成行手仕舞いは、保護記録が無くても新規建ての記録（新設 `FindRecentOpens`）から見分ける。新規建ての記録が無い形・直近 500 件より古い形だけは見分けられず取り消し得る（成行のため板に残る時間は短い）。
- 🔴 利用者の成行の手仕舞い（UC-06・#847）と維持率割れの自動縮小は、判断の手仕舞いと見分けられず取り消す（出し直さない）。調べた結果: DecisionId は承認の側（`PositionCloseService` / `MaintenanceMarginReductionService`）が `Guid.NewGuid()` で採り、`ExecutionRecord` に出どころ・成行かどうかの列が無い。見分けるには列の追加（移行）か承認の側の DecisionId の導出が要り、本件では足さない。S1 は自分の記録の残保護数量しか売らないため、S1 の守っていない株数を売る利用者・自動縮小の決済は消える（Warning ログと約定追跡の取消で分かる。要れば出し直す）。
- 取り消した後の建玉の照会し直しは、証券会社の建玉が約定を即座に映すことを前提にする。映る前の値が返ると取消の最中に約定した分を差し引けず、残りの建玉を超える数量を送り得る（上は記録の残保護数量で押さえられ、超えた分は「建玉が足りない」で拒否され、撃ち直しで正しい数量になる）。映る遅れは実測していない（PR #1123 の監査 🟢-1）。
- 失効した S0 の成行手仕舞いの側は、判断の手仕舞いの処理中を見ない（S0 は SIMULATE で建玉を持たない。IADR-0461 の残余のまま）。
- 🔴 ブローカー側の逆指値（S0/S3）が実弾で売れる数量を押さえるかは未確認（決定 3）。押さえる場合の保護レグを取り消す経路は未起案。
