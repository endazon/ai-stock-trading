## 課題1: 必読規約の母集合（planning#364）

計画側は 2026-08-15 に次を確定した。**母集合は「そのエージェントが自動で読み込む集合」であり、エージェントごとに分けて測り、合算しない。予算値 51,200 の正本は運用ガイド §8。検査器が値を持つのは複製として認めるが、値の隣に出典を書く。**

本リポの現状: `CLAUDE.md` は「総量 50KB の予算」とだけ書き、測定コマンドも母集合の定めも無い。`scripts/check-reading-budget.js` は既定値 **50,000**（出典コメント無し）で、**CI に配線されていない**（IADR-0204 の残余リスクとして自認済み）。

| `CLAUDE.md`「実装作業の進め方」 | 予算記述を「50KB＝51,200 バイト。エージェントごとに分けて測り合算しない」へ改め、測定コマンド 2 本（`cat CLAUDE.md .claude/rules/*.md \| wc -c`＝Claude 用／`wc -c < AGENTS.md`＝別枠観測）と出典（運用ガイド §8・planning#364）を明記 |

| `scripts/scripts.repo.test.js` | 配線の回帰（ジョブの存在・自己試験＋本検査）と、**既定値 51,200 と出典コメントの共存**を固定 |

## 課題5: check-kit-sync.js の版の再判定（HOWTO の手順）

分類 B の記録（2026-08-15）「キット版は `--require-planning` を持たず、フラグを渡しても認識せず skip して exit 0」に対し、kit 版は 15,578 B へ倍増している。**両版を同フラグで実走し exit code を比較した**（キット版は `scripts/` へ一時複製して実走。kit ディレクトリから直接叩くと `REPO` がキット自身になり分類表が無いため比較にならない）。

| 実走 | 本リポ版（7,147 B） | キット版（15,578 B） |
| --- | --- | --- |
| `--require-planning`（populate 済み） | **exit 1**（偽 unclassified 108 件） | **exit 0**（115 件突合・A 83 件バイト一致） |
| `--requre-planning`（未知の引数） | 認識せず本検査を実行（偶然 exit 1） | **exit 1**（未知の引数として拒否） |
| `--self-test` | 無い | **13 件が通る** |
| キットを参照できない＋`--require-planning` | exit 1 | **exit 1**（`KIT_DIR` を合成して実測） |
| Windows の走査 | `\` 区切りのまま | **`.split(path.sep).join('/')` で正規化** |

**キット版が上回る。** B の理由（「フラグを黙って無視する」）は planning#343 で解消済みであり、キット版は `--require-planning`・未知引数の拒否・`--self-test`・`KIT_DIR`・隣接クローンの探索・Windows パス正規化を持つ。**キット版で差し替え、B → A へ移した。** 課題4 は差し替えにより解消し、`scripts.repo.test.js` に区切り正規化の回帰（肯定形＋否定形）を置いた（A に置く以上、検査器本体へは足せない。IADR-0203 決定3 と同じ配置）。
