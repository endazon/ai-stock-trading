# 可観測性資産の検査の射程を広げる（#939）

## 起点

- #939（PR #919 のフレッシュな文脈の監査で実測）。`scripts/check-observability-assets.js` が次の 3 つの壊れた形を OK で通す。
  1. 同一ダッシュボード内のパネル id の重複・gridPos の重なり（PR #919 と PR #925 が末尾へ同じ `id: 15`・`{x:0,y:35,w:24,h:7}` を足していた）
  2. アラートの `for:` 欠落（`parseAlertRules` は読むが A1 が表明しない）
  3. 折り畳みスカラー（`expr: >-`）の式を読まない（式が文字列 `>-` になり、A2 が参照系列 0 件で素通りする）
- 起点 ID: NFR-07（可観測性。IADR-0255 / IADR-0374 と同じ）。**新しい検査器ではなく既存検査器の射程拡張**である（検査器の追加は同型事故 2 回からの規律に触れない）。

## 実測（`origin/develop` = `69d098c`）

| 事実 | 出典 |
| --- | --- |
| 業務ダッシュボードは 17 枚、技術ダッシュボードは 5 枚のパネルを持ち、id はいずれも 1..N で一意、gridPos は重ならない。行（row）パネルは無い | `node -e` で `deploy/observability/dashboards/*.json` を列挙 |
| D2 がすべてのパネルに `targets` を要求するため、行パネル（`targets` を持たない）は現行の検査で既に置けない | `checkDashboardShape` |
| アラートは 2 件。`AstEntriesBlockedByUnknownHoldings` は `for: 30m`、`AstStopLossPositionRowsDegraded` は `for:` 無し。後者は直前のコメントに「一過性の事象ではないので **for は置かない**」と理由を明記している | `deploy/observability/alerts/ai-stock-trading-alerts.yaml` |

## 決定

1. **D4（新設）: パネル id は同一ダッシュボード内で一意。** 重複は赤。id が整数でないパネルも赤（重複を検査できないものを通さない）。
   ダッシュボード間の重複は問わない（Grafana の同一性はダッシュボード内の id。ダッシュボードの同一性は既存 D3 の uid）。
2. **D5（新設）: gridPos の矩形は同一ダッシュボード内で重ならない。** 面積を持つ重なりだけを赤にし、辺が接するだけは重なりに数えない。
   gridPos が読めない（x / y / w / h が非負整数でない・w か h が 0）パネルは赤（読めないものを「重なりなし」と扱わない）。
   行パネル（`collapsed` の子パネル）は扱わない —— 上の実測のとおり D2 が既に行パネルを置けなくしており、起こり得ない形への防御になる。
3. **A1（拡張）: `for:` を要求する。ただし「置かない理由の明示」を許す。**
   - `for:` があれば、Prometheus の期間（`30m` / `1h30m` / `90s` 等）で**正の長さ**であること。`0s` や単位の無い値は赤。
     **下限は置かない** —— PR #951 の `for: 1m` は終端事象（再試行を使い切った後）を見るルールで、猶予を長くすると通知が遅れるだけである。
     下限を置くと、事象ごとに正しい値が違うものを検査器が一律に決めることになる。
   - `for:` が無ければ、**ルール直前に連続するコメント行**（`- alert:` の直前の、コメント行と空行だけの並び）に
     印 **`for は置かない`** が含まれるときだけ通す。含まれなければ赤。
   - **印の選び方の判断理由**:
     - 一律に赤にすると、意図して `for` を置かない `AstStopLossPositionRowsDegraded`（平常時 0 件・一過性でない事象）が赤になり、
       検査器を通すために意味の無い `for` を足す圧力が生まれる（猶予の無い事象に猶予を入れると通知が遅れる）。
     - 専用の機械記法（例: `# check-observability-assets: no-for`）を新設すると、既存アセットへ 1 行足す必要があり、
       同じファイルへ 3 件目を足す open PR #951 との衝突面を増やす。既存のコメントは理由を**日本語の文で**既に書いており、
       その文の中の語句「for は置かない」を印にすれば**アセットを 1 文字も変えずに意図どおり通る**。
     - 印は「理由を書いたコメントの中に置く」形なので、**理由を書かずに印だけを置く**ことは機械では止められない（人のレビューに残す）。
       それでも「黙った欠落」と「意図した不在」は機械で読み分けられる —— #939 が止めたいのは前者である。
     - 印を探す範囲をルール直前のコメントに限るのは、前のルールの印が次のルールへ漏れないためである（自己試験で固定）。
4. **A1（拡張）: `expr:` のブロック／折り畳みスカラー（`|` / `|-` / `>` / `>-` / `>+` 等）は本文まで読む。**
   キーより深く字下げされた続きの行を本文とし、空白 1 つで連結した値を式とする（PromQL は空白を区別しない。`|` と `>` を同じに読んでよい）。
   本文が無ければ式は空になり、既存の「`expr` が空」で赤。万一 `|` / `>` で始まる値が残ったら「本文を読めていない」で赤
   （**黙って 0 系列で A2 を素通りさせない**）。
   同時に、`expr` / `summary` 以外のキー（`description` 等）のブロック本文は**読み飛ばす** —— 本文中の `for:` や `severity:` を
   キーと取り違えないため（上の実測の誤読の芽を摘む）。
5. **非ブロッキングの 2 件（`absent()` 不在・日次のフラッピング）は本 PR で扱わない。** どちらも閾値・式の設計であり、
   実バックエンドでの実測（IADR-0374 フォローアップ 1）が要る。検査器の射程（名前と形の一致）の外である。

記録は **IADR-0374 への追記**で済ませる（アラート規約〔決定 4〕の 1 項目の追加と、検査器の射程拡張の記録であり、新しい意思決定の系統ではない）。
割り当ての IADR-0402 は使わない。

## 受け入れ基準

1. 同一ダッシュボード内のパネル id の重複を D4 で赤にする（自己試験: 重複のみ・重複＋重なり・読めない id）。
2. 同一ダッシュボード内の gridPos の重なりを D5 で赤にする（自己試験: 重なりのみ・辺が接するだけは緑・読めない gridPos・ダッシュボード間は緑）。
3. `for:` の欠落を A1 で赤にし、直前コメントの印「for は置かない」があれば緑にする（自己試験: 欠落・印あり・印の持ち越しなし・`1m` / `30m` / `1h30m` / `90s` は緑、`0s` / `0m` / `30` / `thirty` は赤）。
4. `expr` のブロック／折り畳みスカラーを本文まで読む（自己試験: `>-` / `|` / `|-` / `>` / `>+`。issue の実測の形〔`>-`＋綴り違い＋`for` 欠落〕で A1・A2 の両方が赤。本文の無い `>-` は赤。`description` 本文中の `for:` を誤読しない）。
5. develop の実資産で検査が OK のまま（ダッシュボード 2 枚・アラート 2 件）。PR #951 の alerts YAML（3 件目 `for: 1m`）でも A1 の違反 0 件。
6. `scripts.repo.test.js` に実資産の固定を足す（両ダッシュボードの D4/D5 が 0 件・全アラートが `for` か印を持ち、`AstStopLossPositionRowsDegraded` が印つきと読める）。
7. issue の再現（業務ダッシュボード末尾パネルの複製＋アラートを `>-`・綴り違い・`for` 欠落へ改変）を実資産のコピーで回し、D4・D5・A1・A2 の 4 件が赤になる。
