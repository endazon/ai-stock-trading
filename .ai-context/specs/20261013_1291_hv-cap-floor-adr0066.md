# 区分の上限の値域の下端を ADR-0066 決定 1 に照らす（#1291）

## 背景

- 計画 ADR-0066（planning#793 → planning#794・`a321adb`・利用者裁定 2026-10-13）は、ADR-0063 決定 2 の構成範囲の下端を部分改定した。
  - 旧: 「新規建ての最小の名目額の比率（既定 1%）以上 〜 25%」（構成値に連動すると読める）
  - 新: 「新規建ての最小の名目額の比率の**既定値（1%）**以上 〜 25% 以下」。**下端は構成値 `Sizing:MinEntryNotionalRatio` に連動しない固定値**。
  - 「🔴 構成値を変えるときは、区分の上限の下端（1%）との関係を確かめる」。
  - 読み込みの丸め（下端未満 → 1%）は、保存値と比べると上限を緩める。ADR はこの丸めを改めず、残る制約として記録した。実装の注記「保存値より緩くしない」は数値の上で食い違うと指摘した。
- 依頼: 現行の実装が既に適合しているかをコードで確かめ、適合していれば試験で固定し、仕様書・IADR に記録する。構成値を変えるときの確認について、起動時の検査や試験の要否を判断する。

| # | 確かめたこと | 結果 | 場所 |

| 2 | 書き込みの検証 | `PUT /risk-controls/settings/high-volatility` が `Validate` で値域外を 400（設定・履歴を変えない）。サービス `UpdateHighVolatility` も `ThrowIfInvalid`。書き込みの経路はこの 1 本 | `UpdateHighVolatility/Endpoint.cs`・`RiskSettingsService.cs:94-107` |

## 判断: 構成値を変えるときの確認

ADR は「確かめる」を人の手順として書いた。実装で補う形を 3 通り比べた。

| 形 | 得られるもの | 費用・問題 |
| --- | --- | --- |
| 何もしない（ADR と helm の注記だけ） | — | 構成値を変えた者が注記を読まなければ、区分の銘柄が常に見送りになっても気づけない（ADR の悪い影響 1 そのもの） |
| 起動を止める（構成値 ≠ 1% で fail） | 確実に気づく | 統制は緩まないのに起動を止めることになる。構成値の変更（0 で統制を外す等）は IADR-0495 が認めた操作であり、それを事実上禁じる |
| **起動時に警告を 1 行出す（採用）** | 構成値を変えた構成で、ずれがログに残る | 現在の区分の上限（リスク管理の設定）とは突き合わせない（起動時に照会しない。照会の失敗で起動を左右しないため）。現在値との比較は既存の LLM の前の見送り（`EntryCapacityBelowMinimumNotional`）が記録する |

- 警告は向き別に文を変える: 構成値 > 1% →「区分の上限を構成値未満にすると必ず見送られる」、構成値 < 1% →「区分の上限は 1% より下げられない」。
- helm の values の該当キーの注記にも、同じ確認を書く（変える人が最初に読む場所）。

## 母集合（規則 9・10）

誤りの側の文字列で走査した（`git grep`、`.ai-context/specs/` と IADR-0527 本文は凍結記録として除外）:

- 「保存値より緩」: `RiskSettingsSerialization.cs:110`（注記）・`HighVolatilitySettingsEndpointTests.cs:45`（試験の注記）・`docs/functional/FR-10_risk-controls.md`「緩い側へ倒さない」→ **3 件とも ADR-0066 の指摘どおりに改める**。IADR-0527 本文の「保存値より緩い 5% に倒さず」は凍結記録のため本文は直さず、日付つき追記で訂正する。
- 「最小の名目額の比率 以上」（既定値と書いていない値域の記述）: `TradingDefaults.cs:88`・`RiskSettingsService.cs:88`・`HighVolatilityOrderCapTests.cs:14,188`・`HighVolatilitySettings.cs:76` → 「既定値（1%）」へ改める。`HighVolatilityOrderCapTests.cs:191`・`:199`（T-10-2550 の名）・`TradingDefaultsTests.cs:89`・`HighVolatilitySettingsEndpointTests.cs:112` は「0.01（最小の名目額の比率）」等で値を併記しており誤りではないので**直さない**（試験名の改名は履歴の追跡を切るため避ける）。
- 「厳しい側へ丸める」: `RiskSettingsSerialization.cs:125` → 「既定 5% より厳しい側（保存値よりは緩む）」へ改める。
- 新たに誤りになる自分の記述: 起動時の警告の文に「SC-02」を書くと、SC-02 の入力（ADR-0066 決定 2・別 PR）がマージされる前は誤りになる → **`GET /risk-controls/settings` と書く**（helm 注記も同じ）。

## 変更

1. 取引判断に `HighVolatilityFloorStartupNotice.WarningFor(MinimumEntryNotionalOptions)` を足し、`Program.cs` が起動時に 1 行警告する（一致すれば何も出さない）。
2. 注記の訂正（上の母集合）。挙動は変えない。
3. helm `values.yaml` の `Sizing__MinEntryNotionalRatio` の注記に確認の手順を足す（コメントのみ。描画は変わらない）。
4. IADR-0527 決定 2 へ 2026-10-13 の追記（適合・丸めの訂正・起動時の警告）。索引行にも追記する。
5. FR-10 機能仕様・テスト仕様の該当節を改める。

## 受け入れ基準 → 試験

| 受け入れ基準 | 試験 |
| --- | --- |
| 構成値を 0 / 0.5% / 1% / 2% / 6% にしても、区分の上限の値域の下端は 1%（1% は受理・0.99% は拒否）。構成値を上げた構成では構成値未満も受理する（拒否しない） | T-10-2588 |
| 構成値が 1%（キー未設定を含む）なら起動時の警告は出ない | T-10-2589 |
| 構成値が 1% と違えば、向きに応じた警告の文を返す（起動は止めない） | T-10-2590 |
| 既存の値域・丸めの試験（T-10-2550・T-10-2560）は変わらず緑 | 既存 |

## 残る制約

- 下端未満の保存行の 1% への丸めは、保存値と比べて上限を緩める（ADR-0066 §結果。改めない）。
- 起動時の警告は区分の上限の現在値と突き合わせない（現在値は SC-02 / `GET /risk-controls/settings` で人が見る）。
