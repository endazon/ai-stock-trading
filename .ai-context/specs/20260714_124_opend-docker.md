## 目的・背景

moomoo 発注（#13）は OpenD ゲートウェイの常駐が前提。連結ローカル k8s dev（microservices-platform#266）で
OpenD をコンテナ常駐させる資産を用意し、ADR-0002 の未決「OpenD 無人運用の成立性」を実 PoC で消化する。

## 対象範囲

**対象（本 PR）**
- `deploy/opend/`: バイナリ非同梱の Dockerfile（tar.gz を build context から取り込み）・`entrypoint.sh`
  （env→`OpenD.xml` 生成）・k8s（opt-in Deployment/Service `:11111`・PVC・Secret 雛形・bootstrap-pod）・README。
- `scripts/opend-build.sh`: 参照 tar.gz を一時配置→build→import→後片付け（ランタイム自動判定）。

**対象外**
- moomoo アダプタ実装・`Broker:Provider=moomoo` 解禁（#13）。実弾（`TrdEnv.REAL`）は撃たない（IADR-0016）。
- 本番（Hetzner）配備・GitOps（#24）。

## 設計・PoC 結論

- **バイナリ非同梱**（EULA/再配布回避・`.gitignore`）。ベースは `mcr.microsoft.com/dotnet/runtime-deps:8.0-jammy`
  （nerdctl の docker.io 認証失敗を避け mcr を使用。実口座でビルド成功を確認）。
- **常駐モデル（IADR-0053・PoC 初回結論）**: 初回 PoC では、OpenD は起動/再起動のたびに対話デバイス検証
  （画像/SMS）を要求し、home＋install（AppData.dat）を PVC 永続化しても回避できないと観測した。
  → **⚠️ この「完全無人不可」の結論は後日の追検証で修正された（下記「追検証（2026-07-15）」を参照）。**
  デバイス信頼を一度確立・永続化し、かつ egress IP が安定な単一ノードでは、Pod 再作成をまたいで
  **無人再ログインが成立**することを実証した。起動時のみ有人検証・以降常駐という運用自体は維持しつつ、
  安定 egress IP 環境では再起動時の再検証が不要になり得る。
- **fail-safe**: `opend.yaml` は明示 apply 時のみ起動（既定 off）。資格情報は Secret。実弾は撃たない。

## 追検証（2026-07-15・#13 結合時）— 無人再ログインの成立（前提の修正）

初回 PoC の「永続化しても Pod 再作成のたびに対話再検証が必要（完全無人不可）」という結論は、**本追検証で
反証された**。#13 の実 OpenD 結合の過程で resident `opend.yaml` を複数回ロールアウトした際の観測:

**観測事実（再現可能・verifiable）**
- Deployment `opend` を **3 リビジョン**（revision 1→2→3）ロールアウト。`strategy: Recreate` のため毎回**新しい Pod**
  （Pod IP は 10.42.0.19x と毎回変化）が作られた。
- **3 回とも、対話検証（`kubectl attach`・`input_phone_verify_code`・`input_pic_verify_code`）を一切行わず、
  起動ログに `Login successful` が出て `:11111` 待受・API 利用可能**になった（本セッションで attach は未実行）。
- 直近 Pod（revision 3・IP 10.42.0.196・node `endazon-pc`）でも `Login successful` を確認。
- その状態で #13 クライアントから実 SIMULATE 発注→照会→取消が成功した（PR #130）。

**成立条件（なぜ無人で通ったか）**
1. **デバイス信頼が一度確立・永続化済み**: 先行セッションで対話検証（SMS/画像 CAPTCHA）＋規制アンケートを
   完了し、その状態が PVC `opend-persist`（`/root/.com.moomoo.OpenD`）に永続化されていた。
2. **egress IP が安定（単一ノード）**: クラスタは単一ノード（`endazon-pc` のみ）。moomoo が検証に用いるのは
   **NAT 後の egress IP**であり、これはノードが変わらない限り不変。Pod IP（`10.42.x`・内部）は moomoo の
   デバイス検証には無関係。→ 初回 PoC の「新 Pod＝新 IP だから再検証」は **Pod IP と egress IP を混同**していた
   （あるいは初回 PoC 時点ではデバイス信頼の確立が未完了だった）可能性が高い。

**修正後の評価（ADR-0002「無人運用の成立性」）**
- 「完全無人不可」は**過度に絶対的**だった。**初回のみ有人でデバイス信頼を確立・永続化すれば、以降の Pod
  再作成/再起動は無人再ログインが成立する**（安定 egress IP 環境）。ローカル単一ノード dev では実質的に
  無人運用が成立する。
- **残る前提（無人が崩れる条件）**: egress IP が変わる場合（マルチノード再スケジュール・クラウド/別リージョン・
  NAT 変更）、および moomoo 側のセッション失効・セキュリティ再チャレンジ。これらでは従来どおり有人検証が要る。
- **未確定（要追検証）**: egress IP を意図的に変えた場合の再検証発生の切り分け（信頼確立済みでも IP 変更で
  再チャレンジされるか）。デバイス信頼の有効期限。

→ この修正は ADR-0002 への plan-feedback（`feedback/20260715_adr0002-opend-unattended-limited.md` /
project-planning#25）に反映する（「限定的成立」→「安定 egress IP 下では無人再起動が成立、IP 変動時は有人」）。
