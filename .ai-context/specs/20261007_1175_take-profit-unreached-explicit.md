# 利確条件の未到達を判断へ明示し、丸めた含み損益率の横に到達判定を並べる（#1175）

## 背景（issue の観測）

- PoC（2026-10-05 US セッション・方針「利確: 全銘柄 +3%」）で、MSFT（+2.977%）と NVDA（+2.9986%）を LLM が「+3% に到達」として全量売った。
- 到達判定（`PolicyTakeProfitConditions.Reached`・厳密比較 `gain >= Threshold`）ではどちらも未到達で、到達の明示「方針の利確条件に達しています」はセッション中 0 件だった。
- 一方、プロンプトの含み損益率は小数 2 桁の丸め（`TradeDecisionPromptBuilder.HeldPositionView`）で、NVDA は「+3.00%」と表示されていた。丸めた数字だけを見ると到達と読める。

## オーナー裁定（2026-10-07・issue コメント）

1. 利確ライン未到達での LLM の売りは**許す**（新しい統制は足さない）。ただし「利確:」行が読めて未到達のとき、プロンプトに「方針の利確条件に未到達（現在 +x.xx% / 基準 +y%）」を出し、LLM の判断材料にする（裁量は残す）。
2. 表示は今の桁（小数 2 桁）のまま、到達判定の結果を並べて出す（例「+3.00%（方針の利確条件: 未到達）」）。判定は厳密比較のまま。
3. IADR-0470 の追記で記録する。

### 判断の根拠

1. **判定は共有カーネルの 1 か所。** 「未到達」をプロンプト側で `Reached` の否定から作ると、比べられない条件（円の価格を米国株で・ショートで取得単価より上の価格）を「未到達」と書いてしまう（現在値 190・基準 250 で「未到達」は誤解を生む）。比べられるかどうかもカーネルが決める。
2. **比べられない条件を含むときは何も足さない。** 裁定「読めないときは何も作らない」と IADR-0470 決定 2 の「取り出せないときは何も返さない（推測しない）」に沿う。到達の側は従来も達しない扱いだったので、到達の行の挙動は変わらない。
3. **含み損（率 ≤ 0）は未到達と書く。** 条件は比べられ、達していないことは事実である（「現在 -4.00% / 基準 +5%」）。到達とは従来どおり書かない（多重の防御は残る）。
4. **丸めない比較であることを行で書く。** 「+3.00% / 基準 +3%」で「未到達」と読ませるため、「丸めずに比べた結果」と明記する。注記も丸めた率の直後に置く（裁定 2）。
5. **LLM の裁量は残す。** 未到達の行は「手仕舞いを選ぶかは、方針とリスク制約に照らして判断します」で終え、売りを禁じない（裁定 1）。到達の行と同じ結び。既定の Hold の規則（`ExitFollowsPolicyRule`）は変えない。
6. **一次の縮退の予約は増やさない。** 未到達の行は到達の行より短く、注記を足しても予約 400 に収まることを最悪長の試験で固定する（収まらなければ予約を広げる）。予約を掛ける条件（`ForSymbol` が空でない）は、未到達の行が出うるときと一致する。

変えないもの: 書式の文法（`Parse`・`ForSymbol`）、到達の行の文言、自動の利確を採らないこと、既定の Hold の規則、予約の値と条件、報告書・通知、イベント契約、DB。PR #1191（#1176）と重ならないよう、`TradeDecisionPromptBuilder` の変更は保有状況の節と到達の行の周りに閉じる。
