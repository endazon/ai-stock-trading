## 目的・背景

IADR-0247（#337 / PR #561）でスクリーニング入力の縮退順序（① 銘柄分割 → ② RAG 削減 → ③ ニュース・開示削除）を
`ScreeningContextPlanner`（純関数）として実装したが、**決定4 で opt-in として出荷した** ——
`Decision:ScreeningContextBudgetChars` 未設定＝縮退制御オフが既定であり、**運用構成で誰かが値を入れない限り 1 度も動かない**。
IADR-0247 の残余リスクにも「予算の実値は実測待ち」とだけ書かれ、実値を決める作業が宙に浮いていた。

本作業は (1) 文字数プロキシの係数と既定予算の実値を根拠つきで決め、(2) 縮退制御を**既定で有効**にし、
(3) 統制を落とす操作（無効化）を**明示的な構成**に限る。

## 対象範囲

- 対象:
  - `DecisionOrchestrationOptions` に既定予算の定数を置く
  - `DecisionOptionsLoader` で未設定時に既定予算を適用し、明示的な無効化（`0` / `off`）だけを null へ倒す
  - Helm values（`values.yaml` / `values-local.yaml`）へ明示行を追加して既定を可視化する
  - 既定予算での縮退挙動をテストで固定する（境界値テーブル・プロパティベース・否定形）
  - IADR-0313 の起票、IADR-0247 決定4/決定6 と IADR-0072 決定2 への追記
- 対象外:
  - **呼び出し形（銘柄ごとの独立呼び出し）の変更**（IADR-0247 決定6 を維持。理由は IADR-0313 決定4）
  - `ScreeningContextPlanner` の縮退順序・アルゴリズムの変更（無改修）
  - `Retrieval:TopK` の既定値（5）の変更
  - 月報への件数描画（#338 の射程）
  - 実 LLM による係数の実測（実環境待ち。#690 と同型の残件）

## 設計

### 1. 文字数プロキシの係数と既定予算

実 LLM のトークナイザを走らせられないため、文献値と本リポの実プロンプト計測から**保守側**に決める。

- 文献値: Anthropic のトークナイザは英語で約 3.5〜4 文字/トークン、日本語は約 1〜1.5 文字/トークン（漢字は 1 文字 ≈ 1 トークン前後）
- 実測（本リポ）: `TradeDecisionPromptBuilder.BuildScreening` が組む骨格のリテラル総量は **775 文字**（プレースホルダ展開前）で、
  内訳は**日本語 420 文字（54.2%）／ ASCII ほか 355 文字（45.8%）**。混在比をそのまま文献値へ当てると
  `0.542 × 1.0 + 0.458 × 3.5 ≈ 2.15 文字/トークン` となる
- 採る係数: **1.0 文字/トークン**（＝入力が全量日本語で、かつ日本語の最も重い側に張り付いた場合）。
  実測の混在比に対して **2 倍以上保守側**である
- 既定予算: `200,000 トークン × 1.0 文字/トークン × 0.75（安全率） = 150,000 文字` → **`150_000`**（キリの良い値）
  - 安全率 0.75 が確保するのは、出力トークン・骨格の見積り誤差（`PromptScaffoldChars = 750` の概算）・
    トークナイザの版差である

### 2. 既定で有効にする（無効化は明示操作）

`DecisionOptionsLoader` のベースラインで既定値を与える。**`DecisionOrchestrationOptions.Default` レコードは変更しない** ——
IADR-0278 が `EnableScreening` の反転で採った線引きと同じで、`Default` は単体テストの基準値としても共用されているためである。

| `Decision:ScreeningContextBudgetChars` | 解決後 | 意味 |
| --- | --- | --- |
| 未設定 / 空文字 | `150_000` | 既定（縮退制御あり） |
| 正の整数 | その値 | 運用で上書き |
| `0` / `off`（大小無視・前後空白無視） | `null` | **明示的な無効化**（統制を落とす操作） |
| 負数・非数値（`-1` / `abc` 等） | `150_000` | 不正値は既定へ倒す（**安全側＝統制を残す**） |

🔴 **不正値の倒し先が反転する。** 従来は「不正値 → null（制御なし）」だったが、既定が有効になった以上、
不正値で**統制が黙って外れる**ほうが危険である。無効化したい構成は `0` か `off` を明示する。

### 3. 縮退が起きる条件（実測）

`ScreeningContextAssembler.EstimateChars` は参考情報 1 件を **最大 1,160 文字**（タイトル 200 + 本文 400 + 出典 500 + JSON 化 60）
で見積もる。`Retrieval:TopK` の既定は 5 であるため、**現行構成では削減可能材料は最大 5,800 文字**にしかならない。

- したがって既定予算 150,000 文字のもとでは、**段②・段③は現行構成では発火しない**。
  発火し始めるのは `Retrieval:TopK` を **約 127 以上**へ引き上げたときである
  （`(150,000 − 750〔骨格〕 − 120〔銘柄行〕 − 2,000〔方針要約の想定〕) ÷ 1,160 ≈ 126.8`）
- 唯一の**無上限**の入力は `policy.Summary`（保護対象・共有保護分）である。これが予算を超えた場合は
  `UnresolvableOverflow` が立ち、**保護対象は削らずに**呼び出す（IADR-0247 決定1 のまま）
- **これは「発動しない機能」ではなく安全網である。** 既定で武装させておくことに意味があり、
  `TopK` の引き上げ・方針要約の肥大化が起きた日に人手の設定を待たずに効く

### 4. 既定有効化の副作用（挙動が変わる点）

IADR-0247 決定4 は「**有効時に限り** IADR-0072 決定2（RAG はスクリーニングに載せない）を置き換える」と定める。
既定を有効にすると、**一次スクリーニングのプロンプトに市況（保護）と参考情報が載るようになる**。

- スクリーニング層のトークン量は増える（上限 5,800 文字 ≈ 数千トークン）。
  単価は `claude-haiku-4-5`（本判断 `claude-sonnet-5` の 1/3）であり、二段化の費用統制の趣旨は保たれる
- 監査台帳（`ScreeningContextReduced`）は、上記 3 のとおり**現行構成では 1 件も増えない**
  （縮退が発生しないため publish されない）

## 受け入れ基準

- [x] `Decision:ScreeningContextBudgetChars` 未設定で `ScreeningContextBudgetChars == 150_000` になる
- [x] `Decision:ScreeningContextBudgetChars=0` / `off` で `null`（縮退制御なし）へ倒せる（明示的な無効化の経路が残る）
- [x] 不正値（負数・非数値）は既定 `150_000` へ倒れる（統制が黙って外れない）
- [x] 既定予算で「保護対象（方針・市況）は削られない」ことがテストで固定されている
- [x] 既定予算で段②（RAG）→ 段③（ニュース）の順に削られることがテストで固定されている
- [x] 既定予算で保護対象だけが超過したとき `UnresolvableOverflow` が立ち、削らずに呼び出すことがテストで固定されている
- [x] 現行構成（`TopK=5`・参考情報が上限サイズ）では既定予算で縮退が発生せず、記録も出ないこと（否定形＝陽性対照）
- [x] 呼び出し形（銘柄ごとの独立呼び出し）を変更していない
- [x] `dotnet build` / `dotnet test`（TradeDecisionService）が緑・`dotnet format --verify-no-changes` が差分ゼロ

## テスト方針

統制系の 3 点セット（境界値テーブル・プロパティベース・否定形）を既定予算の値に対して置く。

| 面 | テスト | 置き場所 |
| --- | --- | --- |
| 境界値テーブル | 既定予算ちょうど／1 文字超過／大幅超過で縮退の有無と段の進み方が切り替わる（`[Theory]`） | `ScreeningContextDegradationTests` |
| プロパティベース | 材料サイズを疑似乱数で振っても不変条件（保護対象は必ず残る・段③は段②を使い切ってからしか進まない・削りすぎない）が成り立つ | 同上 |
| 否定形（陽性対照） | (a) 現行構成の現実的な材料量では既定予算で縮退が起きず記録も出ない、(b) `0` / `off` を明示すれば従来プロンプトへ戻る | 同上 / `DecisionOptionsLoaderTests` |

境界値・プロパティベースは `ScreeningContextPlanner` を**既定予算の定数**で直接駆動する
（`ScreeningContextAssembler` 経由では参考情報 1 件あたり 1,160 文字の上限が掛かり、
`TopK=5` の現行構成では 150,000 文字に到達し得ないため。§設計 3）。結線面（プロンプトへ何が残るか・記録が出るか）は
従来どおり `TradeDecisionAppService` を通した経路で固定する。
