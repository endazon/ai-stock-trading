# 同じ銘柄の手法の併存・約定追跡の打ち切り・発注先の設定値（#1048）

## 起点

- [#1048](https://github.com/endazon/ai-stock-trading/issues/1048)（#826 の監査の残り）。利用者の裁定（2026-10-02）:
  - **Q2 = 案 b**: 同じ銘柄・同じ向きに、別の手法（S0 と S2、S0 と S3 を含む）の有効な建玉が残っている間は、新しい手法での新規建てを見送る。
    見送りは理由つきで台帳に残す。決済は止めない。
  - **Q3 = 記録する**: 約定追跡の期限を過ぎて非終端のまま打ち切った注文は、打ち切ったことを監査に記録する。免除の記録が発注数量のまま残る状態を追跡できるようにする。
  - **Q1 = 運用で揃える（IADR-0413 のとおり）**: 稼働中の発注先の設定値を実際の発注先（moomoo SIMULATE）に揃える。揃っていることを確かめる手段（照会または起動時の警告）を用意する。
- 実装判断: [IADR-0481](../adr/IADR-0481_same-symbol-method-coexistence-fill-tracking-abandonment-provider-alignment.md)。

## 計画との整合（着手前に確認）

- 計画 `ADR-0040` 決定 1（SIMULATE に限り S0〜S3 を選べる。S0 以外は SIMULATE だけ）: 見送りは新規建てを減らす向きだけで、手法の選択肢・
  実弾での拒否を変えない。矛盾なし。
- `FR-10`「kill switch・ロックアウト・一時停止は手仕舞い（Close）と損切りは止めない」と同じ扱いで、本件の見送りも **Close には効かせない**。
- `FR-11`（全イベントの時系列記録）: 打ち切りを新しい契約イベントとして監査台帳へ記録する（監査の購読・写像の全数の試験に載る）。
- `FR-20`（実弾への切り替えに確認操作）: Q1 で設定値を観測から**書き換えない**理由になる（書き換えると確認操作の迂回経路になる）。
- 計画との衝突は無い。計画への環流は不要。

## 🔴 窓（規則 11）

### Q2: 照合の窓（照合の読み取り 〜 ブローカーへの送信）

- **増える側**（P2-増）: 予約の前の照合の**後**に、別の手法の記録が現れる（並行した別の承認が自分の行／AwaitingEntry を残す）。
- **減る側**（P2-減）: 予約の前の照合で見えていた別の手法の記録が、送信の**前**に完了する（決済を送って記録を閉じたが、建玉はまだ残っている）。

| 形 ＼ プローブ | P2-増（後から現れる） | P2-減（先に見えて後で消える） |
| --- | --- | --- |
| 前の端だけ（予約の前に 1 回） | ✗ 見落として送る | ✓ 見送る |
| 後の端だけ（送信の直前に 1 回） | ✓ 見送る | ✗ 建玉が残るのに送る |
| **両端（どちらかで見えたら見送る）** | **✓** | **✓** |

採用は両端（T-10-2106 が P2-増、T-10-2107 が P2-減を固定）。

### Q2: 記録の無い建玉の判定（建玉照会の往復のあいだの主張）

S1 の武装の前提条件と同じ `HasUnattributedPositionAsync` を使う。主張の増減の両方向と `min(前, 後)` の表は IADR-0344 追記(11) のとおりで、
本件で形を変えない（再利用するだけ）。

### Q3: 打ち切りの窓（追跡の起点 〜 期限 〜 打ち切る瞬間）

- **減る側**（P3-減）: 最後の巡回の**後**・期限の**前**に注文が終端した（非終端の記録が実は終わっている）。
- **増える側**（P3-増）: 打ち切った後に追跡の起点が進められ（`RenewTracking`）、窓へ戻ってから再び期限を過ぎる（2 回目の打ち切り）。

| 形 ＼ プローブ | P3-減（期限の直前に終端） | P3-増（起点が進んで 2 回目） |
| --- | --- | --- |
| 前の端だけ（期限だけで打ち切る・印は真偽） | ✗ 終端したのに打ち切りを残し、約定も取りこぼす | ✗ 2 回目が残らない |
| 後の端だけ（毎巡回照会して非終端なら打ち切る・期限を見ない） | ✗ 期限内の注文まで打ち切る | ✗ 毎巡回発行し続ける |
| **両端（期限 ＋ 打ち切る直前の照会・印＝打ち切った起点）** | **✓ 終端を記録して打ち切らない** | **✓ 起点が違えば改めて記録** |

採用は両端（T-10-2111 が P3-減、T-10-2112 が P3-増を固定）。

## 受け入れ基準

1. 同じ銘柄・市場・方向に別の手法の有効な保護記録がある新規建ては、理由 `StopLossMethodConflict` で見送り、ブローカーへ送らず、予約を Forgone に残し、
   自分の保護記録を作らない。同じ手法どうしは従来どおり建てる（T-10-2101・T-10-2102）。
2. 送信結果待ち（AwaitingEntry）の記録も有効に数え、完了した記録は数えない（T-10-2103）。
3. 決済（Close）は別の手法の記録があっても止めない（T-10-2104）。
4. moomoo SIMULATE の S0・S3 の新規建ては記録の無い建玉がある銘柄では `UnattributedPosition` で見送る。実弾・内蔵 paper の S0 は建玉照会もしない（T-10-2105）。
5. 窓の両端で照合する（T-10-2106: 後の端・増える側／T-10-2107: 前の端・減る側）。
6. 見送りの理由は末尾追加（序数 8）で、在庫解放の分類は「確実に未発注」（`StopLossMethodContractTests`・`OrderDispatchForgoneLifecycleTests`・`PortfolioLedgerConsumersTests`）。
7. 期限を過ぎて非終端の注文は、打ち切る直前に 1 回照会し、非終端なら最後の観測を載せた打ち切りを返す（T-10-2110）。
8. 打ち切る直前の照会で終端していれば通常どおり約定を記録して打ち切らない（T-10-2111）。
9. 印を書いた打ち切りは二度と照会・発行しない。起点が進んで再び期限を過ぎたら改めて打ち切る（T-10-2112）。
10. 有効な保護記録の逆指値レグは打ち切らない（T-10-2113）。
11. 洗い出しと印の意味論は EF・インメモリで同一（T-10-2114）。Worker は発行してから印を書き、次の巡回では発行しない（T-10-2115）。
12. 設定上の発注先と実際の発注先の判定（3 × 3。実際が実弾なら重い側）（T-10-2116）。
13. 観測のたびに食い違いを知らせ（揃える操作を名指し）、揃っていれば出さず、設定は書き換えない（T-10-2117）。
14. 設定を読めなくても例外を投げない（T-10-2118）。
15. 打ち切りは免除と同じ相関に 1 件だけ残り、免除を打ち消さない。起点が違えば別に残る（T-10-2119。全イベントの写像・購読・実走の試験にも載る）。
16. 打ち切りの記録 Id は注文 ID と追跡の起点だけから決まる（T-10-2120）。
17. （独立監査で追加）打ち切りの発行に失敗した巡回では印を書かず、記録は次の巡回でも洗い出され、バスが戻れば発行してから印を書く（T-10-2121）。
18. （独立監査で追加）有効な保護記録の逆指値レグは洗い出しの問い合わせの段で除き、件数の上限を占めない（EF・インメモリ。T-10-2122）。

## 残余リスク

IADR-0481 §残余リスクのとおり（配備前の既存の併存・S2 と S0 / S3 の同時の新規建ての窓・S0 / S3 の主張は承認数量・人手の建玉も止める・
