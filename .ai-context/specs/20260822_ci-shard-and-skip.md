# 作業仕様書 — 逆転の解消（シャーディング ＋ backend 非変更 PR の skip）

## 起点となる計画書（トレーサビリティ）

計画 ID（FR/UC/SC）を持たない**工程の改善**である。計画側の非機能要件表は稼働する製品の要件を
持ち、CI の所要時間に当たる番号が無いため**無採番の `NFR`** とする（配布規約が許す 2 番目の場合）。

## 背景 —— 逆転は解消していない

第 2 弾（#542・マージ済み）で逆転の**監視**を置いたが、**逆転そのものは残っている**。
監視は実際に鳴り、自動起票された（issue #543）。

| | 実測 |
| --- | --- |
| `build-and-test` の中央値 | **223 秒** |
| `claude-review` の下限 | **146 秒** |
| 余裕 | **−77 秒（逆転）** |

超えている間、**ビルド時間の増加は 1 秒残らず PR の待ち時間になる**。

第 2 弾で「段 1（アセンブリ間並列化）」を試して**不採用**にした（IADR-0208 決定 8）。
最大同時実行数は前後とも 4 本で、**元から 4 並列**だった。**1 ランナー内では頭打ち**であり、
テスト時間の下限は**最長アセンブリの 28 秒**である。残る手は 2 つで、**利用者裁定（2026-08-22）
により両方を採る**。

| 種類 | 件数 | 効く手 |
| --- | --- | --- |

**backend 非変更 PR が 7 割**を占める。それらが触った最上位パスは
`docs`（135 ファイル）・`scripts`（47）・`.github`（30）・`.claude`（12）・`.ai-context`（7）である。

テストアセンブリ **51 本**・所要の合計 **480 秒**・実効並列度 **3.61 本**・最長 **28 秒**。

## 変更内容

### a. テストを 3 シャードへ分割する

- 新規 `scripts/list-test-projects.js` —— テストプロジェクトを**内容で**発見し
  （`Microsoft.NET.Test.Sdk` / `xunit` を参照する `.csproj`）、パスでソートして
  **ラウンドロビン**で N 分割する。`--shard <i> --of <n>` / `--count` / `--self-test`。
  🔴 **0 件なら失敗させる**（発見に失敗したまま「テスト 0 件で緑」を作らない）。
  🔴 **分割の網羅性と排他性を自己試験で固定する**（各シャードの和 ＝ 全体、重複なし）。
- `ci.yml` の `build-and-test` を **matrix の脚 ＋ 集約ジョブ**へ分ける。
  🔴 **必須チェック名 `build-and-test` は集約ジョブが保持する**（改名は恒久的なマージ不能を招く）。
- 各シャードは `xargs -P 4` で**シャード内の 4 並列を維持する**。
  🔴 **プロジェクトを 1 本ずつ直列に回してはならない** —— 現在の 4 並列を失い、
  シャード時間が 480/3 ＝ 160 秒となって**現状 133 秒より遅くなる**。
- カバレッジは各シャードが artifact へ上げ、集約ジョブが集めて `check-coverage.js` を回す。
  同スクリプトは **(ファイル, 行番号) の和集合**で集計するため、シャード間の重複計上は起きない。

### b. backend 非変更 PR では backend ジョブを skip する

- 新規 `scripts/detect-changed-areas.js` —— 変更ファイル一覧を読み、
  **安全と分かっているパスの許可リストに全件が収まるときだけ** `backend=false` を出す。
  🔴 **既定は「走らせる」。** 判定できないパスが 1 つでもあれば `backend=true` に倒す
  （取りこぼしても「余計に走る」側に落ちる。**逆に倒すと退行が無検証でマージされる**）。
- `if:` で `build-and-test`（集約）・`backend-test`（脚）・`lint` を出し分ける。
  ⚠️ **`if` でスキップされたジョブは必須チェック上「合格」**として扱われる
  （`paths:` の恒久 pending とは結果が正反対。IADR-0208 決定 7）。

#### 許可リスト（安全側＝skip してよい）

`docs/**` / `.ai-context/**` / `.claude/**` / `scripts/**` / `frontend/**` /
`.github/ISSUE_TEMPLATE/**` / `.github/PULL_REQUEST_TEMPLATE.md` /
`.github/copilot-instructions.md` / ルート直下の `*.md`

#### 🔴 許可リストに入れないもの（＝ backend を走らせる）

| パス | 理由 |
| --- | --- |
| `backend/**` | 自明。**`.json` フィクスチャ・`appsettings` も含む**（テストが読む） |
| `Directory.Build.props` / `Directory.Packages.props` / `global.json` / `nuget.config` | ビルド全体の入力 |
| **`.github/workflows/**`** | 🔴 **CI 自身を変える PR で backend を skip すると、その変更を検証できない。** 本 PR がまさにその形である |
| `deploy/**` | helm の `pipeline.json` 等をテストが読み得る。切り分けが済むまで保守的に倒す |
| 上記いずれにも当たらないパス | **既定で走らせる**（未知は安全側） |

## 受け入れ基準

1. **必須チェック名が 1 つも消えていない**（`build-and-test` / `lint` ほか）。
2. **テストが 1 本も減っていない** —— 3 シャードの `Test Run Successful` の合計が **51**。
3. 各シャードで **カバレッジレポート数 ＝ そのシャードのプロジェクト数**（1 プロジェクト = 1 レポート）。
   ずれたら失敗させる（走らなかった／二重に走ったのどちらも捕まえる）。
4. カバレッジ床が集約ジョブで**従来どおり強制**され、シャード分割で割れない。
5. backend 非変更 PR で backend ジョブが skip され、**PR 全体は緑**（恒久 pending にならない）。
6. **backend を触る PR では必ず走る** —— 許可リストの取りこぼしが「走らない」側へ倒れない。
7. `build-and-test` の所要が **146 秒（`claude-review` の下限）を下回る**。
8. 逆転監視（`ci-latency-watch.yml`）が、窓が入れ替わったあとに**鳴らなくなる**。

## 検証（実測でしか確かめない）

- ベースラインは run `32510016809` の **208 秒（Restore 13 / Build 43 / Test 133）**。
- 🔴 **本 PR 自身が `.github/workflows/**` を変更するので backend は skip されない。**
  シャーディングの効果はこの PR の CI でそのまま測れる。
- 🔴 **b の「skip する側」は別途 docs のみの PR で確かめる。** 本 PR では確かめられない。
- 🔴 **`Test Run Successful` を数えるときはログを切らない。** 第 2 弾で `tail_lines: 4000` で
  切ったログを数え、**51 → 40 に減った＝走っていない**と報告しかけた（実際はログの切断）。
  **生ログを全部取得して数える。**
- 2 回走らせて flaky 化していないことを見る（分割はテスト間の暗黙の依存を露呈させ得る）。

## 母集合の取り方（規則 6: 引いた結果と除外の理由を残す）

- **テストプロジェクトの母集合**は 2 通りで引いて突き合わせた ——
  パス（`*[Tt]ests*` の `.csproj`）で **51 件**、内容（`Microsoft.NET.Test.Sdk` / `xunit` 参照）で **51 件**。
  **一致した。** 実装は**内容側**を採る（命名に依存しないため）。
- **変更内訳の母集合**は `origin/develop` の直近 40 マージコミット。
  マージコミット以外（未マージのトピック）は含めない。

## 未決事項

- **シャード数 3 は暫定である。** 効果を実測して再検討する。N を上げるほどジョブ起動
  （約 13 秒）とビルド（43 秒）の重複が増えるため、単調に速くはならない。
- `deploy/**` を許可リストへ入れられるかは、テストが実際に読むファイルを洗い出してから判断する。
