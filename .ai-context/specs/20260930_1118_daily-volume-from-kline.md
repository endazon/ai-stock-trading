# 判断へ前営業日の出来高と 20 日平均比を日足 K 線から渡す（#1118）

## 背景

計画 ADR-0048（planning#702 の利用者裁定 2026-09-30）は、定時の判断へ渡す出来高を moomoo の日足 K 線から得る前日までの値とした。

- 決定 2: 渡すのは**前日の出来高**と、**前日の出来高の 20 日平均に対する比**（前日までの確定足 20 本の単純平均を分母とする）。当日の累計は渡さない。
  値が得られない（足が 20 本に満たない・取得に失敗した）ときは「不明」と書き、0 や「少ない」として扱わない。**K 線が取れないことを理由に判断を止めない。**
- 決定 3: 判断へ K 線を流すのは、ADR-0023 決定 5 の確認 1（取得枠の単位と回復周期）が済み、分割をまたいでも比が歪まないことを確かめてから。それまでは「未提供」と明示する。
- 決定 4: 方針を生成する LLM へ、判断へ渡る材料と「未提供」の材料を示す。

#1117 の検証口（IADR-0464）の実測（2026-09-30・実機）:

| 事実 | 本件への帰結 |
| --- | --- |
| 取得枠は**銘柄単位**（同じ銘柄の 2 回目以降は復権区分・期間を変えても +0）。総量 300 | 1 日の取得は監視銘柄の数で抑えられる。**回復周期は未測定** → 既定は無効 |
| 前復権（forward）は**出来高も分割で調整する**（NVDA 10:1: 分割前は forward/none = 10、分割後 1） | 前復権で取れば、1 回の取得の中の足は分割をまたいでも同じ単位。自前の揃えは要らない |
| 今日を含む範囲は**未確定の当日足**を返す（AAPL の出来高が平常の約 1/3） | 当日（米国東部）の足は必ず捨てる。前営業日までだけを使う |
| 2 か月で 46 本・欠けなし・続きの鍵なし | 45 暦日の窓で 20 本（ATR(14) の 15 本も）を 1 回で取れる |

## 範囲

1. 判断側の日足の読み取り口 `IDailyBarsProvider`（OHLCV。ATR(14) を計算する #1122 が再利用する）。
2. 日足を OpenD から読む口を発注執行に置く（`GET /order-execution/daily-bars`・前復権・読み取り専用）。判断は HTTP で読む（借株可否の照会 IADR-0425 と同じ東西の形）。
3. 前営業日の出来高と 20 日平均比の計算（純関数）と、本判断・一次の値動きの行への反映。
4. 銘柄 × 取引日のキャッシュ（前営業日までの確定足は 1 日 1 回の取得で足りる）。失敗は 15 分おいて取り直す。
5. 有効化の設定 `DecisionVolume:Enabled`（**既定 false**）。無効なら K 線の要求を 1 回も出さず、プロンプトは今日と同じ「未提供」の行。
6. 方針の改訂 LLM（`PolicyRevisionPromptBuilder`）へ、判断へ渡る材料と「未提供」の材料の一覧を示す（同じ設定キーで出来高の行を切り替える）。
7. 取得枠の消費を計器で追えるようにする（発注執行の K 線要求の件数・取得後の枠の使用数と残り）。

範囲外: ATR(14) の計算（#1122）、Stage 0 の as-of 入力への出来高（既定の供給口は null のまま）、日本株、回復周期の測定（残件・有効化の条件）。

## 設計の選択（IADR-0467 に記録）

| 論点 | 選んだ形 | 理由 |
| --- | --- | --- |
| OpenD を誰が読むか | 発注執行（接続先・鍵がある唯一の Pod） | BacktestService の Pod には OpenD の接続先・鍵が無い（IADR-0464 の実測）。配備の変更なしで有効化できる |
| 判断からの経路 | REST `GET /order-execution/daily-bars`（`OwnerOrService`）。判断は `HttpDailyBarsSource` | 借株可否（IADR-0425）と同じ。gRPC は宣言で選ぶ段の運用（IADR-0284）があるが、既定の REST で足りる |
| 常駐の接続 | 検証口のクライアントを遅延生成して使い回し、例外で捨てて次で作り直す | 検証口のクライアントは切断後に撃たない（IADR-0464 決定 3）。作り直しは包みの側で行う |
| キャッシュの置き場 | 判断側（`CachedDailyBarsProvider`・singleton）。鍵は（銘柄・市場）、値は米国東部の取引日つき | 読み手の近くで持つと、日付が変わるまでは HTTP も OpenD も叩かない |
| 20 日平均 | 前営業日を**含む**直近 20 本の単純平均 | ADR-0048 決定 2「前日までの確定足 20 本の単純平均」 |
| 足りないとき | 前営業日の出来高は出し、比は「不明」。前営業日の足が無い・古いときは「未提供」 | ADR-0048 決定 2（値ごとに不明と書く） |
| 分割 | 前復権で 1 回に全部取り、足し継がない（日ごとに取り直す） | 取得ごとに調整の基準が揃う。取得をまたいで混ぜない |

## 窓の表（規則 11）

窓 = 「足が確定する時刻」と「判断がその足を使う時刻」の間。プローブは 3 つ。

- **P1（増える側・当日足の混入）**: 要求の範囲に当日が入ると、OpenD は未確定の当日足を返す（実測）。当日足を前営業日として使うと出来高が約 1/3 に見える。
- **P2（減る側・日付をまたいだキャッシュ）**: D−1 に取得した足（最後は D−2）を D に使い続けると、前営業日の足が 1 日古い。分割が D の寄りで効くと、古い取得と新しい取得の足が混ざり比が歪む。
- **P3（前営業日の欠け）**: 取得できた最後の足が前営業日でない（銘柄の停止・データの遅れ）。古い足を「前日」と書く。

| 形 | P1 | P2 | P3 |
| --- | --- | --- | --- |
| 後の端だけ（足の日付 < 当日で切るが、キャッシュは日付で区切らない） | ○ | ✕（翌日も古い取得を使う） | ✕（前営業日と突き合わせない） |
| 前の端だけ（取得した取引日でキャッシュを区切るが、当日足を切らない） | ✕（当日足が最後に来る） | ○ | ✕ |
| **両端（採用）**: 取得の取引日でキャッシュを区切り、足は当日より前だけを残し、最後の足が前営業日（規則計算の休場日と週末を除いた前日）と一致するときだけ出来高を出す | ○ | ○ | ○（「未提供」） |

試験: P1 = T-10-1830、P2 = T-10-1831、P3 = T-10-1828（計算側）・T-10-1830（提供側）。

- `Program.cs`: `DecisionVolume:Enabled`（既定 false）と `OrderExecution:BaseUrl` が揃ったときだけ `CachedDailyBarsProvider`。

## 追加の実測（利用者の再実行 2026-09-30 23:43 JST。コーディネータ経由）

- 同じ銘柄の取り直しは `delta.used=0` だが、枠の詳細の `requestTime` はその銘柄の**最後の取得時刻へ更新される**。回復が「最後の取得から」数えるなら、
  毎日取り直す監視銘柄は常に使用中に数えられる → **使用中の銘柄数 ≒ 監視銘柄の数、毎日取り直す銘柄の回復は起きない想定で見積もる**（IADR-0467 決定 6。監視銘柄 6・枠 300）。
- `requestTime` は UTC+8（moomoo のサーバ時刻）。**本件の経路は枠の詳細を求めず（`bGetDetail=false`）、時刻を解釈しない**（IADR-0467 決定 5）。
- 検証口の CLI 引数（`KLineQuotaProbeCommand`）と `MMApiMoomooKLineProbeClient` には**触れていない**（並行の `--quota-only` と衝突しない）。
  再利用したのは `KLineQuotaProbeComposition.CreateQuery`（変更なし）と `MMApiMoomooKLineProbeClient`（変更なし）だけである。
