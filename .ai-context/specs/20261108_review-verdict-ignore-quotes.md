# 作業仕様書 — 下限の自己申告の読み違い（引用・出力）（NFR）

> 着手 2026-11-08（develop `f55ee1c86`）。判断の記録は IADR-0643。基盤にも同じ直しを入れる（基盤の IADR-0707。番号は基盤のマージ順で変わり得る）。

## 起点（同型 2 回）

1. #1597（run 42382006516 / job 128431415722）: `helm template` の行の「他の Worker の出力は全行を読んでいない。」が、
   「43 ファイルを読んだと申告したが、本文が精読していないと書いている」で落ちた。指しているのは描画の出力で、変更ファイルではない。
2. MSP#2512（run 42396353370 / job 128474457406）: 本文の
   「試験が固定する 5 語句（流用しない・push のたびに・全ファイルを読み直す・前回以後だけは満たさない・M の数え方）は prompt に存在する。」が、
   「下限の自己申告: 本文が下限を満たしていないと書いている」で落ちた。語句を括弧の中で紹介しただけ。本リポの `findFloorAdmissions` は基盤と同じ形なので、本リポでも同じく落ちる（実測）。
- どちらも再実行で通った（言い回しが変わったため）。

## 再現（実測）

- #1597 の issue comment 6708323055 の本文と、PR の変更ファイル 43 件（`pulls/1597/files`）を develop の検査器の `findFloorViolations` に渡すと、
  job のログと同じ 1 行が出る。MSP#2512 の本文（comment 6710653084）を本リポの検査器に渡しても、job のログと同じ 1 行が出る。

## 方式（基盤と同じ直し。本リポの検査器の形に合わせる）

- 引用の外し方（`stripQuotes`）を、自己申告の判定（`findFloorAdmissions`）と未精読の判定（`findNotReadAdmissions`）で共有する。
  - 既存: インラインコード・「」・『』。
  - 足す: 引用ブロック（行頭 `>`）の行は数えない。語句を紹介する括弧（直前が「語句・文言・文字列・フレーズ・表現」の括弧）の中は数えない。
    括弧一般は外さない（「下限は満たしていない（時間切れ）」のような本当の申告の補足を消さないため）。
- 未精読の判定に除外を 1 つ足す（`aboutOutputAsObject`）。次を**すべて**満たす文だけを外す。
  1. 当たった型のすべてで、その直前が「出力・描画・描画結果・ログ・実行結果」＋「は・を・も・の」で終わる（読んでいない物＝出力そのもの）。
  2. 文（引用の中も含む）が、ファイルを指す語（`FILE_TARGET`。差分・ファイル・本文・テスト・拡張子 等。基盤と同じ語）を含まない。
  3. 文（引用の中も含む）が、変更ファイルのパスも名前も含まない。
  判定の単位は**文**。本リポには基盤の #2276 の除外（行の単位）が無く、本 PR でも足さない（「出力が大きく、全行は読んでいない」は従来どおり赤）。
- `findNotReadAdmissions` に変更ファイル（4 番目の引数）を渡す。従来の `unreadable`（#1546）は変えない。

## 母集合（規則 9・10）

- `findFloorAdmissions` / `findNotReadAdmissions` の呼び手: `findFloorViolations` と `scripts.test.js` だけ（`grep -rn` で確認）。
- `stripQuotes` の呼び手: `findNotReadAdmissions` だけ。広げた分は両方に効く（意図どおり）。
