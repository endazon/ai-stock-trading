# 保有中の銘柄の買い増しが必ず拒否されるとき、LLM に選ばせず、返しても Hold に倒す（#1130）

## 背景

監査（2026-10-01）F2。9/30 15:41:08 UTC、定時判断で保有中の `MSFT` に `Buy 数量=436`（買い増し）が出た。LLM（一次と本判断）を
呼んだ後、15:41:17 にリスク審査が `MaxPositionsExceeded` で拒否し、Discord へも通知された。

#1113（IADR-0463）は「保有が既知で 0・未約定が既知で空」の銘柄だけ新規建ての可否を照会する。保有中の銘柄では照会もせず、
プロンプトにも「買い増しは審査で必ず拒否される」とは書かない。LLM は買い増しを提案でき、費用と拒否の通知が無駄になり、
根拠文（「買い増しを検討できる局面」）と結果も食い違う。issue の提案は「保有中でも照会し、塞がっていればプロンプトで明示する。
決済の判断は残す。#1113 の裁定の射程を保有中の買い増しにも広げる」である。

## 前提（読んだ制約）

- 計画 ADR-0003: リスク管理は発注前の最終防衛線。→ **審査は変えない**（両端で止める）。
- IADR-0463 決定 1〜5: 可否はリスク管理が審査と同じ述語で返し、判断側は読むだけ。照会の失敗・未結線は従来どおりへ倒す。計器の移動は受け入れる（裁定 4）。
- IADR-0358 決定 2 / IADR-0119: 決済（Close）は止めない。→ **保有中の銘柄では LLM を必ず呼ぶ**（省かない）。
- IADR-0351: 保有状況節は 3 状態を書き分ける。方針（PolicySummary）は書き換えない。
- IADR-0390: 未約定の新規建てが不明なら買い増しを選ばない（既存の文言と見送り）。
- IADR-0452 決定 1: LLM が結論を出した後に統制が見送らせたものは `TradeDecisionHeld`（判断後の見送り）を出す。
- IADR-0374: 見送りは唯一の出口 `Skip` を通し、`DecisionSkipReason` で計上する（値は末尾へ足す）。
- ADR-0016 決定 9 / IADR-0346: 保有建玉数の上限。審査は新規建て（`PositionEffect.Open`）なら**買い増しでも**建玉数が上限に達していれば拒否する。

## 審査は買い増しをどの述語で拒否するか（確認）

- `RiskEvaluator.Evaluate` の新規建て判定は `isEntry = intent.PositionEffect == PositionEffect.Open` で、買い増し（保有ロングへの Buy、保有ショートへの Sell）は
  判断側の `PositionEffectResolver` が `Open` にする。したがって買い増しにも新規建てと同じ述語が**同じ順序で**掛かる。
- `EntryStateBlockers.MaxPositions` は `snapshot.OpenPositionCount >= MaxOpenPositions` で、**注文が建玉を 1 つ増やすかどうかを見ない**。
  買い増しは建玉数を増やさないが、上限ちょうどでは審査が拒否する（観測の `MaxPositionsExceeded` はこれ）。
- `EntryBlockersService.Build` は `Determine(Buy, …)` と `Determine(Sell, …)` を銘柄の保有と無関係に求める（入力は全体のスナップショット・銘柄の当日の損切り・ロックアウト）。
  → `LongSide` は「この銘柄の買いの新規建て（買い増しを含む）」の、`ShortSide` は「売りの新規建て（売り増しを含む）」の、審査と同じ述語の答えである。
  **リスク管理の口は変えなくてよい**（保有中を仮定した別の答えを足す必要は無い）。T-10-1900 で、保有中の銘柄の買い増しで口と審査が一致することを固定する。
- 買い増しを上限で拒否すべきかは審査の意味論であり、本件では変えない（残余に記録）。

## 設計

### 1. 照会（保有中も）

- 保有が**既知で 0 でない**（`heldPosition is { SignedQuantity: not 0 }`）とき、#1113 の関門の後・RAG の前で可否を 1 回照会する（未約定の状態は問わない）。
- #1113 の経路（保有 0・未約定なし）は**一字一句変えない**（同じ条件・同じ照会 1 回・同じ見送り）。保有不明・保有 0 で未約定あり／不明は照会しない（従来どおり）。
- 照会の失敗・例外・未結線（null）は「不明」で、プロンプトも変換も従来どおり。キャンセルは伝える。
- 保有の方向の答え: ロング → `LongSide`（買い増し＝Buy）、ショート → `ShortSide`（売り増し＝Sell）。

### 2. プロンプト（LLM は必ず呼ぶ）

- 保有の方向の答えが空でないとき、本判断の保有状況節の選択肢の行を差し替える:
  「本日は買い増し（Buy）を選べません。リスク管理の審査で必ず拒否される状態です（理由: 保有建玉数の上限に到達）。保有継続（Hold）・手仕舞い（Sell）のいずれかを判断します。
  買い増しを返しても、システムは発注せず Hold として扱います。」＋全量決済の注記。
  買い増しの条件の 2 行（`NoAddAtStopLossLineRule`・`AddOnlyWithinPolicyRule`）は出さない（選べない行動の条件は要らない）。出口の行は不変。
- 一次（門）の短縮版も同じ条件で「本日は買い増し（Buy）が…必ず拒否されるため候補にしません。手仕舞いの検討に値する場合だけ本判断へ進めます。」へ差し替える。
- 答えが空・不明・保有 0・保有不明では節は従来と一字一句同じ（既定の引数 null）。
- 理由は日本語の短い名前で書く（7 理由。未知は列挙子の名前のまま）。

### 3. LLM の後の変換（Hold に倒す）

- 建玉効果が `Open`（決済でない）で、LLM の前に読んだ答えの**その方向**（`ForEntry(side)`）が空でなければ、`SkipJudgedAsync(AddOnBlockedByRiskControls)` で見送る。
  - `TradeDecisionHeld(Reason="AddOnBlockedByRiskControls")` が監査台帳へ「判断後の見送り」として残る（既存のイベント・スキーマ不変）。急変の基準値も進む（判断をしたので正しい。IADR-0452 決定 1）。
  - `decision_skips{reason="AddOnBlockedByRiskControls"}` に 1 件。`TradeDecisionMade` は出さない（審査に届かない＝拒否の通知も出ない）。
- 位置: 建玉効果の解決・未約定が不明の見送り（`WorkingEntriesUnknownOpen`）の後、参照価格の検証の前。
- 決済（ロング保有の Sell・ショート保有の Buy）は変換しない。保有 0（LLM の間に決済された）で Buy なら、それも同じ方向の新規建てであり、T0 の答えは同じ述語なので変換する。
- 照会しなかった・不明なら変換しない（審査が止める）。

### 4. 審査

変えない（両端）。

## 窓の表（規則 11）

T0＝判断が可否を読む時点（LLM の前）、T1＝審査の時点（LLM の後）。対象は保有中の銘柄の買い増し（同じ方向の新規建て）。

- **増える側**: T0 では塞がっていない → T0〜T1 に塞がる（建玉数の上限到達・損切り・kill switch の投入）。
- **減る側**: T0 では塞がっている → T0〜T1 に空く（他の建玉の決済で枠が空く・kill switch・一時停止の解除）。

| 形 | 増える側 | 減る側 |
| --- | --- | --- |
| 後の端だけ（審査だけ＝是正前） | 拒否（正しい） | 承認（正しい）。塞がっている間は LLM が買い増しを提案し、拒否と通知が出る（#1130 の症状） |
| 前の端だけ（変換だけ・審査を外す） | **通る（統制の穴）** | Hold（1 サイクル） |
| **両端（本件）** | 拒否（正しい。審査は不変。プロンプトは買い増しを示し、変換もしない） | Hold（1 サイクル。安全側。次の判断で読み直す） |

現行より緩む升目は無い。代償は、LLM の間に空いた場合の 1 サイクル分の買い増しの機会損失だけで、#1113 の減る側と同じ（IADR-0463 決定 1 の受容の範囲）。
LLM の後にもう一度照会して減る側を詰める形は採らない（照会の失敗の扱いが 2 つになり、不明のときの向きの説明が要る。#1113 と同じ 1 回に揃える）。

実測（試験）:

- 両端 × 増える側: T0 で空（`EntryBlockers.None`）なら、LLM の Buy は変換されず `TradeDecisionMade(Open)` として審査へ届く（T-10-1904）。審査は変えていない（RiskManagement の全試験が緑）。
- 両端 × 減る側: 変換は T0 の答えだけで決まり、状態を持たない（同じサービスの次の判断で答えが空なら変換しない。T-10-1905）。
- 前の端だけの形は採らない（審査を外す変更は無い）。

## 残余リスク

- 保有中の銘柄では判断ごとに可否の照会が 1 回増える（5 秒で打ち切り。失敗は従来どおり）。
- 保有 0 で未約定の新規建てがある銘柄の追加の新規建ては対象外（#1113 と同じ線引きのまま。LLM を呼び、審査が止める）。
- 建玉数の上限で買い増しを拒否するかどうか（建玉を増やさない注文）は審査の意味論であり、本件は変えない。変えるならオーナー確認と別 issue。
- `TradeDecisionHeld` は急変の基準値を進める（判断をしたため。是正前の `TradeDecisionMade` も進めていた）。
