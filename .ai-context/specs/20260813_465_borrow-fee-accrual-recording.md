# 仕様書: 借株料の累計（記録側）

> 本仕様書は実装着手前に作成する。

- 起点: **ADR-0027**（2026-08-07 Accepted）。ADR-0016 決定 15 が要求した「借株料の累計」の**定義を与える**部分改定である

## 実装の現状（実測 2026-08-13・`develop` = `1cb19c4`）

- **累計を保持する型・ストア・イベントがコード全体に存在しない**（`ShortSellingStatusService` のコメントが実測として明記している）。
- SC-03 は `BorrowFeeAvailability: MetricAvailability.NotSupplied` / 値 `null` を返す（IADR-0154）。**値を発明せず未供給と明示する扱いは表示規約どおりで安全側として正しい。**
- 近い型は `ShortSellOrderContext.BorrowRateAnnual` だが、これは **1 注文の発注前照会の入力**であって累計ではない（IADR-0158 決定3 が費用計算への接続を構造テストで止めている）。

## 決定（[IADR-0183](../adr/IADR-0183_borrow-fee-accrual-recording.md)）

### 決定1: 計上の単位は「建玉 × 取引日」の 1 行とし、合計は**導出**でしか得られない形にする

**主キーは (Symbol, Market, TradingDay)。** 本リポジトリの建玉は符号付き在庫の射影（`PortfolioProjection`）で
(Symbol, Market) ごとに畳まれており、**建玉の一次識別子はこの組である**（ADR-0027 決定2 の「建玉ごと」の実装上の写像）。

- 銘柄別・口座全体・月次の値は**すべて日次行の合算で導出する**。**別々に積まない**（決定2 の要求）。
- 主キーにより**同じ日を二度計上しても金額が狂わない**（冪等）。

### 決定2: 「計上できた日」と「料率が取れなかった日」を**別の型・別のテーブル**で持つ

ADR-0027 決定4 は「**0 として積まない**」と明示している。`decimal? AmountUsd`（null＝未供給）で表すと、
**`Sum()` が null を 0 として畳む経路が自然に書けてしまう**——禁じられた向きが型の上で表現可能なままになる。

| 事実 | 型 | テーブル |
| --- | --- | --- |
| その日の借株料を計上した | `BorrowFeeAccrual`（`AmountUsd` は非 null） | `borrow_fee_accruals` |
| その日の**料率が取得できなかった** | `BorrowFeeUnavailableDay`（金額の欄を持たない） | `borrow_fee_unavailable_days` |

**未供給の行は金額の欄そのものを持たない。** したがって「未供給を 0 として積む」コードは書けない。

### 決定3: 累計の照会は**必ず未供給の日数を伴う**（金額だけを返す API を作らない）

受け入れ基準の「**未供給の日がある期間の累計が、未供給の日数を伴わずに表示されない**」を、
**値ではなく型で**満たす。集計の戻り値は `BorrowFeeAccrualSummary`（金額・計上日数・**未供給日数**）の 1 種類とし、
`decimal` を単独で返す集計 API を公開面に置かない。

### 決定4: 生涯累計と月次合計は**同じ導出の引数違い**として持つ（按分しない）

ADR-0027 決定3 の「按分しない」は、**期間で行を絞り込むだけ**という形で満たす。
月次合計＝当月に属する `TradingDay` の行の合計、生涯累計＝建玉の建て日以降の行の合計。
**両者を同じ語で呼ばない**（決定3 が「別の値である」と明記）。集計器は期間を必須引数に取り、
「期間を指定しない全期間の合計」という入口を作らない（口座全体の生涯累計は ADR-0027 が定義していない）。

### 決定5: 日次の計上額は**監査ログへ残す**。イベントは計上と未供給で分ける

ADR-0027 決定1 が「**日次の計上額は監査ログへ残す。累計だけを保持すると、後から日別の内訳を復元できない**」と定める。

- `BorrowFeeAccrued`（計上した日）／`BorrowFeeAccrualUnavailable`（料率が取れなかった日）の **2 イベント**。
- 決定2 と同じ理由で 1 イベントに畳まない。**監査の要約が「0 円だった」と「取れなかった」を必ず書き分ける。**

### 決定6: 🔴 **供給は開始しない**（PoC 項目 9 の成立前である）

ADR-0027 決定6 が「**PoC 項目 9 が成立するまで累計の供給を開始しない**」と定める。**単位を取り違えると累計は 100 倍ずれる。**

| 経路 | 何で止めるか |
| --- | --- |
| 料率の写像 | **日次の料率照会（`TrdGetMarginRatio`）を実装しない。** 計上サービスは料率を**引数で受ける**だけで、供給元を依存に持たない |
| SC-03 | `ShortSellingStatusService` に本ストアを**結線しない**。`BorrowFeeAvailability` は `NotSupplied` のまま（既存テストが固定） |
| 構造テスト | 計上の公開面に `ShortFeeRate` を含む名前が生えたら赤くなる（IADR-0158 決定3 の T-10-214 と**同型**）／`ShortSellingStatusService` の依存に累計ストアが現れたら赤くなる |

**「記録側は先行してよい」は ADR-0027 §結果 の明示である。** 本作業はその範囲に収める。

## やらないこと（範囲の明示）

- **日次の料率照会の実装**（`TrdGetMarginRatio` の実弾ヘッダ照会・レート制限）。#331 / #342 の範囲。
- **日次で計上を回すスケジューラ**。供給の開始そのものであり、PoC 項目 9 の成立後。
- **SC-03・日報・月報への表示**（決定6。表示は供給が始まってから）。
- **費用計算（FR-17）・バックテスト費用モデル（FR-15）への接続**（IADR-0158 決定3 が禁じている。本作業でも接続しない）。

## 受け入れ基準（issue #465 より）

- [ ] 建玉ごとの日次計上が積み上がり、銘柄・口座の合計が**導出**で得られる（別々に積まない）
- [ ] 計上日の料率で評価される（建玉時の料率ではない）
- [ ] **否定形（最重要）**: 料率が取得できなかった日が **0 として積まれず、未供給として記録される**
- [ ] **否定形**: 未供給の日がある期間の累計が、**未供給の日数を伴わずに表示されない**
- [ ] **否定形**: 単位が未確定の間、**供給が開始されない**（構造テストで遮断する）
- [ ] 生涯累計と月次合計が別の値として取れる
- [ ] `dotnet build`（0 Warning / 0 Error）／`dotnet test`（全緑）／`dotnet format --verify-no-changes`
