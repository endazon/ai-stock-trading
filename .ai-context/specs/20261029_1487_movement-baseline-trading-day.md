# 仕様書: 急変検知の基準値の取引日の区切り（#1487）

> 本仕様書は実装着手前に作成した（着手 2026-10-29。AST `origin/develop` `09e95635`）。

## 起点（トレーサビリティ）

- 起点: #1487（PoC 2026-10-27〜28。SMCI の基準値 33.54 が日をまたいで残り 10/27 に 21 回連続で急変、HOOD の基準値 95.71〔10/27 の売り指値〕が 10/28 に残り
  開場直後に疑似の急変を 2 件。急変の検知は取引判断の LLM を起こす）。
- 計画: FR-03（既定: 前回判断時点比 ±3%）・UC-02・業務フロー 02。
- 前提の IADR: IADR-0014（監視の巡回）・IADR-0380（閉場中は判定しない）・IADR-0452（Hold でも基準値を進める・判断をしていない見送りでは進めない）。
- 本件の判断: IADR-0596（新規。0594・0595 は開いている PR #1490・#1491 が使用中）。

## 原因

- 基準値は判断（`TradeDecisionMade` の指値・`TradeDecisionHeld` の価格）でしか進まず、取引日の区切りを持たない。前日の最後の判断の価格（決済の指値を含む）が
  翌日の寄り付きの判定に使われ、夜間の値の差が急変になる。LLM の前で見送った判断（IADR-0452）では進まないので、同じ日にも古い基準値が残り得る。

## 計画との関係（要確認として報告）

- 計画は「前回判断時点比」と書き、取引日の区切りを定めていない。本件は「前回判断」を**その取引日の判断**と読み、新しい取引日の最初の場中の巡回の現在値を
  基準値に置き直す（#1487 の求め「開場時点の価格に置き直す」）。計画の文言を変える読みかどうかはオーケストレーターへ報告し、判断を委ねる。

## 母集合（規則 9）

```bash
git grep -n "GetBaseline\|SetBaseline\|IPriceBaselineStore" -- backend
```

| 箇所 | 扱い |
| --- | --- |
| `IPriceBaselineStore`（取得の口） | 置いた時刻つきの取得 `GetBaselineEntry` を足す（既定の実装は時刻なし＝従来どおり） |
| `EfPriceBaselineStore`（本番） | 既存の列 `UpdatedAt` を返す（スキーマの変更なし） |
| `InMemoryPriceBaselineStore`（試験） | 時刻を持つ。3 引数で置いた値は時刻なし |
| `MarketMonitorAppService`（判定） | 前の取引日の基準値を置き直して判定しない |
| 基準値を進める 2 つのハンドラ | 変えない |

## 設計

- 監視銘柄の判定で、基準値の置いた時刻（UTC）を市場の現地の暦日（`MarketHours.ZoneOf`）に直し、今の現地の暦日より前なら、
  その巡回の現在値を基準値として置き直し（ログ INFO 1 行）、その巡回では判定しない。同じ日・時刻が分からない基準値は従来どおり判定する。
- 閉場中の巡回は判定も照会もしない（IADR-0380）ので、置き直しは新しい取引日の最初の**場中**の巡回で起きる（＝開場時点の価格）。

## 受け入れ基準（→ 試験）

- [x] 前の取引日の基準値は、翌取引日の最初の判定に使われない（置き直す。是正前に赤）。置き直した後は従来どおり判定する。
- [x] 同じ取引日の基準値・時刻が分からない基準値は従来どおり判定する。
- [x] EF のストアは置いた時刻を返す。

## 残余

- 同じ取引日のうちに、LLM の前の見送りで基準値が進まずに検知が繰り返される形（SMCI の 21 回）は、本件では変えない（クールダウンで間引かれる。IADR-0452 の規律）。
