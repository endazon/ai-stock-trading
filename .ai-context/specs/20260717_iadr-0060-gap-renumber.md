## 目的・背景

`docs/adr/README.md` の運用ルールは「連番はリポジトリ内で一意・昇順・**欠番なし**」を定める。
現状の `develop` はこれを満たしていない。

- 実在: `IADR-0000`〜`IADR-0059` が連続 → **`IADR-0060` が欠番** → `IADR-0061`〜`IADR-0065` が連続
- 重複: なし
- 索引の行の過不足: なし（索引 65 行 ＝ 実ファイル 65 件）

**欠番が生じた経緯**: PR #146（`IADR-0059` の衝突解消）は、未マージの PR #145 が
`IADR-0060` を採番中だったため `0060` を避けて `0061` を用いた。しかし PR #145 は最終的に
`IADR-0064` としてマージされ（`c0442e1`）、`0060` を使わなかった。この結果、
PR #146 が予約扱いした `0060` は**恒久的な欠番**になった。

これは PR #146 の仕様書が「未決事項」として明記していた分岐そのものである。

> **#145 が取り下げ・採番変更された場合は恒久的な欠番になる**。その場合は #145 の帰趨を見て、本 PR の
> `0061` を `0060` へ寄せ直すか、索引に欠番の理由を残すかを判断する必要がある。要判断。

本作業は前者（**`0060` へ寄せ直す**）を採る。`docs/adr/README.md` の「欠番なし」は運用ルール本文で
あり、索引の注記で例外を積み増すより規約を満たす方が単純だからである。

**新規の意思決定は行わない（＝新規 IADR を作らない）**。既存 5 件の決定内容・状態・設計は一切変更せず、
ID 表記と参照のみを機械的に置換する。

## 設計

**繰り下げの方針**: 既存の連続部分を保ち、欠番より上の番号を詰めて gap を埋める（総入れ替えはしない）。
`0061`〜`0065` → `0060`〜`0064` は「番号 −1」の一様変換であり、対象は `IADR-006[1-5]` に閉じる。
`0060` から昇順に空き番号へ移すため、リネームの途中で番号が衝突しない。

**上流（microservices-platform）参照の保護**: 本リポの文書は platform 側の IADR を無修飾で参照して
いる箇所がある。これらは**別の採番空間**であり、本作業の対象外とする。以下は文脈から platform 側と
確定できたため**変更しない**。

| ファイル | 該当 | 判定根拠 |
| --- | --- | --- |
| `docs/adr/IADR-0046_unit-repo-layout.md` | `IADR-0056 / IADR-0060`・`IADR-0062` | 「platform 側の規約」「platform の段階改名方針」と明示 |

**既知の取りこぼしの是正（複合表記）**: `IADR-0022/0061` が 6 ファイルに存在するが、これは
`IADR-0061`（OpenD 本番化）ではなく**公式ソースコネクタの IADR を指す誤参照**である。PR #149 は
自身の ADR を `0061` から `0065` へ採番し直した際、`IADR-` 接頭辞を持たない複合表記の後半
（`/0061`）を置換し損ねた（`5fe92fd` で混入）。文脈（情報源セレクタ・案A+・レート制限）から
コネクタ ADR を指すことが確定できるため、本作業で最終番号 **`0064`** へ是正する。

- `IADR-0022/0061` → `IADR-0022/0064`（6 ファイル。**−1 ではない**＝旧 0065 の追随）
- `IADR-0021/0064` → `IADR-0021/0063`（前提条件。2 ファイル）
- `IADR-0051/0064` → `IADR-0051/0063`（前提条件。1 ファイル）

**先行仕様書の扱い**: `docs/specs/20260717_iadr-0059-number-collision-fix.md` は「なぜ 0060 を避けて
0061 を採ったか」を論証した当時の記録である。本文の番号を機械置換すると「#145 が 0060 を保持するので
本 PR は次の空き番号 0060 を用いる」といった自己矛盾を生む。本リポの慣行
（`20260712_107_runtime-scaffold.md`＝「作業仕様書は作業/PR 単位の記録であり、後日の変更で遡って
書き換えない」）に従い、**本文の論証は当時の記録として保持**し、冒頭に「後日の変更」注記を足す。
ただし frontmatter `related_ids` と**リンク切れを生む相対リンクのみ**は現行番号へ追随させる。
