# 仕様書: ガードの「建玉 0」をエントリーの未約定・建って消えた・照会できないに分ける（#1013）

- ユースケース（UC）: UC-02（損切り）
- 画面（SC）: なし
- 関連 ADR: ADR-0040 決定 1（S0〜S3）。計画 ADR の決定は変えない
- 関連 IADR: IADR-0210 決定 4（ガードの (b) 建玉消滅→残存取消）、IADR-0428（#853。残余リスクに本件を記録済み）、
  IADR-0344（S1・残保護数量の確定はエントリーの記録の終端で行う）、IADR-0113（約定追跡）、IADR-0406（レグの追跡の起点）、

## 目的・背景（#1013 の実測）

エントリーは既定で指値である。受理済み・未約定のあいだブローカーの建玉は 0 であり、`ProtectiveStopGuard` はこの 0 を
「建玉が消えた」と読む。

1. 逆指値が生きている行: **生きている逆指値を取り消し、行を Completed にする**。後でエントリーが約定しても次の巡回は何もしない（無保護）。
2. #853 の経路（逆指値の予約が例外・予約が解放された送信結果待ちの行）: 建玉 0 なら張らずに Completed。約定後も何もしない。
3. 逆指値が失効した行: 建玉 0 なら Completed。約定後も何もしない。

拾うのは帰属不明の建玉の検知（既定 600 秒）だけで、検知は通知しかしない。

## 決定する挙動（原則 A: 不明／まだ建っていない／建って消えた を分ける）

S0 行（ブローカー側の逆指値。S3 も同じ行）で、ガードが「建玉残 0」を理由に**取消・完了**へ進む 3 か所の直前で、
エントリー注文の状態を確かめる。

| エントリー | 判定の材料 | ガードの挙動 |
| --- | --- | --- |
| 受理済み・部分約定（非終端） | 発注記録が非終端 → ブローカーへ注文照会（`IBrokerAdapter.GetOrderAsync`） | **取り消さない・完了させない**。Active のまま次の巡回で改めて評価（`StillActive`） |
| 終端・約定 0（取消・失効・拒否） | 発注記録が終端、または照会が終端 | 従来どおり（生きている逆指値を取り消して完了／失効・送信結果待ちの行は完了） |
| 約定あり（約定・部分約定のあと終端） | 同上 | **建玉を照会し直し**、その結果でも 0 なら従来どおり（建って消えた）。建玉があれば `StillActive`。照会し直せなければ据え置き |
| 不明（記録が無い・注文 ID が空・照会が null／例外） | — | **据え置き**（取り消さない・完了させない）。Warning ログを巡回ごと、通知（`EntryStateUnknown`・Warning）を 1 時間ごと（と再起動後の最初）に |

- 「照会し直す」のは、巡回の建玉照会が**エントリーの状態を見る前**に取られているためである。その間に約定したエントリーは
  「約定あり・建玉 0」に見え、生きている逆指値を取り消してしまう（本件の窓を狭めただけで残す）。建って消えたと言ってよいのは
  **約定を知った後に取った建玉照会**が 0 のときだけとする。照会し直すのは取消・完了へ進む直前の 1 回（稀な経路）に限る。
- 部分約定のエントリーで建玉が 0 より大きいときは従来の経路（建玉あり→何もしない／失効→建玉残の数量で再発注）のまま。
  純額の規則（`ProtectiveStopNetting`）は変えない。
- 可視化: 新しい `ProtectiveStopRemediation.EntryStateUnknown`（末尾・値 7）。`CloseDecisionId`／`CloseIntent` は null
  （何も送っていない・台帳は押さえない）。`Cause` は `LapsedInFlight`（発行元がガードであることだけを表す）。
  通知は Warning（件名「リスク統制: エントリー注文の状態が不明なため保護逆指値を据え置き」）。据え置きの記憶（`HeldCloseNotificationTracker`）を
  **キー＝EntryDecisionId** で共用する（逆指値・手仕舞いのレグの ID と衝突しない）。発行に失敗したら記憶を捨てる（`PublishAllAsync` の補償）。
- 依存は増やさない。エントリーの状態は既存の `IExecutedOrderStore.FindByDecisionId`（エントリーの DecisionId＝保護記録の `EntryDecisionId`）と
  既存の `IBrokerAdapter.GetOrderAsync`、照会し直しは既存の `IBrokerPositionSource` で読む（Program.cs の組み立ては変えない。本番の組み立てで
  ガードがこれらを受け取っていることを試験で固定する）。

## 対象範囲外（報告のみ）

- S0＋S1 が同じ銘柄・方向に混在する群では、S0 の未約定の主張（数量）が外部要因の減少として割り当てられ得る（`ReconcileShares`）。
  S0 が SIMULATE で拒否される現状では成立しない構成。
- 失効した逆指値をエントリーの部分約定中に張り直すと、建玉残の数量で張る（残りの約定分は帰属不明の検知まで無保護）。既存の規則のまま。
- 約定の反映がブローカー側で建玉照会より遅れる窓（注文照会は約定・建玉照会はまだ 0）は照会し直しでも残る（幅は照会 1 回ぶん）。
- 乖離の取り込み（IADR-0370）が未約定エントリーの S0 行に当たる経路は触らない。

## 配備の順序

新しい列挙値を足すので IADR-0428 の追記と同じ順序: リスク管理・通知・監査を先に、発注執行を最後に。発注執行を戻すときは
`EntryStateUnknown` を出す行が無いことを確かめる（旧い通知は既定の件名「保護逆指値が成立せず建玉を解消」で表示してしまう）。
