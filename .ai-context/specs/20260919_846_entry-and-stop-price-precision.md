# 仕様書: S0 の発火価格とエントリーの指値を刻みへ丸める（#846）

## 起点

- #846（bug・**未発生の潜在不具合**）。#845（S3 の保護レグの価格を丸める）の監査で判明した同型の未修正経路。
- #845 は**代替レグ（S3）だけ**を丸めた。**S0 の発火価格（`OrderType_Stop` の AuxPrice）とエントリーの指値は
  丸めを通らない。** S0 は **SIMULATE だけでなく実弾でも使う経路**である。

## 実測（#846 の監査プローブ・一時追加のうえ削除済み）

```
P4 S0(OrderType_Stop): Kind=Stop Price=332.3512 Trigger=332.3512 Trail=
P5 entry(Limit):       Kind=Limit Price=329.0265
```

#844 の実測（稼働環境・2026-09-18）では、同じ刻み外れが次の拒否を招いた。

```
retType=-1 The precision of Price in Place Order does not meet the specification.
```

## 原因

- 損切りライン（＝S0 の発火価格）は `参照価格 ∓ StopLossDistancePerShare` で作られ、
  `StopLossDistancePerShare` は **LLM の JSON をそのまま読む値**である
  （`TradeDecisionParser.ReadDecimal`。**プロンプトにもパーサにも桁の制約は無い**——本 PR で現物を確認した）。
  ATR 由来の幅は 3〜4 桁になり得る。
- エントリーの指値は `TradeDecisionAppService` の `referencePrice = currentPrice ?? decision.ReferencePrice` で、
  **現在値が取れない日は LLM の値がそのまま指値になる**。こちらにも桁の制約は無い。
- `MoomooBrokerAdapter.PlaceCoreAsync`（S0・エントリー・成行が通る経路）は、どちらも丸めずに送っている。

## 決定

1. **S0 の発火価格とエントリーの指値を、送信前に市場の小数桁へ丸める**（既存の `MoomooPriceRounding` を使う。
   新しい丸め規則は作らない）。丸めは `PlaceCoreAsync` の 1 箇所で行う——S3 の経路
   （`PlaceAlternativeStopOrderAsync` → `PlaceWithRejectionDetailAsync`）は**通らない**ので、
   #845 が決めた S3 の向き（指値は約定しやすい側）を二重に丸めて壊すことがない。
2. **S0 の発火価格は #845 と同じ向き**＝**早く発火する側**（`RoundTrigger`。ロングの保護＝売りは切り上げ、
   ショートの保護＝買戻しは切り下げ）。**保護が緩む側へ倒さない。**
3. **エントリーの指値は「約定しやすい側」ではなく「不利にならない側」へ丸める**
   （**買いは切り下げ・売りは切り上げ**。新メソッド `RoundEntryLimit`）。理由:
   - **約定価格が意図より悪くならない。** 指値なので買いは指値以下・売りは指値以上で約定するが、
     丸めの向きは自由に選べる。**選べるなら不利にならない側を採る。**
   - **1 取引リスクの上限（FR-10）を守る側でもある。** 損切りラインは判断時に固定される。
     買いの指値を切り上げると（＝約定価格が上がり得ると）**エントリー − 損切りラインの実幅が広がり**、
     サイジングが前提にした 1 株あたりリスクを超える。切り下げは常にこの向きを狭める。
   - 代償は**約定しにくくなる**ことだが、これは**可逆**（取引機会の見送り）であり、
     意図より悪い価格で建つことは**不可逆**である。#845 の規律（緩む側へ倒さない）と同じ選び方になる。
   - 🔴 **保護レグ（S3 の指値）とは向きが逆である。** 保護レグは「約定しないと保護にならない」ため
     約定しやすい側へ倒す。**エントリーは約定しなくても損をしない。** この非対称は意図的であり、
     `RoundLimit`（保護レグ用）と `RoundEntryLimit`（エントリー用）を別メソッドに分けて取り違えを防ぐ。
4. **同じ経路を通る指値の決済（`PositionEffect.Close`）にも同じ向きが掛かる**（`PlaceCoreAsync` は
   Open / Close を区別しない）。売りの決済は切り上げ＝約定価格が意図より悪くならない側で、代償は
   1 刻みぶん約定しにくくなること。**損切りの保護は逆指値レグが別に持つ**ため保護の喪失にはならない。
   **Close だけ約定しやすい側へ倒す案は採らない**——向きが 2 つあると取り違えるうえ、
   「意図より悪い価格で決済する」を許す理由がここには無い（成行の手仕舞いは価格を送らない別経路）。
5. **LLM が返す損切り幅の桁は、プロンプトでもパーサでも制約しない**（採らない判断）。理由:
   - **LLM の出力は保証にならない。** プロンプトの指示は守られないことがあり、守られたかを**検査していない**。
     丸めが要ることは変わらないため、**二重に守る**ではなく**丸め側だけが守る**形になる。
   - **パーサは市場も刻みも知らない。** `TradeDecisionParser` は JSON だけを見ており、銘柄の市場・価格帯
     （米国 2 桁 / 1 ドル未満 4 桁 / 日本 0 桁）を判定できない。ここで桁を決めると
     **ブローカー固有の知識が判断サービスへ漏れる**うえ、片方が古くなる 2 箇所の正本になる。
   - **上流で丸めると統制の入力が変わる。** `StopLossDistancePerShare` は `PositionSizer` の入力であり、
     丸めれば**数量（＝実弾の発注金額）が動く**。#846 の射程（送信値の刻み）を超えた挙動変更になる。
   - よって**刻みの知識はブローカー境界（アダプタ）の 1 箇所に寄せる**。この判断は IADR-0210 の追記に残す。
6. **既存の発注前検証は無効化しない。** 丸めた**後**の値を検証へ渡す——丸めで 0 になった指値・発火価格は
   従来どおり送信せず終端 Rejected（fail-closed）。**丸めで 1 刻みを足して 0 を避けることはしない**
   （#845 のトレール幅と同じ規律。決定が求めていない価格を捏造しない）。

## 変更しないもの

- S3 の経路（`PlaceAlternativeStopOrderAsync`）の丸めと向き（#845 のまま・二重に丸めない）。
- 成行（`PlaceMarketOrderAsync`）—— 価格を注文へ載せないため丸める値が無い。
- 損切りラインの算出（`TradeDecisionAppService`）・サイジング・台帳・監査・通知・契約（`OrderIntent` 等）。
- プロンプト（`TradeDecisionPromptBuilder`）・パーサ（`TradeDecisionParser`）。決定 4 のとおり触らない。

## 残る制約

- **台帳には丸める前の値が残る**（`ExecutionRecord.Price` / `ProtectiveStopOrder.TriggerPrice` は
  呼び出し側が持つ値をそのまま保存する）。**最大 1 刻みの差**が「記録した価格」と「送った価格」の間に残る。
  #845 も同じ形であり、揃えるには台帳側の契約に手を入れる必要があるため本 PR の射程外とした。
- 東証の呼値は価格帯で刻みが変わる（1 円・5 円・10 円…）。本決定は**小数桁だけ**を揃えるため、
  高価格帯の日本株では刻みの倍数にならないことがある（#845 と同じ既知の制約）。
- 米国株の「1 ドル未満は 4 桁」は慣行に基づく前提で、ブローカーの仕様書と突き合わせた実測ではない。
- **日本株の低位株では丸めの影響が相対的に大きい**（1 円株の買いの指値は 0 になり、発注前検証が止める）。
- 🔴 **拒否が消えたことの最終確認は再実測でしか取れない。** 本 PR はユニットテストで送信値を固定するだけであり、
  ブローカーが受理するかは稼働環境での再実測を待つ（**本 PR では kubectl を実行せず、実発注もしない**）。
