# 夜間の台帳の要約の §9 を現在時刻で切る（#1102）

## 背景

PoC セッションで、利用者が場中の 2026-09-29 22:57 JST に `nightly-ledger-summary.sh --night 2026-09-29` を実行した。
§9「ブローカの観測の欠け」は窓の終端（翌 08:00）を境界に数えるため、「22:52 → 08:00 で 9 時間の欠け」のように、まだ来ていない時間まで欠けとして出た。
翌朝の実行では起きないが、場中の確かめで誤読しやすい。#1092 の後続であり、#1102 で起票した。NFR の運用のメタ作業で、計画 ADR の新たな制約は無い。

## 母集合（規則 9）

`grep -n ":'to'" scripts/nightly-ledger-summary.sh` で終端を使う箇所を全部挙げた。

| 箇所 | 扱い |
| --- | --- |
| §1〜§8 の `"OccurredAt" < :'to'` | 変えない。未来の行は存在しないので、終端が未来でも結果は同じ |
| §9 の観測の抽出（`< :'to'`） | 変えない（同上） |
| §9 の終端の境界（`SELECT t, :'to'`） | **変更**。`GREATEST(from, LEAST(to, now()))` にする（窓が全部未来でも、頭より前へ戻らない） |
| §9 の見出しの直後 | **追加**。終端が現在時刻より後なら、注意を 1 行出す |
| 手順書の §9 の読み方 | **追記** |

## 受け入れ基準 → 試験（`nightly-ledger-summary.pg.test.sh`・実 PostgreSQL）

- 窓の途中の実行も exit 0。
- 窓の途中なら、注意を 1 行出す。
- 最後の欠けは「最後の観測 → 現在時刻」（約 30 分）であり、「→ 窓の終端」（約 10 時間）ではない。
- 過ぎた窓では注意を出さない。
- 過ぎた窓（観測なし）の欠けは、窓の頭から窓の終端まで（12:00:00）で切る。日をまたぐ欠けは出さない。
- 窓が丸ごと未来なら、欠けは 0 行（窓の頭より前へ戻らない）。

変異の確認:
- 終端を窓の終端に戻す変異では 1 件落ちる。
- 注意を出さない変異では 1 件落ちる。
- 常に注意を出す変異では 1 件落ちる。

監査で次の 3 つの変異が生き残った。過ぎた窓と未来の窓の試験を足して殺した。
- `GREATEST` を外す変異: 1 件落ちる。
- `LEAST` を外す変異: 2 件落ちる。
- `now()` だけにする変異: 3 件落ちる。

`nightly-ledger-summary.pg.test.sh` は 22 件成功した。`nightly-ledger-summary.test.sh` は 20 件、`scripts.test.js` は 490 件成功した。

## 残余

- `now()` は読み取り専用トランザクションの開始時刻である（実行中にずれない）。
- DB サーバと現実の時刻がずれていれば、そのずれがそのまま出る。
