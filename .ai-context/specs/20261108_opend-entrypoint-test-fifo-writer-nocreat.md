# 仕様書: entrypoint.test.sh の書き手が FIFO のパスを作らない

## 起点

- 非機能（試験の決定性）。`deploy/opend/entrypoint.test.sh` の T-722-04（残った FIFO があっても起動する）が、まれに落ちる。

## 1. 実測（develop `a584c029d`）

| 回し方 | 結果 |
| --- | --- |
| 負荷なしで 50 回（IADR-0646 の作業ツリー。同じ試験） | 2 回落ちた。どちらも T-722-04（`EEXIST を出さない`。1 回は `残存 FIFO があっても起動する` も） |
| 4 本の CPU の負荷の下で 8 回（develop の未変更のツリー） | 1 回落ちた（T-722-04 の `EEXIST を出さない`） |
| 起動の処理の「消す」と「作る」の間を 0.5 秒に広げ、書き手を 0.2 秒遅らせた写し | 従来の書き手は毎回 `File exists` で落ちる。直した書き手は通る |
| 4 本を並べて同時に 13 回ずつ（計 52 回）・develop の未変更のツリー | 3 回落ちた（すべて T-722-04） |
| 同じ回し方・同じ時刻に・直した試験 | 52 回すべて緑 |
| 4 本の CPU の負荷の下で順に回した・直した試験 | 46 回すべて緑（負荷の打ち切りの時刻を過ぎた 47 回目は時間切れで止めた） |

## 2. 原因

- 試験の書き手 `write_line` はシェルの `>` で FIFO を開く。`>` は O_CREAT で開く。
- 起動の処理（`make_stdin_fifo`）は古い FIFO を消して（`unlink`）から作り直す（`mkfifo`）。その間に書き手が開くと、**通常のファイルを作る**。
- 続く `mkfifo` は EEXIST（`File exists`）で失敗し、偽の OpenD はその通常のファイルを読んで、書いた行を受け取らない。
- 本番の書き手（`FifoOpendStdinWriter`）は O_CREAT を付けずに開く（`O_WRONLY | O_NONBLOCK`）ので、この欠陥は**試験の書き手だけ**にある。起動の処理は変えない。

## 3. 受け入れ基準

| # | 基準 | 試験 |
| --- | --- | --- |
| 1 | 試験の書き手は、パスが無いときに書けず（非 0）、通常のファイルを作らない | T-722-11（新規） |
| 2 | 隙間に当たったときは少し待ってやり直し、作り直された FIFO へ届く | T-722-04（期待値は変えない） |
| 3 | 負荷の下の多数回（並べて 52 回・順に 46 回）で 1 回も落ちない（同じ回し方の develop は 52 回中 3 回落ちる） | 実測（§1） |

陰性対照: 書き手を `>` に戻すと T-722-11 が赤になる。隙間を広げた写しでは、従来の書き手で T-722-04 が赤になる。

## 4. 変えないもの

- 試験の skip・期待値の緩め・待ち時間を延ばすだけの直しはしない。起動の処理（`entrypoint.sh`）は変えない。
