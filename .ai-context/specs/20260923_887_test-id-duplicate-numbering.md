# 仕様書: テスト ID の重複採番（#887）

## 起点

- #887 — `docs/tests/FR-10_risk-controls-tests.md` の T-10 テスト ID に**重複採番**がある。
  本書は T-10 の採番の単一情報源として使われている（新しいテストを足すときに「既存の最大値」を測る先）ため、
  重複があると**採番の衝突を検知できない**。
- 🔴 issue のコメントが「**件数は数え方に依存するので、是正する人は自分で引き直すこと**」と明示している。
  本作業はそれに従い、**自分で引き直した**（下の母集合）。

## 🔴 なぜ単独の PR にしたか（グルーピングの根拠）

- 触る現物が `docs/tests/*.md` と `scripts/check-test-traceability.js` の 2 か所に閉じており、
  同時に進めた #886 / #895（`.ai-context/adr/` の索引行）とも #888 / #894（試験ハーネスと母集合の規則）とも
  **ファイル領域が 1 つも交差しない**。
- 一方で、**この PR の中身はレビューで一番読む必要がある**（採番という共有資源の規約を変え、
  母集合の数え方そのものが論点になっている）。ほかの 2 件と束ねると、
  復元作業やハーネス修正の diff に埋もれる。

**T-10 を引いているファイルは 115 件ある。** そのうえで、**何を「採番」と数えるか**を先に決めた。

| 種別 | 形 | 扱い |
| --- | --- | --- |
| **採番行** | 表の行頭のセルが ID そのもの（`\| T-10-450 \|` / `\| **T-10-450** \|`） | **採番**として数える |
| **枝番** | 行頭のセルが ID ＋ 英小文字 1 文字（`\| T-15-40b \|`） | **別の採番**として数える（実在する。`T-15-40` の枝） |
| **参照行** | 行頭のセルが ID ＋ 全角括弧の注記（`\| T-10-127（否定形） \|`） | **参照**であり採番ではない（同じテストの別観点を指す） |
| 本文・コード中の言及 | `// T-10-450:` 等 | 参照。採番ではない |

🔴 **issue のコメントが指摘した「厳格 20 件 / 緩い 23 件」の差は、この参照行を数えるかどうかで生じていた。**

別番号を振ると**逆に 1 つのテストが 2 つの ID を持つ**）。

### 除外したものと理由

| 除外 | 理由 |
| --- | --- |
| `backend/` のテスト・実装コード中の `T-10-NNN` コメント | **参照であって採番ではない。** 本 PR は**サービスコードを 1 行も触らない**（射程外） |
| `.ai-context/specs/` / `.ai-context/adr/` の言及 | 同上（かつ**凍結記録**であり本文を後から書き換えない） |

| ゼロ埋めの揺れ（`T-10-01` と `T-10-1`） | 数値で正規化して突合した。**現時点で衝突は 0 件**（正規化前後で重複件数は 24 件のまま） |

## 🔴 決定: 既存の重複は改番しない（記録して凍結し、新規だけを止める）

issue の「やること（案）」は「後から足した側を最大値＋1 へ改番する」だった。**これは採らない。**
理由は実測に基づく（詳細と選択肢の比較は IADR-0376）。

1. **改番はサービスコードの書き換えを要求する。** 重複 21 件（FR-10）の外部参照を走査すると、
   `T-10-410` は **9 ファイル 37 箇所**、`T-10-450` は 5 ファイル 15 箇所、`T-10-451` は 5 ファイル 9 箇所が
   `backend/**/Tests/*.cs` と `.ai-context/specs/` に在る。**本 PR はサービスコードを触らない射程である。**
2. **どちらの出現を指しているかが外部参照からは決まらない。** 例: `T-10-197` は
   `.ai-context/adr/IADR-0174`（1 つ目の出現＝FX 鮮度）と
   `MaintenanceMarginReductionServiceTests.cs`（2 つ目の出現＝維持率）から**両方**参照されている。
   どちらを改番しても、**残った側の参照が別のテストを指す**。
3. **`.ai-context/` は凍結記録であり、本文を後から書き換えない**（CLAUDE.md）。改番の追随ができない。
4. **本リポジトリは既に「欠番は許す・再利用は禁止・改番はしない」を IADR 採番で採っている**
   （IADR-0280。繰り下げのコストが参照数に比例して肥大化するため）。**テスト ID も同じ思想へ揃える**。
5. **並行作業が採番中の帯がある。** 本作業と同時に `T-10-622..633` / `634..645` / `646..657` / `658..669` を
   別レーンが確保している。**これらを再利用・再割当してはならない**（本 PR は 1 件も触らない）。

## 設計

### 1. 採番規約（`docs/tests/README.md`）

- ID は `T-<FR 番号>-<連番>`（枝番は英小文字 1 文字。`T-15-40b`）。
- **採番空間は FR 番号ごと**であり、**`docs/tests/*.md` を横断**する（1 FR = 1 ファイルではない）。
- **再利用しない・改番しない・欠番は許す**（IADR-0280 と同じ思想）。
- 新規採番は **`node scripts/check-test-traceability.js` が出す「採番の最大値」＋1**。
  🔴 **並行レーンが develop に載っていない帯を確保していることがある。** 着手時に**互いに素な帯を宣言して確保**し、
  その帯の中から採る（既知の帯は本節に書かず、issue と PR で宣言する——ここへ書くと必ず古くなる）。
- 行頭セルの形で**採番行・枝番・参照行**を区別する（上表と同じ定義を規約として明文化する）。
- **既に重複している番号は改番しない。** `scripts/test-id-duplicate-baseline.json` に記録し、
  **解消したら baseline から消す**（消さないと検査が赤くなる＝ラチェット）。

### 2. 検査 4（`scripts/check-test-traceability.js`）

`docs/tests/*.md` の採番行を集め、次を見る。

| 判定 | 動作 |
| --- | --- |
| baseline に無い重複がある | **fail**（新規の衝突。どのファイルの何行目かを出す） |
| baseline に在るが**もう重複していない** | **fail**（解消したら baseline から消す。ラチェット） |
| baseline の記載と出現箇所（ファイル）が食い違う | **fail**（別の重複と取り違えている） |
| 参照行が指す ID がどこにも採番されていない | **fail**（`T-10-999（否定形）` のような打ち間違い） |
| 上記なし | OK。**FR ごとの採番の最大値を出力へ載せる**（次の採番者が読む） |

- 🔴 **0 件走査で緑を返さない。** `docs/tests/*.md` が 1 件も無い／採番行が 1 件も取れないときは fail する
  （この検査器が既に T1 で採っている fail-closed と同じ思想）。
- 数値は**ゼロ埋めを正規化**して突合する（`T-10-01` と `T-10-1` を同一視する）。表示は原文のまま。
