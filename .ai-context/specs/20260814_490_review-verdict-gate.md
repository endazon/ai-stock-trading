# 仕様書: AI レビューの判定の有無をジョブの結論へ結び付ける

> 本仕様書は実装着手前に作成する。

## 起点

- 起点 issue: [#490](https://github.com/endazon/ai-stock-trading/issues/490)
- 起点 ID: **NFR**（運用保守。工程の統制であり計画側の非機能要件表に当たる番号が無いため無採番。planning#311 の 2）
- 発生: PR [#489](https://github.com/endazon/ai-stock-trading/pull/489)

## 事象（実測 2026-08-14・PR #489）

**同一 PR で 3 回連続、AI レビューが判定（🔴/🟡/🟢 のサマリ）を投稿しなかった。**

| 試行 | 実行時間 | 結論 | 判定 | 形 |
| ---: | --- | --- | --- | --- |
| 1 | 3m55s | **`success`** | **無し** | **A: 待たずにターンを終える** |
| 2 | **20m16s** | `cancelled`（job timeout） | 無し | B: 待って timeout |
| 3 | 11m16s | **`success`** | **無し** | **A** |

3 回とも、PR に残ったのは進行中のプレースホルダだけである。1 回目・3 回目のプレースホルダには
**「`dotnet test backend/backend.slnx` をバックグラウンドで実行中です。完了後にサマリを投稿します」**
と書かれたまま終わっていた。

- `claude-code-review.yml:57` — `timeout-minutes: 20`
- 2 回目は `16:02:31` → `16:22:47` ＝ **20 分 16 秒**でタイムアウト。

### 🔴 形 A が危険である

| 形 | ジョブの結論 | 実害 |
| --- | --- | --- |
| **A: 待たずにターンを終える** | **`success`** | 🔴 **「レビュー済み・指摘なし」と読まれるが、何も判定されていない。マージも止まらない** |
| B: 待って timeout | `cancelled` | マージは止まる（**gate としては正しい**）が、レビューが完了しない |

**A は本リポジトリが繰り返し扱ってきた「緑だが検査されていない」そのものである。**

> **本作業の起点となった PR #489 は、実際にこの形 A の green でマージされた。**
> 自前の検証（CI 24/24 緑・`backend/` 差分 空・build 0/0・test 1798 件・検査器 4 種）があったため
> 内容の risk は低かったが、**「レビュー gate は何の signal も出していなかった」**ことに変わりはない。

### 既存の安全弁では捕まらない

`check-permission-denials.js` は「**AI がツールを 1 つも実行できなかった**」形を捕まえるが、
本件は**ツールは正常に実行できており、最後の投稿だけが無い**。**別の穴である。**

### 🔴 引き金は「コード差分ゼロの PR で全テストスイートを回したこと」である

**#489 は `backend/` の差分が空**の docs のみの PR であった。それでもレビューは
`dotnet test backend/backend.slnx` のフルスイートを実走しようとし、その待ちで詰まった。

プロンプトは「PR 本文が『テストが通る』と主張しているなら**可能な限り自分で実走して確認**」と
求めているが、**変更範囲を見て絞る指示が無い。**

## 決定（[IADR-0190](../adr/IADR-0190_review-verdict-gate.md)）

### 決定1: 判定の有無を**ジョブの結論へ結び付ける**（形 A を緑にしない）

`scripts/check-review-verdict.js` を新設し、`Run Claude Code Review` の後段で
**`if: always()`** で走らせる。実行ログ（`steps.claude.outputs.execution_file`）を読み、
**AI の出力に判定セクションが含まれていなければジョブを落とす。**

- 入力は `check-permission-denials.js` と**同じ実行ログ**であり、`parseEvents` を借りる
  （**2 本セットで扱う**。IADR-0189 決定2 と同じ形）。
- **実行ログを読めないときは warn ＋ exit 0**（fail-open）。ローカル環境差で CI を落とさない
  ——`check-permission-denials.js` と同じ規律。

> **ここは fail-open にしてよい。** 実行ログが無いのは「レビューが動かなかった」ことを意味し、
> **その形は `check-permission-denials.js` が既に捕まえる**。二重に落とす必要は無い。

### 決定2: 判定の検出は**見出しの構造**で行い、語の一致に頼らない

**本文の語（「重大」等）を素で探すと、レビューが本文中でその語を使った瞬間に誤検出する**
（planning#319 知見3 で実証済みの同型のアンチパターン —— 検査器について書いた記録が
語の一致だけで自己発火した）。

**判定セクションの見出し**（`### 🔴 重大` / `### 🟡 推奨` / `### 🟢 軽微` の形）を
**3 つとも**持つことを条件とする。**1 つでも欠ければ判定と認めない。**

### 決定3: プロンプトへ**バックグラウンド実行の禁止**を明記する

**「実行制約・最重要」節はサブエージェントの spawn 待ちでの停止を既に禁じているが、
バックグラウンドプロセスの待ちは書かれていない。** 同じ形の停止であるため足す。

- **コマンドはバックグラウンドで起動しない。** 前景で実行し、完了を待ってから次へ進む。
- **時間が足りないと判断したら、待たずに「未検証（理由）」と書いてサマリを投稿する。**
  **サマリの投稿は、どの検証よりも優先される。**

### 決定4: プロンプトへ**変更範囲に応じた検証の絞り込み**を明記する

- **`git diff --stat -- backend/` が空なら `dotnet build` / `dotnet test` を実行しない。**
- 同様に `frontend/` の差分が空なら frontend の検証を実行しない。
- **実行しなかったことは「実行できなかったこと」節に理由付きで書く**（省略を黙らせない）。

### 決定5: kit へ環流する

**同じ穴はキットを配る全リポジトリにある。** `claude-code-review.example.yml` と
検査器の追加を計画側へ環流する。

## やらないこと

- **`check-permission-denials.js` の変更**（別の穴を見る別の検査器である）。
- **`timeout-minutes` の延長** —— 待ち時間を延ばしても形 A は直らない。**原因は待ち方である。**
- **判定の内容（🔴 の件数等）の検査** —— 本作業が見るのは**判定が在るか**だけである。

## テスト方針

**検査器の自己試験を内蔵する**（`check-permission-denials.js` / kit の検査器と同じ形）。
実ツリーに対する回帰テストは置かない —— **検査対象は CI の実行ログであり、リポジトリの中には無い。**

| 何を守るか | どう守るか |
| --- | --- |
| 判定 3 種が揃えば緑 | 自己試験 |
| **1 つでも欠ければ赤**（形 A の再現） | 自己試験（**最重要**） |
| 本文で「重大」の語を使っただけでは緑にならない | 自己試験（planning#319 知見3 の同型を避ける） |
| 実行ログが読めなければ warn ＋ exit 0 | 自己試験 |

> 🔴 **［2026-08-14 追記］初版は実 CI の初回実行で偽陽性を出した。**
> レビューは判定を投稿していたのに、**実行ログから AI の出力を取り出せず**に落ちた。
> 配送経路を 3 つ見る形へ直し、**取り出せなければ落とさない**（判定不能）ようにした。
> 詳細は [IADR-0190](../adr/IADR-0190_review-verdict-gate.md) 決定6。

## 対照実験（実走した実測）

| 実行ログ | exit | 予測 |
| --- | ---: | --- |
| 判定 3 種を含む | **0** | 一致 |
| **判定を欠く**（#489 の形 A を再現） | **1** | 一致 |
| 判定のうち 1 つだけ欠ける | **1** | 一致 |
| 本文に語だけがある（見出しではない） | **1** | 一致 |

**4 通りとも予測と一致した。** 自己試験 16 件も all passed
（見出しレベル 1〜6 の許容・`assistant` 以外のテキストを使わない・複数メッセージの連結・fail-open の 2 形を含む）。

## 実 CI での実測（2 回・PR #491）

| 回 | レビューの判定 | `Check review verdict` | 判定 |
| ---: | --- | --- | --- |
| 1（初版） | **投稿された**（🔴 0 / 🟡 1 / 🟢 0） | **failure** | 🔴 **偽陽性**（抽出に失敗し「見出し: （無し）」） |
| 2（決定6 の是正後） | **投稿された**（🔴 0 / 🟡 1 / 🟢 1・2m29s） | **success** | ✅ 抽出成功。CI 24/24 緑 |

**2 回目で偽陽性は再発しなかった。** ただし**確認できたのは「判定があれば緑になる」ことまで**であり、
**「判定が無ければ実データで落ちる」ことは未観測**である（自己試験・対照実験でのみ再現）。

**2 回目のレビューの 🟢 も採った** —— 実装は `tool_use` なら**ツール名を問わず** `input.body` を拾うのに、
コメントは特定のツール名を列挙していた。**実測の投稿経路は列挙に無い `update_claude_comment` であり、
ツール名で絞る設計にしていたら取りこぼしていた。** コメントを実装（フィールド名で絞る）へ合わせた。
