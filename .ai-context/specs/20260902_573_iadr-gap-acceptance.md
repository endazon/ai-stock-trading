## 目的・背景

`.ai-context/adr/README.md` の運用ルール「連番は一意・昇順・欠番なし」は、2026-08-28 の
計画大改定（#344）の全面再実装を 12 本のブランチで並行実装した際、各ウェーブが 5 番ずつ
先行割当した範囲を使い切らなかったことで守れなくなった。

issue #573 は当初「20 件の欠番を繰り下げて解消する」ことを目的に起票されたが、14 本の PR が
develop へマージされた時点の再実測で、欠番は **16 件**（起票時に欠番と誤カウントしていた
`IADR-0212` / `0226`〜`0228` の 4 件は実際には使用済みだった）と判明した。

本作業日（2026-09-02）に利用者が裁定した内容は次のとおりである。

> **繰り下げは行わず、欠番を受容してルール側を改める。**
> 根拠: 繰り下げ対象は実測で 47 ファイル改名＋`IADR-0210`〜`0271` の参照 2,339 箇所／450
> ファイル＋クロスリポジトリ追随であり、先例（`IADR-0060` の 5 件・`IADR-0164` の 2 件）より
> 2 桁大きい。かつ force push 禁止の下で他の並行 PR すべてと衝突する。

本仕様書は、この裁定を運用ルール・検査器・関連文書へ反映する作業を確定する。

## 対象範囲

- 対象:
  - `.ai-context/adr/README.md` の運用ルール本文・2026-08-28 の欠番注記の更新
  - `.claude/rules/traceability.repo.md` への「欠番受容・改番は新たな最大＋1」の追記
  - `docs/traceability-appendix.md` §採番衝突時の改番の追随 5 項目 への 1 行の参照追加
  - 検査器（`check-adr-index-sync.js` / `check-commit-messages.js` /
    `gen-knowledge-graph.js --check`）が「欠番なし」を前提にしていないかの確認（前提があれば是正）
  - 本裁定を記録する実装ADR（新規）
- 対象外:
  - 欠番 16 件の繰り下げ（利用者裁定により行わない）
  - `.claude/rules/traceability.md`（キット配布物）の直接編集
  - project-planning への環流（工程のメタ規律であり、製品要件ではないため）

## 設計

### 現状の再実測（着手時点・`.ai-context/adr` 実ファイル走査）

- 実ファイル数: 256（`README.md` を除く）。範囲 `0000`〜`0271`。
- 欠番 16 件（issue #573 のコメントの実測値と一致・変化なし）:
  `0209, 0213, 0214, 0229, 0230, 0231, 0232, 0233, 0234, 0235, 0236, 0237, 0238, 0239, 0243, 0244`
- 新規採番は `0272`（本作業の実装ADR）から続ける。

### ルール改定の方針

1. **運用ルール本文**: 「連番はリポジトリ内で一意・昇順・欠番なし」を
   「連番はリポジトリ内で一意・昇順。欠番は許す（並行実装での先行割当・改番コストが
   参照数に比例して肥大化するため）。ただし再利用は禁止（欠番を後から埋めない＝同じ番号が
   別の決定を指す事故を防ぐ）」へ改める。
2. **2026-08-28 の欠番注記**: 「繰り下げによる解消は本 PR では行わない…後続 PR で解消する」の
   記述を、「本裁定により繰り下げは行わない。16 件の欠番は恒久的に受容する」へ更新する。
   `IADR-0060`（5 件・繰り下げで解消）・`IADR-0164`（2 件・繰り下げで解消）の先例との違い
   （件数の桁・参照数の桁・並行 PR 数）を明記する。
3. **`traceability.repo.md`**: `.claude/rules/traceability.md` の「採番衝突時の改番手順（欠番を
   作らない）」に対する本リポジトリ固有の上書きとして、「本リポは欠番を受容する。衝突時は
   後発が次の空き番号ではなく新たな最大＋1へ改番する」を追記する。
4. **`docs/traceability-appendix.md`**: §採番衝突時の改番の追随 5 項目 の末尾に、本リポジトリが
   欠番受容の方針を採ることへの参照を 1 行加える（`docs/` 配下のため ID は trace ブロックへ、
   本文は内容で呼ぶ）。

### 検査器への影響（読解結果）

- `scripts/check-adr-index-sync.js`: 索引行と本文の同時変更のみを見る。欠番の有無は見ない。
  **影響なし。**
- `scripts/check-commit-messages.js`: `loadExistingIadrIds()` が `.ai-context/adr/` の実ファイル名
  を走査して実在集合を作り、集合への所属で判定する（連番の連続性は見ない）。**影響なし。**
- `scripts/gen-knowledge-graph.js --check`: IADR 実在性検査も同様にファイル実在の集合で判定する
  （計画 ADR のみレンジ判定だが、これは計画側の別名前空間であり本裁定の対象外）。**影響なし。**
- 結論: **欠番を前提に「なし」を検査している検査器は存在しない。是正不要。**
