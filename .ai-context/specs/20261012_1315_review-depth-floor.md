## 問題（点検の実測。#1315 のコメントの要約）

抜き取り 8 対で、切替の前後は次のように変わった。

| 指標 | 切替前 | 切替後 |
| --- | --- | --- |
| agent の中央値 | 371.5 秒 | 33 秒 |
| `scripts.test.js` 全件の実走 | 3/8 | 0/8 |
| 文書系の検査器の実走 | 8/8 | 0/8 |
| `dotnet format` | 7/7 | 0/6 |
| 変更ファイルの読了 | 8/8 | 1/8 |

- `dotnet test` は 4/6 で走ったが、どれも 1〜2 プロジェクトか 1 クラスに絞られていた。
- 未検証の申告の中身も変わった。
  - 切替前は「差分に無いので対象外」と根拠つきで判断したものが 13 件だった。
  - 切替後は「理由なく省略」「読んでいない」が 13 件、「時間優先」が 1 件だった。
- #1317 のレビューは `--publish-out publish.txt` でワークスペースへファイルを書いた。
- 原因は時間・ターン・許可の上限ではない。上限は 20 分で `--max-turns` は無く、後で省いたコマンドはすべて許可済みである。
  モデルの性向で、プロンプトの「変更範囲に応じて絞る」「全スイートは最後の手段」「時間が足りなければ未検証」を早めに使っている。

## やること

1. `claude-code-review.yml` の `prompt:` に【検証の下限・最重要】節を新設する（【実行制約】の直後）。
   - **変更ファイルは全部読む**（生成物だけ除外可。除外したら列挙する）。本文の冒頭に「N ファイル中 M を読んだ」と書く。
   - **`backend/` の差分** → `dotnet build backend/backend.slnx` と、変更したサービス（共有物なら `backend/Shared/**`）のテストプロジェクトを、`--filter` を付けずに全件回す。あわせて `dotnet format backend/backend.slnx --verify-no-changes` も走らせる。
   - **`scripts/`・`.github/` の差分** → `scripts.test.js` 全件を子プロセス形（`REQUIRE_REPO_TESTS=1`）で走らせる。
   - **`scripts/`・`.github/`・`docs/`・`.ai-context/` の差分** → 文書系の検査器 6 本を走らせる: `check-trace-blocks` / `gen-knowledge-graph --check` / `check-doc-links` / `check-adr-index-sync` / `check-commit-messages` / `check-plan-id-qualification`。
   - **`deploy/helm/**` の差分** → `helm lint` / `helm template` を走らせる（既存の【Helm】節に従う）。許可は既に 3 系統にあるので変えない。
   - **理由に使えない語**を定める: 「時間」「時間配分」「時間優先」「差分が大きい」「ファイル数が多い」「静的な読み取りに絞った」。
   - **ワークスペースへ書き込まない。** 出力ファイルを取る引数が要るときは `/tmp/` を指定する。
2. 既存の文言を、下限と矛盾しない形に直す。
   - 【実行制約】の「時間が足りなければ…」→ 打ち切ってよいのは 20 分の上限に近づいた場合だけとする。
   - 【検証の実行】の「全スイートは最後の手段」→ 変更したサービスのテストプロジェクトを全件回す。`backend.slnx` 全体の `dotnet test` は要らない。
   - 同節の絞り込みは「下限の外だけ」とする。
3. `scripts.repo.test.js` に固定試験を足す（#1248 の【Helm】節の試験と同じ型）。
   - 節の存在、要の語、案内するコマンドの許可、旧文言（「時間が足りなければ」「全スイートは最後の手段」）の再混入を見る。
   - 陰性対照がそれぞれ赤になることも確かめる。
4. IADR-0208 決定 1 と IADR-0190 決定 4 に日付つき追記を足す。
