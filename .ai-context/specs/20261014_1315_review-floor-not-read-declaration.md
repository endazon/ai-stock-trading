## やること

1. `scripts/check-review-verdict.js` の (b) に「読んだと申告したファイルを精読していない」自己申告を足す。
   - **節で読む**（#1337 の教訓。行内の否定語だけに頼らない）: 冒頭（最初の判定の見出しより前）と「確認できたこと」の節だけを見る。
     🔍 実行できなかったことの節・指摘の節は見ない（「計画書は未検証」「本体以外の行単位の精読（未実施）」はそこに在る）。
   - 文（「。」と改行）単位で、上表の表記揺れ（全行／行単位／精読せず・精読していない／名前と範囲の確認・名前を一覧／
     要点だけ／検査器の結果だけ／確認にとどまる・確認まで／未読／読めていない／しか目視していない／流し読み等）を探す。
     引用（インラインコード・「」・『』）の中は数えない。否定の否定（「未読のファイルは無い」）は数えない。
   - 冒頭の申告が (a) を満たすとき（M + K ≥ N）だけ判定する（(a) で赤なら重ねない。既存の #1336 の 2 行の期待を保つ）。
   - 偽陽性の除外:
     - 生成物（Designer.cs・ModelSnapshot・messages.ts/po・CHANGELOG.md 等）だけを対象にした文は、冒頭に「生成物 K ファイルを除外」（K>0）
       の申告があるときに限り数えない。生成物以外（テスト・docs・IADR 等）も並べた文は数える。K の申告が無ければ数え、
       「生成物なら冒頭で K を申告する」と案内する（申告との整合）。
     - 計画書（計画 ADR・計画リポ）についての文は数えない。計画書とテスト等を並べた文は数える（生成物と同じ規則。#1346 の AI レビュー 🟢）。
2. `.github/workflows/claude-code-review.yml` の【検証の下限】に「読んだ」の定義を書く: 差分を行単位で読んだこと。
   名前の一覧・検査器の結果・要点だけの確認は「読んだ」に数えない。生成物は除外を申告してよく、EF マイグレーションの
   `*.Designer.cs` / `*ModelSnapshot.cs` と Lingui の `messages.ts` / `messages.po` を生成物の例に足す。
   検査器が読む項目の列挙に本件を足す。起動条件・ジョブ名・ステップ名・`--allowedTools` は変えない。
3. 試験とフィクスチャ（`scripts/fixtures/review-floor/`）:
   - 赤: #1340 の 3 回目（`pr1340-review3.txt`）、#1344 の最終（`pr1344-review2.txt`）、#1336 の 2 回目（`pr1336-review2.txt`）。
   - 緑: #1333・#1337（既存）、生成物除外の合成（`synthetic-generated-excluded-review.txt`）。
   - 表記揺れの陽性・陰性、生成物・計画書の除外、🔍 の節を見ないことを単体で試験する。自己試験にも代表例を足す。
4. IADR-0190 決定 7 に日付つき追記を足す。

## やらないこと

- 🔍 実行できなかったことの節を読むこと（「計画書は未検証」等が恒常的に在り、節で読み分ける (c) と同じ方針）。
  ここだけに「テストは全行を読んでいない」と書いたレビューは素通りする（残余リスク。#1344 は冒頭にも書いていた）。
- 「読んだ」の真偽の検査（嘘の N/N は捕まらない。決定 7 の残余リスクと同じ）。
