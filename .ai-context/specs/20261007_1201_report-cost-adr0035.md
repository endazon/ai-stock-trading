## 設計

### 決定 1: 呼称（ADR-0035 決定 1）

報告書の本文・ゴールデン・散文プロンプトから「実現損益（税引前・費用前）」とその言い換えを消し、**約定代金差額**（売却代金 − 取得代金。費用・税をいずれも控除しない値）と呼ぶ。
`PeriodCostReview.RealizedPnlGross` は `TradeValueDifference` へ改名する。`PnlSummary.RealizedPnlGross` 等の既存の識別子は広く参照されるため改名せず、doc を「約定代金差額」へ直す。

**「実現損益」の列に約定代金差額を入れない。** 月報 §2 の市場別・方向別の「実現損益」は従来、約定代金差額（税引前・費用前）を載せていた。
同じ語に 2 つの意味を持たせないため、**週別と同じ「税引前・費用込み」（約定代金差額 − 売買手数料・取引諸費用）へ揃える**（源泉徴収税額は期間合計にのみ課され配分できないことは従来どおり明記）。

### 決定 2: 事前見積りと事後集計を別の関数にする（ADR-0035 決定 4・5）

- `CostCalculator.EstimateOneWayCost` / `EstimateOneWayCostBreakdown`（手数料＋為替スプレッド相当）は**判断時の事前見積り**に限る（採算判定・バックテスト）。**振る舞いは変えない。**
- 事後集計用に `CostCalculator.FillCost(assumptions, market, side, quantity, price)` を新設する。内訳は **売買手数料＋取引諸費用**で、**為替スプレッドを持たない**（約定ごとの両替は発生しない）。手数料の式は両者で 1 か所に置く。
- 取引諸費用は **米国市場の売り約定**（空売りを含む）にのみ掛かる: SEC = 約定代金 × 料率 / 1,000,000、TAF = min(数量 × 1 株あたり料率, 1 取引あたり上限)。丸めは行わない（他の費用と同じく概算の精度で持つ）。
- 事後集計の為替スプレッド（入出金時の両替の実績）は、**実績を受け取る経路が本サービスに無い**ため `null`＝未供給とする。事前見積りの為替スプレッドとは型も値も別である。
- 報告書側の呼び出し（`PnlAggregator`・`FillPnlAttributionBuilder`・`TradeHistoryViewBuilder`・`PeriodCostReviewBuilder`）は `FillCost` へ切り替える。これにより `PnlSummary.TotalCost`（＝実現損益の控除項）は計画の定義「実現損益 = 約定代金差額 −（売買手数料＋取引諸費用）− 源泉徴収税額」に一致する。

### 決定 3: 諸費用の設定点（ADR-0035 決定 5）

- `TradingAssumptions` に `UnitedStatesSellRegulatoryFees`（`UsSellRegulatoryFeeSchedule(SecFeePerMillion, TafPerShare, TafCapPerTrade)`）を足す。
  **`required` にせず既定値（計画の暫定値）を初期化子に置く** —— 既存の JSON 行・gRPC／HTTP の受け手（取引判断・費用統制）は欄を持たず、欠けたときに計画値で埋まる（それらは事前見積りしか使わない）。
- 既定値は `TradingAssumptionsDefaults` が持ち、`TradingAssumptionsDefaultsTests` で計画の値（$20.60 / 百万ドル・$0.000166 / 株・上限 $8.30。確認日 2026-09-05）に固定する。
- 借株料は引き続き費用計算（`CostCalculator` / `TradingAssumptions`）の公開面に入れない（`借株料は費用計算の入口に存在しない` の構造テストを維持）。借株料は報告書側で記録（`BorrowFeeRecord`）から足す。

### 決定 4: 費用合計の構成と描き方（ADR-0035 決定 3・統制の暫定手段）

- 新設 `PeriodCostTotal(TradingCost, FxSpread?, BorrowFee?, BorrowFeeUnrecordedCount)`。合計＝**供給された区分の和**。未供給の区分は **0 として積まない**。未供給・未計上があれば `IsUnderstated`。
- §1（日報・週報）のラベルを「費用合計（手数料・諸費用・為替スプレッド・借株料）」へ。値の後ろに未供給の区分を名指しし、**費用合計が過小である旨**を同じセルに書く（計画「当該区分を『未供給』と描き、費用合計が過小である旨を凡例へ明記する」）。
- 週報 §5 の内訳: 売買手数料／取引諸費用／為替スプレッド相当額（入出金時の両替の実績）／借株料／費用合計（§1 と同じ値）／源泉徴収税額。
- 月報 §1「費用合計 / 費用率」: 費用合計は §1 と同じセル、費用率は週報 §5 と同じ規則（分母＝約定代金差額・分母 ≤ 0 は「算出不能」・分母を併記・部分値の期間は算出不能）。**フォローアップ 2 を実施**し、月報にも `CostReview` を組み立てる。
- 月報 §2 表 3「費用（うち借株料）」: ショートの行の費用へ借株料（計上分）を**含め**、「うち借株料」を添える。未供給なら「うち借株料 **未供給**」で費用は過小。市場別の「費用」は売買手数料・取引諸費用（借株料は方向別に含める）と凡例に明記する。

### 決定 5: IADR への追記（フォローアップ 1）

IADR-0305・IADR-0306・IADR-0304 の末尾へ `［2026-10-07 追記 / #1201］` を足し、索引行にも同じ追記ブロックを足す（本文の原文は書き換えない）。実装判断は IADR-0501 に記録する。

## 受け入れ基準

1. 日報・週報・月報の本文・ゴールデンに「実現損益（税引前・費用前）」（〔〕表記・「税引前・費用前」の言い換えを含む）が現れず、「約定代金差額」で描かれる。
2. §1 の費用合計のラベルが計画の 4 区分であり、借株料は合計に含まれ、未供給なら「未供給」と描かれ費用合計が過小である旨が出る。
3. 事前見積り（`EstimateOneWayCostBreakdown.FxSpread`）と事後集計（`PeriodCostTotal.FxSpread`）の為替スプレッドが別の値であり、事後集計は実績が無いため未供給と描かれる。報告書の費用は約定ごとの為替スプレッドを含まない。
4. 諸費用（SEC / TAF）が設定点（`TradingAssumptions.UnitedStatesSellRegulatoryFees`、既定値＝計画 §2 の暫定値）から読まれ、米国株の売り約定の費用合計へ算入される。実装コメントの「計画側で要確認」が消える。
5. IADR-0305 / 0306 / 0304 に、計画 ADR-0035 / 0034 による追認が日付つきで追記される。
6. 月報 §1 の費用率が `（データ連携後）` ではなく、週報 §5 と同じ規則で描かれる（フォローアップ 2）。

## テスト方針

- `CostCalculatorTests`: `FillCost` の SEC・TAF・上限・買い/日本株で 0・為替スプレッドを含まない・事前見積りは不変。
- `TradingAssumptionsDefaultsTests`: 諸費用の既定値を計画値に固定。
- `PnlAggregatorTests` / `FillPnlAttributionTests` / `PeriodCostReviewTests`: 費用合計が諸費用を含み為替スプレッドを含まないこと、借株料の算入と未供給。
- 描画（`ReportRendererRiskCostReviewTests`・`ReportRendererMonthlyBreakdownTests` ほか）と全文（ゴールデン 6 本）。ゴールデンは `UPDATE_GOLDEN=1` で再生成し差分を確認する。
- 変異（各受け入れ基準ごとに 1 つ以上、意図的に壊して赤になることを確かめる）。

## 対象外・残るもの

- 取引判断の事前見積り（採算判定・バックテスト）へ諸費用を算入すること —— 費用関数の引数（売買・数量）を事前見積りの全呼び出しへ通す変更で、取引判断の振る舞いを変える。別 issue で扱う。
- 日報 §2 の明細の「実現損益」列（約定単位の約定代金差額）と Discord 要約の「費用」（手数料・諸費用のみ）—— 今回の走査語に一致せず、計画の列定義との突合が別に要る。残余として報告する。
- 入出金の両替の実績の供給経路（為替スプレッドの事後集計）—— 供給元が無い。未供給と描き続ける。
- ADR-0034 決定 3〜5（件数の下限・空売り 0 件の扱い・戦略の変更）の実装 —— 追認の追記だけを行う。
