# 仕様書: ADR 索引行の完全性（#886 / #895）

## 起点

- #886 — `.ai-context/adr/README.md` の **IADR-0327 の索引行から `［2026-09-11 追記 / #743］` が消えたまま
  develop に残っている**（索引行欠落の 3 件目・**未復元のものとしては唯一**）。
- #895 — #884 で入れた検査器（`scripts/check-adr-index-addendum-loss.js`）は**追記ブロックしか見ない**ため、
  索引行の中の**追記ブロックではない句**が衝突解決で置換・消失しても素通りする。

## 🔴 なぜこの 2 件を 1 本の PR に束ねたか（グルーピングの根拠）

- **対象の現物が同一**である。両方とも `.ai-context/adr/README.md` の**索引行**と
  `scripts/check-adr-index-addendum-loss.js` の**同じ 1 本の検査器**しか触らない。
- **束ねないほうが危ない。** #886 は「索引行を書き戻す」作業であり、#895 の候補 2（索引行も
  原文を残して追記を足す＝置換しない、という規約の明文化）は**同じ索引ファイルの運用ルール節**を触る。
  別 PR にすると、数千文字の索引行を持つ同一ファイルに対して**2 本の PR が順に衝突解決を要求する**
  —— それは #886・#895 が記録している事故そのものの形である（#886 本文が「PR #884 / PR #830 より後に
  行うこと。先にやると索引行で三つ巴の衝突になる」と明示的に警告している）。
- **#895 の候補 1（長さ検査）は #886 の復元を回帰データにできる。** 復元前の行（2,037 バイト）と
  復元後の行（2,473 バイト）は「非追記句・追記句が丸ごと落ちた行」の実物であり、
  新しい notice の固定データとして**同じ PR の中で**使える。
- 運用標準の「同型・低リスクの変更は 1 PR に束ねる（PR を刻まない）」（CLAUDE.md）にも合う。

**束ねなかったもの**: #887（テスト ID の採番）・#888（試験ハーネス）・#894（母集合の規則）。
いずれも索引行にも本検査器にも触らず、ファイル領域が交差しない。

## 母集合（規則 9・10 に従って自分で引いた・2026-09-23 / `origin/develop` = `03737bd3`）

🔴 **記憶で挙げず、誤りの側の文字列で走査した。**

### 走査 1 — 索引行から追記ブロックが消えている IADR（#886 の対象は本当に 1 件か）

```
$ node scripts/check-adr-index-addendum-loss.js --range=bdff6736..HEAD
```

`bdff6736`（消失の直前のコミット）を base に置いた**厳格モード**（2 ドット）で走らせ、
`bdff6736` 時点の全印が HEAD に在るかを見る。**是正前は IADR-0327 の 1 件だけが赤**であることを実測した
（出力は「実測」節）。IADR-0210 は `b6adebe3` で、IADR-0118 は PR #830 で復元済みであり、
**未復元は #886 の 1 件だけ**という issue の主張を自分で追試した。

### 走査 2 — 本体（`.ai-context/adr/IADR-0327_*.md`）に同じ追記が残っているか

```
$ grep -n "2026-09-11 追記" .ai-context/adr/IADR-0327_*.md
139:    - ［2026-09-11 追記 / [#743](https://github.com/endazon/ai-stock-trading/issues/743)］
```

**本体には残っている。** よって本作業は**索引行の側だけ**を本体へ合わせる（#886 の「本体にも無ければ
本体側も復元が要る」は該当しない）。

### 走査 3 — 索引行の長さが縮んだ行（#895 の候補 1 が何件鳴るか）

`origin/develop` と `bdff6736` の索引行をバイト長で突き合わせた。**IADR-0327 の 1 行だけが縮んでいる**
（2,473 → 2,037 バイト）。他の行はすべて同長または増加である。**つまり #895 の長さ検査は、
この母集合では偽陽性を 1 件も出さない**（それでも `notice` に留める。理由は下の設計）。

## 対象範囲

## 設計

### 1. IADR-0327 の索引行の復元（#886）

`git show bdff6736:.ai-context/adr/README.md` の当該行から、**逐語で**次のブロックを取り出し、
現在の行の `残余リスク: …〔発注しない経路のため別 issue〕` の直後へ**項目単位の和集合**で戻す。

- 🔴 **要約・言い換えをしない。文字単位の共通接頭辞で切らない**（それ自体が本件と同型の事故である）。
- 現在の行は追記ブロック**以外**は `bdff6736` 時点と完全一致しており（差分はブロック 1 個の有無のみ）、
  和集合＝**ブロックを末尾へ戻すこと**と等しい。これは復元後に
  「HEAD の行 == `bdff6736` の行」をバイト比較で確かめて固定する。
- 逃げ道（`[remove-adr-addendum]`）は**使わない**（消すのではなく戻すため）。

### 2. 索引行の「縮み」を `notice` で出す（#895 候補 1）

`check-adr-index-addendum-loss.js` へ、**赤にしない**観測を足す。

- 対象は**我々が触った行**だけ（既存の `touched` と同じ読み方＝ours 起点。規則 3 を緩めない）。
- 比較相手は **theirs（統合ブランチ）の同 ID の行**、theirs に無ければ base の行。
- 判定は**バイト長**（`Buffer.byteLength`）。`ours < 相手` なら `notice` を 1 行出す。
- 🔴 **`notice` であって `warn` でも `fail` でもない。** 要約の短縮は正当な編集としてありふれており、
  赤にすれば**検査そのものが外される**（この検査器が自分で 4/10 の偽陽性を作って学んだ結論）。
- 追記ブロックの消失（既存の規則 1・2）で**すでに赤になっている行は縮みを重ねて出さない**
  （同じ事故を 2 度報告しても読み手の手数が増えるだけである）。
- 縮んだ行が 1 件も無ければ**何も出さない**（無音を保つ）。

### 3. 「索引行も原文を残して追記を足す」を運用ルールへ明文化（#895 候補 2）

`.ai-context/adr/README.md` の「運用ルール」へ 1 項足す。**置換ではなく追記**であることを人に守らせ、
2 の長さ検査を「置換が現れやすい形」にする。**機械では中身の正しさを判定できない**ため、
規約（人）＋ notice（機械）の組で受ける。

### 4. 見送った候補と理由

| 候補 | 判断 |
| --- | --- |
| 「develop 側の全語が HEAD 側にある」ことを要求する | **採らない。** 要約の言い換え・短縮が軒並み赤になる（#895 本文の見立てと同じ） |
| 縮みを `warn` / `fail` にする | **採らない。** 上と同じ理由。**止めない**ことが肝である |
| 検査器を変えず残余リスクに書くだけ（#895 候補 3） | **採らない。** 同型が既に 3 件起きており、記録だけでは次を止められない |

## テスト方針

検査器の自己試験（`--self-test`）へ追加する。**正の確認と同数以上の否定形を置く**（既存の方針を踏襲）。

1. 🔴 実例の固定: IADR-0327 の索引行が 2,473 → 2,037 相当に縮むと `notice` が出る。
2. 縮んでいない（同長・伸びた）行では何も出さない。
3. 触っていない行は縮んでいても出さない（規則 3 を緩めていないことの固定）。
4. 追記ブロックの消失で赤になっている行は、縮みを重ねて出さない。
5. 縮みだけでは**終了コードを変えない**（exit 0）。
