# 仕様書: ADR 索引行の ID 重複を止める（#955）

## 起点

- #955。develop の `.ai-context/adr/README.md` に IADR-0354・IADR-0369 の索引行が 2 本ずつ並んでいた
  （PR #954 で是正。仕様書 `20260925_adr-index-duplicate-rows.md`）。並行 PR の取り込みで、
  両側が同じ行へ追記した衝突を行単位の和集合で解いたのが原因。
- `check-adr-index-addendum-loss` は追記の**消失**しか見ず、`check-adr-index-sync` は「触った IADR に
  索引行の変更があるか」しか見ないため、CI は緑のまま通した。
- さらに、重複を畳む正しい是正のほうが「消失」として赤になった（PR #954 は `[remove-adr-addendum]`
  宣言で通すと仕様書に書いたが、**スカッシュ後の develop のコミット本文には宣言が無い**。
  `node scripts/check-adr-index-addendum-loss.js --range=f703843..6dcc7b5` が本 PR の是正前に
  4 件の消失を報告して exit 1 になることを実測した）。

PR #954 の仕様書は「索引の二重行を畳むデータ是正」であり、検査器の変更は「射程外（別 issue）」と明記している。
本仕様はその別 issue であり、データは触らない（develop は既に重複 0）。

## どちらの検査器へ足すか

**`check-adr-index-addendum-loss.js` へ足す。** 理由:

- 同検査器は索引ファイルの**中身**を版ごとに読み、IADR 番号ごとに行を畳んでいる（`parseIndex`）。
  重複の判定は「ours の中身に同じ ID の行が何本あるか」であり、既存の読み取りの上に 1 規則で乗る。
- `check-adr-index-sync.js` は**差分に現れたファイル名と変更行**だけを見る設計で、索引ファイルの全体を
  読まない。重複は「衝突解決で行が増えた」ことで生じ、その PR が IADR 本文を触ったかとは無関係である
  （#954 の原因の取り込みは本文も触っていたが、取り込みだけで生じる形もある）。sync へ足すと
  「本文を触った PR でだけ重複を見る」ことになり、取り込みだけの重複を素通りさせる。
- 事故の族も同じである（衝突解決で索引行が壊れる）。#955 の後半（畳む是正を消失と数えない）は
  addendum-loss の比較単位の変更であり、同じファイルで扱うほうが一貫する。

## 決定（詳細と却下案は IADR-0400）

1. **規則 4（重複）**: ours（HEAD。手元では作業ツリー）の索引で、同じ IADR 番号の索引行が 2 本以上
   あれば赤。**状態の検査**であり、base・theirs は見ない。検査範囲を決められない場合（浅いクローン等）も
   作業ツリーの索引だけは読んで重複を検査する（範囲が要らないため）。逃げ道は用意しない
   （同じ ID の行を 2 本持つ正当な理由が無い）。
2. **比較単位**: 各 IADR 番号の印の数を「その ID の全行の合計」ではなく「**行ごとの出現回数の最大値**」で持つ。
   - 重複 2 行に 1 回ずつ在った印を 1 行へ畳む → 数 1 → 1。消失と数えない（#955 が求めたこと）。
   - 1 行に同じ印が 2 回あり 1 回消えた → 2 → 1。**従来どおり赤**（IADR-0363 決定 1 が多重集合を選んだ理由）。
   - issue の案「ID ごとの印の集合」を字義どおり採ると、上の 2 つ目が緑になり既存の自己試験
     （「同じ行に同じ印が 2 つあり 1 つ消えても赤」）を覆す。最大値なら両方を満たす。

3. **縮みの notice（IADR-0375）**: 比較相手に同じ ID の行が複数あれば、連結した長さではなく最も長い 1 行と比べる
   （連結と比べると畳む是正が必ず「縮んだ」と告げられる。`f703843..6dcc7b5` で 22215 → 11746 バイトの notice を実測）。

## 母集合（規則 9〜11 / 規則 6）

- 規則 9（誤りの側の文字列で走査）: 変更で誤りになる語は「多重集合」（合計で数える、の意）。
  `git grep -n "多重集合" -- ':!.ai-context/specs'` の結果 9 件:
  - `scripts/check-adr-index-addendum-loss.js` 4 箇所（冒頭注記 2・`parseIndex` の注記・自己試験 2 名）→ **直す**
    （冒頭注記と `parseIndex` の注記。自己試験名 2 件は「行ごとの多重集合」のまま意味が正しいので据え置く）。
  - `scripts/scripts.repo.test.js:2906`（`parseIndex は索引行ごとに印の多重集合を持つ`）→ 1 行内では多重集合のままで正しい。据え置き。
  - `scripts/README.md:31` →「印の単位の多重集合（行ごと）」は同 ID の複数行を合算する意味に読めるため**直す**。
  - `.ai-context/adr/IADR-0363_*.md`（3 箇所）→ **凍結記録。書き換えない**（IADR-0400 が部分的に改める）。
  - `.ai-context/adr/README.md:396`（IADR-0363 の索引行）→ **書き換えない**（索引行も原文を残す。IADR-0375）。

  - `backend/…/LlmUsageAggregatorTests.cs`・`frontend/…/RiskSettingsPage.tsx` → 無関係（別の突合）。除外。
- 規則 9（2 軸目・検査器名で走査）: `git grep -n "addendum-loss" -- docs .github AGENTS.md .claude` →
  `ci.yml` の 2 step のみ（配線は変えない）。`scripts/README.md` の表 2 行（31・191）。
  191 行（CI ジョブの説明）へ「索引行の ID 重複」を足す。
- 規則 10（自分の新しい記述）: `.ai-context/adr/README.md` の運用ルール（21〜28 行）は「機械検査は
  **追記ブロックの消失だけ**を赤にし」と書いており、本変更で**誤りになる**。原文を残し、重複も赤にする旨を
  追記として足す（書き換えない）。
- 規則 11（窓）: 該当しない（時間差を扱う是正ではない）。

## 検証

- 自己試験に足すケース: 重複行 → 赤／base にも重複があっても ours の重複は赤／重複を畳む是正 → 緑（宣言なし）／
  畳むときに片方の印を落とす → 赤のまま／索引行の外の同 ID 言及は重複に数えない／同じ行の同じ印の片方の消失 → 赤のまま（既存）。
- `scripts.repo.test.js`: `findDuplicateRows` の単体、実データ（f703843 の索引は重複で赤・
  f703843 → 6dcc7b5 の是正は宣言なしで緑）。履歴に無ければ skip を出力して抜ける（既存の形）。
- develop の現状で `check-adr-index-addendum-loss.js` と `check-adr-index-sync.js --range=origin/develop..HEAD` が OK。

## 射程外

- 索引行の昇順の検査（#954 仕様書が「昇順・重複 0」を人手で確かめた項目の前半）。事故は起きていない。
- `.ai-context/adr/` 本体・`docs/` の trace ブロック（IADR-0363 決定 5 のまま）。
