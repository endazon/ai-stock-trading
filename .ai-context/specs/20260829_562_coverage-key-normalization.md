# カバレッジ集計キーを cobertura の `<source>` 根で正規化する（#562）

## 背景と事象

`scripts/check-coverage.js` の `accumulate()` は cobertura の `class/@filename` を**生のまま集計キー**に
していた。coverlet が出す `filename` は**そのレポートの `<source>` 根からの相対パス**であり、根は
**テストプロジェクトごとに違う**。結果、**同一の実ファイルが別キーとして複数回数えられる**。

🔴 **皮肉なことに、`coverage-floor.json` の `$comment` は当初から
「集計は (ファイル, 行番号) の和集合で行う（複数テストプロジェクトの重複計上を避けるため）」と
宣言していた。** 意図は文書化されていたが、キーが揃っていないため**実装が意図に達していなかった**。

## 母集合の引き直し（規則 9・10）

**「集計キーを作っている箇所」と「キーを消費している箇所」の両方**を引いた。

| 走査 | 結果 |
| --- | --- |
| `acc` のキーを作る箇所 | `accumulate()` の 1 箇所のみ |
| `acc` のキーを消費する箇所 | `summarize()`（キーを見ない）／`applyExcludes()`（`normalizePath` して glob 照合）／`findShadowedPatterns()` |
| キーの形に依存する除外パターン | `**/Migrations/*.Designer.cs` ／ `**/Migrations/*ModelSnapshot.cs` |

**除外パターンは `**/` 始まりのため、キーが相対パスから絶対パスへ変わっても一致し続ける**
（`globToRegExp` の `**/` は 0 段以上のディレクトリに一致する）。`applyExcludes` は
受け取ったキーを再度 `normalizePath` するが、正規化は冪等なので二重適用は無害である。

**除外したもの**: `findWrongfullyExcluded()` は実ツリーを歩く関数でありカバレッジのキーを使わない。
`findSourceFiles` / `isAutoGenerated` も同様。よって本変更の射程外とした。

## 決めたこと

1. `<sources><source>…</source></sources>` を読み、`filename` が相対なら根と結合して
   **絶対パスを集計キーにする**（`resolveCoverageKey`）。
2. `filename` が既に絶対パスならそのまま使う（結合しない）。
3. **根が複数ある場合は実在する結合を優先**する。実在判定は差し替え可能にした
   —— ファイルシステムに触れずに肯定・否定の両方を固定できるようにするためである。
   どれも実在しなければ最初の根へ倒す（キーが未定義にならないこと）。
4. `<sources>` が無いレポートは従来どおり `filename` をキーにする（後方互換）。

## 🔴 検証手順そのものの落とし穴（本作業で踏んだ）

**`node scripts/scripts.repo.test.js` を直接叩くと、何も実行せずに exit 0 で返る。**
同ファイルは `module.exports = ({ ok, assert }) => {…}` の**モジュール**であり、
実行の入口は `scripts/scripts.test.js` である（同ファイル冒頭のコメントにそう書いてある）。

実際にこれで欺かれた —— **実装をわざと壊した状態で「テストが通る」という結果を得た。**
正しい入口（`node scripts/scripts.test.js`）で走らせて初めて変異が捕まった。
**「テストが緑」は、走らせたコマンドが本当にテストを走らせている場合にのみ意味を持つ。**

## 変異試験（検出力の実証）

| 変異 | 結果 |
| --- | --- |
| `resolveCoverageKey` を使わず `filename` を生でキーにする（＝是正前の挙動） | **exit 1**（和集合のテストが落ちる） |
| 根が 1 つのとき常に同じキーを返す（＝過剰併合） | **exit 1**（過剰併合の否定形が落ちる） |
| 無変異 | exit 0 |

**肯定形（畳むべきものを畳む）と否定形（畳んではいけないものを畳まない）の両方向で落ちる**ことを
確認した。片方だけでは「全部同じキーにする」壊れ方を検出できない。
