# 仕様書: 為替の情報源の状態を 3 経路へ可視化する（#381 第 2 層）

> 本仕様書は実装着手前に作成する。

## 起点

- 起点 issue: [#381](https://github.com/endazon/ai-stock-trading/issues/381)（**第 2 層**。第 1 層は [PR #507](https://github.com/endazon/ai-stock-trading/pull/507)・[IADR-0194](../adr/IADR-0194_boj-fx-rate-source-and-ordered-fallback.md) で完了）
- 起点 ID: **FR-10**（リスク統制）・**FR-17**／表示側は **FR-06**（報告）・**FR-09**（通知）・**FR-11**（監査）・**UC-06**
- 計画: ADR-0022（計画リポ） **決定2**（フォールバック中である旨を記録・通知する）・**決定5**（警告は日報・監査ログへ記録し Discord へ通知する）・**決定1**（日銀のクレジット表記）

## 課題 — 第 1 層は「気づく仕組み」を作ったが、宛先がログしかない

第 1 層で情報源は二段になり、鮮度の 3 段縮退も効くようになった。**しかし出力先はアプリケーションログだけである。**

```csharp
// FallbackFxRateSource.cs（第 1 層で書いた自分のコメント）
// **本 PR ではログのみであり、3 経路への配線は #381 の第 2 層（次 PR）で行う**
// ログに留まる間は、**切り替わった事実は運用者が能動的に見に行かないと分からない。**
```

計画は 3 回にわたり同じことを求めている。

| 計画 | 求めているもの |
| --- | --- |
| ADR-0022 **決定2** | フォールバックへ切り替わった事実**・切り替わっていた期間**を日報および監査ログへ記録し、Discord へ通知する。**黙って劣化させない** |
| ADR-0022 **決定5** | 警告（5 日超）を日報・監査ログへ記録し Discord へ通知する |
| ADR-0022 **決定1** | 日銀のデータ利用には**クレジット表記が必要**。報告書の為替欄に出典を明記する |

> 🔴 **「黙って劣化させない」は統制の要件であって、ログの要件ではない。**
> **能動的に見に行かないと分からないものは、黙っているのと区別がつかない。**

## 決定

### 決定1: **状態の遷移で発行する。呼び出しごとには発行しない**

為替レート源は **watchlist の銘柄ごと・巡回ごと**に呼ばれる。呼び出しのたびにイベントを出すと
**1 巡回で N 件**、巡回ごとに再発する。

**同型の事故は既に起きており、[IADR-0096](../adr/IADR-0096_notify-daily-policy-unconfirmed.md) 決定4 が営業日単位の重複抑止で解いている。**

本件は**そこからもう一歩進めて「遷移」で発行する。**

| 遷移 | イベント |
| --- | --- |
| 第一の源が使えている → **使えない** | `FxRateSourceFellBack` |
| 使えない → **回復した** | `FxRateSourcePrimaryRestored` |

> **遷移で発行すると、決定2 が求める「切り替わっていた期間」が自然に得られる。**
> 回復イベントが `FellBackAt` を持つため、**期間は受け手が引き算するのではなく、発行側が事実として渡す。**

**鮮度警告は遷移ではなく「状態」である**（数日continue する）。こちらは
**IADR-0096 と同じ営業日単位の抑止**とし、**日をまたげば再通知する**（気づくための警告であり、
1 度出して終わりでは役に立たない）。

### 決定2: **押す経路と引く経路を、サービスごとの既存の作りに合わせる**

**3 経路を 1 つの仕組みで実現しようとしない。**

| 宛先 | 経路 | 根拠 |
| --- | --- | --- |
| **監査ログ** | **push**（イベント購読） | `AuditService` は全イベントを購読する。`AuditConsumerCoverageTests` が**網羅を強制する** |
| **Discord** | **push**（イベント購読） | `NotificationService` の既存の作り |
| **日報** | **pull**（供給ポート） | `ReportService` は `I*Source` で**期間を指定して引く**（`IPeriodFillSource` 等）。イベントを購読していない |

**日報だけ経路が違うのは、報告書が「ある瞬間の通知」ではなく「期間の集計」だからである。**
無理に統一すると、ReportService にイベント永続化層を新設することになる（過剰）。

### 決定3: 🔴 **日報の供給不達を「切替なし」へ倒さない**

`IFxSourceStatusSource` は**取得不能のとき `null` を返す**。空列（＝発動なし）ではない。

**[IADR-0133](../adr/IADR-0133_maintenance-margin-auto-reduce.md) 決定7（`IMarginReductionRecordSource`）と同じ判断である。**

> **「照会できなかった」を「切替は無かった」と書くことは、劣化を隠したのと同じ結果になる。**
> **それは決定2 が禁じていることそのものである。**

描画側は `null` のとき「**照会できませんでした（要確認）**」と明記する。

### 決定4: **クレジット表記は情報源が持ち、報告書が引く**

`BojFxRateSource.Credit` を**唯一の情報源**とし、報告書はそれを引く。
**文字列を報告書側へ書き写さない** —— 写すと、利用条件が変わったときに片方だけ古くなる。

**日銀を実際に使ったときだけ出す。** FRED フォールバック中に日銀のクレジットを出すのは**事実に反する**。

## やること

1. `Shared.Contracts.Events` に **3 イベント**を追加する
2. `AuditService` に**監査ハンドラ 3 件**（`AuditConsumerCoverageTests` が強制する）
3. `NotificationService` に**書式と購読**（Discord）
4. `ReportService` に**供給ポート `IFxSourceStatusSource`** と**為替欄**（クレジット表記を含む）
5. 発行点: `FallbackFxRateSource`（遷移）・`CachingFxRateSource`（鮮度・日次抑止）

## やらないこと

- **鮮度の判定ロジックの変更** —— 第 1 層で確定済み（5 日 / 30 日）。本 PR は**宛先だけ**を広げる
- **[#506](https://github.com/endazon/ai-stock-trading/issues/506) の是正** —— 鮮度切れが手仕舞いも止める乖離は別 issue。**本 PR で触ると監査台帳の通貨誤りを招く**
- **報告書テンプレートの他の節** —— 為替欄のみ

## 受け入れ基準

- [x] 遷移でのみ発行される（**同一巡回で N 件出ない**ことをテストで固定）
- [x] 回復イベントが `FellBackAt` を持ち、**期間が受け手で計算できる**
- [x] 鮮度警告が**日をまたげば再通知される**（1 度で終わらない）
- [x] `AuditConsumerCoverageTests` が緑（＝ 3 イベントすべてに監査ハンドラがある）
- [x] Discord 書式に**劣化の内容**（どの源へ落ちたか・鮮度が週次へ悪化し得ること）が出る
- [x] **否定形**: 日報の供給不達が「切替なし」ではなく「照会できませんでした（要確認）」になる
- [x] **否定形**: **FRED フォールバック中に日銀のクレジットを出さない**
- [x] クレジット表記が `FxSourceCredits.Boj` **単一情報源**から来る（文字列を写していない）
- [x] **ミューテーションで効きを実測する**（🔴 **強い変異を当てる**。#507 で弱い変異が生き残った反省）

## テスト方針

| 何を守るか | どう守るか |
| --- | --- |
| 洪水を出さないこと | 同一状態で連続呼び出し → **発行 1 件**（否定形） |
| 期間が取れること | 落ちた → 回復 の順で `FellBackAt` が一致 |
| 監査の網羅 | `AuditConsumerCoverageTests`（**既存の強制機構に乗る**） |
| 供給不達の扱い | `null` → 「照会できませんでした」（否定形） |
| クレジットの単一情報源 | 日銀採用時のみ出る／**文字列リテラルが報告書側に無い**ことを検査 |

> **`AuditConsumerCoverageTests` に乗せるのが要点である。** 自分でテストを書くのではなく、
> **既にある強制機構の対象へ入れる**ほうが、次にイベントを足す人にも効く。

## 母集合（規則 6: 引いた結果と除外した理由を残す）

**引き方**: 「ログにしか出ていない FX の劣化」を**誤りの側から**引いた。

| 走査 | 結果 |
| --- | --- |
| `FallbackFxRateSource` の `LogWarning` | **3 箇所**（源が解決できない／フォールバック採用／全滅） |
| `CachingFxRateSource` の `LogWarning` | **2 箇所**（上限超で不採用／警告域） |
| `MarketFxRateProvider` の `LogInformation` | **1 箇所**（レート未解決） |

**イベント化する 3 箇所**（計画が名指ししているもの）:

- フォールバック採用（決定2）／回復（決定2 の「期間」）／警告域（決定5）

**除外した 3 箇所と理由**:

| 箇所 | 除外の理由 |
| --- | --- |
| 「源が解決できない・次を試す」 | **中間状態**である。次の源で解決すればフォールバック採用イベントが、全滅なら下の行が立つ。**ここを出すと、成功した巡回でも通知が飛ぶ** |
| 「全滅（どの源からも取れない）」 | **新規建てが止まる**という結果は既に `TradeDecisionService` 側の統制として扱われる。**本 PR の範囲は「劣化して continue している」ことの可視化**であり、停止の可視化は別軸（#506 と重なる） |
| 「上限超で不採用」 | 同上（停止側）。**[#506](https://github.com/endazon/ai-stock-trading/issues/506) が手仕舞いまで止める乖離を扱っており、そこで一緒に見るのが筋** |

> **除外した 3 箇所は「出さない」のではなく「本 PR では出さない」である。**
> 停止側の可視化は #506 の是正と同時に設計しないと、**同じ事象で 2 種類の通知が飛ぶ**。

## 変異試験（実走した実測）

**5 通りとも「変異が実際に適用されたこと」を diff で確認してから実行した。**

| # | 変異 | 落ちたテスト |
| ---: | --- | --- |
| 1 | 遷移判定を潰す（毎回発行＝洪水） | 「続いている間は再発行しない」 |
| 2 | 暦日の抑止を潰す | 「同じ日に 1 回だけ」ほか 2 件 |
| 3 | 監査ハンドラを 1 本消す | `AuditConsumerCoverageTests`（`FxRateStale` を名指し） |
| 4 | 報告書のクレジット出力を消す | 「日銀を使った期間はクレジット表記を出す」 |
| 5 | 照会不能を「劣化なし」へ潰す | 「切替なしとは書かず要確認と明記する」 |

### 🔴 変異試験の手順自体で 2 つ踏んだ

1. **当たらなかった変異は「生き残った変異」と見分けがつかない。**
   変異 4 は最初 exit 0 で「生き残った」——実際は**引用符の都合で置換が 1 件も一致していなかった**。
   **[#507](https://github.com/endazon/ai-stock-trading/pull/507) の「弱い変異」に続く同型である。**
   **是正**: 一致件数を検査し **0 なら中止**、適用後に **`git diff --numstat` で実変更を確認**する。
2. **`git checkout --` で変異を戻すと、同じファイルの未コミットの実装ごと消える。**
   実際に為替欄と監査ハンドラ 3 本を失い、やり直した。**変異試験の前に必ずコミットする。**
