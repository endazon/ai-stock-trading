## 範囲

1. **新規 `frontend/e2e/sc04-opend-auth.spec.ts`**（L1）。
2. **`opend-auth/state` の契約フィクスチャ**（オーケストレーターの指示で E-21 に含める）:
   - `backend/Bff/AiStockTrading.Bff.Endpoints.Tests/OpendAuthContractFixtureTests.cs`（新規）が BFF の
     `GET /bff/opend-auth/state` を既存の `OpendAuthTestHost` で叩き、`frontend/src/testing/contract-fixtures/opend-auth.state.json`
     を生成・突合する。csproj に `AiStockTrading.TestSupport.ContractFixtures` の参照を足す。
   - `frontend/src/features/sc04-opend-auth/types/contract.test.ts`（新規）が JSON を型 `OpendAuthStateView` へ代入する（`tsc` の突合）。
     `testing/` に置かないのは、`testing` 層から `features` を参照できないため（ADR-0067 決定 5。lint が止める）。
   - `frontend/e2e/fixtures.ts` の `OPEND_AUTH_STATE_WAITING` を、E-20 で置いた literal から本フィクスチャの読み込みへ替える。
3. **`frontend/e2e/harness/apiClient.ts`**: 400 / 409 の**解析済み本文を `ApiError` へ渡す**（platform の apiClient と同じ）。
   SC-04 はレート制限の 409 を本文（`reason` / `retryAfterSeconds`）で読み分けるため、渡さないと E2E だけが本番と違う文言を
   描き、A-064 を検証できない。SC-02 の 400 の扱いには影響しない（`details` は従来どおり）。

## 受け入れ基準（試験への写像）

| ID | 基準 | 試験 |
| --- | --- | --- |
| A-060 | owner で到達し、状態（接続・プロンプト・最終ログイン・デバイス信頼・egress・発注先）と送信履歴（供給が無い）を描く | 「到達と状態の表示」 |
| A-001 / A-060 | `trading-owner` を持たない利用者は NotFound で、`/bff/` を 1 件も呼ばない | 「権限外は NotFound」 |
| A-006 | paper 稼働中は警告バナーを出し、SIMULATE では出さない | 2 本 |
| A-061 | 入力を待っていない（idle）なら入力欄と送信が無効。待機中は 6 桁の数字が揃うまで送信が無効 | 2 本 |
| A-062 | 入力欄は 1 つ、ボタンは送信と再送だけ。送る本文はコードだけ。許可リストは 3 許可・2 送れない | 1 本 |
| A-063 | 「待機していない」と「取得できない（500）」「供給が無い（unavailable の宣言）」を描き分ける | 2 本 |
| A-064 | 再送・送信のレート制限（BFF の 409 `rate_limited`）を alert と残り秒数で表示し、自動で再試行しない | 2 本 |
| A-065 | 送った後に入力欄が空になり、画面のどこにもコード値が出ない（成功・失敗とも） | 2 本 |

- **A-064 の「429」は BFF の境界では 409 である**（#1456。上流の 429 を BFF が `{ reason: 'rate_limited', retryAfterSeconds }` の
  409 へ写す）。画面が受け取るのは 409 なので、試験も 409 で組む。網羅表の文言の訂正は PR 本文で親 #1410 へ渡す。
- **再送ボタンは idle でも押せる**（`disabled` は状態を読めないときと送信中だけ）。計画は「待機中でないときは入力欄と送信を無効」と
  定め、再送の可否は定めていない。本 issue は現状を固定も否定もしない（報告に書く）。

## 是正の母集合（規則 9）

- harness の変更で `ApiError.body` が入るようになる。`error.body` を読む画面: `grep -rn "\.body" frontend/src --include=*.tsx` で
  `VerificationCodeForm.tsx` の `rateLimitRetryAfterSeconds` だけ。既存 E2E は SC-04 を持たないため挙動の変わる試験は無い。
- `OPEND_AUTH_STATE_WAITING` の利用箇所: `defaultBff()` だけ。値は literal と同じ形（`lastLoginAt` は比較器の正規化値になる）。
