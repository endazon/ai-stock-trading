# 仕様書: SC-03 の強制買戻し発生回数の結線

> 本仕様書は実装着手前に作成する。

## 起点となる計画書（トレーサビリティ）

- 起点 issue: [#470](https://github.com/endazon/ai-stock-trading/issues/470)（[IADR-0181](../adr/IADR-0181_buy-in-inference-query-and-observation-arrival.md) 決定4 が名指しで約束した follow-up）
- 起点 ID: **FR-21** / **FR-10** / **SC-03** / **UC-06**（計画 ADR-0016 決定15）

計画 FR-21 は**両方向**に効く。

> **供給されている 0 が「取得できていません」と表示されない**（FR-21・05_screens §供給が無い値の表示規約）。
> **規約は両方向に効く** —— 未供給を 0 に見せないことと、**正当な 0 を未供給に見せない**ことの**両方**をテストで固定する

現時点では観測が 1 件も到達していないため表示は事実として正しい。**しかし観測が流れ始めた日に、
SC-03 は「正当な 0 を未供給に見せる」側の規約違反へ黙って転じる。** 供給が入った日は誰も画面を見直さない。

## 🔴 決めるべきこと: SC-03 の「期間」を計画が定めていない

FR-21 は「**報告期間**が覆われている場合に限り供給する」と定めるが、**SC-03 は報告書ではなく現況画面**であり、
**その期間を計画は明示していない**（05_screens の供給元の表も「報告期間がそれに覆われている場合に限り供給する」とだけ書く）。

**実装が期間を発明してはならない**（ADR-0027 が塞いだ「表示されている数字が何を意味するか誰も答えられない」状態と同型）。
そこで**計画から導出できる最も説明可能な読み**を採り、**同時に計画へ環流して裁定を仰ぐ**。

| 案 | 期間 | 評価 |
| --- | --- | --- |
| A | **当月（月初〜当日）** | **ADR-0016 決定15 は「発生回数」を月報（当月）に、「発生有無」を日報（当日）に割り当てている。** SC-03 の当該項目の名称は**発生回数**であり、決定15 の語彙にそのまま対応する |
| B | 当日 | SC-03 は当日損益を持つため画面の枠としては自然だが、決定15 で当日に割り当てられているのは**発生有無**であって回数ではない |
| C | 全期間 | 計画に定義が無い。**観測は OpenD 常駐の開始後にしか届かない**ため被覆が永久に成立せず、恒久 `NotSupplied` になる（本 issue の目的を満たさない） |

**案 A を採る。** 名称（発生回数）と決定15 の割り当てが一致する唯一の案である。

## 決定（[IADR-0186](../adr/IADR-0186_sc03-buy-in-count-supply.md)）

### 決定1: 期間は**当月（月初〜当日）**とし、被覆の判定は `ObservationCoverage.Covers` を使う

- **判定規則を再実装しない。** 照会 API（#469）と**同じ純関数**を通す —— 規則が 2 か所に分かれると必ず食い違う。
- **1 日でも欠ければ `NotSupplied`。** 部分的な観測を「覆っている」と扱うと、観測が止まっていた日の推定 0 件が
  正当な 0 として画面に出る（FR-21 の失敗モード 2）。

### 決定2: 被覆が成立したときに限り `Available` ＋ `CountInferredBetween` の件数を返す

- **被覆を見ずに件数だけを結線しない**（issue の禁止事項）。IADR-0162 決定2 が塞いだ fail-open が戻る。
- 被覆が成立していれば**推定 0 件でも `Available` かつ 0**（＝正当な 0）。これが本 issue の主目的である。

### 決定3: **他の指標の供給状態を条件に混ぜない**（IADR-0154 残余リスク4）

維持率・現在値・空売り比率の供給が入った日に、本項の可否が黙って変わってはならない。
本項の入力は**観測の到達と推定台帳だけ**である。

### 決定4: 結線は**必須依存**にする（省略可能引数にしない）

`IADR-0163` 決定2（`OrderScreeningService` の推定台帳）と同じ規律。省略可能にすると、
**配線を落としても既定値で緑のまま通る**（「緑だが検査されていない」）。構造テストで必須性を固定する。

### 決定5: SC-03 に操作を足さない（参照専用）

issue の禁止事項。BFF・フロントにも経路を足さない（`BffPassThroughTests` の網羅突合が既に守っている）。

## やらないこと

- **観測そのものを流すこと**（OpenD 常駐は A-1 / A-2 の範囲）。本作業は「届いたら供給する」経路のみ。
- **日報・月報側の変更**（#463 / IADR-0181 で結線済み）。
- **フロント（SC-03 画面）の変更**。サーバが `Available` を宣言すれば既存の表示規約がそのまま描く
  （IADR-0154 の「供給可否はサーバ側にしか置けない」）。
