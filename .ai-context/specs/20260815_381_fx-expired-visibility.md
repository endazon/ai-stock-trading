# 仕様書: 停止側の可視化（#381 の残り）

> 本仕様書は実装着手前に作成する。

## 起点

- 起点 issue: [#381](https://github.com/endazon/ai-stock-trading/issues/381)（**停止側の可視化＝残りの範囲**）
- 起点 ID: **FR-10**（統制）・**FR-11**（監査）・**FR-09**（通知）・**FR-06**（報告）・**UC-06**
- 計画: ADR-0022（計画リポ） **決定2**（黙って劣化させない）・**決定5**
- 前提: [IADR-0196](../adr/IADR-0196_fx-source-visibility.md)（警告域の 3 経路可視化）・[IADR-0197](../adr/IADR-0197_fx-stale-exit.md)（出口を開けた）

## 課題 — **出口は開いたが、通った記録が残っていない**

[PR #510](https://github.com/endazon/ai-stock-trading/pull/510) で鮮度切れ（30 日超）でも手仕舞いが出るようになった。
**しかし「古いレートで決済した」事実はどこにも永続化されていない。**

| 経路 | `Expired` で決済したことが残るか | 理由 |
| --- | --- | --- |
| 監査台帳（`ApprovedOrderRow`・**7 年保持**） | ❌ | `FxRateToBase`（数値）のみ。**観測日 `AsOf` の列が無い** |
| 監査イベント / Discord / 日報（IADR-0196） | ❌ | **`NotifyStaleAsync` は `Warning` 分岐でしか呼ばれない** |
| アプリケーションログ | ⚠️ | 出るが**7 年保持の対象外** |

> 🔴 **統制が「発動した」ことも、「劣化した値で取引した」ことも記録に残らない。**
> ADR-0022 決定2 の「**黙って劣化させない**」は、警告域だけの話ではない。

## 決定

### 決定1: **`FxRateStale` を停止側にも使う。イベントを増やさない**

`FxRateStale` に **`EntryBlocked`** を足し、**警告域と停止域の両方で発行する。**

**別イベントにしない理由**: **同じ「鮮度が閾値を超えた」事実**であり、
**別イベントにすると受け手が 2 つ購読することになり、抑止も 2 系統になる**
——**同じ事象で 2 種類の通知が飛ぶ**（#381 で繰り返し避けてきた形）。

> **後方互換の追加のみ許可**（IADR-0079・`EventBackwardCompatibilityTests`）。
> **フィールドの追加は許される。** 基準ファイルを更新する。

### 決定2: **抑止の鍵に「状態」を含める。昇格は同日でも知らせる**

現在の抑止は **(通貨, 暦日)**。ここへ**状態**を加えて **(通貨, 状態, 暦日)** にする。

**理由**: **警告 → 停止への昇格は、同じ日に起きても知らせる必要がある。**
状態を鍵に入れないと、**朝に警告を出した通貨が夕方に停止域へ落ちても黙る。**

**同じ状態が続く間は従来どおり 1 日 1 回**（洪水は防いだまま）。

### 決定3: 🔴 **「決済した」事実は別イベントで残す。レートの状態とは別の事実である**

`PositionClosedWithStaleFxRate` を新設し、**鮮度切れのレートで決済意図を作った瞬間**に発行する。

| イベント | 何の事実か | 抑止 |
| --- | --- | --- |
| `FxRateStale` | **レート源の状態**が閾値を超えた | (通貨, 状態, 暦日) で 1 回 |
| `PositionClosedWithStaleFxRate` | **その値で実際に取引した** | **抑止しない**（1 件ごとに残す） |

> **抑止しないのは、これが「状態」ではなく「取引」だからである。**
> **取引は 1 件ずつ台帳に残さなければ、後から件数も金額も復元できない。**

**これが「台帳から `AsOf` を復元できるようにする」の実現手段である** ——
**監査台帳はイベント全量を JSON で保存する**ため、`RateAsOf` を載せれば
**EF マイグレーションなしで観測日が 7 年保持へ入る。**

### 決定4: **`OrderIntent` は変えない**

`FxRateToBase` の隣へ `AsOf` を足す案（＝永続化の列追加）は**採らない**。
**[IADR-0197](../adr/IADR-0197_fx-stale-exit.md) 決定1 で案 A を退けたのと同じ理由**であり、
**決定3 のイベントで同じ情報が残る**ためである。

## やること

1. `FxRateStale` に `EntryBlocked` を足し、基準ファイルを更新する
2. `FxSourceStatusTracker` の抑止鍵へ状態を加える
3. `CachingFxRateSource` の `Expired` 分岐からも通知する
4. `PositionClosedWithStaleFxRate` を新設（監査ハンドラ・通知書式・識別子固定）
5. `TradeDecisionService` が鮮度切れの決済で発行する
6. 日報の為替欄へ**停止域と鮮度切れ決済**を出す

## やらないこと

- **`OrderIntent` / 永続化の変更**（決定4）
- **鮮度しきい値の変更**（計画で確定済み）
- **フォールバック側の変更**（IADR-0196 で完了）

## 受け入れ基準

- [ ] `Expired` で `FxRateStale` が発行され、**`EntryBlocked` が true** である
- [ ] **否定形**: 警告域では `EntryBlocked` が **false**
- [ ] **警告 → 停止の昇格は同じ日でも通知される**
- [ ] **否定形**: 同じ状態が続く間は 1 日 1 回（洪水を戻していない）
- [ ] 鮮度切れの決済で `PositionClosedWithStaleFxRate` が発行され、**`RateAsOf` を持つ**
- [ ] **否定形**: 鮮度が正常な決済では発行されない
- [ ] **否定形**: 新規建てが止まった場合は「決済した」イベントを出さない
- [ ] 監査要約に**「古いレートで決済した」ことと観測日**が出る
- [ ] Discord の書式が**警告と停止で読み分けられる**
- [ ] 日報の為替欄に停止域・鮮度切れ決済が出る
- [ ] `AuditConsumerCoverageTests` / `EventMessageTypeNameTests` が緑
- [ ] **変異試験で効きを実測する**（適用を diff で確認・`error CS` が 0 であることも確認）

## テスト方針

| 何を守るか | どう守るか |
| --- | --- |
| 停止側が見えること | `Expired` → 発行・`EntryBlocked=true` |
| 昇格が埋もれないこと | 同日に Warning → Expired → **2 件発行** |
| 洪水を戻していないこと（否定形） | 同状態の連続呼び出し → **1 件** |
| 取引の記録 | 鮮度切れ決済 → `RateAsOf` を持つイベント |
| 正常時に鳴らないこと（否定形） | 鮮度正常の決済 → **発行なし** |
| 入口の停止と混同しないこと（否定形） | 新規建てが止まった場合 → **発行なし** |
