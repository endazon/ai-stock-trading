# 仕様書: axe とキーボード経路を 4 画面に（#1414 / E-22）

> 本仕様書は実装着手前に作成した（AST `origin/develop` `e9d00da8`＝#1466 のマージ後）。初回の走査の結果は着手後に追記した。

## 起点（トレーサビリティ）

- 起点: #1414（親 #1410 の網羅表 A-010・A-011。設計の正本は MSP#2013 の E-22 行と基準書 §8）。
- 計画: **NFR-19**（WCAG 2.2 レベル AA。機械検査のタグ `wcag2a`・`wcag2aa`・`wcag21a`・`wcag21aa`・`wcag22aa`。planning#814 の裁定
  2026-10-21 / 2026-10-22。値は基盤 NFR-30 と同じ）。SC-01〜SC-04。planning `origin/main` で読んだ。
- 揃える相手: 基盤の E-10（MSP#2015・PR MSP#2183・IADR-0614）。タグ（5 つ＋`best-practice`）・指紋の台帳（一致を求める）・

## 範囲

- 新規 `frontend/e2e/a11y.spec.ts`。`frontend/package.json` に `@axe-core/playwright` `4.13.0`（基盤と同じ版・完全固定）。
- 走査面（A-010）: SC-01・SC-02・SC-03・SC-04、REAL 警告モーダルを開いた状態、監視銘柄の削除確認を開いた状態、取引ガードの危険な緩和の確認を開いた状態。
- キーボード経路（A-011）: REAL 警告モーダル（取消側への初期フォーカス・Esc で閉じて送らない・キーボードだけで確定）、監視銘柄の削除確認
  （開くと削除理由へ・取り消すと押した行へ・確定後は残る行へフォーカス）。

## 初回の走査（台帳に載せず、すべて直した）

| 面 | 規則 | 原因 | 直し方 |
| --- | --- | --- | --- |
| 4 画面 | `landmark-one-main`・`region`（best-practice） | **ハーネス**が `<main>` を持たず、画面の全内容がランドマークの外にあった。本番は基盤の共通シェルの `<main>` の中に描かれる | `e2e/harness/main.tsx` の Layout を `<nav aria-label>` ＋ `<main>` にした |
| 4 画面 | `target-size`（WCAG 2.5.8） | **ハーネスだけ**にある素のナビのリンク（当たり領域が 24 px 未満） | ハーネスのリンクに 24×24 px の当たり領域を与えた（本番のナビは基盤が描き、基盤の axe が測る） |
| SC-02 | `heading-order`（best-practice） | 高ボラティリティの区画で、`Panel` の `h2` の直下に `h4` があった（`h3` を飛ばす） | `HighVolatilityForm.tsx` の見出しを `h3` にした（文言・見た目は変わらない） |

キーボード経路で見つけた欠陥（axe では検出されない）:

- **監視銘柄の「削除」を押すとフォーカスが `<body>` へ落ちる**（WCAG 2.4.3 / 2.1.1）。行の「削除」は確認中に無効化されるため。
  `WatchlistForm.tsx` で、確認を開いたら削除理由へ、取り消したら押した行の「削除」へ、削除後に行が消えたら残る先頭の行へフォーカスを移す。

## L1 の射程の限界（埋めたことにしない）

- ハーネスは `@platform/ui` をスタブで描き、トークンの CSS を載せない。**色のコントラストはブラウザ既定の配色でしか測れず、テーマも無い**。
  本ユニットの画面の実配色は、基盤の SPA へ合成したときにしか測れない（基盤の E-10 は基盤の 22 画面だけを走査し、本ユニットの画面を含まない）。
- Dialog のスタブはフォーカストラップを写さない。トラップは実物（Base UI）の性質であり、本 spec では確かめない。
- 機械検査の 0 件は適合の証明ではない（NFR-19）。

## 是正の母集合（規則 9）

- `h4` の見出し: `grep -rn "<h4" frontend/src` で 2 件。`HighVolatilityForm.tsx`（`h2` の直下で `h3` を飛ばす。直した）と
  `ShortSellingStatusSection.tsx`（`h3` の下にあり順序どおり。SC-03 の axe は合格）。
- 「押すと自分が無効化される」ボタンでフォーカスを失う形: `disabled={pendingKey !== null}` 型の走査で `WatchlistForm.tsx` の行の「削除」だけ。
  REAL モーダルは Dialog が初期フォーカスを持ち、SC-02 の他フォームの保存ボタンは送信中だけ無効になる（送信後に有効へ戻り、
  フォーカスは要素に残る）ため対象外。
- ハーネスの `<main>` 追加: 既存 spec で `main` を引くものは `grep -rn "'main" frontend/e2e` で 0 件（影響なし）。

## 受け入れ基準

- 4 画面 ＋ REAL モーダル ＋ 削除確認（＋ガードの危険の確認）で違反 0（台帳 0 件）。タグは NFR-19 の 5 つ＋`best-practice` で走ったことを毎回確かめる。
- 変異: 3 つの是正（ハーネス・見出し・フォーカス）をそれぞれ戻すと赤になる。
