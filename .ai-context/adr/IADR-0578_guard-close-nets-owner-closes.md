# IADR-0578: ガードの成行手仕舞いは、利用者の手仕舞い・自動縮小を取り消さずに差し引く

> 実装リポジトリ内の意思決定記録（Implementation ADR）。1 ファイル = 1 意思決定。

- 状態: **Accepted**
- 日付: 2026-10-23
- 決定者: Claude Code（#1452 の求めに沿う実装の形。計画の規則は変えない）

## 起点・関連

- 起点: #1452（IADR-0577 の残余 2。親 #1423）。
- 計画: ADR-0050 決定 1（処理中の決済を差し引く）、決定 3（売れる数量を押さえるかは実弾解禁前の確認）。規則は変えない。
- 前提（覆さない）: IADR-0515 決定3（利用者・自動縮小の決済は猶予の内は取り消さない）・決定4（S1 は差し引く）、IADR-0577（ガードの取消の段）、
  IADR-0575（直列化・照会し直し）、IADR-0462 決定2（照会の成否の報告）。

## コンテキスト

1. IADR-0577 でガードの成行手仕舞いは取消の段（`DecisionCloseYield`）を通すようになったが、段は猶予の内の利用者・自動縮小の決済を取り消さない。
2. S1 はその残りを `NetOwnerClosesAsync` で差し引くが、ガードは差し引かず、建玉の照会値で全量を送っていた。
   未約定の売りを押さえない証券会社では利用者の指値と成行の両方が約定し得て、反対建玉になる。

## 決定

1. **S1 の差し引きを `Features/OrderExecution/OwnerCloseNetting.cs`（`OwnerCloseNetting.NetAsync`）へ移設し、S1 とガードが共通に呼ぶ**（`DecisionCloseYield` と同じ置き場所）。
   数える対象（非終端の Close の記録から保護逆指値レグを除き、証券会社が生きていると答えたものの残り）、猶予を見ないこと、照会の順（記録 → 注文照会 → 建玉照会）、
   結果（`NotApplicable` / `Applied` / `PositionsUnknown`）は IADR-0515 決定4 のまま変えない。
   建玉の照会だけを呼び出し側の関数にする（S1 は照会して成否を報告し、ガードは報告しない＝巡回の先頭の 1 回に留める IADR-0575 決定 3 の追記と同じ）。
2. **ガードは、取消の段（と `Changed` の後の照会し直し）の後・成行の予約の前に差し引きを通す。**
   - `NotApplicable` → 従来どおり（建玉照会も増えない）。
   - `PositionsUnknown` → **送らない。** 確実に未発注として人手対応（`ProtectiveStopRemediation.None`）。記録は Active。
   - `Applied` で送れる数量が 0 以下 → **送らない。** 記録は Active・保護喪失の通知なし・失敗に数えない（S1 の Deferred と同じ扱い）。
     利用者の決済が売り切れば次の巡回が建玉 0 を見て完了させ、約定しないまま猶予（2 分）を過ぎれば次の巡回の取消の段が取り消してから送る。
   - `Applied` で送れる数量が `min(数量, 照会値)` より小さい → その数量へ縮める。
3. **取り消さない。** 利用者の意思を尊重する IADR-0515 決定3 の規則をガードでも保つ。

## 検討した選択肢

| 案 | 採否 | 理由 |
| --- | --- | --- |
| (a) S1 の差し引きを共通化し、ガードも取り消さずに差し引く | **採用** | S1 と同じ物差し・同じ対象の見分けを 1 か所で持つ。利用者の意思を尊重する |
| (b) ガードは利用者・自動縮小の決済も取り消して全量を送る | 不採用 | IADR-0515 決定3 の規則が S1 とガードで分かれる。利用者の意思を覆す |
| (c) ガード用に同型の差し引きを書く | 不採用 | IADR-0577 (c) と同じ理由（2 か所に分かれ、片方だけ直す事故を招く） |

## 計画との関係（環流の要否）

- 規則は変えない（IADR-0515 決定4 をガードの経路にも及ぼす実装の詰め）。環流は不要と判断した。

## 結果

- 試験（`ProtectiveStopGuardTests`）: T-10-3022（猶予の内の利用者・自動縮小の決済 4 株を差し引いて 6 株を送り、合計が建玉を超えない）、
  T-10-3023（建玉をすべて覆えば送らない）、T-10-3024（差し引きの照会が不明なら送らず None）。T-10-3021 の利用者の決済の場合（全量を送る）は外した。
- 変異: 差し引きを外すと T-10-3022・T-10-3023 が赤、0 でも送ると T-10-3023 が赤、`PositionsUnknown` を無視すると T-10-3024 が赤（作業仕様書）。
  S1 の既存試験は無変更で緑（移設が挙動を変えない）。
- 平常時（利用者・自動縮小の決済が無い）は、処理中の決済の記録を 1 回読むだけで、注文照会・建玉照会は増えない。

## 残余リスク

1. **確かめられない（照会 null・例外）利用者の決済は数えない**（IADR-0515 決定4 と同じ。損切りを止めない側）。照会が一時的に落ちた巡回では重なり得る。
2. 差し引いた結果 0 で送らない巡回は、利用者の指値が約定しないまま猶予（2 分）を過ぎるまで続く（その間は無保護。通知はしない＝S1 と同じ）。
3. 保護喪失の成行手仕舞い（`CloseUnprotectedPositionAsync`）は対象外（IADR-0577 残余 3 と同じ）。
