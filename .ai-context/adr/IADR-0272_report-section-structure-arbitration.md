# IADR-0272: 報告書の節構造の食い違いは「欠落は機能追加・順序と統合は計画への環流」で併用し、月報・週報の並びは動かさない

## 起点・関連

- 関連する計画書 ID: FR-06（報告サイクル）、FR-07（報告書の階層管理）、FR-16（報告書テンプレート）
- 対象 Issue: [#612](https://github.com/endazon/ai-stock-trading/issues/612)
- 関連する実装仕様書: [20260902_612_report-section-structure-survey](../specs/20260902_612_report-section-structure-survey.md)
- 関連 IADR: [IADR-0269](IADR-0269_trade-history-wiring-and-record-based-supply.md)（決定5で「週報・月報の並びと番号は変更しない」と確定した先行決定。本 IADR はその決定を維持しつつ、#612 が新たに指摘した「節そのものが計画に無い／計画にあるが実装に無い」を扱う）

## コンテキストと課題

#612 は「月報の三者比較・OpenD 稼働率分布の節番号が計画と実装で逆転している」ことを事実として報告した。
着手時の指示に従い日報・週報・月報の全数を計画 `04_report-templates.md` と突合したところ（詳細は仕様書の全数突合表）、
実際の食い違いは #612 が報告した「順序の逆転」だけでなく、次の 3 種類に分かれることが分かった。

1. **順序の逆転／統合／分割**: 月報の三者比較（計画§5 vs 実装§6）・OpenD 稼働率分布（計画§6.2 vs 実装§5）、
   日報の市況・振り返り統合（IADR-0269 で既に決定済み）。**内容は出ており実害は無い**（#612 の記述どおり）。
2. **完全な欠落（計画にあり実装に無い）**: 週報の日別推移・ハイライト取引・リスク費用レビュー、
   月報の週別・市場別の内訳、月報の税金レビュー。**内容そのものが読み手に渡っていない**。
3. **実装のみの追加**: 為替レートの情報源・強制買戻し（推定）・散文生成に使用した LLM の各節。
   いずれも既存の別 IADR（IADR-0196／IADR-0159／IADR-0217）で決定済みであり、本 IADR の対象外。

この 3 種類を同じ結論（A/B/C いずれか単独）で扱うと、性質の異なる問題を同一の対応へ押し込めることになる。
「1. 順序」は既に IADR-0269 で「動かさない」と決めた対象であり、覆すコストに見合う便益が無い。
「2. 欠落」は #563（日報の取引履歴節が本番から一度も呼ばれていなかった）と同種の
「テンプレートは正しく定義されているのに出口に出ていない」状態であり、放置すると同じ事故の再発になる。

## 検討した選択肢

### 全体の対応方針

1. **A（実装を計画へ全面的に寄せる）を一律採用** — **採らない**。月報の順序を計画へ合わせるだけで
   `ReportRenderer.Labels()`・ゴールデン 6 本・関連仕様書の番号参照を全て動かす必要があり、
   IADR-0269 決定5 の判断（動かさないコストに見合わない）を覆す新しい理由が無い。
2. **B（計画へ環流し計画を実装へ合わせる）を一律採用** — **採らない**。週報・月報の欠落節（日別推移・
   ハイライト取引・週別市場別内訳）は**入力データが既に存在する**ため、計画側を「無いことにする」環流は
   実装の手抜きを計画の誤りにすり替えることになる。
3. **C（受容記録のみ）を一律採用** — **採らない**。欠落節を受容するだけでは、計画が要求する情報
   （週次の変動要因・月次の市場別成績）が読み手に永久に渡らない。
4. **性質ごとに A/B/C を使い分ける（採用）** — 下記「決定」のとおり。

### 欠落節の対応（A vs C）

1. **一括で C（受容）** — **採らない**。日別推移・ハイライト取引・週別市場別内訳は `PeriodTradeFill`
   （`Symbol`/`Market`/`Side`/`PositionEffect`/`ExecutedAt`）から算出できることを実装調査で確認済みであり、
   データが無いわけではない。
2. **一括で A（機能追加）** — **採らない**。月報の税金レビューは**年初来の累積**を求めるが、
   月間サマリの「年初来累計損益」自体が `（データ連携後）` のままであり、跨期間の累積を持つ権威源が
   システム全体に存在しない。口座区分（NISA/特定口座）・配当（外国税額控除の前提）も未実装であり、
   本 issue の範囲で機能追加 issue を起票しても着手できない。
3. **入力データの有無で個別判定する（採用）** — 下記「決定」のとおり。

## 決定

### 決定1: 順序の逆転・統合・分割は現状維持し、計画へ環流する

月報の三者比較（計画§5・実装§6）と OpenD 稼働率分布（計画§6.2・実装§5）の番号の食い違いは、
**内容が両方とも出ているため実害が無い**（#612 の記述と一致）。IADR-0269 決定5 の「週報・月報の並びと
番号は変更しない」を維持し、実装は変更しない。計画側へ「実装の出力順（三者比較→リスク統制→稼働率分布は
リスク統制の子節ではなく独立節）へ節番号を合わせる改定」を提案する feedback issue を起票する
（[#612](https://github.com/endazon/ai-stock-trading/issues/612) 案B）。日報の §5/§6 統合は IADR-0269 の
既存決定をそのまま維持し、再議論しない。

### 決定2: 入力データが揃っている欠落節は、実装側の機能追加 issue として起票する（issue 案A）

対象: 週報の**日別推移**・**ハイライト取引**、月報の**週別・市場別の内訳**（週別損益表・市場別内訳表・
建玉方向別内訳表）。これらは `PeriodTradeFill` の既存フィールドから算出可能であり、算出ロジックの新設のみが
不足している。実装しない理由（データが無い）が成立しないため、計画への環流ではなく実装側の機能追加として
別 issue を起票する。

### 決定3: 前提整備が必要な欠落節は、受容として記録し先送りする（issue 案C）

対象: 月報の**税金レビュー**（年初来課税対象実現益・源泉徴収税額・納税引当・NISA 枠消化状況・外国税額控除）。
年初来累積の権威源・口座区分の記録源・配当機能のいずれも存在しないため、単一 issue では着手できない。
本 IADR では「実装できない理由（前提整備の欠如）」を記録するに留め、前提整備そのものは範囲外とする。

週報の**リスク・費用レビュー**は複合的であり、費用の内訳・費用率（`PnlSummary` から算出可能）は決定2と
同じ扱い（機能追加 issue に含める）とする一方、**上限使用率（1注文/日次）** は算出元自体が存在しない
（日報 §4 の同項目も未実装であり、報告書サービス固有ではなくリスク管理サービス側の共通ギャップ）ため、
本 issue の範囲では見送り、事実の記録に留める。

### 決定4: 実装のみの追加節は本 IADR の対象外とする

為替レートの情報源（IADR-0196）・強制買戻し（推定）（IADR-0159）・散文生成に使用した LLM（IADR-0217）は
既存の別決定に基づく計画外の透明性向上であり、#612 の主題（計画との食い違い）ではない。是正の要否は
問わない。

## 理由

- 「順序」「欠落」「追加」は原因も対応も異なる。単一の案で一律処理すると、
  データが既にある欠落を「計画の誤り」に、データが無い欠落を「実装の手抜き」に、それぞれ誤って帰属させる。
- IADR-0269 決定5 が既に「動かさない」と決めた対象を、新しい理由（実害の有無に変化なし）無く覆さない。
- 欠落節をデータの有無で仕分けることで、着手可能な作業（決定2）と着手不能な作業（決定3）を issue の
  起票段階で区別でき、「blocked のまま止まる issue」を作らずに済む。

## 結果

- 良い影響: 週報・月報の欠落節のうち着手可能なものが機能追加 issue として顕在化する。着手不能なもの
  （税金レビュー）は「なぜ今は無理か」が記録され、次にこの領域へ触れる者が同じ調査をやり直さずに済む。
  順序の逆転は計画へ環流され、計画側の裁定を仰げる。
- 悪い影響・トレードオフ:
  - 3 種類の対応（issue 起票2件＋環流1件）に分かれるため、#612 は 1 つの PR では完結せず、
    後続 issue の完了までフォローが必要。
  - 上限使用率（日次発注上限/1注文上限の使用率）の欠如は、報告書サービス単体では解消できない
    （リスク管理サービス側の対応が要る）ため、機能追加 issue に含めず記録のみとした。
- フォローアップ:
  1. 決定2 の機能追加 issue（週報3節・月報1節）の実装。
  2. 決定1 の計画への環流 issue の裁定待ち。
  3. 決定3 の前提整備（年初来累積・口座区分・配当）の要否は、着手前に人間の裁定を要する。
  4. 損切り執行件数・発注拒否件数・上限使用率の期間集計（日報にも共通する欠如）は、別途棚卸しの対象とする。
