# IADR-0516: 監査台帳を引く報告書の入力をセッションの窓に揃える（#1224）

> 実装リポジトリ内の意思決定記録（Implementation ADR）。1 ファイル = 1 意思決定。
> 計画リポジトリの ADR（`ADR-XXXX`）とは別系統（`IADR-XXXX`）とし、実装に閉じた決定を記録する。

- 状態: **Accepted**
- 日付: 2026-10-08
- 決定者: Claude Code（実装）。計画 ADR-0053 決定 2（各報告書は前回の同種の報告書の生成の後から今回の生成までに閉場したセッションを集計する）と
  フォローアップ 3 の範囲の実装判断である。LLM 利用実績は現状（JST の暦日）を維持する。借株料の月次（ADR-0027 決定 3 の「月」）と LLM 費用の月・日が
  暦か報告書の窓かは **planning#746 の裁定待ち**である（§残余リスク）。本 IADR はどちらも計画の現行の記述に反しない形を採る。

- 作業仕様書: [`.ai-context/specs/20261008_1224_report-ledger-inputs-session-window.md`](../specs/20261008_1224_report-ledger-inputs-session-window.md)（実測・母集合・試験の表）
- 前提: [IADR-0492](./IADR-0492_report-session-window-by-market-close.md)（セッションの窓。本 IADR は同 §残余リスクの 1 行目を解消する）

## 背景

- IADR-0492 は約定・乖離の取り込み・稼働率を窓 `(ClosedAfter, ClosedUntil]`（前の営業日の生成境界の後〜期間の最終営業日の生成境界）で引くようにしたが、
  監査台帳（と強制買戻しの推定台帳）を期間の集計として引く入力は **JST の暦日 `[PeriodStart, PeriodEnd]`** のままだった。
- 日報 daily-D は D 16:00 JST に生成されるため、JST の暦日で引く記録のうち D 16:00〜24:00 のものは生成時点でまだ無く、daily-D+1 は JST D+1 だけを引く——
  **米国のセッション（ET D ＝ JST D 22:30〜D+1 05:00）の前半の記録はどの日報にも載らず**、後半は約定（daily-D+1）と同じ日報に載る。

## 決定

1. **記録は「報告可能になる瞬間」が窓に入る報告書に載せる。**
   - 市場を持つ記録: そのセッション（市場の現地取引日）の**大引け**と**記録の時刻**の遅いほう（`ReportSessionWindow.ReportableAt`）。
     セッション中・寄り付き前・閉場後の記録はそのセッションの約定と同じ報告書に載る（既定の構成では約定の `Includes` と同じ結果）。
     生成境界の後に記録されたもの（東証の夜の記録など）は次の報告書に載る（生成の時点でまだ無い記録を生成済みの報告書へ割り当てない）。
   - 市場を持たない記録: 記録の時刻（`ReportSessionWindow.Contains`）。
   - 窓は端で接し、報告可能になる瞬間は記録ごとに 1 つなので、**どの記録も同じ種別の報告書のちょうど 1 つに入る**。生成は `ClosedUntil` 以後なので、
     窓に入る記録は生成時点で台帳にある（記録の書き込みの遅れが無い限り）。週報・月報の窓は日報の窓の和である（IADR-0492 決定 1）。
2. **入力ごとの扱い**:

| 入力 | 扱い | 報告可能になる瞬間 / 理由 |
| --- | --- | --- |
| 借株料（計上 `BorrowFeeAccrued`・未計上 `BorrowFeeAccrualUnavailable`） | **窓** | 他の入力と同じく (市場, 記録の時刻 `AccruedAt` / `ObservedAt`)。🔴 **`TradingDay` は配置に使わない**——契約上は「計上の帰属日（基準タイムゾーン＝JST の取引日。リスク管理の `TradingDay.Of(instant)`）」であり、市場の現地の日として読むと共有契約の意味を変える（独立監査 🔴-1）。`AccruedAt` は計上を記録した時刻（`BorrowFeeAccrualService.Accrue` の `now`）。按分しない。計上日の「月」を暦の月と読むか報告書の窓の月と読むかは planning#746 の裁定待ち |
| 損切りの手法（承認時点 `OrderApproved`） | **窓** | (承認の市場, 承認時刻の現地取引日)。手法別の件数は残った承認から引き直す |
| 損切りの手法の解決（`StopLossMethodResolved`） | **承認に従う** | 承認と DecisionId で突き合わせる（解決の時刻では数えない。IADR-0429）。承認と同じ外包で引く |
| 強制買戻しの推定（`BuyInInferred`） | **窓** | (市場, 推定時刻の現地取引日) |
| 維持率割れの自動縮小（`MaintenanceMarginReductionExecuted`） | **窓** | 明細の市場ごとの瞬間の**最も早いもの**（1 回の執行を 2 つの報告書へ割らない）。明細が無ければ執行時刻 |
| 為替の情報源の状態（切替・復帰・鮮度警告・使用記録） | **窓** | 発生時刻（市場を持たない）。鮮度切れのレートでの決済（`PositionClosedWithStaleFxRate`）は市場を持つ約定なので市場の形。クレジットは残った記録から引き直す |
| LLM 利用実績（費用・フォールバック・取引判断スキップ） | **JST の暦日のまま** | 下記 |

   - **LLM 利用実績を窓に揃えない理由**: (1) 費用の集計であり市場を持たない。(2) 計画は月次 LLM 費用上限（15,000 円/月・暦の月）への**消費率**を月報に書くと定める
     （05_trading-assumptions §6.1・04_report-templates 月報 §7）。窓へ寄せると月報の「当月」が前月末の生成境界〜当月末の生成境界になり、上限の月と食い違う。
     (3) ADR-0053 決定 2 が窓の範囲で集計すると明記したのはセッションの損益と税金レビューであり、費用の月次は書いていない。現状維持は計画に反しない。
3. **照会の契約は変えない。** 供給元へは窓を覆う JST の暦日の外包 `ReportSessionWindow.JstLedgerRange`
   `[min(PeriodStart, 窓の照会範囲の始まり, ClosedAfter の JST 日付), max(PeriodEnd, ClosedUntil の JST 日付)]` を渡し、受け取った後に純関数
   `ReportLedgerWindowing.Within` で絞る（約定と同じ「外包で引いて絞る」形・IADR-0492 決定 3）。判断根拠の照会範囲も同じ関数から引く（値は従来と同じ）。
   - 強制買戻しの推定の観測の被覆（FR-21）は外包の全日で判定される。窓は外包の前日の夜（米国のセッション）を含むため、その日の観測を要するのは正しい。
     🔴 **これにより被覆には前の営業日の観測も要る**——観測を始めた最初の日報・月報（前の営業日の観測が無い）は強制買戻しの推定が「未供給」と出得る。
4. **損切りの月報 §6 の「日数」は、承認を数える日報の日付（JST）で数える**——承認の報告可能になる瞬間を窓に含む日報
   （`ReportSchedule.DailyReportDayOf`・`StopLossMethodApproval.ReportDay`・`StopLossMethodComparison.ReportDayOf`）。承認の JST 暦日では米国の
   1 セッションの承認が 2 日に割れ、市場の現地の日では ET と JST の日付が混ざる（独立監査 🟡-4）。例: 米国 ET 10-05 の承認（日報 10-06）と東証 JST 10-05 の承認
   （日報 10-05）は 2 日、米国 ET 10-05 と東証 JST 10-06 は同じ日報 10-06 なので 1 日。窓で絞っていない値（市場を持たない旧い明細）は JST 暦日。
5. **窓に揃えない入力は「集計したセッション」の行で明記する**（IADR-0492 決定 6 の行の末尾）。LLM 利用実績を使う種別（日報・月報）だけ:
   `集計したセッション: 米国 2026-10-05（ET）／東証 2026-10-06（JST）・LLM 利用実績は JST の暦日 2026-10-06（生成時点まで）`（日報は生成の時刻までの記録しか
   引けないため `（生成時点まで）` を付ける。月報は `2026-10-01〜2026-10-30`）。
   週報・窓を持たない経路（手動の生成 API）は書き足さない。散文には渡さない。

## 却下した案

- **約定と同じ `Includes`（記録の時刻の現地取引日が窓の取引日に入る）で絞る。** 東証の生成境界（16:00 JST）の後〜24:00 の記録は daily-D の取引日に属するが
  daily-D の生成時点ではまだ無く、daily-D+1 の取引日にも入らない——**どの日報にも載らない**（受け入れ基準 4 に反する）。報告可能になる瞬間で数えれば
  その記録は daily-D+1 に載る。セッション中の記録の扱いは同じである。
- **すべてを記録の時刻だけで窓に入れる（市場を見ない）。** 米国の寄り付き前（ET 00:00〜03:00 ＝ JST 13:00〜16:00）の承認・推定が、そのセッションの約定より
  1 つ前の日報に載る。市場を持つ記録は大引けで揃えるほうが約定と揃う。
- **LLM 利用実績も窓に揃える。** 日報のスキップ件数の欠落（生成後〜24:00 JST）は解消するが、月報の費用が暦の月の上限と食い違う（決定 2）。
  月次の費用を窓に揃えるかは計画の判断（費用の月の定義）に属するため、本 IADR では採らない（§残余リスク）。
- **供給元の照会を瞬間の範囲（窓そのもの）へ変える。** 契約・REST/gRPC の両実装・試験の偽物の追随が要り、得るものが無い（外包で引いて絞れば足りる）。

## 結果

- 良い影響: 米国のセッションの借株料・損切りの手法とその解決・強制買戻しの推定・自動縮小・為替の状態が、その約定と同じ日報・週報・月報に**ちょうど 1 回**載る。
  東証のセッション中の記録は従来どおり同じ日付の日報に載る。生成境界の後の記録（従来はどの日報にも載らなかった）は次の日報に載る。
- 悪い影響 / トレードオフ:
  - 月曜の日報は金曜〜日曜（ET）の記録（週末に記録された借株料を含む）を数える。週報・月報の最終営業日の米国セッションの記録は次の週報・月報に入る（約定と同じ）。
  - 東証の生成境界の後〜24:00 の為替の状態・承認ほかの記録は、従来の暦日の照会（作り直せば載った）と違い翌日報に載る。
- 残余リスク:
  - **LLM 利用実績の JST の暦日の集計は既存の欠落を残す**: 日報は生成（16:00 JST）の後〜24:00 の記録（米国のセッション前半の取引判断スキップを含む）を
    どの日報にも載せず、月報は最終営業日の生成の後〜月末の記録を含まない。費用統制サービスの月次カウンタは UTC の暦の月（`CostControlAppService.MonthKey`）で、
    月報の JST の暦日とも一致しない。**計画の裁定の候補**: 「月報 §7 の LLM 利用実績（費用・消費率）と日報のスキップ件数は、暦の月・日で集計するか、
    セッションの窓で集計するか。暦で集計するなら、生成後〜期末の記録をどの報告書に載せるか」——**planning#746 として起票済み（裁定待ち）**。
    同じ issue が借株料の月次合計の「月」（ADR-0027 決定 3）を暦か窓かも問う。裁定が窓なら LLM 利用実績も本 IADR の決定 1 の形へ、暦なら借株料の月報の合計の
    集計を改める（本 IADR の改定または新 IADR）。
  - 本文を復元できなかった承認の記録の数（`StopLossMethodUsage.UnreadableCount`）は、台帳の記録（`AuditLedgerEntry`）が記録時刻を運ばないため絞れず、
    外包の範囲で数える（隣り合う報告書の両方に出得る。独立監査 🟡-1）。記録時刻を運ぶ是正は #1255。
    - ［2026-10-08 追記・#1255］**本項は解消した（残余から外す）。** 台帳の記録（`AuditLedgerEntry`）は台帳の記録時刻 `OccurredAt`（照会の期間を絞るのと同じ時刻）を
      運ぶ——REST は応答の `occurredAt` を読み（契約の変更なし）、gRPC は `LedgerRecord` に `optional string occurred_at = 4`（往復書式・フィールド追加＝非破壊）を足した。
      本文を復元できなかった承認の記録は、本文が読めず市場が分からないため**市場を持たない記録と同じく記録時刻**（`ReportSessionWindow.Contains`）で数え、
      同じ種別の報告書のちょうど 1 つに入る（月報は日報の和。`StopLossMethodUsage.UnreadableOccurredAt`）。記録時刻を欠く応答（旧版の台帳）の記録は従来どおり外包の範囲で数え
      （黙って 0 件にしない）、gRPC の `occurred_at` が在るのに読めない値は id と同じく応答全体を未供給にする（原則 A・IADR-0445 決定 3）。
      損切りの手法の解決の復元できなかった数（`StopLossMethodResolutionFeed.UnreadableCount`）は決定 2 のとおり窓で絞らない入力のまま。
      試験 T-06-073〜T-06-076。作業仕様書 [`.ai-context/specs/20261008_1255_ledger-entry-occurred-at.md`](../specs/20261008_1255_ledger-entry-occurred-at.md)。
  - 記録の書き込みが生成より遅れた場合（報告可能になる瞬間は窓の中だが、生成の時点で台帳に無い）は載らない。作り直しで拾える。
  - 借株料の計上・自動縮小の発火元は未結線（呼び出し元が無い・既定は空列）。結線時に記録の時刻（`AccruedAt`・`ExecutedAt`）を実時刻で書くこと。
    借株料は記録の時刻で配置するため、計上の処理を走らせる時刻（例: 米国の閉場後か、JST の深夜の一括か）がどの日報に載るかを決める。
  - 約定・乖離の取り込みは IADR-0492 の `Includes`（現地取引日）のまま。既定の構成では本 IADR の瞬間と同じ結果だが、米国の時間外（16:00〜20:00 ET）の約定は
    生成境界が ET 16:00〜20:00 に入る構成でだけ食い違い得る。
