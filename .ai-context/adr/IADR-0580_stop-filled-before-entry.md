# IADR-0580: 保護逆指値がエントリーより先に約定したときのガードと検知

> 実装リポジトリ内の意思決定記録（Implementation ADR）。1 ファイル = 1 意思決定。

- 状態: **Accepted**
- 日付: 2026-10-23
- 決定者: Claude Code（#1454 の推奨 1・2 のうち、記録の扱いと照会できない場合の扱いを本 IADR で決める、と issue が委ねた点）

## 起点・関連

- 起点: #1454（親 #1423「試験の穴 3」。現行の挙動は T-10-3025・T-10-3026 が固定していた）。

  業務フロー 02 §損切りの実行機構（二重決済で残る注文が反対方向の建玉を生む）。
- 前提（覆さない）: [IADR-0428](./IADR-0428_protective-leg-indeterminate-hold-and-reconciled-entry-protection.md)（2026-09-26 追記。建玉 0 を消滅と読む前にエントリーを見る。`ObserveEntryAsync`）、
  [IADR-0344](./IADR-0344_s1-software-stop-loss.md) 追記(9)・[IADR-0412](./IADR-0412_unattributed-position-detection-on-position-snapshot.md)（帰属不明の検知。検知であって是正ではない）、
  [IADR-0576](./IADR-0576_close-gate-positions-field-and-guard-cancel-confirm.md) 決定 3（完了は最新の行が同じレグのときだけ）。
- 範囲外: issue の推奨 3（エントリーと逆指値を同時に置かない）は ADR-0040 の射程。自動の買い戻し・エントリーの取消も本 IADR は決めない。

## コンテキスト

1. S0 / S3 は承認数量の保護逆指値を、未約定のエントリー（指値）と同時に板へ置く。窓開けでは逆指値が先に約定し、建玉 0 からの決済＝
   反対方向の建玉（買いのエントリーなら売り建玉）が生じ得る。
2. develop `6c5369a8` のガード（`ProtectiveStopGuard.EvaluateAsync`）は、逆指値の `Filled` をエントリーの状態も建玉の符号も見ずに
   「損切りの成立」と読み、記録を完了させていた。エントリーが約定しないまま終わると売り建玉が残り、完了した記録はガードの巡回に載らない。
3. 帰属不明の検知（`ProtectiveStopNetting.DetectUnattributedPositions`）は「S1 の足跡が無い群には触れない」ため、S0 だけの銘柄の売り建玉を拾わなかった。
   検知の通知済みの印（`UnattributedNotifiedQuantity` / `UnattributedNotifiedAt`）は S1 の行だけが持ち、印の読み戻しは行のエントリー方向の群で行っていた。
4. エントリーの状態は既存の `ObserveEntryAsync` が分類する（終端の発注記録はそのまま使い、非終端なら証券会社へ照会する）。
   平常の損切り（エントリーは全量約定済みで記録も終端）では照会は増えない。

## 検討した選択肢（記録の扱い）

| 判断材料 | A. Active のまま据え置き、エントリーの終端で完了（採用） | B. 完了させ、事実を 1 回だけ出す |
| --- | --- | --- |
| 繰り返しの通知 | 既存の据え置きと同じ記憶（`HeldCloseNotificationTracker`）で 1 時間ごと。巡回ごとには重ねない | 1 回きり。見逃すと、エントリーの結末（全量約定で 0 に戻るか、失効で売り建玉が残るか）を誰も見ない |
| エントリーの結末の観測 | ガードが巡回のたびに照会し、終端を見た巡回で完了する | 誰も見ない（検知が残った売り建玉を拾うだけ） |
| 既存の状態との整合 | 「有効・エントリー未約定・建玉 0」の記録は #1013 で既に存在する状態（T-10-1120）。ガード・突き合わせの扱いが決まっている | — |
| 新しい状態・列・Migration | 要らない | 要らない |

**A を採る。** 新しい状態を足さない（既存の Active の据え置きの形に揃える）。

## 決定

### 決定 1: 逆指値の `Filled` を見たら、記録を完了させる前にエントリーの状態を見る

`HoldIfStopFilledBeforeEntryAsync`。反対方向の純額は巡回の建玉照会（スナップショット）から決済の方向で引く。

| エントリー | 反対方向の純額 | 扱い |
| --- | --- | --- |
| 生きている（未約定・一部約定） | 問わない | **Active のまま据え置く**（`Outcome.StillActive`）。取消・成行・張り直しを送らない |
| 分からない（記録が無い・注文 ID が空・照会が null／例外） | 見えている | 同上（`Outcome.Unknown`）。**分からないを「終わった」と読まない** |
| 分からない | 見えない | 従来どおり完了（通常の損切りの成立と区別が付かない）。Warning を残す |
| 終端（全量約定・取消・失効・拒否） | 問わない | 従来どおり完了。反対方向の純額が見えていれば Error を残す（事実は決定 2 の検知が出す） |

- 据え置くときは、このプロセスで未通知、または前回から 1 時間（`HeldCloseNotificationTracker.RenotifyInterval`）のときだけ
  Error ログと `ProtectiveStopCoverageLost`（Remediation=**`StopFilledBeforeEntry`**・列挙の末尾・序数 9）を出す。他の巡回は Warning だけ。
  記憶のキーは約定した逆指値レグの `StopDecisionId`（据え置きの他の通知と同じ表。記録の完了で `ForgetEntry` が捨てる。
  発行に失敗したら `PublishAllAsync` が捨てる）。
- 事実の `CloseDecisionId` は約定した逆指値レグ（相関のため）、`CloseIntent` は null（何も送っていない。台帳は何もしない）、`Cause` は専用の **`FilledBeforeEntry`**（`ProtectiveStopLossCause` の末尾・序数 2）。失効を表す `LapsedInFlight` を借りると、集計・表示で「失効した」と取り違える（PR #1458 の AI レビュー 🟡。原因の列挙の消費者は通知の `RejectedAtEntry` との二択と監査の要約の名前の表示だけで、追加の網羅は要らない）。
  `Quantity` は逆指値の約定数量（0 なら記録の数量）。通知は Critical、監査の要約は「逆指値がエントリーより先に約定（反対方向の建玉の可能性）」と書く。
- 約定追跡の起点（`RenewStopLegTracking`）は据え置く場合も先に進める（逆指値レグの約定が台帳へ届く）。

### 決定 2: 帰属不明の検知は、逆方向の S0 の記録がある群を除外しない

- 群（銘柄・市場・方向）に S1 の足跡（有効・完了・印）が無いとき、**その方向と逆の方向をエントリーとする S0 / S3 の記録**
  （有効な行と `FindRecentFor` の上限 50 件。状態を問わない）があれば、それを代表の候補にして検知する。無ければ従来どおり触れない。
- 通知済みの印の読み戻しは**印が指す方向の群**へ対応させる（`WatchedSide`: S1 の行はエントリー方向＝従来どおり、S0 の行は決済の方向）。
  S0 の行が印を持つのはこの経路で代表になったときだけであり、既存のデータ（S1 の行だけが印を持つ）の扱いは変わらない。
- 差し引き（その方向の有効な行の主張・帳簿に現れない株数・確定前の見込み）は従来の式のまま。S1 の足跡がある群は候補を変えない（S0 の行を代表にしない）。
- 呼び出し元の 2 経路（常駐ガード・建玉観測の常駐）とも同じ関数なので、記録の完了後も建玉観測の常駐が 1 時間ごとに知らせ続ける。

## 結果

- 窓開けで逆指値が先に約定した売り建玉は、エントリーが生きているあいだはガードが（Critical・1 時間ごと）、エントリーが終わった後は
  検知が（Warning・1 時間ごと）知らせる。**無通知で残らない。**
- T-10-3025・T-10-3026 の期待を是正後の挙動へ書き換えた。新しい試験は T-10-3027〜T-10-3034。

## 残余リスク

1. **売り建玉は自動では解消しない**（買い戻し・エントリーの取消は別途の判断。計画への環流の候補）。
2. 据え置くあいだ、記録は承認数量を主張し続ける（#1013 の未約定の据え置きと同じ）。同じ銘柄の別の手法の判定に影響し得る。
3. 据え置きの事実と帰属不明の建玉の事実は別の通知として両方出る（どちらも 1 時間ごと）。
4. 逆方向の S0 の記録がある銘柄では、手動・他の実行機構の反対方向の建玉も帰属不明として知らせる（黙るより知らせる側）。
5. 反対方向の純額はスナップショットの値であり、照会の遅れで 0 に見えると「分からない・見えない」の行で完了する（以後は検知が拾う）。
6. 実弾での発火順は未確認（現物口座では保有 0 からの売りの逆指値は拒否される見込み）。台帳が「建玉 0 への決済の約定」をどう扱うかは本 IADR では確かめていない。
