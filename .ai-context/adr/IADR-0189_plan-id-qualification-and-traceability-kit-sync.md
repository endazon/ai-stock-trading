# IADR-0189: 計画 ID 修飾の検査器を kit から取り込み、修飾の表記を一貫させる

> 実装リポジトリ内の意思決定記録（Implementation ADR）。1 ファイル = 1 意思決定。

- 状態: Accepted
- 日付: 2026-08-14
- 決定者: Claude Code（[IADR-0047](IADR-0047_kit-template-sync-policy.md) 決定1「kit 追随を原則とする」の適用）

## 起点・関連

- 計画書 ID: **NFR**（運用保守。工程の統制であり計画側の非機能要件表に当たる番号が無いため無採番。planning#311 の 2 に該当）
- 対象 Issue: [#477](https://github.com/endazon/ai-stock-trading/issues/477) の**残り 3 項目**
- 作業仕様書: [20260814_477_plan-id-qualification-kit-sync](../specs/20260814_477_plan-id-qualification-kit-sync.md)
- 先行: [IADR-0188](IADR-0188_feedback-vocabulary-and-dispatch-kit-sync.md)（環流語彙の項。PR #486）

## コンテキストと課題

#477 が挙げる残り 3 項目を実測したところ、**難易度がまったく違った**。

| # | 項目 | 実測 |
| --- | --- | --- |
| 1 | `traceability.md` の companion 機構 | **本リポ固有の内容は 0 件**。差分 3 行はすべて kit の旧版 |
| 2 | `check-plan-id-qualification.js` 新設 | **未導入。** 依存する `check-cross-repo-refs.js` も未導入。**違反 46 件** |
| 3 | `claude-code-review.yml` の `reopened` | **導入済み**（IADR-0185 決定3。kit は planning#313 と、**別経路で同じ結論**） |

### 1: companion は不要であった

kit の companion 機構は「配布物を直接編集せず、固有規約は `traceability.repo.md` へ書く」というものである。
**本リポの差分に固有の追加は 1 行も無く**、次の 3 行がいずれも**kit の旧版**であった。

| 本リポ（旧） | kit（新） |
| --- | --- |
| `NFR`: 非機能要件 | `NFR-xx` の個別 ID 参照と、無採番を許す 2 例外（planning#311） |
| 起点 ID の書式に `NFR` | `NFR-\d+`（計画側が ID 列を持たない場合に限り `NFR`） |
| bot 除外を `user.type == 'Bot'` で行う | **スクリプト側の `BOT_AUTHORS` 完全一致**（planning#202。GitHub App の PR まで除外され「最後の砦」が skipped になる） |

> 🔴 **3 行目は文面だけの差分ではなく、実装の欠陥であった。**
>
> **本 ADR の初版は「本リポの `pr-title.yml` は既にスクリプト側で除外しているため挙動は正しく、
> 文面だけが誤っていた」と書いたが、これは誤りである**（AI レビューの指摘を受けて実測し確認した）。
> 実際には `pr-title.yml:37` が `if: github.event.pull_request.user.type != 'Bot'` のままであり、
> `check-commit-messages.js` に `PR_AUTHOR` も `isBotLogin()` も**存在しなかった**。
>
> **つまり planning#202 が警告する事故（`claude[bot]` 等の PR で PR タイトル検査が skipped になる）は
> 本リポで実在していた。** しかも kit の規約を取り込んだことで、**規約と実装が食い違う状態**を
> 新たに作っていた。**決定7 で実装する。**

### 2: 検査器は 2 本セットで、修飾の表記が割れていた

`check-plan-id-qualification.js` は **`check-cross-repo-refs.js` を実行時に `require` する**
（`maskCode` を借りている）。**片方だけ入れると動かない。**

置換点 `PROJECT_PREFIXES` の実測:

| 設定 | 違反 |
| --- | ---: |
| `MSP` のみ | 1 |
| **`MSP,AST`** | **46** |

**本リポは `AST/` を自プロジェクトの修飾として実際に使っており**（`AST/FR-17` 24 件ほか）、
**同じ文書内で `/` と空白が混在していた。**

## 決定

### 決定1: `traceability.md` は kit 版をバイト一致で取り込み、companion は作らない

固有の内容が 0 件であることを実測したため**失うものが無い**。
kit 自身が「companion が無くても壊れない。未作成なら固有規約が無いだけ」と定めている。

> `check-commit-messages.js` は既に `NFR(?:-\w+)?` を受理するため、書式の更新に伴う変更は不要であった（実測）。

### 決定2: 検査器 2 本をバイト一致で取り込み、置換点は**環境変数で与える**

kit は「配布時に置換点を書き換えること」と書くが、**両スクリプトとも環境変数での上書きに対応している**。
**環境変数を使えばファイルをバイト一致のまま保てる**ため、次の kit 更新がそのまま届く（IADR-0047 決定1 の趣旨）。

### 決定3: `PROJECT_PREFIXES` に **`AST` も含める**

kit の定義は「**他**プロジェクトの短縮名」であり、字面どおりなら `MSP` だけである。
しかし**本リポは `AST/` を修飾として実際に使っている**（複数プロジェクトの ID が同じ文書に並ぶため）。

**修飾を使うと決めた以上、その表記は一貫していなければ機械的突合の役に立たない。**
`/` と空白が混在する状態は、修飾を導入した目的（誤帰属の防止）を損なう。**46 件を揃えた。**

### 決定4: `check-cross-repo-refs.js` は**入れるが CI へは配線しない**

**依存として必要**（決定2）だが、**実ツリーには 269 件の違反がある**（実測）。

| 型 | 件数 |
| --- | ---: |
| 長い表記 | 213 |
| 空白区切りの修飾 | 44 |
| 列挙形の修飾漏れ | 12 |

**これは追随ではなく規約の決定である。** 本リポの規約は
「**短縮形とフルパス形式のどちらに寄せるかを最初に決め、混在させない**」と書くが、
**本リポはその決定をしていない** —— 分布は `project-planning#N` 288 件 / `planning#N` 241 件で拮抗する。

さらに違反の **24 件は `feedback/`、244 件は `docs/`** にあり、多くが
**作業仕様書・環流記録＝point-in-time の記録**である。kit 自身が
「後から表記だけ直すと当時の記述と食い違う」として姉妹検査器では除外している。

**よって配線しない。規約の決定と母集合の引き方を含めて別 issue（[#487](https://github.com/endazon/ai-stock-trading/issues/487)）とする。**
**配線しないことを本 ADR に残す** —— 黙って入れないと「入れ忘れ」と区別がつかない。

### 決定5: `claude-code-review.yml` は変更しない

条件は既に満たしている。kit のコメントを取り込むと**本リポ固有のセットアップ手順を落とす**ことになり、
#391 で塞いだ穴（許可だけ足してセットアップを入れず「実行したが失敗した」と報告される形）が戻る。

### 決定6: 回帰テストは**環境変数を自前で与える**

CI ジョブは `PLAN_ID_PREFIXES` を渡すが、**その環境変数を落とすと `PROJECT_PREFIXES` が空になり
検査は skip して緑になる**（fail-open。「他プロジェクトを参照しないリポジトリ」のための正常な挙動）。

**回帰テストは環境変数を自前で明示的に与える**ため、CI 側の設定を落としても別経路で赤くなる。

### 決定7: `pr-title.yml` の bot 除外を**スクリプト側へ移す**（規約と実装の食い違いを解消する）

規約を取り込んだ以上、**実装をそれに合わせる**。文面を実装に合わせて緩めるのではない ——
planning#202 が実測した事故は本リポでも実在しており、**本リポの主要な経路（AI が PR を作る）でだけ
「最後の砦」が抜けていた**からである。

| | 変更前 | 変更後 |
| --- | --- | --- |
| 判定の場所 | ワークフローの `if: user.type != 'Bot'` | **スクリプト（`isBotLogin()`）** |
| 判定の対象 | PR 作成者の**種別** | PR 作成者の**ログイン名**（`PR_AUTHOR`） |
| 照合 | —— | **`BOT_AUTHORS` への完全一致** |
| `claude[bot]` の PR | **skipped**（検査されない） | **検査される** |

- **完全一致にする。** コミット著者向けの `isBot()` は「著者名＋メール」への**部分一致**だが、
  PR 作成者は単一のログイン名で得られるため、部分一致にすると `not-dependabot-really` のような
  無関係なログイン名まで除外され得る。
- **`PR_AUTHOR` が空なら bot 扱いしない**（fail-closed 側へ倒す）。イベント外での実行や
  設定漏れで検査が黙って無効になることを避ける。

> **これは [`docs/specs/20260716_129_ci-gates-pr-title-helm.md`](../specs/20260716_129_ci-gates-pr-title-helm.md)
> がワークフローレベルの判定を「意図した設計」として記録した箇所を置き換える。**
> 同仕様書は PR 単位の point-in-time 記録であるため**書き換えない**（当時の判断は当時として正しい）。
> **置き換えの事実は本 ADR に残す。**

> 決定6 の主張を支えるのは 2 ではなく 3 である。

### 副産物: 検査器が本作業自身のコメントを捕まえた

CI ジョブのコメントに**違反の実例を平文で書いて**自分の検査に捕まった。
規約は「意図的な誤例はインラインコードへ入れる」と定めるが、
**その除外は Markdown でしか効かない**（YAML のバッククォートはコード記法ではない）。
**誤例を書かない形へ改め、その旨をコメントに残した。**

## 影響

- 肯定的:
  - **`<PROJ>/<ID>` の表記が一貫した**（46 件）。修飾を導入した目的（誤帰属の防止）が機械で守られる。
  - `traceability.md` が kit とバイト一致になり、次の更新がそのまま届く。
  - **fail-open の穴を実験 3 で実測して塞いだ。**
  - 🔴 **`pr-title.yml` の実在した穴を塞いだ**（決定7）。**`claude[bot]` の PR が PR タイトル検査を
    skip していた** —— 本リポの主要な経路でだけ「最後の砦」が抜けていた。**AI レビューの指摘が無ければ
    「対応済み」という誤った記録を正本に残すところであった。**
- 否定的 / トレードオフ:
  - **`check-cross-repo-refs.js` は入っているが働かない**（決定4）。**269 件は残る。**
  - **kit の定義から意図的に外れた**（決定3。`AST` は自プロジェクトだが `PROJECT_PREFIXES` へ入れた）。
    kit を同期しても環境変数側の設定なのでファイルは壊れないが、**kit の想定とは違う使い方である**。

## 残余リスク

- 🔴 **`check-cross-repo-refs.js` の 269 件は未着手である。** 規約の決定（短縮形かフルパス形式か）が
  前提であり、対象の多くが point-in-time 記録である。**別 issue（[#487](https://github.com/endazon/ai-stock-trading/issues/487)）とした。**
  **それまで issue / PR 番号の表記ゆれは検出されない。**
- **`PLAN_ID_PREFIXES` の fail-open は残る。** CI 側で落ちても skip して緑になる性質そのものは
  kit の設計であり変えない。**回帰テストが唯一の番人である**（決定6・実験 3）。
- **検査は空白区切りだけを見る。** kit が明記するとおり「**文脈から裸の ID を推測する形は検出しない**」
  （偽陽性が避けられないため）。`FR-17` と書いて MSP の意味で使っていても検出できない。
- **`BOT_AUTHORS` は手で保守する。** 新しい bot（例: 別の GitHub App）が PR を作るようになっても、
  リストに足すまでは検査される。**それが安全側である**（検査されすぎるほうが、抜けるより良い）。
  ただし**bot が規約外の件名で PR を作ると CI が赤くなる**ため、その時は「除外を足す」か
  「bot 側の件名を直す」かを判断すること。
- **`.md` 以外では誤例を書けない。** `maskCode` は Markdown のコード記法しか外さないため、
  YAML・C# のコメントに違反の実例を書くと検査に捕まる（本作業で実際に踏んだ）。

### ［2026-08-28 追記 / IADR-0262］決定2・決定6 は部分的に Superseded

**決定2**（検査器の置換点は環境変数で与え、ファイルはキットとバイト一致のまま保つ）と**決定6**
（その結果生じる fail-open を、回帰テストを唯一の番人として受容する）は、
[IADR-0262](IADR-0262_plan-id-qualification-default-and-doc-contradictions.md) により部分的に
Superseded された。

理由: 両決定の動機は「キットとのバイト一致を保つ」ことにあったが、その後の資料再編（計画 ADR-0029・
2026-08-21）が「kit との乖離は受容する」方針へ転換し、kit-sync のバイト一致検査も退役した。動機が
失われたまま、**CI では検査され、素の実行（env なし）だけが skip して緑になる**という非対称
（本節が「fail-open は残る」と自認していたリスクそのもの）が残っていた。IADR-0262 は
`PROJECT_PREFIXES` の既定を `['MSP', 'AST']` としてファイルへ直接埋め、この非対称を閉じた。

**決定1・決定3・決定4・決定5・決定7 は影響を受けず、引き続き有効である。** 決定3（`AST` を
`PROJECT_PREFIXES` へ含める判断）は IADR-0262 の既定値へそのまま引き継がれた。
