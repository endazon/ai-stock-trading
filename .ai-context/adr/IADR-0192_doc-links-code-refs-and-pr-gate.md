# IADR-0192: doc-links の 2 つの穴を塞ぐ

> 実装リポジトリ内の意思決定記録（Implementation ADR）。1 ファイル = 1 意思決定。

- 状態: Accepted
- 日付: 2026-08-14
- 決定者: Claude Code（実測で破損 20 件を検出したため）

## 起点・関連

- 計画書 ID: **NFR**（工程の統制。計画側の非機能要件表に当たる番号が無いため無採番。planning#311 の 2）
- 対象 Issue: [#493](https://github.com/endazon/ai-stock-trading/issues/493)（コード拡張子）／[#496](https://github.com/endazon/ai-stock-trading/issues/496)（PR 段階へ戻す）
- 作業仕様書: [20260814_493_496](../specs/20260814_493_496_doc-links-code-and-pr-gate.md)
- 発見元: [IADR-0191](IADR-0191_kit-sync-classification.md) のキット突合
- 先行: **microservices-platform の IADR-0058**（夜間分離の元になった決定。MSP#232）。
  🔴 **本リポの [IADR-0058](IADR-0058_helm-chart-ci-gate.md) は Helm チャートの CI ゲートであり別物である**
  —— 計画 ID・実装 ID はリポジトリごとに独立採番であり、**裸の `IADR-0058` は本リポのものを指す**
  （`.claude/rules/traceability.md`）。本作業中に実際に取り違えかけた。

## コンテキストと課題

**`doc-links` には独立した 2 つの穴があり、どちらも「緑だが検査されていない」であった。**

### 穴1: コードファイルへのリンクが検査対象外（#493）

`LINK_EXT` にコード拡張子（`js` / `ts` / `cs` / `csproj` / `slnx` / `sh` ほか）が無く、
**仕様書・IADR からコードへの相対リンクが一度も検査されていなかった。**

**キット版には入っている。** キット側のコメントは、この穴が**実際に事故になった**と記録している ——
「コード拡張子が抜けていた間、仕様書からコードへの live link は一切検査されず、破損したまま
『OK: 384 件』と報告された（MSP#470 / planning#167。
**検査器を作る PR が、検査器の穴で自分の参照切れを見逃した型**）」。

**本リポジトリは、その是正が入る前のキットから枝分かれしたまま追随していなかった。**

#### 🔴 実測: **20 件**が壊れていた

| 原因 | 件数 | 内容 |
| --- | ---: | --- |
| **`src/` → `backend/` の移行に未追随** | **17** | IADR-0046 / platform ADR-0019 のユニットリポジトリレイアウト移行。**IADR-0002〜0008 のリンクが移行前のまま** |
| **`.Worker` → `.Api` の改名に未追随** | **2** | `RiskControlEndpoints.cs` / `MonitorSettingsEndpoints.cs` |
| **隣接クローンへのパス** | **1** | `../microservices-platform/...`。**CI に隣接クローンは無く、原理的に解決できない** |

**リンク先はすべて実在する。指している場所だけが存在しなかった。**
**レイアウト移行から今日まで、`OK` が出続けていた。**

### 穴2: 計画書実在検査が PR 段階で働いていない（#496）

`ci.yml` の `doc-links` / `test-traceability` は、**「PR CI には `PLANNING_REPO_TOKEN` が無い」**を
根拠に planning 配下の実在検査を skip し、夜間の `doc-links-planning.yml` へ委ねていた（microservices-platform の IADR-0058 の方式）。

**この前提は [PR #495](https://github.com/endazon/ai-stock-trading/pull/495) の実測で反証された** ——
`kit-sync` ジョブが**同じトークンで PR の CI から submodule を取得し success した。**

夜間方式の弱点は**当の `doc-links-planning.yml` のヘッダに明記されていた** ——
「**マージを止められず、夜間に初めて赤くなる**。しかも失敗が PR に紐づかないため気付かれにくい」
（**実運用で 14 夜連続の失敗が放置された実績**にも言及）。
同ヘッダは**「トークンが PR CI でも使える場合は PR 段階で落とす方が望ましい」**と、
あるべき姿を先に書いていた。**条件が満たされていることに、誰も気付いていなかった。**

## 決定

### 決定1: キット版の `LINK_EXT` と自己試験を取り込む。**#399 は失わない**

**単純な上書きは退行になる。** 本リポは [#399](https://github.com/endazon/ai-stock-trading/issues/399) で
「同一ディレクトリ内の裸ファイル名」の検査を持ち、**キットには無い**。**マージした形にする。**

- キットから: `LINK_EXT`（コード拡張子込み）・`selfTest()`・`--self-test`・`module.exports`
- 本リポから: `bareFileName` の判定とその根拠コメント
- **自己試験へ #399 の正例・負例を足す**（3 件）——**キットの自己試験はこの機能を知らない**。
  **固定しないと、次のキット追随で黙って消える。**

### 決定2: 20 件は**経路を是正する。除外しない**

**除外は「検査したことにする」であり、次に同じ形が来ても気付けない。**

- 17 件: `../../src/` → `../../backend/`
- 2 件: `.Worker` → `.Api`
- 1 件: **live link をやめる。** 隣接クローンへの `../` 始まりのパスは **CI で原理的に解決できない**。
  **リポジトリ名を明示する表記**へ改めた（他リポジトリのファイルを自リポの相対パスで書かない）。

### 🔴 決定3: `doc-links` / `test-traceability` を PR 段階で実効させる

両ジョブへ `submodules: recursive` ＋ `PLANNING_REPO_TOKEN` ＋ **`--require-planning`** を付ける。

**`--require-planning` は必須である。** 付けないと取得失敗時に skip して緑になり、
**「配線したのに一度も検査しない」状態が固定される**（[IADR-0191](IADR-0191_kit-sync-classification.md) 決定3 と同じ判断）。

### 決定4: 夜間の `doc-links-planning.yml` は**畳まない。役割を書き直す**

冗長に見えるが、**見ているものが違う。**

> **PR CI が見るのは「その PR の差分」である。計画側が更新されて実装側の参照が切れる事故は、
> 実装側に PR が無い間に起きる。それを拾えるのは定期実行だけである。**

**MSP#430 の事故（4 夜連続の失敗が放置）は「夜間に検査したこと」ではなく
「放置したこと」が問題である。** 気付く導線（Notify ステップ）が要点であり、それは既にある。

## 対照実験（実走した実測）

| # | 壊し方 | 結果 | 予測 |
| ---: | --- | --- | --- |
| 1 | `LINK_EXT` を拡張して実走 | **破損 20 件を検出** | 一致 |
| 2 | 是正後に実走 | **OK 465 件** | 一致 |
| 3 | **#399 の `bareFileName` を外す**（キット版で上書きした状態の再現） | **自己試験 1 件 失敗・exit 1** | 一致 |
| 4 | `doc-links` の run 行から `--require-planning` を外す | **回帰テストが赤** | 一致（**初版は緑だった。後述**） |
| 5 | `test-traceability` の run 行から `--require-planning` を外す | **回帰テストが赤** | 一致 |
| 6 | `test-traceability` から `submodules` を外す | **回帰テストが赤** | 一致 |

**自己試験 37 件**（キット 34 ＋ #399 の 3）。**scripts テスト 218 件。**

### 🔴 変異試験が、こちらの回帰テストの欠陥を検出した

**実験 4 は初版で緑のままだった。** 原因は**回帰テストが本文の語に一致していた**ことである ——
ジョブ本文には `--require-planning` が **2 箇所**あり、1 つは **この設定を説明するコメント自身**
（「`--require-planning` を必ず付ける」）であった。**run 行からフラグを外しても、コメントに
一致して素通りしていた。**

**是正**: コメント行を落としてから、**`run:` を含む行だけ**を照合する。

> **これは planning#319 知見3 と同型である** ——「検査器について書いた記述が、語の一致だけで
> 自己発火（ここでは自己充足）する」。**本 ADR の作業中に、同じ罠へ 2 度目に落ちた。**
> **変異試験を回していなければ、「守っているつもりの回帰テスト」がそのまま残っていた。**

## 影響

- 肯定的:
  - **仕様書からコードへのリンクが検査されるようになった**（今まで 0 件が検査対象）。
  - **20 件の陳腐化したリンクが解消**。うち 17 件はレイアウト移行以来のものである。
  - **計画書実在検査が PR 段階で落ちるようになった** —— マージ前に止まる。
  - **PR CI と夜間の役割分担が「実測に基づく」ものへ更新された**（前提の誤りが除かれた）。
- 否定的 / トレードオフ:
  - **`PLANNING_REPO_TOKEN` への依存が 2 ジョブ増えた**（計 3）。トークンが失効すると
    **3 ジョブが赤になる**（skip ではなく赤であることが決定3 の趣旨だが、原因がリンク破損では
    ないときも赤になる）。
  - **CI 時間が増える**（2 ジョブが submodule を取得するようになった）。
  - **フォーク PR では secrets が使えないため機能しない。** 本リポは同一リポのブランチ運用であり
    現時点では問題にならないが、**フォーク運用へ移るなら再設計が要る。**

## 残余リスク

- 🔴 **`check-commit-messages.js` の計画 ADR 実在性検査は、今も PR CI で skip される。**
  `commit-messages` ジョブが submodule を取得しないためである。**同じ手で塞げるが本 ADR では
  やっていない** —— 実効するのは実装 ADR（IADR）側のみという状態が残る。
- 🔴 **#399 の分はキットに無い。** 環流するまで**キット追随のたびに手動マージが要る**（[#494](https://github.com/endazon/ai-stock-trading/issues/494)）。
  **自己試験で固定したため黙って消えることはない**が、**追随の手間は残る。**
- **`LINK_EXT` に無い拡張子への参照は依然として検査されない**（`txt` / `log` / `lock` 等は
  誤検知リスクのためキットが意図的に外しており、その方針は自己試験で固定されている）。
- **リンクの「実在」しか見ない。** 参照先が実在しても、**内容が意図と合っているかは見ない。**
