# IADR-0552: 週報の本文を、散文と同じ決済の種別で描く（#1362）

> 実装リポジトリ内の意思決定記録（Implementation ADR）。1 ファイル = 1 意思決定。
> 計画リポジトリの ADR（`ADR-XXXX`）とは別系統（`IADR-XXXX`）とし、実装に閉じた決定を記録する。

- 状態: **Accepted**
- 日付: 2026-10-17
- 決定者: claude が起案（起点 [#1362](https://github.com/endazon/ai-stock-trading/issues/1362)。レビューは PR で受ける）

## 起点・関連

- 計画: `04_report-templates` 週報 §1「取引回数（うち変動トリガー・損切り） <n（n・n）>」・§3「最良／最悪」・§5「損切り執行 <n 件>」。FR-16（数値はコード集計）。
- 関連 IADR: IADR-0540（散文へ決済の種別を渡した。§残余リスク 1 が本件）、IADR-0305（§5 の 3 項目を未供給で描いた）、IADR-0381（期間より前に建てた建玉の決済）、IADR-0480（未供給と 0 の区別）。

## コンテキスト

IADR-0540 で散文に決済の種別（`FillPnlAttribution.Kind`）を渡した。週報の本文は同じ帰属の列を持つのに種別を描かず、§5 は「損切り執行: 未供給（判断の起点が記録されていません）」のままだった。散文が「TSLA の損切り」と書くと、本文の §5 は「未供給」を示し、食い違って見える。

## 決定

### 決定 1: 損切りの件数は共有の純関数 `SettlementKinds.Tally` で数え、§1 と §5 に同じセルで描く

- 数える母集合は**決済**（`Realizing`、または損益を算定できなかった決済 `Unvalued`）。全量を算定できなかった決済は `Realizing=false` だが決済であり、`FillPnlAttributionBuilder.Build` はこの行にも種別を付ける（IADR-0540 決定 2 は「決済の行だけ」で、算定できなかった決済を落としていた）。損切りが執行された事実は損益の算定と別である。
- 損切り＝`SettlementKind.StopLoss`（S0 の約定・S1 の決済）。保護逆指値が成立しないときの手仕舞いは数えない（IADR-0540 決定 2 の表）。
- 種別未供給の決済が m 件あれば「n 件（ほかに種別未供給の決済 m 件。その中に損切りがあり得ます）」と書く（n は下限。**推測で数えない**）。損切りのうち算定できなかった決済があれば件数を書く。
- **約定を照会できなかった週は「未供給」**: `ReportView.FillsUnsupplied`（`UnsuppliedInputs` に約定がある。散文の `Settlements`＝null と同じ判定）または帰属が null。帰属は空列でも「0 件」と書かない。決済 0 件（照会できた）は「0 件」。
- §1 は週報だけ、「取引回数（買/売/決済）」の直後に行「うち損切り（決済の種別）」を足す。既存の行の名前・値は変えない。計画の「うち変動トリガー」は記録源が無いため出さない（IADR-0305 の欠如のまま）。

### 決定 2: §3 の最良・最悪に「種別: <語>」を足す

- 語は散文と同じ `SettlementKinds.Label`（null＝「種別未供給」）。同じ決済が本文と散文で同じ語になる。凡例に記録源（承認行の由来と判断の記録の有無）と「種別未供給は推測で埋めていない」を書く。

### 決定 3: 散文の「損益を算定できなかった決済」の行にも種別の内訳を渡す

- 散文の種別ごとの件数は損益を算定できた決済だけを数える（IADR-0540 決定 3）。本文の損切りの件数は算定できなかった決済を含むため、散文の該当行（「期間より前に建てた建玉の決済 N 件（種別: …）」）にも内訳を出す。2 行の損切りの和が本文の件数になる。

## 却下した案

| 案 | 理由 |
| --- | --- |
| §1 の行名を計画どおり「取引回数（うち変動トリガー・損切り）」へ改める | 変動トリガーの記録源が無く、値の半分が埋まらない。既存の「取引回数（買/売/決済）」の行（日報・月報と同じ書式・多数の試験と §2 の注記が引く）を壊す |
| 損切りの件数を損益を算定できた決済だけで数える（散文と同じ母集合） | 期間より前に建てた建玉の損切りを数え落とす。「損切り執行」は執行の件数であり損益の算定と別 |
| 種別未供給の決済を損切りの件数から除いて「n 件」とだけ書く | 未供給を 0 と読ませる（IADR-0480）。損切りがあり得ることを隠す |
| 帰属が空列なら常に「0 件」 | 約定を照会できなかった週（中核の入力の欠落で見送りの上限を超えた生成）でも 0 件と書く。散文は同じ週に「入力に含まれていません」と書く |

## 帰結

- 週報の本文と散文が、同じ決済に同じ種別を描く。§5「損切り執行」が初めて件数を持つ。
- §5 の残る 2 項目（発注拒否・上限使用率の週間最大）は未供給のまま（IADR-0305）。

## 残余リスク

- 日報 §2 の「トリガー」列（定時・変動・損切り）と日報 §4「損切り執行」は描いていない（判断の起点の記録源が無い／本文が未実装。IADR-0272 残余 4）。日報の本文はハイライトを持たないため散文と食い違う文は無い。
- 約定を照会できなかった週の §2・§3 は従来どおり空の帰属から描く（「決済なし」と読める）。本件は §1・§5 の損切りだけを未供給にした。§2・§3 の扱いは本件の範囲外（別件）とする。
- 2026-10-07 より前の判断由来の決済の分類の限界（IADR-0540 残余 2）は本文にも同じく及ぶ。
