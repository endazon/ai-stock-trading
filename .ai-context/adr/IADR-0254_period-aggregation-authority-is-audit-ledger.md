# IADR-0254: 期間集計の権威源は監査台帳

- 状態: Accepted
- 日付: 2026-08-28
- 決定者: claude（起票 #338）

## 起点・関連

- 関連する計画書 ID: FR-06・FR-11（監査）・FR-16、`04_report-templates` 月報 §6.1 / §7、`05_trading-assumptions` §6.1
- 関連する実装仕様書: [`20260828_338_reporting-cycle-and-templates.md`](../specs/20260828_338_reporting-cycle-and-templates.md)

## コンテキストと課題

月報 §7（当月の LLM 利用実績）と §6.1（当月の空売りの記録）は、いずれも**期間の集計**である。
供給元の候補は 2 つあった。

- **費用統制サービスの月次カウンタ**（LLM 費用）
- **監査台帳**（`GET /audit/events/by-type`。イベント全量を JSON で 7 年保持）

## 検討した選択肢

1. 費用統制サービスの月次カウンタを引く
2. **監査台帳を種別 × 期間で引く**（採用）
3. 報告書サービス自身がイベントを購読して独自に積む

## 決定

**決定1: 権威源は監査台帳とし、`GET /audit/events/by-type`（OwnerOrService）で引く。**
既存の `HttpFxSourceStatusSource`（IADR-0199）と同型であり、新しい照会 API を足さない。

🔴 **決定2: 費用統制サービスの月次カウンタを引かない。**
あちらは**月次上限の対象ぶんしか積まない**（`LlmCostScope.IsGoverned` が false の用途は別カテゴリ・
IADR-0218）。したがって**報告書生成の費用が引けない**——
#282 で計上点を作った（IADR-0219）のに月報へ出せない、という状態になる。
計画 §6.1 は「対象外とし、**抑制動作も行わず、月報に実績を記載する**」と定めており、
**対象範囲の議論と記録の有無は別問題**である。

**決定3: 選択肢 3（独自の購読・積み上げ）を採らない。** 状態がプロセスごと・再起動で消える
（IADR-0199 決定1 が退けた形と同じ）。期間の集計は 7 年保持の台帳からしか復元できない。

**決定4: 供給不達はすべて `null`（未供給）へ倒す。**
非 2xx・応答 null・タイムアウト・例外のいずれも同じ。
費用 0 円・スキップ 0 件・借株コスト 0 USD と書けば、計上漏れが正常として読まれる。

**決定5: 借株料は「計上できた日」と「料率が取れず未計上の日」を別の種別で引く**
（`BorrowFeeAccrued` / `BorrowFeeAccrualUnavailable`）。
ADR-0027 決定4 が 2 つのイベントに分けたのは、**未計上を 0 円として合計へ混ぜない**ためである。
片方だけを引けば、その分離が報告書の側で崩れる。

**決定6: 縮退件数（分割 / 切り詰め・計画 INDEX 決定44）の種別は要求しない。**
発生源（スクリーニング層）が未実装であり、種別そのものが存在しない。
🔴 **存在しない種別を要求すると台帳は 0 件を返し、それが「縮退が無かった」に化ける。**
未供給（`null`）のまま描き、「**0 回 / 0 件ではありません**」と本文へ書く。

**決定7: 期間の写像（JST 暦日 → UTC 半開区間）を 1 箇所へ集約する**（`AuditPeriodRange`）。
照会元が 3 つに増えたため、各アダプタが自前で書くと**どれか 1 つで境界を間違えても他が正しいため
気づかない**（`ReportRenderer.AppendFxCredits` を 3 出口すべてから呼ぶのと同じ理由）。

## 理由

- 台帳は書き手（`AuditEntryFactory`）が `nameof(型名)` を `EventType` として書くため、
  **種別名がそのまま引き当てになる**。追加の対応表を持たなくてよい。
- 復元には書き手と同じ `AuditDetailJson.Options` を使う（IADR-0199 決定6）。
  ここへ設定を書き写すと、命名規約を片側だけ変えたときに
  **`JsonSerializer` は例外を投げず、既定値で埋めた record を黙って作る**。

## 結果

- 良い影響: 報告書生成の費用が月報へ出る（#282 の指摘が「計上したが見えない」で止まらない）。
  借株コストの合計が未計上ぶんを混ぜずに出る。
- 悪い影響・トレードオフ: 監査台帳が落ちていると月報の §6.1 / §7 が「照会できませんでした」になる。
  **費用統制サービスは生きていても報告書は数字を出さない**——権威源を 1 本に決めた帰結である。
- フォローアップ: 縮退件数の供給（#337 が担当するスクリーニング層の計数と、その契約イベント）。
