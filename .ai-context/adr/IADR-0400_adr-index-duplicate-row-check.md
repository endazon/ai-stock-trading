# IADR-0400: ADR 索引行の IADR 番号の重複を赤にし、印は行ごとの出現回数の最大値で比べる

- 状態: Accepted
- 日付: 2026-09-25
- 決定者: claude (Claude Code) / #955 の起票者の案に沿う（比較単位だけ下の理由で絞る）

- 関連する計画書 ID（FR/UC/SC/ADR）: 無し（NFR・文書統制）

## コンテキストと課題

develop の `.ai-context/adr/README.md` に、IADR-0354・IADR-0369 の索引行が 2 本ずつ並んだまま入った
（f703843）。並行 PR の取り込みで、両側が同じ行へ追記した衝突を「両側の行を並べる」和集合で解いたのが原因である。

- `check-adr-index-addendum-loss.js`（IADR-0363）は印の**消失**しか見ない。重複した行は印を失っていないので緑。
- `check-adr-index-sync.js` は「差分で触った IADR 本文に索引行の変更があるか」しか見ない。緑。
- さらに、IADR-0363 決定 1 は同じ IADR 番号の行が複数あれば印の数を**合算**していた。重複 2 行に 1 回ずつ在った
  印を 1 行へ畳む**正しい是正**（6dcc7b5。PR #954）は「2 → 1」の消失として赤になる
  （`--range=f703843..6dcc7b5` で 4 件を実測。スカッシュ後のコミット本文に撤去の宣言は残っていない）。

## 検討した選択肢

### どちらの検査器へ足すか

| # | 選択肢 | 評価 |
| --- | --- | --- |
| A | `check-adr-index-addendum-loss.js` へ規則 4 を足す | **採る。** 索引ファイルの中身を版ごとに読み、IADR 番号ごとに畳む処理（`parseIndex`）を既に持つ。事故の族（衝突解決で索引行が壊れる）も同じ |
| B | `check-adr-index-sync.js` へ足す | 採らない。差分のファイル名と変更行だけを見る設計で、索引の全体を読まない。「本文を触った PR」に限って重複を見ることになり、取り込みだけで生じた重複を素通りさせる |

### 印の比較単位

| # | 選択肢 | 評価 |
| --- | --- | --- |
| 1 | 合算（従来） | 重複を畳む是正を赤にする。#955 の症状そのもの |
| 2 | ID ごとの印の**集合**（issue の案の字義） | 畳む是正は緑になるが、**1 行に同じ印が 2 つあり 1 つ消えた**形を見逃す。IADR-0363 決定 1 が多重集合を選んだ理由と、既存の自己試験を覆す |
| 3 | ID ごとに、**行ごとの出現回数の最大値** | **採る。** 畳む是正は緑（1 と 1 の最大は 1）、1 行内の片方の消失は赤（2 → 1）。両方を満たす |

## 決定

1. **決定 1（規則 4・重複）**: ours（HEAD。手元では作業ツリー）の索引に、同じ IADR 番号の索引行が 2 本以上あれば
   赤にする。**状態の検査**であり base・theirs は見ない（統合ブランチ側に既に重複があっても、それを取り込んだ PR は赤になる。
   重複 0 の develop を保つのが目的なので、それでよい）。検査範囲を決められない場合も作業ツリーの索引で検査する。
   **逃げ道は用意しない**（同じ ID の行を 2 本持つ正当な理由が無い）。
2. **決定 2（比較単位）**: IADR 番号ごとの印の数は、全行の合計ではなく**行ごとの出現回数の最大値**で持つ。
   IADR-0363 決定 1 の「IADR 番号ごとの多重集合」を、同じ番号の行が複数ある場合に限って改める
   （行が 1 本なら従来と同じ値になる）。
3. **決定 3（縮みの観測）**: IADR-0375 決定 1 の比較相手に同じ ID の行が複数あるときは、連結した長さではなく
   **最も長い 1 行**と比べる。連結と比べると畳む是正が必ず「縮んだ」と告げられる（6dcc7b5 で実測）。

## 理由

- 重複は「印の消失」と違い**状態として定義できる**（行数を数えるだけで偽陽性が無い）。
  偽陽性を出さない規則は赤にしてよい（本検査器が繰り返し書いている「偽陽性は検査を外させる」に当たらない）。
- 比較単位は、畳む是正（緑にしたい）と 1 行内の消失（赤のままにしたい）の両方を 1 つの数で表せる最小の変更を選んだ。

## 結果

- 良い影響: 衝突解決で行が 2 本並ぶ事故が CI で止まる。重複を畳む是正に `[remove-adr-addendum]` の宣言が要らなくなる。
- 悪い影響・トレードオフ: 同じ ID の 2 行の**それぞれに**同じ印が 2 回ずつあり、畳んで 1 回になった形は
  最大値 2 → 1 で赤になる（正しい）。一方、重複した 2 行が**異なる数**で同じ印を持つ場合、少ない側の行が
  失ったかは区別しない。重複そのものが規則 4 で赤なので、畳む時点の人の確認に委ねる。
- 残余リスク: 索引行の**昇順**は検査しない（事故は起きていない）。IADR-0363 決定 6 の見逃しはそのまま残る。
