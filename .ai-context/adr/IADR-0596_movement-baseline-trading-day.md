# IADR-0596: 急変検知の基準値を取引日で区切る

> 実装リポジトリ内の意思決定記録（Implementation ADR）。1 ファイル = 1 意思決定。

- 状態: **Accepted**
- 日付: 2026-10-29
- 決定者: Claude Code（#1487。計画の「前回判断時点比」の読みはオーケストレーターへ報告済み）

## コンテキスト

基準値（前回判断時点の価格）は判断でしか進まず、取引日の区切りを持たない。前日の最後の判断の価格（決済の指値を含む）が翌日の寄り付きの判定に使われ、
夜間の値の差を急変として検知して LLM を起こした（PoC 2026-10-28: HOOD の売り指値 95.71 で開場直後に 2 件）。

## 決定

- 判定で基準値の置いた時刻（EF の既存の列 `UpdatedAt`）を市場の現地の暦日に直し、今の現地の暦日より前なら、その巡回の現在値へ置き直して判定しない。
  同じ日・時刻が分からない基準値は従来どおり判定する。スキーマは変えない（取得の口 `GetBaselineEntry` を足す。既定の実装は時刻なし）。
- 閉場中は判定も照会もしない（IADR-0380）ので、置き直しは新しい取引日の最初の場中の巡回＝開場時点の価格になる。

## 却下した案

- **前日終値に置き直す**: 終値の取得の口を新たに要する。開場時点の現在値でも夜間の差を急変と見ない目的は満たす。
- **日付が変わったら基準値を消す**: 次の判断まで変動判定が止まる（基準値未確定は判定しない）。開場直後の本当の急変も見逃す。

## 結果

- 前の取引日の基準値で寄り付きの疑似の急変を検知しない。置き直した後の変動は従来どおり検知する。
- 🔴 計画（FR-03）の「前回判断時点比」を「その取引日の判断」と読んだ。計画の確認が要るかはオーケストレーターの判断に委ねた。
- 残余: 同じ日のうちに LLM の前の見送りで基準値が進まない形（IADR-0452）は変えない。
