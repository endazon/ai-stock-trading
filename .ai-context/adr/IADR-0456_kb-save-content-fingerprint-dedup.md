# IADR-0456: 情報収集の KB 保存で同じ内容を送らない（#1084）

> 実装リポジトリ内の意思決定記録（Implementation ADR）。1 ファイル = 1 意思決定。
> 計画リポジトリの ADR（`ADR-XXXX`）とは別系統（`IADR-XXXX`）とし、実装に閉じた決定を記録する。

- 状態: **Accepted**
- 日付: 2026-09-29
- 決定者: Claude Code（実装）。計画の内側で保存の仕方を選ぶ実装判断であり、裁定は要らない

## 起点・関連

- 関連する計画書 ID: FR-01（収集）・FR-08（KB 保存）・ADR-0001（基盤は改修しない）
- 関連する実装仕様書: [`.ai-context/specs/20260929_1084_kb-save-dedup.md`](../specs/20260929_1084_kb-save-dedup.md)
- 前提: [IADR-0069](IADR-0069_knowledge-base-rag-foundation.md) 決定 4（`KnowledgeBaseWriterSink`。本 IADR は写像と fail-safe を変えない）、
  [IADR-0454](IADR-0454_kb-search-scope-symbol-recency.md) 決定 5（KB 検索の足切りは 168 時間）

## 背景

巡回（300 秒）ごとに、同じ内容を新しい文書として KB へ保存していた（#1084）。基盤の `POST /documents` には、外部キーによる同定も upsert も無い（仕様書 §基盤の調査）。

## 決定

1. **`KnowledgeBaseWriterSink` は、保存に成功した内容の指紋を覚え、同じ指紋の内容を writer へ送らない。**
   未保存（fail-safe の縮退）は覚えない。そのため、次の巡回で送り直される。同じ巡回の中の重複も、先の 1 件が保存できていれば止まる。
2. **指紋は全項目（種別・源・銘柄・表題・本文・公開時刻〔UTC〕・URL）の SHA-256 の上位 128 ビットとする。**
   各項目は長さ前置で連結し、null と空文字を区別する。一部の項目では同定しない。FRED は URL が一定で値だけが変わり、現在値は URL を持たないため、一部の項目で同定すると新しい観測を捨てる（取りこぼしは重複より悪い）。
3. **指紋はプロセス内（シンクと同じ singleton）に保ち、保持は 7 日・上限は 100,000 件とする。上限を超えたら古い順に捨てる。**
   7 日は、ニュースの取得期間（既定 1 日）と KB 検索の足切り（168 時間）の長い方を覆う。上限はメモリの天井で、数 MB に収まる。
   再起動で指紋は空になり、取得中の内容を 1 回だけ保存し直す（下記「残余」）。
4. **ログの分母は「送った件数」とする。** 保存済みと同じで送らなかった件数は別に出す。運用の障害表は「`0/N` が続く＝保存失敗」で見分けるため、送らなかった分を分母へ混ぜない。

## 採らなかった案

- **A. source＋url、または source＋symbol＋publishedAt で同定する（issue の案）**: FRED・現在値・BoJ で新しい観測を捨てる（仕様書の表）。
- **B. 起動時に `IKnowledgeDocumentCatalog.ListAsync` で既存文書を読み、指紋を種まきする**: 基盤の `GET /documents` は絞り込みもページングも持たず、KB 全体（他ユニットの文書も含み得る）を起動のたびに取る。
  このポートは保守の操作用に分けたもので（IADR-0436 決定 2）、業務経路へ持ち込むと意味が変わる。残余（再起動 1 回分の重複）に比べて費用が大きい。
- **C. 基盤へ upsert／外部キーを足す**: ADR-0001（基盤は改修しない）に反する。
- **D. 指紋を DB に永続化する**: 情報収集サービスは永続層を持たない。残余に比べて過剰である。

## 結果

- 巡回ごとの重複保存が止まる。変わった内容（新しい観測・新しい記事）は、これまでどおり保存される。
- **残余 1**: 再起動のたびに、取得中の内容を 1 回だけ保存し直す。
- **残余 2**: 同じ記事でも、要約が書き換わると別の内容として保存する（本文が違うため）。
- **残余 3**: 情報収集を複数レプリカで動かすと、指紋はレプリカごとに分かれる（現状は `deploy/helm/ai-stock-trading/templates/deployment.yaml` の `replicas: 1`）。
- 既に KB に溜まった重複文書は消さない。
