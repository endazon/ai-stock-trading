# IADR-0409: 規則 11 の 3 つの形と表の軸は必読規約の条文へ置き、同じ量以上の重複を必読集合から削る

- 状態: Accepted
- 日付: 2026-09-25
- 決定者: claude (Claude Code) / #924 の起票者の勧め（案 1）に沿う

## 起点・関連

- 関連する計画書 ID: 無し（NFR・運用統制）
- 関連する実装仕様書: `.ai-context/specs/20260925_924_rule11-inline-shapes.md`
- 起点 issue: #924（PR #917 の監査が実測した指摘）
- 部分的に改める決定: IADR-0377 決定 5（「3 通りの表は別紙へ置く」の部分だけ）

## コンテキストと課題

IADR-0377 決定 5 は、規則 9〜11 の**条文だけ**を `.claude/rules/traceability.repo.md` へ置き、
根拠・破れた実例・3 通りの表を別紙 `docs/how-to/correction-population-and-window-procedure.md` へ置いた。

規則 11 は「3 通りの形で実測する」「表を出せるまで形を確定しない」と課すが、
**どの 3 通りか・表の軸が何か**は別紙にしか無かった。規則 9・10 は必読側だけで自足するのに、
**11 だけは別紙を開かないと守れない**（条文として欠けている）。

制約は読み込み予算である。着手時点の実測（`node scripts/check-reading-budget.js`）は
Claude Code 母集合 **46,055 バイト（予算 51,200 の 90%）**。warn のしきい値は 46,080 バイトで、
残りは 25 バイトしかない。3 つの形を書き下すと数百バイト要る。

## 検討した選択肢

| # | 選択肢 | 評価 |
| --- | --- | --- |
| 1 | 3 つの形と表の軸を条文へ最短で inline 化し、**同じ量以上の重複を必読集合から削る** | **採用** |
| 2 | 規則 11 を「別紙を読むこと」の誘導にし、自足を諦めると明記する | **採らない**。条文が守り方を持たないまま残り、規則 9・10 との非対称が消えない。予算の余白も作らない |
| 3 | 予算そのものを見直す | **採らない**。予算値の正本は計画リポの運用ガイド §8 であり、実装側の都合で動かせない。案 1 で足りる |

## 決定

- **決定 1**: 規則 11 の条文に **3 つの形**（窓の**後**の端だけを見る／**前**の端だけを見る／**両端**を突き合わせる。
  例 `min(前, 後)`）と **表の軸**（行＝形・列＝プローブ・升目＝期待どおりか）を書く。
  形は「後の端・前の端・両端」という**一般形**で書き、`min(前, 後)` は例に留める
  —— 実際の適用（`20260925_923_775` の基準の取り方: develop 先端／`HEAD^1`／マージベース）は
  `min` ではない両端の形を採っており、`min` を唯一の形と書くと条文が適用例と食い違う。
  列は増える側・減る側の 2 本が最小で、足してよい（同適用例は 4 列）。
- **決定 2**: 削る先は**必読集合の中で、凍結記録が既に全文を持つ経緯・実測値**に限る（内容は失われない）。
  - IADR 欠番受容の「理由」節の実測値（12 本・16 件・47 ファイル・2,339 箇所／450 ファイル）→ IADR-0280 が全文を持つ。
    必読側には「参照数に比例して肥大化する」という理由の要旨と出典だけを残す。
  - `check-plan-id-qualification.js` の置換点の経緯（IADR-0189 決定 2・6 の動機と部分 supersede）→
    IADR-0262（と IADR-0189 の追記、検査器本体の冒頭注記）が全文を持つ。必読側には「非対称を塞ぐ」という理由と出典だけを残す。
- **決定 3**: 別紙は条文と重なる文（「表を出せるまで形を確定しない」）を削り、表を**実例の結果**として位置づけ直す
  （CLAUDE.md「2 箇所に置くと片方が古くなる」）。別紙は必読集合の外なので予算には効かない。

## 理由

- 規則 11 の欠落は「守れない条文」であり、誘導（案 2）では直らない。直すには条文へ書くしかない。
- 削った 2 箇所は、いずれも**決定の経緯と数え**であって規範ではない。規範（欠番を埋めない・再利用禁止・
  既定を直書きする・`AST` を含む・env で上書きできる）はすべて必読側に残る。
- **予算の実測**: 着手前 **46,055 バイト（90.0%）** → 着手後 **45,361 バイト（88.6%）**、差 **−694 バイト**
  （規則 11 の inline 化で約 +350、削除で約 −1,040）。warn のしきい値（46,080）から 719 バイトの余白ができた。

## 結果

- 良い影響: 規則 11 が必読側だけで守れる。必読集合は 694 バイト減る。
- 悪い影響・トレードオフ: 欠番受容の実測値と置換点の経緯は、必読側から IADR を開かないと読めなくなる
  （読む必要があるのは、その決定を覆そうとするときだけである）。
- 残余リスク: 規則 9〜11 に機械検査は無い（IADR-0377 決定 6 のまま）。
