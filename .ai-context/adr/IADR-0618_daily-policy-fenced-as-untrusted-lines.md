# IADR-0618: 日報方針の節をデータとして分ける

> 実装リポジトリ内の意思決定記録（Implementation ADR）。1 ファイル = 1 意思決定。

- 状態: **Accepted**
- 日付: 2026-11-05
- 決定者: Claude Code（実装）／ オーケストレーター（方針の本文をデータとして分け、信頼しない入力と明示する。#1524 の接頭辞・model・effort・max_tokens は変えない、の指示）

## 起点・関連

- issue: #1529（3 件の 1 つ）
- 前提: IADR-0169（参考情報の構造分離）・IADR-0542（境界語）・IADR-0607（キャッシュできる接頭辞）・IADR-0351 決定 3（方針の本文は書き換えない）。
- 実装仕様書: [`.ai-context/specs/20261105_1529_fail-closed-auth-price-policy.md`](../specs/20261105_1529_fail-closed-auth-price-policy.md) §3

## コンテキストと課題

方針の節は本文を素のまま入れる。方針は利用者が確定したものだが、報告書の生成で外部由来の情報（ニュース・開示）を材料にしており、外部の文が残り得る。本文の行が `# ` で始まると、プロンプトの節の見出しと区別が付かない。参考情報の節は同じ問題を構造で塞いでいる（IADR-0169・IADR-0542）。

## 検討した選択肢

1. **1 行 1 件の JSON 文字列＋フェンス＋境界語＋案内（採用）** — 行は割れず、見出しを名乗れない。行の並びと文言は残るので、「条件 X:」の行などは読める。参考情報の節と同じ規律。
2. 本文全体を 1 つの JSON 文字列にする — 改行が `\n` になり、行ごとの条件が LLM から読みにくい。採らない。
3. 境界語で囲むだけ（素の行のまま） — 行頭の `# ` が残り、見出しの偽装を塞げない。採らない。

## 決定

1. `TradeDecisionPromptBuilder.PolicySection(policy)`: 見出し → 案内（`PolicyBoundaryNotice`）→ フェンス → 開きの境界語 → 各行の JSON 文字列 → 閉じの境界語 → フェンス。
2. 各行は境界語を不変点まで落とし、制御文字を空白へ、バッククォートの 3 連以上を潰す（`Sanitize`）。長さは切らない。改行の種類は問わない。
3. 接頭辞（`DecisionCacheablePrefix` / `ScreeningCacheablePrefix`）はこの節で終わり、方針だけで決まる。全文はその接頭辞で始まる（IADR-0607 の不変条件）。
4. 縮退の見積りは方針の節の文字列そのものの長さを数える。
5. model・effort・max_tokens・呼び出しの引数は変えない。

## 結果

- プロンプトの方針の節の字句が変わる（試験の固定点 `PromptCachePrefixTests` を更新）。キャッシュは方針が変わるまで従前どおり読まれる（初回だけ書きが掛かる）。
- 方針の文言は書き換えない（IADR-0351 決定 3）。

## 残余

1. 報告書の側（方針の改訂のプロンプト）の入れ方は本決定の対象外。
2. 多層防御の一層であり、注入を完全には排除しない（IADR-0022）。
