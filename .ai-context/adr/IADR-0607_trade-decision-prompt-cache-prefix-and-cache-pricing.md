# IADR-0607: 取引判断のプロンプトキャッシュの接頭辞と、キャッシュの欄による計上

> 実装リポジトリ内の意思決定記録（Implementation ADR）。1 ファイル = 1 意思決定。
> 計画リポジトリの ADR（`ADR-XXXX`）とは別系統（`IADR-XXXX`）とし、実装に閉じた決定を記録する。

- 状態: **Accepted**
- 日付: 2026-11-05
- 決定者: Claude Code（実装）／ オーケストレーター（接頭辞は呼び出しごとに変わらない部分だけ・全文と判断の内容は変えない・単価は MSP の単価表に合わせる、の指示）

## 起点・関連

- issue: #1523（MSP#2396 の AST 側）。ゲートウェイの契約は MSP の IADR-0671（MSP develop `b05b19b9`）。
- 前提: IADR-0122（実効モデルで単価を引く）・IADR-0524（Haiku 5.5 の 2 段）・IADR-0550（入力トークン数が取れないときは高い側の段）・IADR-0553（未知モデルの計上単価）・IADR-0212（用途は層ごと）・IADR-0318（Stage 0 の記録の計上の付け替え）・IADR-0332（輸送の継ぎ目）。
- 実装仕様書: [`.ai-context/specs/20261105_1523_trade-decision-prompt-cache-prefix.md`](../specs/20261105_1523_trade-decision-prompt-cache-prefix.md)

## コンテキストと課題

ゲートウェイは、呼び手が分けて渡した接頭辞の末尾にキャッシュの区切り（5 分）を置く。接頭辞が 1 バイトでも違うと読まれず、書きの割増（入力の 1.25 倍）だけが掛かる。
取引判断のプロンプトは「前文 → 当日の日報方針 → 監視銘柄 → 銘柄固有部（時刻・現在値・保有ほか）」の順に組まれている。呼び出しの間隔は 5 分より短い。
応答の `InputTokens` はプロンプト全体のままで、うちの書き・読みが別の欄で返る。AST の計上は全体を入力単価で数えているため、キャッシュが効くと過大の側にずれる。

## 検討した選択肢（接頭辞の範囲）

1. **前文＋方針の節まで（採用）** — 当日のうちは変わらない。銘柄・時刻・価格を含まない。
2. **監視銘柄の一覧まで含める** — 長くなり読みが増える。ただし一覧は市場監視の読み取りのたびに件数・並びが変わり得る。節の末尾には判断対象の所属の行（銘柄ごと）がある。所属の行の手前で切ると、節の文言を変えずには済まない。変わるたびに書きの割増が掛かるため採らない。
3. **固定の規則（リスク制約・出力形式）を前へ移して接頭辞に含める** — 最も長く読めるが、全文の順序が変わる＝判断の入力が変わる。採らない（全文は変えない）。

## 決定

1. **接頭辞は「前文＋当日の日報方針の節」だけ**（本判断 `DecisionCacheablePrefix`・一次 `ScreeningCacheablePrefix`）。`Build` / `BuildScreening` はこの関数で先頭を書く（同じ関数から作るので全文と食い違わない）。
2. **送る直前に `全文.StartsWith(接頭辞, Ordinal)` を確かめ、合わなければ接頭辞を付けずに全文を送る**（`LlmPrompt.Split`）。食い違いは「キャッシュが効かない」に留まり、モデルが読む本文は変わらない。
3. **ポートは既定の実装つきの多重定義で足す**（`ILlmCompletionClient.CompleteAsync(LlmPrompt, model, purpose, ct)`。既定は全文を従前の多重定義へ渡す）。ゲートウェイへ送る実装と Stage 0 の中継だけが上書きする。model・purpose・max_tokens は変えない。
4. **費用 = 残り×入力 ＋ 書き×書き単価 ＋ 読み×読み単価 ＋ 出力×出力**（残り＝全体−書き−読み。負は 0）。段（Haiku 5.5 の 100K）は全体の入力トークン数で選ぶ。取れない（null）ときは従前どおり高い側の段で、金額の式の入力は 0。
5. **単価の行に書き・読みの単価（`CacheWritePer1kTokens` / `CacheReadPer1kTokens`、第 2 段は `LongContextCacheWritePer1kTokens` / `LongContextCacheReadPer1kTokens`）を任意で持たせる。** 値は MSP の単価表を 163.71 円/USD で換算する（既存の行と同じ丸め）。
6. **書き・読みの単価が無い（未設定・解析できない・0 以下）と、書き＝入力単価×1.25、読み＝入力単価で数える。** 未知モデルの計上単価・表が空のときの既定ペアも同じ。行は外さない（入力・出力の単価は正しいため）。

## 結果

- 良い影響: 当日の 2 回目以降の呼び出しで、方針の節がキャッシュから読まれる（読みは入力の 1/20〜1/10 の単価）。計上がキャッシュの欄に追随し、過大の側のずれが消える。
- 悪い影響: 接頭辞が 512 トークン未満の日（方針が短い日）はキャッシュされない（エラーにはならない）。読みの率は PoC で見る（仕様書 §PoC での確かめ方）。

## 残余

1. 報告書（ReportService）は接頭辞を渡さず、計上の式も従前のまま（書き・読みは 0 で返るため金額は同じ）。報告書で接頭辞を使うときは同じ式へ移す。
2. 単価が無い行の読みを入力単価で数えるのは過大の側である。単価の設定漏れは、PoC で計上の 1 回あたりの金額が下がらないことで気付ける。
