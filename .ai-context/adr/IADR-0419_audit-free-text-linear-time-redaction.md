# IADR-0419: 監査の自由記述の伏せ字を線形時間の照合へ替え、壁時計の打ち切りを無くす

- 状態: Accepted
- 日付: 2026-09-25
- 決定者: claude（起票 #984。利用者レビューは PR で受ける）

## 起点・関連

- 対象 Issue: #984（`AuditFreeTextTests` が高負荷で断続的に赤）。
- 関連する実装仕様書: [20260925_984_audit-free-text-linear-redaction](../specs/20260925_984_audit-free-text-linear-redaction.md)
- 関連 IADR: [IADR-0405](IADR-0405_s3-audit-followups-broker-order-id-and-free-text-bound.md) 決定2（自由記述欄の線引きと上限）。
  **本 IADR は決定2 の最後の項（正規表現の形と「200 ms で打ち切られたら文面を載せず、整形できなかった旨だけを残す」）を置き換える。**
  線引き（何を伏せ、何を伏せないか）・畳み・上限 500 文字は**変えない**。

## コンテキストと課題

- IADR-0405 決定2 は、伏せ字の正規表現に 200 ms のマッチタイムアウトを持たせ、`RegexMatchTimeoutException` なら理由文を
  定型文「（理由文は整形できなかったため記録しない）」へ置き換えた（伏せ字を保証できない文面を台帳へ入れないため）。
- マッチタイムアウトは**壁時計**で測る。CPU が混むとスレッドが走れない時間も予算を食う。実測（作業仕様書）: 2 万文字の照合は
  CPU で数 ms・入力長に線形だが、負荷下で 16 スレッド × 20 回 × 6 種の照合のうち **1,920 回中 724 回が打ち切られ**、
  壁時計は最大 50 秒だった。試験は 3 プロセス同時 × 4 巡で 12 回中 2 回赤。
- 🔴 **本番でも同じ条件で理由文が台帳から黙って欠ける**（7 年保持の監査台帳に「整形できなかった」だけが残る）。結果が入力ではなく
  実行時の混み具合で決まっていた。

## 検討した選択肢

1. **予算を伸ばす** — どの値でも「混めば捨てる」が残る（実測の最大 50 秒）。**却下**。
2. **入力長の上限を先に切ってから照合する** — 伏せ字は文面を縮める（長い URL → 5 文字）ので、出力の先頭 500 文字を決める入力の長さを
   上から抑えられない。切れ目が接続先の途中に落ちると形が崩れて伏せ損ねる。壁時計の予算も残る。**却下**。
3. **旧パターンのまま予算だけ無くす** — 実測では線形だが、線形であることの保証がバックトラック・エンジンの挙動の論証頼みで、
   選択肢の追加で 2 乗化しても気付けない（今度は台帳の購読が CPU を食い続ける）。**却下**。
4. **手書きの走査器** — 線形は読めば分かるが、5 つの形の境界規則を手で写す量が大きく、写し違いの危険が高い。**却下**。
5. **`RegexOptions.NonBacktracking`（入力長に線形。.NET が保証する）へ替え、予算を持たない**（採用）。

## 決定

1. **伏せ字の照合は `RegexOptions.NonBacktracking` で行い、マッチタイムアウトは `Regex.InfiniteMatchTimeout` を明示する**
   （未指定だとプロセスの `REGEX_DEFAULT_MATCH_TIMEOUT` で壁時計の予算が戻る）。`RegexMatchTimeoutException` の捕捉と
   定型文への置き換えは**削除する**。伏せ字の結果は入力だけで決まる。
2. **NonBacktracking が持てない構文は、同じ意味の形へ書き換える。**
   - 語の先頭の条件（後読み）→ 直前の 1 文字（または文字列の先頭）を消費する。伏せるのは名前つきの組 `e` だけ。
   - 語の終わりの条件（先読み）→ 直後の 1〜2 文字（または文字列の末尾）を消費する。
   - ホスト名の「英字を含む」（先読み）→ 英字が最初のラベルにあるか後のラベルにあるかの 2 通りの選択肢。
   - 原子グループ → 外す（旧パターンでも `:` がクラスに無いので結果は同じ）。
3. **消費した前後の文字は隣の接続先の境界を兼ね得る**（例 `[::1]1.2.3.4`・`1.1.1.1 2.2.2.2`）ので、`Regex.Replace` ではなく
   `Match(text, startat)` を繰り返し、**次の照合は伏せた `e` の末尾の 1 文字手前から始める**。
4. **意味が変わっていないことは旧パターンとの差分試験で固定する**（T-10-980。旧パターンは試験の中にだけ参照実装として残し、
   予算を持たせない）。予算を持たず線形時間の照合であることは型の中の全 `Regex` を見る試験で固定する（T-10-981）。

## 理由

- 監査台帳は 7 年消せない（NFR-10）。記録するかしないかが CPU の混み具合で変わるのは、監査証跡として成り立たない。
- 「伏せ字を保証できない文面は載せない」という IADR-0405 の安全側の判断は、**保証できない場合が無くなる**ことで満たされる
  （線形時間で必ず終わる照合）。捨てる分岐を残す理由が無い。
- NonBacktracking の線形性は .NET の文書が保証する性質であり、パターンの書き方に依らない。

## 結果・残余リスク

- 良い影響: 是正後に本番で理由文が捨てられる条件は**無い**（変わるのは従来どおり上限 500 文字での切り詰めだけ）。
  試験の 2 万文字の反復入力 6 種のうち 5 種で CPU 時間は数 ms から 1 ms 未満へ下がった（作業仕様書の計測）。
- 接続先が密に並ぶ入力（例 `1.1.1.1 ` の反復）では照合 1 回あたりの固定費が効き、旧形より遅い（32 万文字で最大約 90 ms。旧形は約 20〜35 ms）。
  入力長に比例する範囲であり、台帳へ入る理由文の実測の最長級（約 250 文字）では問題にならない。
- 線引きを意図して変えるときは、試験の参照実装（旧パターン）も同じ変更で改める必要がある（差分試験が赤で知らせる）。
- `Match(text, startat)` の繰り返しで前後の `e` が重ならないことは、`[` で終わる `e` が URL だけで URL の直後が区切りか末尾である
  ことに依る（コードのコメントに記す）。差分試験 5,000,000 件（試作）で重なりは 0 件。
