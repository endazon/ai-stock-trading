# IADR-0510: 参照の無い側のテスト ID を改番し、テストコードが使うテスト ID の採番を検査する（#1240）

> 実装リポジトリ内の意思決定記録（Implementation ADR）。1 ファイル = 1 意思決定。
> 計画リポジトリの ADR（`ADR-XXXX`）とは別系統（`IADR-XXXX`）とし、実装に閉じた決定を記録する。

- 状態: **Accepted**
- 日付: 2026-10-08
- 決定者: Claude Code（実装）。起点 [#1240](https://github.com/endazon/ai-stock-trading/issues/1240)（#1239〔#1217〕の独立監査の 🟡 を範囲外として切り出したもの）

## 起点・関連

- 関連する計画書 ID: FR-17（全体前提条件。テスト ID の帯 `T-17-…`）・FR-10（既定値の試験を載せるテスト仕様書）。要求そのものは変えない
- 先行 IADR: **IADR-0376**（テスト ID の既存の重複は改番せず baseline へ記録する。本 IADR はその決定 1 の**例外を 1 つだけ**定める）・IADR-0280（IADR 番号の欠番受容。テスト ID の規約の「思想」の出典であり、テスト ID を直接拘束する決定ではない）・IADR-0177（`T-17-01`〜`04` を採算の境界試験に使った #461）・IADR-0508（`T-17-05`〜`13` を足した #1217）
- 作業仕様書: `.ai-context/specs/20261008_1240_t17-test-id-collision.md`（母集合の表・選択肢の比較・検査の実測）

## コンテキストと課題

テスト ID `T-17-01`〜`T-17-04` が 2 つの試験を指していた。

| 意味 | 在り処 | 外部の参照 |
| --- | --- | --- |
| A: リスク統制・取引ガード・段階の**既定値**（`TradingDefaultsTests`） | `docs/tests/FR-10_risk-guard-core-tests.md` の表（2026-07-09 から） | **0 件**（テストコードにも `.ai-context/` にも無い） |
| B: 最小期待利益の**解が無い境界**（`CostCalculatorTests`。#461） | テストコードのコメント・作業仕様書 `20260808_461_…`（凍結） | テストコード 2 か所・作業仕様書 4 行 |

さらに #1217 が B の続きとして `T-17-05`〜`T-17-13` をテストコードと IADR-0508（凍結）にだけ書き、
`docs/tests/*.md`（採番の単一情報源）には載せなかった。検査器の出す採番の最大値は `T-17-4` のままで、
次の採番者は `T-17-05` 以降を**さらに別の意味で**採り得た。

`check-test-traceability` の検査 4（T2。#887）は `docs/tests/*.md` の**中だけ**で一意性を見る。
B はテストコードの側にしか無かったので、T2 には何も見えていなかった。

### 改番を禁じる規則の確認

- `docs/tests/README.md`「再利用しない・改番しない・欠番は許す」と **IADR-0376 決定 1**（既存の重複 ID を改番しない）が、テスト ID の改番を禁じている。
- **IADR-0280 は IADR 番号の決定であり、テスト ID を拘束しない。** テスト ID の規約は「同じ思想に揃える」として引いているだけである。
- IADR-0376 が改番を禁じた理由は 3 つで、**いずれも外部参照に依る**: ①コードの書き換えを要求する ②どちらの出現を指すか外部参照からは決まらない ③凍結記録は追随できない。

本件の A は外部参照を 1 件も持たない。A を改番しても、①書き換えるコードは無く、②残る参照はすべて B を指し、
③凍結記録（作業仕様書 `20260808_461_…`・IADR-0508）はむしろ**正しい意味を指すようになる**。

## 検討した選択肢

| # | 選択肢 | 評価 |
| --- | --- | --- |
| 1 | **A（参照 0 件の側）を改番し、B を新しい FR-17 のテスト仕様書に `T-17-01`〜`13` として載せる** | **採用**。変更は表の 4 セル。外部参照は 1 件も書き換えない。曖昧さが無くなる |
| 2 | B（参照を持つ側）を別の帯へ改番する | **採らない**。テストコード 4 ファイル 11 か所の書き換えが要り、凍結記録（作業仕様書 `20260808_461_…`・IADR-0508）は書き換えられないので、旧番号が A を指す誤った参照として残る |
| 3 | 改番せず、B を表に載せて `T-17-01`〜`04` を重複の baseline へ記録する（IADR-0376 の形） | **採らない**。曖昧さを恒久化する。B を正とする参照しか無いのに、表の上では 2 つの意味が並び続ける |
| 4 | A を `T-10-…` の帯へ移す（issue の案 1） | **採らない**。既定値は全体前提条件（FR-17）の値であり、`T-17` の帯が正しい。帯を変える理由が無い |

## 決定

- **決定 1（改番の例外）**: 同じテスト ID が 2 つの試験を指し、外部の参照（テストコードのコメント・`.ai-context/` の記録・他の `docs/` 文書・コミット件名と CHANGELOG・issue / PR の本文）が
  **片側にだけ**在るときは、**参照を 1 件も持たない側**をその帯の最大値＋1 へ改番してよい。参照を持つ側の意味を正とする。
  改番した節には旧番号を注記する。**両側に参照があるときは IADR-0376 のとおり改番せず baseline へ記録する。**
  - 本件の適用: A を `T-17-14`〜`T-17-17` へ移した。B は新設の `docs/tests/FR-17_profitability-tests.md` に `T-17-01`〜`T-17-13` として載せた。
  - 参照の有無は**誤りの側の文字列で全文書を走査して**判定する（規則 9）。本件の走査結果は作業仕様書の表にある。
- **決定 2（検査 5＝T3）**: `scripts/check-test-traceability.js` は、テストの `.cs` に完全な形で書いた `T-<FR>-<N>` のうち、
  `docs/tests/*.md` がその帯を 1 件でも採番しているものが表に採番されていることを検査する。docs/tests に 1 行も無い帯
  （`T-6` / `T-16` 等。テスト仕様書が任意の機能要求）は対象外とし、件数だけ出力する。
- **決定 3（既知の未採番のラチェット）**: 導入時点で未採番だった 16 件（`T-10-…`）は `scripts/test-id-unassigned-baseline.json` へ
  理由つきで記録する。baseline に無い未採番・在り処の食い違い・解消済みの残置を赤にする（T3）。baseline の entry が
  マージベースの版より増えたら赤にする（T3b）。**宣言による例外は持たない**——未採番はテスト仕様書へ行を足せば常に解消できる
  （重複は改番できないことがあるので T2b には宣言が要るが、未採番にはその事情が無い）。基準の版に baseline が無い
  （本 IADR を導入する変更）ときは理由つきで skip する。

## 理由

1. **曖昧さを無くす変更のうち、最も小さい。** 変更は表の 4 セルと、FR-17 のテスト仕様書の新設だけである。テストコードは 1 行も変えない。
2. **IADR-0376 の理由をどれも破らない。** 同 IADR が改番を禁じた理由はすべて外部参照に依る。参照を持たない側の改番は、その前提の外にある。
   IADR-0376 のフォローアップは参照 0 件の重複の改番を「**単独では行わない**」とした。理由は、改番のたびに「どちらの出現か」の
   判断が要り、間違えると参照が別のテストを指すことだった。本件はその判断を人の走査で済ませ（作業仕様書に母集合を残す）、
   改番の後で使われ続ける側の取り違えを検査 T3 が捕まえる（表に無い番号をテストコードが使えば赤）。単独で行っても、
   同条が恐れた取り違えが黙って残る経路は塞がれている。
3. **#1240 が起きた経路を塞ぐ。** B は「テストコードが使うが表に無い」状態で生まれ、育った。T2 は表の中しか見ないので見えなかった。T3 はこの状態そのものを赤にする。
   導入前の実測で、T3 は `T-17-05`〜`T-17-13` の 9 件を検出した（陽性対照。作業仕様書に出力を残す）。

## 結果

- 良い影響: `T-17-01`〜`T-17-04` は採算の境界試験だけを指す。凍結記録の参照はすべて正しい意味を指すようになった。
  採番の最大値は `T-17-17` と出る。テストコードで新しい番号を使って表へ載せ忘れると CI が止まる。
- 悪い影響・トレードオフ:
  - **意味 A で採番済みの番号をコードが意味 B で使う形は、機械では捕まえられない**（#461 の当初の衝突はこの形だった）。
    表の行とコメントを突き合わせる手掛かり（メソッド名・クラス名）を書いていない行が多く、メソッド名とクラス名で照合する試作は
    1,007 種の ID を「不一致」と出して使えなかった。採番時に表の行を引く運用（`docs/tests/README.md`）が担う。
  - 略記（`T-17-01/02/03`・`T-10-917〜920`）の 2 つ目以降は拾わない。表の側の範囲表記（`T-10-917〜920`）と行頭の印つき
    （`🔴 **T-10-483**`）は T2 の解析が採番として数えないので、T3 では未採番として baseline に載っている。
  - テスト以外の `.cs`（実装のコメント）に書いた番号は対象外である。

## 残余リスク

- baseline の 16 件（`T-10-…`）は、表へ行を足すか表の書式を採番行の形へ直すまで残る。解消は別 issue で行う。
  ［2026-10-08 追記 / [#1242](https://github.com/endazon/ai-stock-trading/issues/1242)］**16 件とも解消した。** `T-10-483` は行頭の印を別の列へ移し、`T-10-917`〜`920` は範囲表記の 1 行を 4 行へ分け、`T-10-600`〜`607`・`609`（＋ T3 の対象外だった同じ帯の `T-10-608`）と `T-10-682`・`683` はテストコードの意味のまま `docs/tests/FR-10_risk-controls-tests.md` へ採番行を足した（改番なし）。**baseline は撤去せず `unassigned: []` で残す**——撤去すると T3b はマージベースに baseline が無いとして skip し、以後に entry を足す変更を止められなくなるため（作業仕様書 `20261008_1242_unassigned-test-ids-rows`）。
- 決定 1 の「外部参照が片側にだけ在る」の判定は人が走査して行う。機械検査は無い。
