# IADR-0380: 市場の開場判定を共有カーネルへ寄せ、閉場中は評価そのものを止め、保護の空白を声に出す

## コンテキストと課題

稼働 PoC（2026-09-22/23・SIMULATE・`stopLossMethod=1`）で、**米東 16:00 の引けから 5 時間後も市況 API への照会が
60 秒ごとに続いていた**。原因は `WeekdayMarketSchedule.IsOpen` が **UTC の曜日が土日でないか**しか見ていないことである。

1. **閉場中の終値で S1 の到達判定が成立し得る。** 閉場中の価格は終値のまま動かないので、**終値がラインを割った日は
   閉場中ずっと到達が成立し続ける**。発動すると成行の手仕舞いが出るが、**閉場中の成行はその場では約定しない**
   （翌寄りまで持ち越し、寄り値は終値と乖離し得る）。
2. 逆に**夜間・寄り前の急落からは守れない**。S1 が「開場中だけの保護」であることがどこにも書かれていない。
3. 閉場中も市況 API を叩き続ける（FR-01 の趣旨に反する）。

🔴 **実測で分かった重要な事実: 「市場の時刻構造」を写した純関数はリポジトリに既にあった。**
取引判断サービスの `MarketSessions`（米国 9:30–16:00 ET・半日 13:00 ET、東証 9:00–11:30 / 12:30–15:30 JST）と
`MarketCalendar`（`TimeZoneInfo` で市場ローカル時刻へ写す）である。**市場監視だけがそれを使っていなかった。**
一方で、その休場日・半日取引日は**構成注入で既定は空**であり、`deploy/` に設定が 1 件も無かった
（`grep -rn "Holidays\|HalfDays" deploy/` ＝ 0 件）——**取引判断サービスも、実配備では休場日を 1 日も知らなかった**。

## 決定

1. **「今その市場は場中か」の単一情報源を共有カーネルへ置く。** `MarketSessions` を
   `AiStockTrading.Shared.Kernel/Trading/` へ移し、同じ場所へ `MarketHours`（タイムゾーン変換＋休場日＋セッション時間の合成）と
   `MarketHolidays`（休場日・半日取引日の規則計算）を新設する。市場監視のポート `IMarketSchedule` は
   **市場を引数に取る**形へ改め（`IsOpen(Market, DateTimeOffset)` / `NextOpen(Market, DateTimeOffset)`）、
   実装 `MarketHoursSchedule` は構成の注入点だけを持つ。取引判断サービスの `MarketCalendar` も同じ `MarketHours` へ寄せる。
   - 🔴 **ポートは残す**（サービス自己所有の継ぎ目。外部カレンダー API へ差し替える余地は #21 のため）。
   - 🔴 **引数の無い旧ポートへ戻さない。** 引数が無いことが「全市場を一括で開場と読む」近似を許し、本件を生んだ。
   - 共有カーネルは `Contracts` しか参照しない葉である（`SharedKernelIsLeafTests`）。この制約は保たれる。
2. **閉場中は「到達だけ」ではなく評価そのものを止める（市場単位）。** 閉場している市場の銘柄は
   **1 回も価格照会しない**・評価記録を作らない・到達を出さない。どの市場も開いていない巡回は従来どおり早期 return する。
   - 「照会は続けて到達の発行だけ抑える」案は**採らない**。閉場中の価格は終値で凍っていて得られる情報がゼロであり、
     費用（FR-01）だけが残るからである。
   - 🔴 **保護を「弱める」変更ではない。** 閉場中に出した成行は翌寄りまで約定しないので、**出さないことが正しい**。
     次の開場の最初の巡回が生きた価格で判定し、そこで到達していれば成行が出る（寄りで約定し得る）。
3. **保護の空白を閉場のたびに 1 回だけ声に出す。** `StopLossLivenessReporter.OnMarketClosed` を、
   市場・その市場の保有・次の開場時刻を受け取る形へ広げる。保有ごとに「ライン・最終観測値・到達していたか」を並べ、
   **最終観測値が既にラインを越えていた保有があれば Critical**、無ければ Warning で出す。
   開場して最初に評価できた巡回で「保護を再開した」Information を 1 回出す。既出の印は**市場ごと**に持つ。
   - 🔴 **黙って忘れさせないことが目的である。** 建玉は次の寄りまで無保護であり、その事実は fail-loud で出す
     （fail-close ——「不安だから閉じる」——には倒さない。出口は決して塞がない）。
   - 何も知らない閉場（再起動直後で保有を照会していない）では**何も出さず、既出にも数えない**。
     「保有 0 件」と「照会していない」を混同させない（本サービス全体の規律）。
4. **休場日・半日取引日は規則計算（コード）を基礎とし、構成は「足す」側だけにする。**
   規則は NYSE / Nasdaq が休場とする 10 日（元日・キング牧師記念日・ワシントン誕生日・グッドフライデー・戦没者追悼日・
   ジューンティーンス〔2022 年以降〕・独立記念日・レイバーデー・感謝祭・クリスマス。曜日規則と土日振替を含む）と、
   半日取引日 3 規則（独立記念日前日・感謝祭翌日・クリスマスイブ）である。
   - 🔴 **日付表を持たない＝期限が無い。** 表は必ず期限を持ち、**期限が切れたことは「平常どおり動いている」ようにしか
     見えない**（更新を促す別の仕組みが要る）。曜日規則で完全に決まるものを表に落とす理由が無い。
   - 構成（`Monitor:Holidays:<Market>` / `Monitor:HalfDays:<Market>`、取引判断は `TradeCycle:*`）は
     **臨時休場（国葬・服喪・災害）を足すためだけ**に使う。**規則を外す経路は作らない** ——
     外せる経路は、設定ミスを「閉場中に終値で損切りを回す」側（本件の事故）へ倒す。
   - **東証の休場日は射程外**（国民の祝日法に依存し、春分・秋分は天文計算になる）。週末＋構成のままで、#21 で扱う。
5. **取引判断サービスも同じカレンダーを見る。** 2 つのサービスが「今は開場か」で食い違うと、
   片方が開場と読んで発注し、片方が閉場と読んで保護を止める組み合わせができる。

## 🔴 記録する挙動変更（黙って変えない）

| 変更 | 前 | 後 |
| --- | --- | --- |
| 米国株の監視 | UTC の平日なら 24 時間 | 米東 9:30–16:00・休場日と半日取引日の午後は止まる |
| 日本株の監視 | UTC の平日なら 24 時間 | JST 9:00–11:30 / 12:30–15:30（昼休みは止まる）。休場日は構成のみ（#21） |
| **取引判断サイクルの起動** | 構成が空だったため**米国市場の休場日にも起動していた** | 規則計算の休場日には起動しない |
| 市況 API の照会 | 閉場中も 60 秒ごと | 開場している市場の銘柄だけ |
| 閉場時のログ | 無音（状態を捨てるだけ） | 市場ごとに 1 回 Warning（到達済みを含むときは Critical） |

**取引を弱める向きの変更（サイクルが起動しない・監視が止まる）は、いずれも「市場が閉じている時間帯」に限られる。**
出口（損切り・手仕舞い）が塞がれる時間帯は増えていない —— 閉場中はもともと約定しないからである。

## 採らなかった案

- **閉場中も照会を続け、到達の発行だけ抑える。** 得られる情報はゼロ（終値で凍る）で費用だけが残る。
  「閉場中に到達していたこと」を知りたくなるが、それは終値とラインの比較であり、引け際の最終観測で既に分かる。
- **休場日を日付表（ハードコード or 構成）で持つ。** 期限が切れたことが無音である（決定4）。
- **閉場中に到達が成立していたら指値・逆指値を予約する。** 発注の作り方を変える判断であり、ADR-0040 / IADR-0344 の
  射程を越える。本 ADR は**観測と抑止**までに留める。
- **未知の市場を開場として扱う（fail-open）。** `MarketSessions` は既定で閉場と答える（ADR-0003「不確実なら取引しない」）。
  `Market` は 2 値で到達不能であり、既存の規律を曲げてまで変える理由が無い。**到達可能になったら再考する**（下の残余リスク）。

## 結果・残余リスク

- 🔴 **S1 は通常取引時間しか保護しない。** 夜間・寄り前の急落からは守られない。これは
  **IADR-0344 の追記 (13)**・`docs/functional/FR-10_risk-controls.md`・**日報 §3 の注記**・
  **S1 配置通知（`SoftwareStopArmed`）の文面**へ開示する（コードのコメントに留めない）。
- 規則計算の誤り（規則改定・臨時休場）は「閉場と読んで保護が止まる」側へも倒れ得る。
  **閉場と読んだ最初の巡回は必ずログに出る**ため、誤りは無音にならない。
- 再起動が閉場中に起きると、その閉場期間の保護の空白は出せない（保有を照会していないので何も知らない）。
  発注執行の常駐ガード（IADR-0210 決定4）は Active な S1 行を別に見ているため、行そのものは失われない。
- 東証の休場日は規則計算を持たない（構成のみ）。日本株は取引対象外（監視・検証用）であり、**#21 の射程**。
- 未知の市場は閉場と読む（`Market` は 2 値で到達不能）。3 値目を足すときは、足した側が本 ADR を読み直すこと。
- 半日取引日の規則が外れると、その日の 13:00–16:00 ET の保護が止まる（年 3 日・最大 3 時間）。
  倒れ方は「成行を出さない」側であり、無保護のまま成行が滑る側ではない。
