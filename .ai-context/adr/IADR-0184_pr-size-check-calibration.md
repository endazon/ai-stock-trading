# IADR-0184: PR サイズ検査の較正（#473）

> 実装リポジトリ内の意思決定記録（Implementation ADR）。1 ファイル = 1 意思決定。

- 状態: Accepted
- 日付: 2026-08-14
- 決定者: Claude Code（実装）

## 起点・関連

- **NFR**（運用保守）
- 実装 issue: **#473**（受け入れ基準 1）
- 正本: `planning/tools/impl-handoff-kit/repo-template/.github/workflows/pr-size.yml`（kit `e0bc81c`・pin `cff0e7b`）
- 参照実装: MSP#704（MSP/IADR-0181。**同じキットを同じ方針で較正した先例**）
- 作業仕様書: [20260814_473](../specs/20260814_473_guide-enforcement.md)

## コンテキストと課題

運用ガイド §1 は「見込み diff 400 行超の PR は分割を検討する」を規範として置くが、実装リポには測る仕組みが無かった。キットが `pr-size.yml`（warn 方式・しきい値 400）を配布しており、**新規に設計する課題ではなく、キットへ追随して較正する課題**である（MSP が #703 で同じ結論に至っている）。

キット自身が「除外パターンはプロジェクトに応じて調整すること」「しきい値を動かす場合もまず実測してから」と明示しており、**`EXCLUDES` は逸脱ではなく想定された調整点**である。

## ★ 決定 1: **しきい値 400・warn 方式・警告文・permissions は 1 文字も変えない。固有デルタは `EXCLUDES` に限る**

400 は issue #473 と正本 §1 の両方が名指しした数値である。動かせば動かした側が説明責任を負う。**失敗させない**（warn のみ・マージは止めない）こともキットの明文であり変えない。出力先は `GITHUB_STEP_SUMMARY` のみで PR コメントを投稿しないため、`pull-requests: write` を持たない点もそのまま保つ。

## ★★ 決定 2: **`EXCLUDES` は「本リポに実在する生成物・非実装文書」だけで構成する**

### 実測（develop 直近の squash マージ 30 PR・2026-08-14。ワークフローが実行する式そのもの）

| 数え方 | 400 行超 | 中央値 | 最大 |
| --- | ---: | ---: | ---: |
| 除外なし | **19 / 30 ＝ 63%** | 553 | 4,110 |
| **本決定の EXCLUDES** | **10 / 30 ＝ 33%** | 211 | 3,390 |

60 PR へ窓を広げると 26 / 60 ＝ 43%。**MSP（23% / 31%）より発火率は高い**が、これは本リポの大玉 PR（例: #438 の 3,390 行・#435 の 1,897 行）が**単一 issue の実装＋テスト**として正当に大きいためであり、警告文自身が「分割すると実装を歪める束ねならそのままでよい」と書いている。**しきい値の側を動かして発火率を下げることはしない**（決定 1）。

### キット既定との差分と根拠

| 操作 | パターン | 根拠 |
| --- | --- | --- |
| 追加 | `planning` | 計画 submodule の pin。1 行だが実装 diff ではない |
| 追加 | `CHANGELOG.md` | `changelog.yml` の生成物。automation/ の PR は差分の大半がこれになる |
| 削除 | `**/pnpm-lock.yaml` / `**/orval/**` / `**/*.po` | **本リポに 1 ファイルも存在しない**（`git ls-files` で実測 0 件）。当たらない除外を残すと「効いている」と誤読される。MSP/IADR-0181 の「生成物は設定ファイルが指す出力先で決まる。自リポの設定を見て書く」と同じ規律 |
| 維持 | `docs/**` / `feedback/**` | 必須文書（作業仕様書・IADR・環流記録）は issue を細かく割るほど増える＝本検査の目的に対して逆向きに動く指標（MSP 実測: 必須文書だけで中央値 393 行） |
| 維持 | `**/Migrations/**` | EF Core のマイグレーション（Designer / スナップショット含む）。生成物 |
| 維持 | `**/*.lock` / `**/package-lock.json` / `**/*.generated.*` | ロック・生成物の一般形（`frontend/package-lock.json` が実在） |

## 決定 3: **本リポ固有の検査器・テストは足さない**

キットの `pr-size.yml` は自己完結のワークフローであり、`scripts/` に呼び出し口を持たない。回帰テストで固定すべき「消えたら困る規範」は正本（ガイド §1）とキット側にあり、本リポ側で二重化しない。

## 結果

- 良い影響: 400 行超の PR が**マージ前に**可視化される（従前は誰も測っていなかった）。除外前後の両方を出すため、除外の妥当性をその場で検算できる
- 悪い影響・トレードオフ: 発火率 33% は MSP より高く、警告が読み流される危険がある。**まず運用し、雑音が実害になったら実測を添えて較正し直す**（キットの明文どおり「まず実測してから」）
- フォローアップ: required check には**しない**（warn 方式の趣旨に反する。required check の扱いは [IADR-0185](IADR-0185_required-check-contexts-and-blocked-record.md)）
