# IADR-0173: 最小期待利益の税込み基準

- 状態: Accepted
- 日付: 2026-08-07
- 決定者: 実装（Claude Code）／ 起点 [#358](https://github.com/endazon/ai-stock-trading/issues/358)
- 作業仕様書: [20260807_358_minimum-expected-profit](../specs/20260807_358_minimum-expected-profit.md)

## コンテキストと課題

**計画 §4 は 2026-07-23 に「往復費用＋税の 2 倍」で確定したが、実装は 2 点で乖離していた。**

| | 実装（〜本作業） | 計画 §4 |
| --- | --- | --- |
| 倍率 | **1.5** | **2** |
| 基準 | **往復費用のみ**（税なし） | **往復費用＋税** |

原因は時系列である —— 計画は `fbe162f` 時点では未確定の「&lt;1.5 倍&gt;」で、`4f594cb`（2026-07-23 利用者決定）で確定した。**2026-07-18 の実装は確定前の暫定表記をそのまま既定値にしていた**。[IADR-0021](./IADR-0021_trading-assumptions-configuration.md) が「最小期待利益倍率 1.5 は**確定値**」と書いていたのは、**倍率については誤り**である。

**着手時点で計画適合テストが緑だったのは、値が一致していたからではない。** `KnownPlanDeviations` に #358 を担当とする登録行があったためである（[IADR-0127](./IADR-0127_plan-conformance-known-deviation-registry.md) の運用）。

### 本作業の難所 — **税をどう算入するかは計画に書かれていない**

計画 §4 は「往復費用＋税の 2 倍 を下回る取引は見送り」とだけ書き、**「税」が何に対する税かを定めていない**。#358 も「税の算入方法は §1 譲渡益税率 20.315% と整合させる。**設計判断は IADR に記録**」として実装へ委ねている。

**自明ではない理由は、税が結果に依存することである。** 日本の譲渡益税は譲渡益（＝ 利益 − 費用）に掛かるため

```
税 = (期待利益 − 費用) × 税率
```

であり、**税を知るには利益が要るが、求めたいのはその利益のしきい値**である。素直に書くと循環する。

## 決定

### 決定1: しきい値は **不動点として解く**

```
T = m × (C + (T − C) × r)          m = 倍率 / C = 費用 / r = 譲渡益税率
⇔ T = m × C × (1 − r) / (1 − m × r)
```

`m = 2` / `r = 0.20315` で **T ≈ 2.684 × C**（旧実装 `1.5 × C` の約 **1.79 倍**）。

**本式は「税引後で費用の m 倍が残る」ことを意味しない。** 計画が書いているのは「利益が**費用と税の合計**の m 倍以上であること」であり、本式はそれをそのまま解いたものである。**計画の文言に忠実であることを、解釈で綺麗にすることより優先した。**

### 決定2: 🔴 **`m × r ≥ 1` は解が無い —— fail-closed へ倒す**

分母 `1 − m × r` が 0 以下になると、**どれだけ利益が大きくても条件を満たせない**（利益を増やすと税も同じ速さで増え、要求が伸び続ける）。

**このとき負のしきい値を返すと、あらゆる取引が採算成立になる。** 統制が最も強く効くべき構成異常で、統制が完全に消える。`Threshold` は `null` を返し、採算ゲートは `Indeterminate`（＝見送り）へ倒す。

現行値では `2 × 0.20315 = 0.4063` で余裕があるが、**倍率も税率も運用で変更できる設定値**であり、この状態は実際に到達し得る。

### 決定3: 式の**単一情報源**を `Shared.Contracts` に置く

同じ式を必要とするのは設定サービスの `CostCalculator` と取引判断の `ProfitabilityGate` であり、**両者は別ユニットの Domain で互いを参照できない**（`ProfitabilityGate` の既存方針「Domain を設定サービスに依存させない」）。両者が既に参照している `AiStockTrading.Shared.Contracts` へ純関数として置く。

**式を 2 か所に書くと、片方だけ直したときに気付けない。** これは [IADR-0172](./IADR-0172_plan-risk-defaults-value-level-conformance.md) 決定3（規制側の値も表に入れる）と同じ「検査されない複製を作らない」規律である。

### 決定4: 税率は `TradeCostAssessment` で運ぶ

採算ゲートは Domain にあり設定サービスへ依存できないため、税率は既存の費用見積り DTO に載せて渡す。既定値 `0m` を持たせ、**税率を渡さない呼び出しは従来式へ退化**する（既存の呼び出しを壊さない）。

## 理由

- **決定1 は「計画の文言をそのまま解く」ことに尽きる。** 別解釈（税引後の利益が費用の m 倍）も文法上は可能だが、それは計画が書いていない読み替えである。**解釈を足すなら計画側で裁定すべき**であり、実装が確定させるべきではない（後述の環流）。
- **決定2 は決定1 の代償である。** 不動点を導入した以上、解が存在しない領域が生まれる。**その領域を「気付かないまま全通過」にしないことが、この変更の安全性そのもの**である。

## 結果

- **実効しきい値が `1.5 × C` から `≈ 2.684 × C` へ上がる**（約 1.79 倍）。通過する取引は減る。
- `KnownPlanDeviations` から #358 の行が消え、**計画適合が登録行なしで成立する**。
- **[IADR-0076](./IADR-0076_trade-decision-profitability-gate.md) 決定 7 を撤回した。** 同決定は「計画 05 §4 は『往復費用＋税』を挙げるが……税は後続に委ねる」と述べていたが、**その計画 §4 は 2026-07-23 の利用者決定で既に確定していた** —— つまり「後続に委ねる」は**計画からの逸脱**であった。本 ADR がこれを正す。
- 次の **5 文書**の誤った記述に**日付付きの訂正**を入れた（本文は書き換えず point-in-time 記録として残す）: [IADR-0021](./IADR-0021_trading-assumptions-configuration.md)／[IADR-0076](./IADR-0076_trade-decision-profitability-gate.md)（決定 7 と §影響の「税の非対応」）／`docs/specs/20260718_trade-decision-profitability-gate.md`／`docs/specs/20260710_configuration-assumptions.md`／`docs/data/trading-assumptions.md`。

  **「税は後続」という記述は 5 か所に散っていた。** 1 か所でも残すと、次に読んだ者が**現行と矛盾する記述を根拠に判断する**——本リポジトリが [IADR-0166](./IADR-0166_plan-source-digest.md) で繰り返し戒めてきた「古い記述が確かめた気にさせる」形そのものである（**本 PR のレビュー指摘で 2 か所の漏れが判明した**）。

### 悪い影響（記録する）

- 🔴 **実効倍率が大きく上がるため、通過する取引が減る。** 安全側ではあるが、**Stage 1 の最小取引件数（100 件）に到達しにくくなる**可能性があり、段階昇格の実績に影響し得る。**運用開始後に実測で見直す前提**である（計画 §4 も「値は運用で調整」と書いている）。
- **`m × r ≥ 1` の fail-closed は「解が無い」場合だけを捕まえる。** 「解はあるが極端」（例 `r = 0.49` / `m = 2` で 51 倍）は捕まえない —— **統制は止まらないが、事実上すべての取引が見送りになる**。値域の検証は本作業の範囲外である。
- **見積りの税は実際の課税と一致しない**（損益通算・繰越控除・NISA 区分を無視する）。**過大に見積もる方向であり安全側**だが、精緻な税額ではない。
- **「税」の解釈が計画で確定していない。** 本 ADR は不動点解を採ったが、**これは実装の判断であり計画の裁定ではない**。下記のとおり環流する。

## 計画への環流

**「往復費用＋税の 2 倍」の「税」の算入方法は、実装の判断で確定させるべきではない** —— 実効倍率が 1.5 → 2.684 へ変わり、**発注件数に直接効く**ためである。
