# IADR-0000: 実装意思決定の記録方針

- 状態: Accepted
- 日付: <YYYY-MM-DD>
- 決定者: <氏名 / 役割>

## コンテキストと課題

実装中に下す技術・設計・運用の判断（内部構成、ライブラリ選定、命名/配置規約など）には、後から経緯を辿れる記録が必要である。計画リポジトリの ADR は上流（プロダクト全体）の意思決定を扱うため、実装に閉じた判断の記録先が別途要る。

## 検討した選択肢

- 記録しない（コミット履歴のみ）。
- 計画リポジトリの ADR に混在させる。
- 実装リポジトリに独立した実装ADR（IADR）を設ける。

## 決定

実装リポジトリに **実装ADR（`docs/adr/`、ID は `IADR-XXXX`）** を設け、重要な実装判断を 1 ファイル = 1 意思決定で記録する。計画ADR（`ADR-XXXX`）とは ID 体系・配置を分離する。

## 理由

- 計画と実装の意思決定を混同せず、トレーサビリティを保てる。
- 実装の経緯がリポジトリ内で完結し、レビュー・引き継ぎが容易になる。
- 計画に影響する決定は `/plan-feedback` で計画側へ環流でき、責務が明確になる。

## 結果

- 良い影響: 実装判断の透明性・追跡性が向上する。
- 悪い影響・トレードオフ: 記録の手間が増える（重要判断に限定して軽減する）。
- フォローアップ: `/new-spec adr` で IADR を採番作成し、`docs/adr/README.md` の一覧を更新する。
