# IADR-0225: 為替の出典を「静かな期間」にも証拠づける

## コンテキストと課題 —— **平常時こそ出典が出ない**

遷移でしか発行しないため（IADR-0196 決定1）、台帳に残るのは次の 4 通りだけである。

| 台帳にある記録 | 証明できること |
| --- | --- |
| `FxRateSourceFellBack(SourceName)` | **その源を使った** |
| `FxRateSourcePrimaryRestored(SourceName)` | **第一の源へ戻して使った** |
| `FxRateStale` / `PositionClosedWithStaleFxRate` | レートを使った（**源の名前は分からない**） |
| **記録なし** | 🔴 **何も分からない**（静かに第一の源を使った／為替を一度も使わなかった、の区別が付かない） |

**そして「記録なし」が平常時の姿である。** その結果、日報の為替欄は平常時に
「出典: **記録からは特定できません**」としか書けなかった。

> 🔴 **証拠が無いのに書くよりは正直である。しかし「毎日出る正直」は読み飛ばされる。**
> IADR-0196・IADR-0199 が 2 度残余リスクとして予告した形であり、
> **読み飛ばされる行は、隣にある本物の警告（要確認・鮮度警告）まで一緒に読み飛ばさせる。**

**やらない選択もあり得た。** ADR-0022 §利用条件（2026-08-05 裁定）により、日銀 API 側の
クレジット義務は「サービスを公開した場合」の条件付きであり、**私的運用では発生しない**。
**それでも解いたのは、同じ裁定が「報告書への出典明記の方針は維持する」と明記しているからである**
——**掲げた方針が平常時に一度も満たされない状態は、掲げていないのと区別が付かない。**

## 決定

### 決定1: **(通貨, 源, 暦日) を鍵に、1 日 1 件の「使用記録」を発行する**

`FxRateSourceUsed(Quote, SourceName, Rank, TotalSources, OccurredAt)` を新設し、
`FxSourceStatusTracker.OnSourceUsed` が遷移を返さないときに**当日・当該源で未発行なら 1 件だけ**返す。

**抑止の形は鮮度警告と同じ暦日抑止である**（IADR-0198 決定2）。暦日は **UTC**（IADR-0096 決定4 の慣行）。
**洪水は防いだまま**であり、`OnStale` で既に検証済みの形をそのまま当てている——
**新しい抑止の形を発明しない**（形が 2 つになると、どちらが正しいかを毎回考えることになる）。

🔴 **鍵に源の名前を含める。** フォールバック中に源が入れ替わっても（rank 2 → rank 3）**遷移は起きない**。
含めないと**実際に使った源が台帳に残らない**——本 ADR が解こうとしている穴と同じ形の穴が残る。

### 決定2: **遷移イベントは、その日の使用記録を兼ねる**

`FxRateSourceFellBack` / `FxRateSourcePrimaryRestored` は **`SourceName` を運ぶ＝使用の証拠そのもの**である。
遷移を発行した日は (源, 暦日) を記録済みとして印を付け、**同じ事実を 2 件台帳へ入れない。**

**`OnSourceUsed` の戻り値は従来どおり「1 件または `null`」に保つ。** 2 件返す形にすると、
呼び出し側（`PublishingFxSourceStatusNotifier.PublishIfAny` の**巻き戻し**）まで作り替えることになる——
**巻き戻しは「発行できなかった事実」を状態へ正確に戻す唯一の場所**であり、そこを複雑にする対価が見合わない。

### 決定3: 🔴 **巻き戻しは「多めに出る」側へ倒す**

発行に失敗したときの `Rollback` は使用記録の印を消す。**消しすぎても当日に 1 件余分に出るだけ**だが、
消し損ねると**その日にどの源を使ったかの証拠が永久に欠ける。**

> **欠測と重複は対称ではない。** 重複は読めば分かるが、**欠測は「使わなかった」と区別が付かない**
> ——それは本 ADR が消そうとしている状態そのものである。

### 決定4: **集計型に `Usages` を足す。ただし `IsClean` には入れない**

**使用記録は劣化ではない。** `FxSourceStatus.IsClean` へ混ぜると
**平常運転の日が「劣化あり」と読める日報になる。** 否定形のテストで固定した。

### 決定5: **通知（Discord）へは流さない**

監査は「**全イベント**を記録する」（FR-11）が、**通知は選んだ事象だけを出す**
（IADR-0198 副次② が母集合の違いを明記している）。**平常運転の記録を毎日 Discord へ流すのは、
劣化の通知を埋もれさせるだけである。** `NotificationConsumerCoverageTests` の母集合はアセンブリ内の
ハンドラであるため、**足さないことが規約違反にもならない。**

### 決定6: **出典の文面を 3 分岐にする**（証拠が増えたことで**旧文が誤りになった**）

🔴 **是正のたびに「この変更で新たに誤りになる自分の記述」を引き直す**（`traceability.repo.md` 規則 10）。
旧文は「記録からは特定できません（情報源の記録は**切替時にのみ残る**ため…）」であり、
**本 PR 後は理由の部分が事実と違う。** さらに **FRED だけを使った期間**では
「**使った源は分かるが、その源はクレジットを求めていない**」という、旧文が想定していない状態が生じる。

| 台帳の状態 | 出す文面 |
| --- | --- |
| クレジットを要求する源を使った証拠がある | `- 出典: <クレジット文言>`（従来どおり） |
| 使った源は分かるが、その源はクレジットを要求しない | `- 出典: <源名>（クレジット表記を求めていない情報源です）` |
| **使用記録が 1 件も無い** | `- 出典: **記録からは特定できません**（期間内に情報源の使用記録が残っていません）` |

あわせて、**第一の源（rank ≤ 1）の使用記録がある平常日**に限り、劣化なしの文へ
「**第一の情報源（<源名>）から取得できており**」を戻した。

> **IADR-0199 決定5 がこの文言を外したのは「証拠が支えていない主張」だったからであって、
> 文言そのものが誤りだったからではない。証拠ができたので戻す。**
> **証拠が無ければ従来の文のまま**である（否定形テストで固定済み・既存テストが不変で通る）。

## イベントを 1 種増やしたことの追随（**CI が強制する 4 点**）

**母集合は記憶で挙げず、`FxRateSourcePrimaryRestored` と `PositionClosedWithStaleFxRate` の
2 つの文字列でツリー全体を走査して引いた**（規則 5・9。走査の生の出力と除外理由は作業仕様書）。

| 追随 | 実体 | 強制する機械 |
| --- | --- | --- |
| **識別子の固定** | `EventMessageTypeNameTests` の `[InlineData]` | `識別子固定の対象はイベント型の母集合と完全に一致する` |
| **監査ハンドラ** | `FxRateSourceUsedAuditHandler` ＋ `AuditEntryFactory.From` | `AuditConsumerCoverageTests`（母集合＝**全イベント**） |
| **契約基準の再生成** | `event-schemas.baseline.json`（`UPDATE_EVENT_BASELINE=1`） | `全イベントが基準に登録されている_追加は許容するが記録漏れは許容しない` |
| **ハンドラの実行テスト** | `AuditEventConsumersTests.為替の情報源の使用記録は_通貨ごとの相関で台帳へ記録される` | —（Wolverine ホストを実走させて発見漏れを見る） |

**相関は切替・復帰と同じ `fx-rate-source:{Quote}`** に置いた——通貨ごとの 1 本のタイムラインに
「使った・落ちた・戻った」が時系列で並ぶ。**別相関にすると期間の追跡が 2 本に割れる**（IADR-0196 決定6）。

## 影響

- 肯定的:
  - **平常時に出典が出る。** 「記録からは特定できません」が、証拠のある期間から消える。
  - **「第一の情報源から取得できており」が根拠つきで書ける**（IADR-0199 が外した文言の回復）。
  - **フォールバック中に源が入れ替わっても、実際に使った源が台帳に残る**（従来は遷移が無く空白だった）。
- 否定的 / トレードオフ:
  - **イベントが 1 種増える**（監査のキューが 1 本増える。通知は増やさない・決定5）。
  - **台帳の行が 1 日あたり「通貨 × 使った源」ぶん増える**（現状 USD/JPY のみで日 1〜2 件）。
  - **再起動した日は使用記録がもう 1 件出る**（状態は in-memory・決定3 と同じ「重複側へ倒す」向き）。

## 残余リスク

- **暦日は UTC** であり JST の日付境界とずれる（IADR-0196 から不変）。
- **抑止はプロセスごと**。水平展開すると台帳にインスタンス数ぶんの使用記録が入る（**重複であり欠測ではない**）。
- **`Audit:BaseUrl` 未設定の環境では従来どおり「要確認」が出る**（IADR-0199 から不変。結線は構成による opt-in）。
- **「為替を一度も使わなかった期間」と「照会できた が記録が無い期間」は今も同じ文面になる**
  （どちらも「使用記録が残っていません」）。**使わなかったことを積極的に記録するイベントは作らない**
  ——**起こらなかったことの記録は際限が無い。**
