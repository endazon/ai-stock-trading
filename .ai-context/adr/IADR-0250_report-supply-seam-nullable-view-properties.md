# IADR-0250: 報告サイクル拡張の供給は ReportView の nullable プロパティを継ぎ目にする

- 状態: Accepted
- 日付: 2026-08-28
- 決定者: claude（起票 #338。利用者レビューは PR で受ける）

## 起点・関連

- 関連する計画書 ID: FR-06（報告書の階層管理）・FR-16（数値はコード集計）・ADR-0016 決定15・ADR-0027 決定4
- 関連する実装仕様書: [`20260828_338_reporting-cycle-and-templates.md`](../specs/20260828_338_reporting-cycle-and-templates.md)

## コンテキストと課題

計画大改定で `04_report-templates.md`（fixed）が拡張され、報告書へ **6 種類の新しい記載事項**が加わった
（三者比較・統制作動状況・LLM 利用実績・為替差損益・空売り・OpenD 稼働率）。
それぞれ供給元が異なり、**本 PR で結線できるのは監査台帳から引ける 2 種類だけ**である
（LLM 利用実績・借株料）。残る 4 種類は本リポジトリ内に供給元が存在しない。

ここで最も起こりやすい誤りは、**供給が無い期間を「0」「なし」と描いてしまう**ことである。
既存の節（強制買戻し・為替の情報源）は同じ罠を 2 度踏んでおり、そのたびに
「**照会できていない**」と「**事象が無かった**」を別物として扱う規律が積み上がってきた
（IADR-0159 決定3 / IADR-0196 決定3 / IADR-0199 決定4）。

## 検討した選択肢

1. **供給ごとにポートを増やし、未結線のものは登録しない**
2. **供給を `ReportView` の nullable プロパティに集約し、結線できるものだけアダプタを持つ**（採用）
3. 供給が無い節は描かない（節ごと出さない）

## 決定

**決定1: 新しい供給はすべて `ReportView` の nullable プロパティとして表す。**
`null` ＝**照会できていない**、空の値 ＝**事象が無かった**。両者を同じ描画へ潰さない。

**決定2: 結線できない 4 種類にもポートを作らない。** 常に `null` を返すだけのポートと
DI 登録は、**動いていない配管を「ある」ように見せる**。
`ReportView` の nullable プロパティ 1 本があれば、供給が入った時点で継ぎ目はそこ 1 箇所で済む。

**決定3: 供給が無くても節は描く**（選択肢 3 を採らない）。節が無いことは
「該当が無かった」とも「出し忘れた」とも読める。**計画が求めた節が出ていないこと自体が差異**であり、
「照会できませんでした」と明記することでその差異を報告書の読み手へ届ける。

**決定4: 未結線であることをテストで固定する。** 未供給の描画（否定形）だけでなく、
**供給されたときに正しく出ること（対の肯定形）**を必ず対で置く。
不在の表明だけでは、節が丸ごと壊れていても緑になる。

## 理由

- **失敗の向きを揃えない。** 同居する `HttpPeriodFillSource` は供給不達を**空列**へ倒すが、
  これは「報告書は発注判断を行わないため欠測が過大発注へ繋がらない」という限定的な理由による。
  本 PR が足す供給はいずれも**統制・費用の記録**であり、0 と書くことが直ちに誤読を生む。
- **ポートを増やさない方が、後から結線するときのコストが小さい。**
  常に null のポートは「登録されているのに何も供給しない」状態を作り、
  結線の有無を composition root のテストで区別できなくする。

## 結果

- 良い影響: 供給の有無が型（`null` かどうか）で表れ、描画側が両者を混ぜる書き方をしにくい。
- 悪い影響・トレードオフ: 三者比較・稼働率・為替差損益は当分「照会できませんでした」と出続ける。
  **読み手には「まだ供給が無い」と正しく伝わる**が、節としては空に見える。
- フォローアップ:
  - 三者比較の供給（バックテスト結果 × 発注先別実績の横断集計）
  - OpenD 稼働率の期間照会 API（`Stage1SessionUptime` の権威源はリスク管理サービスにある）
  - 為替差損益の供給（台帳が**換算前の外貨額と換算レート**を保持していないため、台帳側の変更が要る）
