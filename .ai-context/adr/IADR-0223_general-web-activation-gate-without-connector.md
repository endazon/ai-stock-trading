# IADR-0223: 一般 Web 収集は「発動条件の判定と記録」だけを実装し、取得経路は作らない

- 状態: Accepted
- 日付: 2026-08-28
- 決定者: claude（起票 #336。利用者レビューは PR で受ける）

## 起点・関連

- 関連する計画書 ID: FR-01 / FR-11（記録）/ ADR-0020 決定4（発動条件 4 件）/ ADR-0005（有料化の判断プロセス）
- 関連する実装仕様書: [`.ai-context/specs/20260828_336_information-collection-tiers-and-degradation.md`](../specs/20260828_336_information-collection-tiers-and-degradation.md)

## コンテキストと課題

ADR-0020 決定4 は、一般インターネット収集（許可リスト外の一般サイトからの取得）を
**4 条件をすべて満たす場合に限り、利用者の承認を得て次回月報までの暫定措置として**用いると定める。
発動・解除はいずれも監査ログに残し、月報へ記載する。

「発動条件を実装する」の範囲が決定点である。**取得コネクタまで作るのか、条件の判定と記録に留めるのか。**

## 検討した選択肢

1. **判定と記録だけを実装し、取得経路は作らない**（採用）
2. 一般 Web コネクタも併せて作り、承認フラグで有効化する — **承認前に「使えるもの」が存在する。**
   フラグ 1 つで規約違反・誤情報の取り込みが起こり得る状態を、条件が成立してもいないうちから作ることになる。却下
3. 判定も実装しない（運用の判断に委ねる） — **条件のない「最終手段」は運用時の裁量になる**という
   ADR-0020 §課題3 がそのまま残る。却下

## 決定

1. **`GeneralWebActivationPolicy`（Domain・純関数）が 4 条件を AND で判定する。**
   条件1 の境界は**欠測 5 営業日以上**（または提供終了・有料化の公表）であり、
   **満たしていない条件をすべて列挙して返す**（「だいたい満たしている」を作らない）。
2. **暫定期限は次回月報＝翌月 1 日 00:00Z** とする。承認されたときだけ期限が付く。
3. **申請は `POST /internal/collection/general-web-activation`（OwnerOnly）で受ける。**
   run-once（OwnerOrService・IADR-0176 決定1）とは**非対称**であり、これは意図である ——
   ADR-0020 決定4 は**利用者の承認**を要件としており、無人サービスが自動で発動してよいものではない。
4. **発動・解除は `GeneralWebCollectionStateChanged` 1 契約で表す**（2 系統を購読させない）。
   監査台帳へ記録し、**種別 × 期間の照会（IADR-0199 決定2）で月次集計から引ける**形にする。
   相関はカテゴリごとに分け、発動と解除を 1 本で辿れるようにする。
5. **一般 Web からの取得は実装しない。** 条件が成立し利用者が承認した時点で、
   別 issue として取得経路を起こす。

## 理由

- **承認前に取得経路を置かない**のは、統制の対象そのものを「あとはスイッチ 1 つ」の状態にしないためである。
  ADR-0020 が 4 条件を課したのは裁量を排するためであり、実装で裁量を復活させない。
- **記録先を監査台帳にしたのは、月報の集計が既にその経路を持つからである**（IADR-0199 が日報の為替欄のために
  開けた `GET /audit/events/by-type`）。新しい保存先を作ると、**7 年保持の台帳とは別の記録が二重にできる。**
- **月報テンプレートへの描画は本 PR の対象外**である（報告サイクル＝#338 の射程）。
  本 PR の到達点は**台帳の期間照会で引けること**であり、テストもそこまでを固定している。

## 結果

- 良い影響: 「最終手段」が条件を持ち、発動が記録として残る。条件を満たさない申請は理由つきで拒まれる。
- 悪い影響・トレードオフ: **発動しても実際に一般 Web から取得する手段は無い。**
  条件が成立したときに追加の実装が要る（意図した順序である）。
  また**解除の申請経路は用意していない**（発動と同じ契約で表せるが、endpoint は発動側のみ）。
- フォローアップ:
  - 月報テンプレートへの記載（発動理由・対象カテゴリ・期間・裏取りの成否）は #338 で結線する。
  - 解除の操作面（Discord Bot もしくは同エンドポイントの拡張）は、発動が実際に起きる時点で決める。
