# IADR-0475: 監視銘柄の権威源が読めないときに構成の既定へ倒さない（#1134）

> 実装リポジトリ内の意思決定記録（Implementation ADR）。1 ファイル = 1 意思決定。
> 計画リポジトリの ADR（`ADR-XXXX`）とは別系統（`IADR-XXXX`）とし、実装に閉じた決定を記録する。

- 状態: **Accepted**
- 日付: 2026-10-01
- 決定者: Claude Code（実装）。統制の値（リスク統制・取引ガードの既定値）は変えない

## 起点・関連

- 関連する計画書 ID: FR-02（定時サイクルの判断対象）・FR-13（監視銘柄の変更が判断へ届く）
- 計画 ADR: ADR-0044（監視銘柄は権威源〔市場監視〕から読み、読めなければ「不明」）
- 起票: [#1134](https://github.com/endazon/ai-stock-trading/issues/1134)
- 関連する実装仕様書: [`.ai-context/specs/20261001_1134_watchlist-no-fallback.md`](../specs/20261001_1134_watchlist-no-fallback.md)
- 改める: [IADR-0095](IADR-0095_watchlist-authoritative-wiring.md) 決定 3 のうち「照会失敗（非 2xx・timeout・例外・不正応答）は構成 watchlist へ委譲する」。未結線（`MarketMonitor:BaseUrl` 未設定）で構成を使う部分は有効のまま
- 前提: [IADR-0435](IADR-0435_watchlist-driven-finnhub-collection-symbols.md)（情報収集の直前値）・[IADR-0440](IADR-0440_structured-watchlist-in-decision-prompt.md) 決定 2（プロンプトの口は不明を返す）・[IADR-0446](IADR-0446_report-monitor-cost-read-grpc-stage4.md)（gRPC 実装。倒す向きは REST と同じ）

## 背景

2026-09-30 09:59 UTC にクラスタを一斉に再起動した直後、取引判断は市場監視より先に起動し、
「監視銘柄（watchlist）を権威源から読めないため、既定 watchlist（構成）へフォールバックします」を出して、
定時サイクルの判断対象を構成の `TradeCycle:Watchlist`（経路 B では AAPL のみ）へ切り替えた。閉場中のため実害は無かった。
場中に同じことが起きれば、利用者が SC-02・Discord で決めた監視銘柄ではなく構成の銘柄で判断する。ADR-0044（権威源は市場監視）と食い違う。

IADR-0095 決定 3 は「前回値キャッシュ」を「追加の状態を持たない」理由で却下し、構成の既定を採っていた。
構成の既定は「運用者が明示制御できる決定的な既定」だが、**利用者が決めた監視銘柄とは別の一覧**であり、本番既定は構成の一覧を持たない（空＝判断しない）一方、経路 B は持つ（AAPL）——再起動の直後の判断対象が配備ごとに変わる。

## 決定

### 決定 1: 定時サイクルの口は、読めなければ直前に読めた一覧、一度も読めていなければ不明（null）

- `IWatchlistProvider.GetWatchlistAsync` の戻り値を `IReadOnlyList<WatchedSymbol>?` にする。null＝不明。
- `HttpWatchlistProvider` / `GrpcWatchlistProvider` は構成の供給口を持たない。読めた行は従来どおり寛容に読み（`ToCycleWatchlist`）、その結果（空を含む）を直前の値として覚える。
  読めなければ直前の値を返し、一度も読めていなければ null を返す。この倒す向きは REST と gRPC で 1 つの定義（`HttpWatchlistProvider.ToCycleWatchlistOrLastKnown`）を共有する。
- `InformationCollectedHandler` は null のサイクルで**判断も発行もしない**（例外にしない＝再配送で同じサイクルを繰り返さない）。ニュースの状態の記録は従来どおり先に行う。
- 未結線（`MarketMonitor:BaseUrl`・`MarketMonitor:Grpc` のどちらも無い）では従来どおり `ConfigurationWatchlistProvider`（権威源が無いので代替ではない。後方互換）。

### 決定 2: 直前の値はプロセス内の singleton（`WatchlistLastKnown`）。永続化しない

- 供給口はスコープごと（Wolverine のハンドラごと）に作られるため、直前の値は外の singleton に置く（scoped だと次のサイクルで失われる＝T-10-1998）。
- 永続化（DB・ファイル）はしない。**再起動の後は不明から始まり、市場監視が答えるまで判断しない**（安全側）。永続の直前値は現状どこにも無い（母集合 5）。
- 期限は設けない。市場監視が落ちている間は監視銘柄の変更も受け付けない（変更の入口はいずれも市場監視へ書く）ため、直前の値は多くの場合いまの値と同じである。食い違うのは「市場監視は動いているが取引判断からだけ読めない」窓に限られる（残余）。

### 決定 3: ログは障害ごとに 1 回

- 読めた → 読めないへ変わったときに Warning 1 回（一度も読めていなければ「見送ります」、読めた後なら「直前に読めた N 件（銘柄）で続けます」。どちらも「構成の既定 watchlist へは倒しません」と書く）。
- 回復（読めない → 読めた）で Information 1 回。障害の継続中は Debug。
- 照会そのものの失敗（非 2xx・例外・打ち切り）の Warning は従来どおり供給口が照会ごとに出す（変えない）。
- メトリクスは足さない（取引判断に監視銘柄の出所のメトリクスの前例が無い。情報収集の `finnhub_symbol_set_resolutions` と同型を足すなら別作業）。

### 決定 4: プロンプトの口は変えない（直前の値も使わない）

`GetAuthoritativeWatchlistAsync` は従来どおり読めなければ null（「監視銘柄: 不明」）。直前の値は「判断時点の監視銘柄」ではないため載せない（ADR-0044 決定 2。T-10-1999）。

### 決定 5: 情報収集・報告書・認証は変えない

- **情報収集**（`FinnhubSymbolSelector`）は直前値を既に持つ（IADR-0435）。一度も読めていないときの構成の固定リストは**収集にしか効かない**（判断対象は取引判断が決め、初回は不明で見送る）ので残した。
  収集も見送る形にすると、Finnhub の 2 ソースは 0 銘柄を「取得成功・0 件」と返し（ニュースを「取得済み」と偽る）、失敗へ倒すと再起動のたびに「ニュース系の全滅」へ倒れる。どちらも別の設計変更が要る。
- **報告書**の「見送り → 上限で縮退版を生成」は IADR-0352 の設計どおり（監視銘柄を読まない）。
- **サービストークンの取得の例外**（Keycloak の起動待ち）は失敗をキャッシュせず次の要求で取り直すため自己回復する。起動時に依存の readiness を待つ形（issue の案 2）は採らない。

## 窓（規則 11）

窓は「最後に読めた時刻（前の端）」と「いまのサイクル（後の端）」の間。形 A（後の端だけ＝読めなければ常に見送る）・形 B（前の端だけ＝是正前の構成）・形 C（両端＝採用）をプローブ 6 本で突き合わせた表は作業仕様書。

- A は読めた後の一過性の打ち切り 1 回で全銘柄の判断を 1 サイクル落とす。
- B は一斉再起動で構成の銘柄を判断する（#1134）。読めて 0 件の後も構成へ倒す。
- C は「減る側」（読めない間に削除された銘柄）で直前の一覧に残る。上の決定 2 の窓に限られる。

## 却下した代替案

- **起動時に市場監視の readiness を待つ**（issue の案 2）: 起動の順序を作るだけで、起動後の障害（市場監視の再起動）では同じ問題が残る。待つ間に他の常駐（急変・ガード）も止まる。
- **直前の値を永続化する**: 再起動をまたいで古い一覧で判断し得る。再起動の直後は不明（見送り）が安全側。
- **読めなければ常に見送る（形 A）**: 一過性の打ち切り 1 回で全銘柄のサイクルが落ちる（既定の照会の打ち切りは 5 秒）。
- **構成の既定を残し、起動直後だけ見送る**: 読めた後の障害で構成へ倒す問題（B の P4・P6）が残る。

## 結果

- 一斉再起動の直後、取引判断は市場監視が答えるまで定時サイクルの判断を見送る（構成の銘柄で判断しない）。答えた後は市場監視の一覧で判断し、その後の障害では直前の一覧で判断を続ける。
- `TradeCycle:Watchlist` は結線時には使われなくなる（経路 B の値は未結線に戻したときだけ効く）。
- 試験: T-10-1990〜T-10-1999。既存の試験のうち構成への委譲を表明していたもの（HTTP 6 本・gRPC 1 本・プロンプトの T-10-1544・契約 2 本の偽の供給口）を改めた。変異の表は試験仕様書。

## 残余リスク

- 「減る側」: 取引判断からだけ市場監視を読めない窓では、削除された銘柄を直前の一覧で判断し続ける（プロンプトの節は「不明」）。期限を足すなら値をオーナーに決めてもらう。
- 情報収集は一度も読めていないとき構成の固定リストで収集する（判断には効かない）。
- 定時サイクルの見送りはログだけで、メトリクスでは数えない。
