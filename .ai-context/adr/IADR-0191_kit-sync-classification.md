# IADR-0191: キット追随の分類表と機械検査

> 実装リポジトリ内の意思決定記録（Implementation ADR）。1 ファイル = 1 意思決定。

- 状態: Accepted
- 日付: 2026-08-14
- 決定者: Claude Code（実測でドリフト 5 件を検出したため）

## 起点・関連

- 計画書 ID: **NFR**（工程の統制。計画側の非機能要件表に当たる番号が無いため無採番。planning#311 の 2）
- 対象 Issue: [#492](https://github.com/endazon/ai-stock-trading/issues/492)
- 作業仕様書: [20260814_492_kit-sync-classification](../specs/20260814_492_kit-sync-classification.md)
- 先行実装: MSP#734（同リポの IADR-0192）
- 派生 Issue: [#493](https://github.com/endazon/ai-stock-trading/issues/493)（`check-doc-links.js` の穴）/ [#494](https://github.com/endazon/ai-stock-trading/issues/494)（環流 4 件）

## コンテキストと課題

**キット配布物への追随を、本リポジトリは一度も機械検査していなかった。**

実測（2026-08-14）で、**バイト一致であるべきファイルが 5 件ドリフト**していた。
同じ計測で基盤実装リポ microservices-platform は **0 件**である。

| リポジトリ | vs pin (`130a109`) | vs planning 最新 (`3144424`) | 仕組み |
| --- | --- | --- | --- |
| **ai-stock-trading** | 一致 60 / **差分 5** | 一致 60 / **差分 5** | **無し** |
| microservices-platform | 一致 65 / 差分 0 | 一致 65 / 差分 0 | 有り（分類表＋検査器） |

**pin と最新で結果が同一である**ことを先に確かめた —— キット側は動いておらず、
**pin 遅れではなく本リポ側のドリフトである。**

### 🔴 これは「緑だが検査されていない」の一種である

CI は緑であり続けたが、**キット追随という範囲がそもそも検査対象に入っていなかった。**
[IADR-0190](IADR-0190_review-verdict-gate.md) が扱った「判定なしの success」と同じ型であり、
**差は「検査が甘い」ではなく「検査が無い」**である。

### 🔴 ドリフトの方向はばらばらであった

**一律にキットで上書きする解決は誤りである。**

| 方向 | 件数 | 例 |
| --- | ---: | --- |
| 本リポが**遅れている** | 1 | `check-ai-workflow-config.js`（キットの検出機能を丸ごと欠く） |
| 本リポが**進んでいる** | 2 | `check-permission-denials.js`（`hasQuotedPipe()`） |
| **双方向にずれている** | 1 | `commit-allowlist.json`（方針文を互いに独自に持つ） |
| **正当なデルタ**（分類が誤り） | 1 | `.editorconfig`（xUnit1051 の抑止＝スタック固有） |

> 🔴 **［訂正］初版はこの表で `commit-allowlist.json` を「遅れ」に数え、分類表にも
> 「方針文はキットへ揃えた」と書いていた。どちらも誤りである。**
> 実際は**双方向**であり、**揃えていない**（本 PR で当該ファイルは 1 バイトも変更していない）。
> **AI レビューが「分類表の記述が実態と食い違う」として検出した** ——
> **本 ADR は「検査されていなかったものを機械検査する」ことを主題にしながら、
> その分類表自身に事実と異なる記述を置いていた。**
> **機械検査は分類表の「内容の正しさ」を見ない**（後述の残余リスク）ことの実例である。

## 決定

### 決定1: 分類表（A/B/C/対象外）をリポジトリに置く

**どのファイルがどの分類かを記した表が無ければ、機械判定を回す対象が決まらない。**
`scripts/kit-sync-classification.json` に**キット 108 件すべて**を分類する。

- **A（72 件）**: バイト一致であるべき。**機械検査の対象。**
- **B（11 件）**: キット土台＋固有デルタ。**理由を必ず書く。** 4 種（1 構成 / 2 スタック / 3 固有成果物 / 4 Actions 版）
  のどれにも当たらないものは **X** とし、**追跡先の issue 番号を必須**とする。
- **C（17 件）**: 本リポの中身そのもの、または置換点を持つ配布物。同期しない。
- **対象外（8 件）**: `*.example.yml`（本リポは有効化済みの実名を持つ）。

### 決定2: `check-kit-sync.js` を置く。**ただしキットの複製ではない**

MSP 版のコメントは **MSP の issue 番号を裸で引用している**（`#713` 等）。
**そのまま複製すると本リポジトリの issue を指す誤リンクになる**
（`.claude/rules/traceability.md`「クロスリポジトリの issue / PR 番号の修飾」）。書き直した。

> **本ファイルはまだキットに無い**ため、**分類 C として置く**。キットが採用したら分類 A へ移す。
> **その時点で初めてバイト一致が要求される。**

### 🔴 決定3: CI では `--require-planning` を必須とする（fail-open を CI では閉じる）

検査器は planning が未 populate なら **skip（exit 0）** する。ローカル環境差で CI を落とさないためである。
**しかしこの fail-open を CI にそのまま持ち込むと、致命的になる。**

**本リポジトリの CI は、どのジョブも submodule を取得していなかった**（実測: `ci.yml` に
`submodules` の指定が 0 件）。**素朴に配線すれば、この検査は永久に skip して緑を返し続けた。**

- `--require-planning` を付けると、**未 populate は skip ではなく fail** になる。
- `kit-sync` ジョブだけは `submodules: recursive` ＋ `PLANNING_REPO_TOKEN` で submodule を取得する。
- **両方が揃って初めて実効する。** 片方でも落ちれば検査は死ぬため、**CI 設定側を回帰テストで固定した**
  （`ci.yml` の当該ジョブが `submodules: recursive` と `--require-planning` を持つことを検査する）。

### 決定4: PR 段階で落とす（夜間ジョブに置かない）

planning を要する既存検査は夜間の `doc-links-planning.yml` に分離されている。
**キット追随はそこに置かない。** ドリフトは **PR が持ち込むもの**であり、夜間に初めて赤くすると
**「PR に紐づかない赤」**になって放置される —— **その弱点は同ワークフロー自身のヘッダに
明記されている**（実運用で 14 夜連続の失敗が放置された実績がある、と書かれている）。

### 決定5: 進んでいる 2 件はキットの内容で上書きせず、環流する

上書きは改善を捨てることになる。**分類 B（X・環流候補）とし、追跡先を [#494](https://github.com/endazon/ai-stock-trading/issues/494) に置いた。**
反映されたら分類 A へ戻す。

## 対照実験（実走した実測）

**「壊して赤を実測する」形で行った。** 緑のまま「効いているはず」とは書かない。

| # | 壊し方 | exit | 予測 |
| ---: | --- | ---: | --- |
| 1 | 分類 A のファイルを 1 バイト変える | **1**（`[drift]`） | 一致 |
| 2 | 分類表から 1 件落とす | **1**（`[unclassified]`） | 一致 |
| 3 | キットを空にする | **1**（0 件走査／照合 0 件） | 一致 |
| 4 | キットのパスを外す（`--require-planning` 無し） | **0**（skip） | 一致 |
| 5 | キットのパスを外す（`--require-planning` 有り） | **1** | 一致 |

**回帰テスト自体も変異試験で確かめた**（3 通りとも意図した assertion で赤になった）。

| 変異 | 落ちたテスト |
| --- | --- |
| CI から `--require-planning` を落とす | 「未 populate 時に skip して緑になり、検査が実効しない」 |
| CI から `submodules: recursive` を落とす | 「submodule を取得していない」 |
| 分類表の X から追跡先 issue 番号を消す | 「X 分類なのに追跡先の issue 番号が無い」 |

## 影響

- 肯定的:
  - **キット追随という検査されていなかった範囲に、初めて網が掛かった。**
  - **配線しただけで実効しない形（永久 skip）を、設計と回帰テストの両方で塞いだ。**
  - 取り込んだ `check-ai-workflow-config.js` が**即座に実在の欠陥を検出した**
    —— `claude-coding.yml` に `Bash(sed:*)` が無く、レビュー用とだけ非対称であった。対称にして解消した。
- 否定的 / トレードオフ:
  - **分類 B の妥当性は機械では見ない。** 4 種のどれに当たるかは表に書くが、**内容の妥当性は人が判断する。**
    文字列一致では意味を読めない。
  - **キット側に新しい規範が入ったことは捕まえられない**（[IADR-0189](IADR-0189_plan-id-qualification-and-traceability-kit-sync.md) 決定5 と同じ限界）。
    本検査が見るのは**バイト一致**であって規範の移動ではない。
  - **`PLANNING_REPO_TOKEN` への依存が 1 ジョブ増えた。** トークンが失効すれば `kit-sync` は赤になる
    （**skip ではなく赤である**のが決定3 の趣旨だが、原因がキットのドリフトではないときも赤になる）。

## 残余リスク

- ✅ **［解消・2026-08-14 実測］`--require-planning` は実 CI で意図どおり働いた。**
  PR [#495](https://github.com/endazon/ai-stock-trading/pull/495) の初回 CI で **`kit-sync` は success**（14 秒）。
  ジョブログに **`Entering 'planning'`** が出ており、**submodule の取得に成功している**
  ——`PLANNING_REPO_TOKEN` は PR コンテキストで使える。
  **`--require-planning` を渡しているため、未取得なら fail していたはずである。**
  よって **success は「skip して緑」ではなく「実際に 108 件を突合して緑」を意味する。**
  決定4（PR 段階で落とす）の見直しは不要である。

  > **🔴 副次的に、隣接する設計前提が反証された。** `ci.yml` の `test-traceability` は
  > **「PR CI には `PLANNING_REPO_TOKEN` が無い」**ことを根拠に、計画書実在検査を PR では skip し
  > 夜間ジョブへ委ねている。**その根拠は成り立たない。** `doc-links` も同じ前提の上に立っており、
  > **2 つの検査が PR 段階で働いていない。** 夜間方式の弱点（PR に紐づかない赤が放置される。
  > 実運用で 14 夜連続の実績）は `doc-links-planning.yml` 自身のヘッダに書かれている。
  > **移行は [#496](https://github.com/endazon/ai-stock-trading/issues/496) で追う** ——
  > 移行時に溜まっていた破損が噴き出す可能性があるため、本 ADR の範囲では
  > **反証された前提のコメントを是正するに留めた。**
- 🔴 **本 ADR 自身が、索引行の追随漏れを 1 回起こした。** 本体を訂正しながら
  `docs/adr/README.md` の索引行を直さず、**AI レビューが検出した**（2 回目のレビュー）。
  **同型は [IADR-0190](IADR-0190_review-verdict-gate.md) でも起きており（自己試験の件数が索引だけ古いまま）、
  連続する 2 つの PR で 2 回**である。**「検査器の追加は同型事故 2 回から」の閾値に達したため
  [#497](https://github.com/endazon/ai-stock-trading/issues/497) を起票した**（構造的な検査。内容の一致は機械では見ない）。
  **それまでは規則 7 を人が守るしかなく、実績としては 2 回とも守れていない。**
- 🔴 **分類表は「今の姿」を固定するだけであり、分類そのものの正しさは保証しない。**
  誤って A を B へ移せば、**その差分は永久に検査されなくなる**。B へ移す変更は
  **人のレビューで見る**前提である（分類理由と追跡先の必須化は、その助けにすぎない）。
- **本リポが進んでいる 4 件は、環流されるまで分類 B に留まる**（[#494](https://github.com/endazon/ai-stock-trading/issues/494)）。
  **その間、配布先の他リポジトリは同じ穴を踏み続ける。**
- **`check-doc-links.js` の穴は本 ADR では直していない**（[#493](https://github.com/endazon/ai-stock-trading/issues/493)）。
  **仕様書からコードへのリンクは、現時点でも検査されていない。**
- **`check-kit-sync.js` 自体はキットに無い。** MSP と本リポが別々に実装した状態であり、
  **キットへ環流しないと 3 つ目のリポジトリは同じ穴を持つ。**
