# IADR-0460: 新規建ての損切り幅を構造化ログで観測する（#1104）

> 実装リポジトリ内の意思決定記録（Implementation ADR）。1 ファイル = 1 意思決定。
> 計画リポジトリの ADR（`ADR-XXXX`）とは別系統（`IADR-XXXX`）とし、実装に閉じた決定を記録する。

- 状態: **Accepted**
- 日付: 2026-09-30
- 決定者: Claude Code（実装）。観測の置き場所を選ぶ実装判断であり、統制（数値の下限）は決めない（planning#703 の裁定待ち）

## 起点・関連

- 関連する計画書 ID: FR-10（1 取引あたりリスク・銘柄別損切りライン）・FR-04（取引判断）・FR-02（価格文脈）
- 関連する実装仕様書: [`.ai-context/specs/20260930_1104_stop-width-observability.md`](../specs/20260930_1104_stop-width-observability.md)
- 前提:
  - [IADR-0003](IADR-0003_position-sizing-responsibility.md): サイジングは取引判断サービスが行う。
  - [IADR-0035](IADR-0035_stop-loss-authoritative.md): 損切り価格を `OrderIntent` に載せ台帳へ永続化する。
  - [IADR-0099](IADR-0099_current-price-context-for-decision.md) 決定2: 参照価格を権威ある現在値へアンカリングする。
  - [IADR-0451](IADR-0451_scheduled-decision-intraday-price-context.md): 判断の価格文脈に日中の高安（`IntradayPriceContext`）を持つ。

## 背景

計画（FR-10・05_trading-assumptions §5）は 1 取引あたりリスク 1% を「ATR 連動でサイズ算出」と定める。
実装は ATR を計算していない。損切り幅は LLM の出力 `stopLossDistancePerShare` をそのまま使い、検証は `0 < 幅 < 参照価格` だけである。
損切りラインはアンカリング済みの参照価格 ∓ 幅、株数は `floor(equity × 1% × 縮小係数 ÷ 幅)` を 1 注文 25% と残枠で上から抑えた値になる。
幅が狭いほど株数は増える（25% の上限が効くのは幅が 4% より狭いとき）。

それなのにコード・IADR・docs は「ATR 連動」と書き、実装が満たしているように読めた。
また、幅が当日の値動き（ノイズ）に比べて狭すぎるかを、運用のログから確かめる手段が無かった。
幅の数値の下限は計画側へ裁定を依頼した（planning#703）。

## 決定

1. **観測はログだけにする。監査イベント（共有契約）の項目は足さない。**
   - `TradeDecisionMade` / `OrderIntent` はすでにアンカリング済みの `Price` と `StopLossPrice` を運び、幅は両者の差として台帳から復元できる。
   - 足りないのは LLM の参照価格と日中の高安だが、どちらも判断時の観測量であり、発注・統制の入力ではない。
   - 共有契約（`AiStockTrading.Shared.Contracts`）へ足すと、発注執行・リスク管理・監査・報告書の購読側（直列化・台帳の列）を巻き込む。
   - planning#703 の裁定で下限を強制するときに、その統制の記録として契約へ載せるかを改めて決める。
2. **出す地点は、新規建ての損切りラインを算出した直後の 1 か所**（`TradeDecisionAppService`）。
   決済（Close）と見送りでは出さない（損切り幅を使わない、または発注意図を作らない）。判断（数量・損切り価格・見送り）は変えない。
3. **出す値**（構造化 Information ログ。計算は純関数 `StopWidthObservation.Of`）:
   - 銘柄・売買方向・株数・損切り価格
   - LLM の参照価格・アンカリング済みの価格・差（アンカリング済み − LLM。符号つき）
   - 1 株あたり幅・幅の比率（アンカリング済みの価格に対する %。小数 4 桁・四捨五入）
   - 日中の値幅（高値 − 安値）と、幅の値幅に対する倍率（小数 4 桁）。日中文脈は IADR-0451 の `IntradayPriceContext` から取る
   - 🔴 **高値・安値のどちらかが不明、または高値 ≦ 安値なら、値幅も倍率も「不明」と書く**（0 を書かない。0 除算しない）。
     現在値の供給が無い構成（既定 NoOp）では日中文脈そのものが無く、アンカリング済みの価格は LLM の参照価格と同じになる（差 0）。
4. **プロンプトへの指針（「損切り幅は当日の値動きより広く取る」）は足さない。** LLM への指示を変えると判断の挙動が変わり得るが、
   観測値が無いままでは効果を測れない。指示の要否は planning#703 の裁定と本決定の観測値を見て決める。
5. **「ATR 連動」の主張を直す。** コードのコメントと生きた文書（`docs/`）は「計画は ATR 連動を定めるが、実装は ATR を計算せず
   LLM の幅をそのまま使う（planning#703 の裁定待ち）」と書く。凍結記録（IADR-0003・IADR-0030・IADR-0035）は本文を残し、
   日付つき追記ブロックを足す。作業仕様書（`.ai-context/specs/`）は point-in-time の記録として書き換えない。
   `DefaultStopLossRatio`（実体 `StopLossApproximation.DefaultRatio`）の出典「§5 の『損切り幅3%』目安」は、現行の §5 に無い。
   旧版の §5（円建て資金の時期の「初期投入資金」行の備考）の目安であり、実装側の過渡的な近似値であると直す。

## 採らなかった案

- **`TradeDecisionMade` に観測値を足す**: 監査台帳（7 年保持）へ残せるが、共有契約の追加は購読側の互換性の確認と台帳の列の追加を伴う。
  観測の目的（幅が狭すぎないかを確かめる）はログで足り、統制の記録ではない（決定 1）。
- **メトリクス（ヒストグラム）にする**: 銘柄・日中の値幅との対応が失われ、1 件ずつの突き合わせができない。件数が少ない（1 日数件）ためログで足りる。
- **ATR を計算して幅を置き換える／下限を掛ける**: 統制の変更であり、planning#703 の裁定が要る。

## 結果

- 新規建てごとに、幅が価格の何 % か・当日の値幅の何倍かを運用ログから読める。
- **残余**:
  - ログの保持期間は監査台帳より短い。長期の集計が要るなら、planning#703 の裁定の後に契約へ載せるかを決める（決定 1）。
  - 現在値の供給が無い構成では日中の値幅が常に「不明」になる（IADR-0451 と同じ制約）。
  - Stage 0（`Stage0DecisionRecorder`）は発注しないため対象外。
  - 計画の「ATR 連動」と実装の差そのものは解消していない（planning#703）。

## ［2026-09-30 追記 / #1120］決定 1・決定 4 を改める（計画 ADR-0049 の裁定）

本文は書き換えない。planning#703 は計画 ADR-0049（利用者裁定 2026-09-30）で裁定され、下限（1.0 × ATR(14)。ATR が得られないときは参照価格の 2%）の強制を
[IADR-0465](IADR-0465_stop-width-floor-fallback-2pct-widen-and-audit.md) で入れた。

- 🔴 **決定 1（監査イベントの項目は足さない）を改める。** 下限は統制であり、ADR-0049 決定 3 が「監査に AI の幅・下限とその出所・適用した幅を残す」
  と求めた。`TradeDecisionMade` に既定 null の `StopWidth`（AI の幅・下限・出所・適用した幅・広げたか）を足した（IADR-0465 決定 2）。
  LLM の参照価格と日中の高安は引き続きログだけに出す（統制の入力ではない）。`OrderIntent` は変えない。
- 🔴 **決定 4（プロンプトへの指針は足さない）を改める。** ADR-0049 決定 5 が暫定運用として求めたため、本判断のリスク制約節に
  「損切り幅は当日の値動きより広く」の案内を足した（IADR-0465 決定 4）。
- 決定 3 の観測ログに下限・出所・適用した幅・広げたかを足した。`stopWidth`・比率・倍率は AI の幅のまま（意味を変えない）。
- 「結果」の残余のうち「Stage 0 は対象外」は観測ログについてであり、下限は Stage 0 のサイジングにも掛けた（IADR-0465 決定 5）。
  「計画の『ATR 連動』と実装の差」は、ATR が未供給で 2% が効いている差として残る（ATR の供給は ADR-0048 決定 3 の条件の後）。
