## コンテキストと課題

`.ai-context/adr/README.md` の索引行は **1 行が数千文字**に達する。決定の骨子に加えて、後から足した
**日付つき追記ブロック**（`［YYYY-MM-DD 追記 …］`）が同じ 1 行に積み上がっていくためである。

この形は、**マージの衝突解決で行の一部が黙って消える**。しかも消えたことが誰にも見えない:

- `git diff` は行単位でしか表示しない。数千文字の行の置換は「**1 行削除・1 行追加**」としか出ない。
  差分を読んでも、何が減ったのかは分からない。
- `check-adr-index-sync.js` は「本文を変更した IADR に索引行の**変更**があるか」しか見ない。
  **内容が減ったか**は見ていない。
- 残るのは「人／AI が**項目単位の和集合**で解決する」という約束だけである。**それが 2 回破られた。**

| # | 消えたもの | どう消えたか |
| --- | --- | --- |
| 1 | IADR-0210 ← `［2026-09-18 追記 / #820］` | develop の取り込みを**最長共通接頭辞**で解決し、2 つの追記が分岐する直前（`**［2026-09-1`）で行が切れた。別 PR の監査が発見し、両側の全文から再構成して修復した（`b6adebe3`） |
| 2 | IADR-0118 ← `［2026-09-19 追記 / #849］` | #851 の作業中に develop を取り込み、衝突を自分側で解決して約 260 文字を丸ごと落とした。**develop 上に現存した**（復元は PR #830 側） |

運用標準は「**検査器・規約の追加は同型の事故が 2 回起きたら**」である。**2 回に達した。**

さらに、書いた検査器を develop の直近 59 世代へ当てたところ、**3 件目**（IADR-0327 ←
`［2026-09-11 追記 / #743］`。`bdff6736` → `1cf92ed8`）が見つかった。**約束は 3 回破られていた。**
残る 57 ペアは緑であり、偽陽性は 0 件だった。

## 決定

### 決定 1: 索引行を「**印の多重集合**」として持ち、行の再構成の仕方に依らず「消えたこと」だけを見る

`scripts/check-adr-index-addendum-loss.js` を新設し、索引行（第 1 セルが `IADR-XXXX` のテーブル行）から
`［<日付> 追記 …］` を全部拾って **IADR 番号ごとの多重集合**にする。

- **行ごとに持つ理由**: 同じ印（`［2026-09-19 追記 / #866］`）が 3 行に現れる。ファイル全体で集合を比べると
  **行を跨いだ相殺**が起きる。
- **多重集合にする理由**: 同じ行に同じ印が 2 つ置かれることがある。集合だと 1 つ消えても気付けない。
- **印の中身は見ない。** 機械には読めない。見るのは「在ったものが在るか」だけである。
- **issue 番号を必須にしない。** 実データに `［2026-09-03 追記］`・`［2026-08-28 追記 / IADR-0259］`・
  `［2026-09-12 追記 / planning#123］`・`［2026-09-03 追記・決定 7/8］` がある。
  **番号を必須にすると実在する 10 件が検査の外に落ちる**（＝落ちたことに気付けない）。

### 決定 2: 3 つの版（`base` / `theirs` / `ours`）で判定し、**触っていない行には統合ブランチ側を要求しない**

- 規則 1（削除）: 印が `base`（マージベース）の行 R に在り `ours`（HEAD）の行 R に無ければ fail。
- 規則 2（衝突解決）: **我々が行 R を触ったとき**、印が `theirs`（統合ブランチ先端）の行 R に在り
  `ours` に無ければ fail。**3 件の事故はすべてこの形である。**
- 規則 3（不干渉）: 触っていない行は `theirs` を要求しない。統合ブランチが先へ進んだだけの PR は
  3-way マージで統合ブランチ側が採られるため、赤にする理由が無い。

`--range=A..B`（2 ドット）は厳格モード（`base = theirs = A`。A の印をすべて要求する）とし、
**過去の事故を再現データとして実走で固定する**ために使う。既定と CI は 3 ドット。

### 決定 3: 偽陽性を潰す —— ただし「印が残っているか」の判定は緩めない

IADR-0190 の「偽陰性より偽陽性へ倒す」は本検査にも当たるが、**この検査器は毎 PR で走る**。
規約どおりの是正（`.claude/rules/traceability.repo.md`「Markdown の明示リンクもテキストは短縮形」）を
赤にすると、**検査そのものが外される**。よって突合の前に印を正規化する:
`[表示](URL)` → `表示`、連続空白を 1 つへ。**印が丸ごと消えた場合は依然として赤になる**
（3 件目の IADR-0327 は明示リンク形のまま消えており、正規化を入れても検出できる）。

行の**並べ替え**・**散文の書き換え**・印の**追加**では赤にしない（決定 1 の持ち方から自動的に従う）。

### 決定 4: 意図的な撤去は**コミット本文で 1 件ずつ宣言**させる（allowlist ファイルにはしない）

`scripts/` の既存の作法を読んで決めた。

| 既存の手段 | 使われ方 | 本件に馴染むか |
| --- | --- | --- |
| `scripts/commit-allowlist.json` | `check-commit-messages.js`。**過去のコミット**（force push 禁止で件名を直せない）を SHA で恒久除外 | 馴染まない。本件は**これから行う撤去**であり、SHA は撤去の時点で存在しない |
| コミット本文の印 `[skip-adr-index]` | `check-adr-index-sync.js`。**その PR の作者が意図を宣言する** | 馴染む。同じ検査対象（ADR 索引）・同じ性質（作者の意図） |

→ コミット本文の印を採る。書式は次のとおりで、**行として単独**のときだけ発動する。

```
[remove-adr-addendum] IADR-0118 ［2026-09-19 追記 / #849］
[remove-adr-addendum] IADR-0118 *
```

- 🔴 **全体スキップは用意しない。** 検査を丸ごと黙らせる印は「とりあえず書いて通す」に使われ、
  **次の消失を隠す**。撤去した印を 1 件ずつ名指しさせ、`notice` で CI へ出す。
- 🔴 **行として単独のときだけ発動する。** 素朴な部分一致にすると、**この逃げ道を説明した文章そのものが
  逃げ道を発動させる**（`check-adr-index-sync.js` が自分自身で実測した自己発火）。
- 記録は commit に残る（＝ `git log` と PR に残る）。

### 決定 5: 射程は**索引行だけ**。索引の持ち方は変えない（別 issue）

同じ弱さは `.ai-context/adr/IADR-XXXX_*.md` 本体や `docs/` の trace ブロックにもあるが、
**事故が観測されたのは索引行**であり、まずそこだけに絞る（#875）。

**索引の持ち方を変える案（1 IADR = 1 行の要約に留め、決定の全文は本体だけが持つ）も評価した。**
根本原因は「1 行が数千文字であること」なので、これを直せば事故は構造的に消える。しかし
(a) 現時点で 9 本の PR が並走し、**全部が `.ai-context/adr/README.md` へ索引行を足す** ——
索引を組み替えると 9 本すべてと衝突する。(b) 索引行は「本文を開かずに決定の骨子を読む」ために
使われており、要約へ削ると `check-adr-index-sync.js` が守っている「本文と索引の同時更新」の
意味も変わる（同検査の射程の再設計が要る）。(c) **本検査器は索引の形に依存しない**
（印の単位で持つため、1 行が短くなっても効き続ける）。
よって**検査器を先に入れ、索引の持ち方は別 issue で扱う**。

## 残余リスク

- **3 件目（IADR-0327 ← `［2026-09-11 追記 / #743］`）は develop 上に現存したままである。**
  本 PR は索引行を 1 行しか触らない約束（並走 9 本との衝突回避）のため復元しない。**別 issue で復元する。**
  復元元は `git show bdff6736:.ai-context/adr/README.md` の当該行。
- **`.ai-context/adr/` 本体と `docs/` の trace ブロックは未保護である。**（決定 5）
- **印の形が変わると検出できない。** `［<日付> 追記` で始まる形に依存する。
  別形の追記記法を導入するなら、`MARK_RE` を同時に直すこと。
- **索引行の外**（README 冒頭の運用ルール等）の追記ブロックは対象外である。
