# IADR-0147: 裸ファイル名リンクを検査対象に含め、実在しないファイル名の例示リンクは `<...>` で囲む

> 実装リポジトリ内の意思決定記録（Implementation ADR）。1 ファイル = 1 意思決定。

- 状態: Accepted
- 日付: 2026-08-05
- 決定者: endazon（with Claude Code）

## 起点・関連

- 関連する計画書 ID（FR/UC/SC/ADR）: **NFR**（CI ゲート・ドキュメント整合）。計画書由来の機能ではなく
  CLAUDE.md「自動化・検証・安全」が定める CI ゲート（`doc-links` ジョブ）自体の性質に関する決定。
- 関連 issue: [#399](https://github.com/endazon/ai-stock-trading/issues/399)（発見は
  [#395](https://github.com/endazon/ai-stock-trading/pull/395) の AI レビュー指摘）
- 関連する実装仕様書: [作業仕様書 20260805（#399）](../specs/20260805_399_doc-links-bare-filename.md)
- 関連 IADR: [IADR-0143](IADR-0143_coverage-denominator-generated-code-exclusion.md)・
  [IADR-0145](IADR-0145_permission-denial-fixability-classification.md)（いずれも「検査器は効かない
  方向に壊れると CI が緑のまま気付けない」ため否定形を正の確認と同数以上置く先例）

## コンテキストと課題

`scripts/check-doc-links.js` はヘッダで「本文の Markdown リンク `[text](path)` を検査する」と宣言して
いるが、`isBrokenRef` の相対参照判定が `./` / `../` 始まりか `/` を含む形しか対象にしておらず、
**`/` を含まない同一ディレクトリ内の裸ファイル名は実在検査に到達しないまま素通り**していた。

`docs/adr/` の IADR 相互参照はこの裸の形で書くのが通例であり、**最も壊れやすい箇所がまるごと
検査対象外**という状態だった。実際 `develop`（`01fda7f`）上に破損 1 件が現存したまま CI は
`OK: 367 件` を報告し続けていた。判定を広げること自体に異論はない。

決めるべきなのは、**判定を広げた帰結として文書の「例示リンク」が実在検査に掛かる**問題の扱いである。
検査器の本文リンク走査（`/\]\(([^)]+)\)/g`）はコードフェンス・インラインコードを区別しない**既存の
設計**であり、判定拡張によってこの性質が初めて実害として現れる。実際、本件の作業仕様書が判定拡張を
説明するために書いた例示リンク 2 件がそのまま破損として検出された。

## 検討した選択肢

| 案 | 内容 | 評価 |
| --- | --- | --- |
| **A** | 例示リンクは `<...>` で囲む執筆規約を課す（検査器は変更しない） | **採用**。既存の除外機構（テンプレ変数）をそのまま使う。検出力を一切下げない |
| B | 本文リンク走査からコードフェンス／インラインコードを除外する | 棄却。`/` 形を含む**既存**の検出範囲まで狭める。フェンス内に本物の参照を書く文書があれば黙って検査対象外になり、まさに本 issue が是正しようとしている「効かない方向の劣化」を新たに作る |
| C | 除外リスト（検査しないファイル・リンクの列挙）を持つ | 棄却。破損を隠す道具になる。issue #139 で planning 配下 753 件の除外が破損 20 件の蓄積を生んだのと同型 |
| D | 裸ファイル名だけフェンス内を除外する（B の限定版） | 棄却。同じ記法が場所によって検査されたりされなかったりする二重基準になり、執筆者が結果を予測できない |

## 決定

1. **`isBrokenRef` の相対参照判定に「`/` を含まないが `LINK_EXT` に一致する裸ファイル名」を加える。**
   `.md` 限定にはしない——直後の行が既に `LINK_EXT`（md/yaml/json/puml/mmd/png/jpeg/svg/drawio）を
   要求しており、ここだけ `.md` 限定にすると同一ディレクトリの図・スキーマ参照が対象外に残り、
   判定の基準がファイル内で二重になる。
2. **拡張子（`LINK_EXT`）を必ず要求する。** 本文中の普通の語（`README` / `IADR-0119`）をリンク扱い
   しないため。裸の語まで対象にすると誤検出が常態化し、赤が読まれなくなる。
3. **インラインコード内の裸ファイル名は対象外のまま据え置く。** `collectBroken` の第 3 経路が
   `./` `../` 始まりのみを拾う設計を変えない（`` `IADR-0119_x.md` `` のような言及は参照ではない）。
4. **実在しないファイル名を示す例示リンクは `<...>` で囲む**（例: `[IADR-0119](<IADR-0119_xxx>.md)`）。
   検査器は `<` 始まりをテンプレ変数として既に除外しており、新しい記法・新しい除外機構を作らない。
5. **否定形テストを正の確認と同数以上置く**（[IADR-0143] / [IADR-0145] と同じ思想）。検査器は
   「効きすぎる方向」に壊れれば赤が出て気付けるが、「効かない方向」に壊れると**CI が緑のまま
   誰も気付けない**。本件はまさにその形で 1 件の破損を通し続けていた。あわせて**変異検査**
   （意図的に壊した裸ファイル名リンクを検査器が exit 1 で名指しすること）を常設テストに含める。

## 理由

決定4 が本 IADR の実質である。判定拡張（決定1〜3）は「宣言どおりに動いていなかった検査器を宣言に
合わせる」実装漏れの充足であり、それ自体は記録するほどの設計判断ではない。しかし決定4 は
**今後すべての文書執筆者（人間・AI）に課される執筆規約**であり、作業仕様書（PR 単位の point-in-time
記録）ではなく決定単位の記録に残すべきものである。

案 B・D（検査器側を狭める）を採らないのは、**検出力を下げる方向の解決は本 issue が是正しようと
している欠陥と同じ形**だからである。例示リンクの escape は執筆者に軽い手間を課すが、その手間は
「書いた瞬間に CI が赤で教える」形で可視であり、忘れても破損が静かに残ることはない。一方 B・D は
「検査されない範囲」を増やす解であり、その欠落は誰にも見えない。**非対称な誤りは、症状が出る側へ
倒す。**

## 影響・残余リスク

- **既存文書への影響は無い**（実測: 新たに検査対象へ入る 724 件のうち破損は真の破損 1 件のみで、
  誤検出 0 件）。是正した破損は `docs/adr/IADR-0131` → `IADR-0119` の 1 件
  （`IADR-0119_decision-derived-position-effect.md` は実在せず、正は `IADR-0119_decision-derived-close.md`）。
- **残余リスク**: 執筆規約（決定4）は機械的に強制されない。escape を忘れた例示リンクは破損として
  赤くなるため**気付ける**が、赤の理由が「本物の破損」か「escape 忘れ」かは人が読んで判断する。
  赤の原因が 2 種類あることは、赤を軽く扱う動機になり得る。
- **残余リスク**: `scripts/check-doc-links.js` は impl-handoff-kit の配布物であり、キット同期で
  本修正が巻き戻る可能性がある。テストは companion（`scripts/scripts.repo.test.js`）側に置いてあり、
  巻き戻れば `node scripts/scripts.test.js` が赤くなって検知できる。キット側への還流は本リポジトリの
  範囲外であり未実施である。
- **範囲外**: `docs/adr/README.md` の `[[IADR-XXXX]]` 記法は本検査器の対象ではない（別系統であり、
  本決定はそちらの検査を提供しない）。
