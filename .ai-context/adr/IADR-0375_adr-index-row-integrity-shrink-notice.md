# IADR-0375: ADR 索引行は「原文を残して追記を足す」を規約とし、縮みは止めない notice で告げる

- 状態: Accepted
- 日付: 2026-09-23
- 決定者: claude (Claude Code) / #895 の起票者の推奨（候補 2 ＋ 1）に沿う

## 起点・関連

- 関連する計画書 ID（FR/UC/SC/ADR）: 無し（NFR・文書統制）
- 関連する実装仕様書: `.ai-context/specs/20260923_886-895_adr-index-row-integrity.md`
- 起点 issue: #895（本決定）／#886（同じ PR で復元した 3 件目の実害）／#875・IADR-0363（検査器の新設）

## コンテキストと課題

IADR-0363 で入れた `scripts/check-adr-index-addendum-loss.js` は、`.ai-context/adr/README.md` の索引行から
**`［YYYY-MM-DD 追記 …］` の形をした追記ブロック**が衝突解決で消えることを止める。実際に効いており、
PR #873 で起きた取りこぼしを 1 件捕まえた。

**しかし同じ衝突解決で起きたもう 1 つの欠落は素通りした。** 検査器が見るのは追記ブロックだけであり、
索引行の中の**追記ブロックではない句**が置換・消失しても検出されない。

```
theirs: …保有 0 からの売りになり得る（対策は #864。**台帳とブローカーの一致を確認してから稼働環境へ反映する**）／…
ours  : …保有 0 からの売りになり得る（［2026-09-19 追記 / #864］**IADR-0355 が…塞いだ**。…）／…
```

追記ブロックは**増えている**ので緑。しかし theirs 側に在った句が消えている。内容としては
「その対策が済んだ」という趣旨の置換であって不当ではないが、**本体（`IADR-XXXX_*.md`）は原文を残して
追記を足す形**なので、索引行だけ扱いが非対称になっていた。

**索引行は 1 行が数千文字あり、`git diff` は「1 行削除・1 行追加」としか出さない。**
追記ブロックの消失とまったく同じ理由で、非追記句の消失も差分としては読めない。

### なぜ機械化が難しいか

索引行は本文の散文要約であり、**句の言い換え・短縮が正当な編集としてありふれている**。
「theirs 側の全語が ours 側にある」を要求すると要約の改善が軒並み赤になる
（`check-adr-index-sync.js` が「索引行の内容が本文と一致しているか」を機械では判定できないとして
見ないと決めたのと同じ壁である）。一方で、**「短くなった」ことだけなら測れる。**

## 検討した選択肢

| # | 選択肢 | 評価 |
| --- | --- | --- |
| 1 | **警告どまりの長さ検査**: 触った索引行が統合ブランチ側より短くなったら `notice`（赤にしない） | 偽陽性は要約の短縮で必ず出るが、**止めない**ので検査を外させる圧力が生まれない。差分では読めない縮みを可視化できる |
| 2 | **規約で寄せる**: 「索引行も本文と同じく原文を残して追記を足す（置換しない）」を明文化し、人とレビューで守る | 単体では守られない（規則 6 が「規約として書くだけでは守られない」ことを実証済み）。ただし 1 と組めば、置換が「短くなった」として現れやすくなる |
| 3 | **記録に留める**: 射程外であることを IADR-0363 の残余リスクへ明記し、検査器は変えない | 同型が既に 3 件起きている。記録だけでは次を止められない |
| 4 | **theirs の全語を要求する**（語の包含検査） | **採らない。** 要約の改善が軒並み赤になる。**偽陽性は検査そのものを外させる**——この検査器は初版で在庫の PR を 4/10 赤にして、その教訓を自分で得ている |

## 決定

**2 ＋ 1 を採る**（#895 の起票者の推奨と同じ）。

1. **決定 1（機械）**: `check-adr-index-addendum-loss.js` へ `findShrunkRows` を足し、
   **我々が触った索引行**（`isTouched`。規則 3 と同じ ours 起点の読み方を共用する）が
   **theirs の同 ID の行より短くなっていれば `notice` を 1 行出す**。長さは**バイト長**で測る。
   - 🔴 **終了コードを変えない。** `warn` でもなく `notice` である。
   - 追記ブロックの消失として既に赤になっている行、および `[remove-adr-addendum]` で意図的に
     撤去を宣言した行には**重ねて出さない**（同じ事故を 2 度読ませない）。
   - 縮んだ行が無ければ**何も出さない**（無音を保つ）。
2. **決定 2（規約）**: `.ai-context/adr/README.md` の「運用ルール」へ
   **「索引行も本文と同じく、原文を残して追記を足す（置換・短縮しない）」**を明記する。
   notice が出たときに人が何を確かめるか（両側の索引行を全文で突き合わせ、項目単位の和集合か）も併記する。
3. **決定 3（射程）**: 本 IADR は**索引行だけ**を対象とする。`.ai-context/adr/` 本体の追記と
   `docs/` の trace ブロックは IADR-0363 と同じく**射程外のまま**（広げるかは別 issue）。

## 理由

- **測れることだけを測る。** 「置換されたか」は機械では判定できないが「短くなったか」は判定できる。
  判定できないものを判定しようとすると偽陽性で検査が外れ、**判定できていたもの（追記ブロックの消失）まで失う。**
- **`isTouched` を共用する**ことで、「消失は規則 3 を守るが縮みは守らない」という非対称が
  黙って生まれることを防ぐ。片方だけ緩める是正が入っても、両方に同時に効く。
- **規約と notice の役割を分ける。** 規約は置換そのものを減らし、notice は残った置換を
  「短くなった」という観測可能な形へ押し出す。どちらか一方では効かない。

## 結果

- 良い影響: 索引行の非追記句の消失が、差分では読めないまま素通りする経路に**光が当たる**。
  本 PR で復元した IADR-0327 の行（2,473 → 2,037 バイト。`wc -c`・末尾の改行を含む）は、
  この notice が在れば当時その場で見えていた形である。
- 悪い影響・トレードオフ: **偽陽性は必ず出る**（要約の短縮は正当な編集である）。
  notice を読み飛ばす習慣がつけば効かない——**赤にしないことと引き換えに、人の注意に依存する。**
- 残余リスク:
  - **短くならない置換は検出できない**（同じ長さで別の句に入れ替わる形）。規約と人のレビューだけが受ける。
  - IADR-0363 決定 6 の見逃し（衝突を base の本文へ戻して解決した形）は**そのまま残る**。
    縮みの観測も `isTouched` を共用するため、同じ形では発火しない。
  - 索引行**以外**（本体・trace ブロック）は引き続き未保護である。
- フォローアップ: 同型の事故が**縮まない置換**の形でもう一度起きたら、そのときに射程を広げるか判断する
  （運用標準「検査器・規約の追加は同型の事故が 2 回起きたら」。今回は縮む形で 3 件目まで来ている）。
