# IADR-0251: 数値の LLM 非介在をアーキテクチャで担保する

- 状態: Accepted
- 日付: 2026-08-28
- 決定者: claude（起票 #338）

## 起点・関連

- 関連する計画書 ID: FR-16（数値はコードで集計し LLM に計算させない）・FR-06
- 関連する実装仕様書: [`20260828_338_reporting-cycle-and-templates.md`](../specs/20260828_338_reporting-cycle-and-templates.md)

## コンテキストと課題

計画（`04_report-templates` 採用方針）は「**数値（損益・費用・税）は LLM に計算させない**。
集計はコードで行い、LLM は評価・振り返り・目標案の文章生成のみを担う」と定めている。

既存実装は `PnlAggregator` でこれを守っていたが、#338 で**新たに 5 種類の集計**が加わる
（LLM 利用実績・借株料・為替差損益・稼働率分布・三者比較）。
**規約として書くだけでは守られない**——集計値を散文プロンプトの文脈へ「参考として」渡す実装は
容易に書け、しかも壊れたことがテストに現れない。

## 検討した選択肢

1. 規約（コメント・レビュー）で守る
2. **集計をすべて Domain の純関数に置き、LLM 文脈の型（`ReportNarrativeContext`）に集計値を入れない**（採用）
3. LLM の出力を後から検算する

## 決定

**決定1: 新しい集計はすべて `ReportService.Domain` の純関数に置く**
（`LlmUsageAggregator` / `BorrowFeeAggregator` / `FxTranslationAggregator` /
`OpenDUptimeAggregator` / `ControlActivationCatalog`）。副作用も I/O も持たない。

**決定2: `ReportNarrativeContext` に新しい集計値を 1 つも入れない。**
LLM は本 PR が追加した数値を**見ることも書き換えることもできない**——
これは規約ではなく**型の事実**である。

**決定3: 為替差損益は取引損益（`PnlSummary`）と別の型で持つ。**
計画は「取引損益と混ぜず独立した行として表示する」と定めており、
型を分けることで**合算する書き方が存在しなくなる**。

**決定4: 退行防止は「散文を差し替えても数値節がバイト単位で一致する」テストで行う。**
🔴 否定形（LLM が数値を書かない）は観測しにくいが、**この形なら観測できる**——
散文だけを変えた 2 つの描画を突き合わせ、数値を含む節が完全一致することを見る。
**対の肯定形**（散文は確かに差し替わっている）を同じテストへ添え、
比較が空振りしていないことも同時に固定する。

## 理由

- 選択肢 3（検算）は、**LLM が数値を書ける前提**を残す。書けてしまえば、
  検算が漏れた経路から必ず入ってくる。
- 型で塞ぐのは、レビューの注意力に依存しない唯一の方法である。

## 結果

- 良い影響: 数値の出所が 1 系統に閉じ、散文の品質・モデルの差し替えが数値へ波及しない。
- 悪い影響・トレードオフ: LLM は集計値を踏まえた散文を書けない（例:「費用が上限の 20% に達した」）。
  数値に言及した散文が要る場合は、**プロンプトへ渡す集計値を明示的に増やす**判断が別途要る。
