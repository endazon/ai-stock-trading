# IADR-0377: 試験ハーネスは中断せず件数を出し、母集合の規則 9〜11 は必読規約に条文・別紙に根拠を置く

- 状態: Accepted
- 日付: 2026-09-23
- 決定者: claude (Claude Code)

## 起点・関連

- 関連する計画書 ID: 無し（NFR・運用統制）
- 関連する実装仕様書: `.ai-context/specs/20260923_888-894_test-harness-and-population-rules.md`
- 起点 issue: #888（ハーネスの中断）／#894（母集合の規則の置き場所。**裁定を求めていた**）

## コンテキストと課題

### A. 試験ハーネスが 1 件の例外で止まる（#888）

`ok()` が `fn()` の例外をそのまま抜けさせていたため、`scripts.repo.test.js` の `setup.sh` 系テストが
`spawnSync bash ENOENT` を投げた時点で**スイート全体が中断**していた。

🔴 **実害は「4 件落ちた」ことではなく「後ろが走っていないことが読めない」ことである。**
中断したスイートは、以降のテストについて「通った」とも「落ちた」とも言わない。

**実測（Windows・本作業で自分で採った）**: 是正前は **323 件目で中断**し、
**残り 39 件（うち `setup.sh` 系 4 件）が一度も実行されていなかった**。
是正後は **総数 370 / 成功 366 / 失敗 0 / skip 4** で最後まで走る。

`setup.sh` 系 4 件は `env.PATH` を toolbox（symlink を集めた一時ディレクトリ）で**上書き**しており、
Windows には `/usr/bin` `/bin` が実在しないため toolbox が空になる。
**呼び出し側が Git Bash を PATH へ足しても解消しない。** しかも PATH を絞ること自体は必要である
（CI の ubuntu イメージは `/usr/bin/dotnet` を持ち、絞らないと自己修復の分岐へ入らない）。

### B. 規則 9・10 が本リポジトリに存在しないのに引かれている（#894）

```
$ git grep -l -E "規則 (9|10)" -- '*.md' | wc -l
55
$ grep -c "規則 9\|規則 10" .claude/rules/traceability.repo.md
0
```

🔴 **実害がある。** 監査が「規則 9 を破っていた」と書いても、**その番号は本リポジトリの必読規約に
存在しないため読み手が原文へ到達できない。** 配布物 `traceability.md` が持つのは規則 1〜8 である。

あわせて「窓（時間差）を扱う是正では増える側・減る側の両方を先に測る」手続きが、
**ある PR 固有の凍結記録の中にしかない**。同型の事故（是正が自分の鏡像を新設する）は **2 回**起きており、
運用標準の「同型 2 回で規約・検査器」の条件を満たす。

🔴 **読み込み予算の制約が置き場所の選択を縛る。** 着手時点の実測は **44,880 バイト（87.7%）**で、
予算 51,200 バイトまでの残りは **6,320 バイト**しかない。

## 検討した選択肢

### A（ハーネス）

| # | 選択肢 | 評価 |
| --- | --- | --- |
| A1 | `ok()` が例外を捕捉して続行し、末尾で件数を出す | **採用**。#888 の「直し方（案）1」そのもの |
| A2 | `setup.sh` 系 4 件だけを直す（toolbox へ実 `bash` のディレクトリを足す） | **不足**。中断そのものは残り、**次に別の例外が出れば同じ穴が開く** |
| A3 | ハーネスを `node:test` へ移す | **採らない**。外部依存ゼロ・キットとの同期という既存の制約を変える大きさで、#888 の射程外 |

### B（母集合の規則の置き場所）

| # | 選択肢 | 評価 |
| --- | --- | --- |
| B1 | **(a)** 必読規約へ全文（根拠・実例・表を含む） | **採らない**。1〜2 KB では収まらず、予算 90% を超える |
| B2 | **(b)** 別紙のみ ＋ 必読規約からは 1 行参照 | **不足**。番号（規則 9・10）が必読規約に実在しないままで、**#894 の実害が消えない** |
| B3 | **(b) を基本としたハイブリッド**: 必読規約に**条文だけ**、別紙に根拠・実例・表 | **採用** |

## 決定

- **決定 1（A1）**: `ok()` は例外を捕捉し、**その 1 件を fail として記録して次へ進む**。
  末尾に **総数 / 成功 / 失敗 / skip** を出し、失敗の詳細をまとめて再掲する。
  **失敗が 1 件でもあれば終了コード 1**（CI の赤/緑の意味は変えない。変わるのは「どこで止まるか」だけ）。
- **決定 2**: ハーネスを **工場関数 `createHarness()`** にする。
  🔴 **そうしないとハーネス自身の回帰テストが書けない** —— 本物の `ok()` へ「わざと落ちるテスト」を
  通すと、その失敗がスイートの失敗として残ってしまう。独立した実体なら**記録した内容**を検査できる。
- **決定 3**: `skip(name, reason)` を足し、companion（`scripts.repo.test.js`）へも渡す。
  **黙って飛ばさない**（理由を 1 行出し、末尾の件数にも載せる）。skip も「登録件数」に数える
  —— 数えないと「全件 skip」と「1 件も登録していない（export 忘れ・空実装）」が区別できなくなる。
- **決定 4**: `setup.sh` 系 4 件は **toolbox に `bash` が入ったかを実際に確かめ**、無ければ skip する。
  skip の理由に**なぜ PATH を上書きしているのか**まで書く（「直せる skip」と誤解させないため）。
  `bash -n` の 1 件は PATH を上書きしないので対象外。**CI（ubuntu-latest）では skip は発火しない。**
- **決定 5（B3）**: `.claude/rules/traceability.repo.md` へ **規則 9・10・11 の条文だけ**を置き
  （実測 **＋1,175 バイト**）、根拠・破れた実例・3 通りの表は
  `docs/how-to/correction-population-and-window-procedure.md`（新設）へ置いて 1 行で指す。
  **規則 11** は「窓を扱う是正では増える側・減る側の両方を先に測る」を新しく立てた条文である。
- **決定 6**: **機械検査は置かない。** 「母集合を正しく引いたか」は機械では判定できない
  （引くべき語が何かを機械は知らない）。規則 1〜8 にも検査器は無い。
  **置いたふりをしないために、検査器が無いことを規約と別紙の両方へ明記する。**

## 理由

- **中断は「落ちた」より悪い。** 落ちたテストは名前が出るが、走らなかったテストは**何も言わない**。
  実測で 39 件が沈黙していた。**件数を 4 つ（総数 / 成功 / 失敗 / skip）出すこと**が、
  この沈黙を塞ぐ最小の手段である。
- **番号を実在させることが #894 の最小の担保である。** 起票者は「(b) は毎セッション読まれないため、
  破られたときに気づく仕組みとセットでないと効かない」と但し書きしたが、**本件の実害は
  「破られること」ではなく「番号で引かれた先が無いこと」**である。条文を実在させれば実害は消える。
  根拠と実例まで必読規約へ入れる必要は無い（読む必要があるのは**是正に着手するとき**だけである）。
- **予算の実測**: 着手前 44,880（87.7%）→ 着手後 **46,055 バイト（90%・ok）**。
  🔴 **90% に張り付いた。** 次にこの集合へ足す作業は、**同じ量を削ってから足すこと。**

## 結果

- 良い影響: 手元で `node scripts/scripts.test.js` を走らせたときに**何が走って何が走らなかったかが読める**。
  規則 9・10 を番号で引いた記録（実測 55 件）が、**原文へ到達できるようになる**。
- 悪い影響・トレードオフ:
  - **必読規約が 90% に達した。** 残りは約 5 KB であり、**次の追加は削ってから**になる。
  - skip は「走っていない」ことに変わりはない。**Windows では `setup.sh` の中身は依然として検証されていない**
    （CI だけが見ている）。skip を読み飛ばせば、それに気づかない。
- 残余リスク:
  - **規則 9〜11 に機械検査は無い**（決定 6）。規則 6 を提案した作業自身が規則 6 を破った前例がある。
  - **中断しなくなったことで、失敗が「まとめて末尾」に出る**。途中で気づいて止める運用に慣れていると、
    末尾を読まずに緑と誤読し得る（終了コードは正しいので CI は誤らない）。
  - `createHarness()` によりキット配布物 `scripts.test.js` との乖離が増える
    （**乖離は受容する**のが本リポジトリの方針であり、追随義務は無い）。
- フォローアップ: Windows でも `setup.sh` 系を実走させたいなら、toolbox へ実 `bash` のディレクトリを
  足す道がある。**本 IADR では採らない**（skip が発火することで「実走していない」ことは可視である）。
