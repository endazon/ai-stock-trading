# IADR-0648: 実コミットの回帰の素材と旧配置

> 実装リポジトリ内の意思決定記録（Implementation ADR）。1 ファイル = 1 意思決定。

- 状態: Accepted
- 日付: 2026-11-08
- 決定者: claude（依頼はオーケストレーター 2026-11-08。「手元でだけ赤になる scripts.test.js の 1 件」の原因究明）

## 起点・関連

- 計画書 ID: **NFR**（工程の統制。無採番）
- 改める記録: [IADR-0193](./IADR-0193_adr-index-sync-check.md) 決定 5（「履歴が浅い環境では skip」の前提）。[IADR-0363](./IADR-0363_adr-index-addendum-loss-check.md) の実データ回帰も同じ素材の問題を持つため併せて扱う。
- 作業仕様書: [20261108_scripts-test-index-history](../specs/20261108_scripts-test-index-history.md)（再現・実測・陰性対照）。

## 文脈

`scripts.test.js` の「過去の索引追随漏れ 2 件を検出できる（#491 / #495 の実コミットで回帰）」が、手元では常に赤、develop の CI では緑だった。「手元が浅いクローンだから」と推測されていたが、**実測ではどちらも浅くない**（手元 `--is-shallow-repository`＝`false`・CI は `fetch-depth: 0`）。原因は 2 つが重なっていた。

1. **素材が develop から辿れない。** `270a7c1` / `4788905` / `a39e3e7` / `04126d8` は PR #491 / #495 のスカッシュマージ前のブランチのコミットで、`refs/pull/491/head` / `refs/pull/495/head` からしか辿れない。`actions/checkout` は `fetch-depth: 0` でもブランチとタグしか取らないので、**CI には素材が無く、テストは「履歴が浅いため skip した」と誤った理由を出して緑を返していた**（develop の run 42448659197 の scripts-tests のログ 543 行目）。手元のクローンは未参照のオブジェクトとして素材を持っていたため、テストが実際に走った。
2. **走ると検査器が偽陰性を返す。** 資料再編（#536・9b9c676）で `check-adr-index-sync.js` のパスを `docs/adr/` → `.ai-context/adr/` へ書き換えたため、再編前の範囲では IADR を 1 件も見つけられず「OK: 実装ADR の本文を変更していません」（exit 0）を返す。再編前の版の検査器は同じ 2 範囲で exit 1・是正範囲で exit 0 を返す。

同じ素材の問題は `check-adr-index-addendum-loss` の実データ回帰（事故 1 の `67628182..c1023d74`＝PR #830、BLK-1 の `be97cf2b`＝#878・`e6f58d1e`＝#877・`e02b4229`＝#830）にもあり、CI では skip して緑だった（同じ run の 636・640・642 行目）。こちらは素材があれば緑で、検査器は正しい。

## 決定

1. **`check-adr-index-sync.js` は旧配置 `docs/adr/` も見る。** 配置を `ADR_LAYOUTS` に列挙し、IADR は**自分と同じ配置の索引の行**で突き合わせる（旧配置の IADR を現行の索引の行で満たしたことにしない。逆も同じ）。
   - 理由: 検査器の守る対象は「本文と同じ差分で索引行を変えたか」であり、配置は偶然の事実である。旧配置を外すと再編前の範囲（回帰テストの素材そのもの）で黙って緑になる。新配置だけに戻す退行は自己試験（陰性対照つき）と実データ回帰の両方で赤になる。
2. **実コミットの回帰テストの素材は PR の head として CI が明示的に取得する。** 素材を持つ PR 番号の単一情報源は `scripts.repo.test.js` の `HISTORY_FIXTURE_PRS`。`ci.yml` の scripts-tests が `refs/pull/<n>/head` を取得し、同ファイルの配線テストが両者の一致を見る。
   - 理由: `refs/pull/<n>/head` は PR を閉じても消えない不変の参照で、スカッシュマージ前のコミットを辿れる唯一の公開された経路である。`refs/pull/*` を丸ごと取る案は 900 本超を取るため採らない。
3. **`REQUIRE_HISTORY_FIXTURES=1` のときは素材の欠落を赤にする。** 未設定（手元・AI レビューの実行）では、理由（スカッシュマージ前のコミットで手元に無い）と取得コマンドを出して skip する。「浅いクローン」とは書かない。
   - 理由: 素材を取得したのに無いなら配線の故障であり、skip して緑にすると今回と同じく「検査していない」が成功として報告される。`REQUIRE_REPO_TESTS` と同じ opt-in の形に揃えた。

## 結果

- develop の CI で、#491 / #495・#830 / #877 / #878 の実データ回帰が初めて実際に走る（素材を取得したシミュレーションで 636 件すべて通過・develop の版の検査器へ戻すと「過去の索引追随漏れ」が赤）。
- 手元では素材の有無で走るか skip かが分かれる（素材があれば走り、今回の是正で緑）。

## 残るリスク

- 素材の PR を増やすとき `HISTORY_FIXTURE_PRS` へ足し忘れると、配線テストは既存の番号しか見ないので気付けない（CI では `REQUIRE_HISTORY_FIXTURES=1` により当該テストが赤になって気付ける）。
- フォークからの `pull_request` でも `refs/pull/<n>/head` は基のリポジトリから取れるが、GitHub が PR の参照を消す運用へ変えれば素材は失われる（その場合は CI が赤になり、黙っては通らない）。
- IADR の配置を再び動かすときは `ADR_LAYOUTS` へ足す必要がある（足さなければ旧配置の素材で実データ回帰が赤になる）。
