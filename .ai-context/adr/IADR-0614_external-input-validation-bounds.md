# IADR-0614: 外部から受け取る値の検証

> 実装リポジトリ内の意思決定記録（Implementation ADR）。1 ファイル = 1 意思決定。

- 状態: **Accepted**
- 日付: 2026-11-05
- 決定者: Claude Code（実装）／ オーケストレーター（点検の結果のうち実在するものを同じ PR で直す、の指示）

## 起点・関連

- issue: #1532。前提: IADR-0068（Finnhub の現在値）・IADR-0469（外部の HttpClient の打ち切り）・IADR-0322（OpenD の認証サイドカーの閉じた入力）。
- 実装仕様書: [`.ai-context/specs/20261105_1532_external-input-validation.md`](../specs/20261105_1532_external-input-validation.md)

## コンテキストと課題

1. `DateTimeOffset.FromUnixTimeSeconds` は範囲の外で例外を投げる。外部の応答の値をそのまま渡していた箇所では、呼び手がその例外を捕えない（市場データの現在値）か、銘柄の全件ごと落とす（企業ニュース）。未来の時刻はそのまま受け入れ、鮮度の判定を素通りする。
2. HttpClient の応答の本文の上限は既定でほぼ無制限（約 2 GiB）である。外部の相手が巨大な本文を返すと、1 要求で容器のメモリを使い切る。
3. OpenD の再認証の受け口は、最後の `Command Tips` 行だけで入力待ちを判定する。案内の後にログインが成功しても、新しい `Command Tips` 行が出るまでは入力待ちと判定し、コードを受け付けてしまう。

## 決定

1. `UnixTime.TryFromSeconds`（負・範囲の外は false）を共有に置き、外部の Unix 秒の写しはすべてこれを通す。現在値は不正・未来 5 分超を取得不可、企業ニュースは不正な記事を飛ばす（as-of は不明）。欠け（0）の扱いは現在値では変えない。
2. 外部を取る名前付き HttpClient（10 登録）に `MaxResponseContentBufferSize = 16 MiB`（`ExternalHttpResponseLimits`）。既知の最大の応答（数 MiB 以下）に桁の余裕を取った値。
3. `ConsoleTail.DetectPrompt` は後ろから遡る途中で `Login successful` に当たったら null（入力待ちでない）を返す。

## 検討した選択肢

- 未来の許容: 0（厳密）は時計のずれで正常な応答を落とす。5 分は桁の余裕。1 時間は古い値が新しく見える窓が長い。
- 上限: 1 MiB は市場データには十分だが、SEC・EDINET の一覧で足りない恐れがある。クライアントごとに値を分けると置き場所が増えるので 1 つにした。
- OpenD: 成功の語の代わりに `>>>` のプロンプトの形で判定する案は、OpenD の版で表示が変わる。成功の語は既存の確認の手順でも使っている。

## 結果

- 良い影響: 異常な外部の値で巡回・情報源の取得が落ちない。巨大な応答でサービスが落ちない。ログインの後に再認証の受け口が開いたままにならない。
- 悪い影響: 発行時刻が 0 の企業ニュースの記事は採らなくなる（従来は 1970 年の記事として採っていた）。
- 残る制約: 上限は本文をバッファする読み方にだけ効く（流し読みのアダプタは今は無い）。OpenD の成功の語が版で変わると、判定は従来（最後の案内）へ戻る（安全側ではないが、従来より悪くはならない）。
