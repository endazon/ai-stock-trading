# IADR-0273: 基盤 MCP 公開許可リストのドリフト検出

- 状態: Accepted
- 日付: 2026-09-02
- 決定者: 実装（Claude Code）／ 起点 [#500](https://github.com/endazon/ai-stock-trading/issues/500)
- 作業仕様書: [20260902_500_mcp-non-exposure-integration-check](../specs/20260902_500_mcp-non-exposure-integration-check.md)

## 起点・関連

- 計画 ADR: **ADR-0012**（Accepted・2026-07-23。取引報告書・判断根拠・収集情報を MCP 公開許可リストに含めない。
  §結果 のフォローアップが「構成情報 API / SC-11 のドリフト検出で監視する」と書いている）
- 基盤 ADR: platform ADR-0024（MCP サーバー統合。**既定非公開＝許可リスト方式**）／ADR-0034 決定 9（サービスアカウントの個人資料一律除外）
- 先行する実装 ADR: [IADR-0171](./IADR-0171_mcp-non-exposure-structural-guard.md)（本リポジトリ内の構造ガード。
  §結果 の「悪い影響」に **「本テストは本リポジトリ内しか見ない」** と自ら記録している）／
  [IADR-0166](./IADR-0166_plan-source-digest.md)（「緑だが検査されていない」を作らない規律）

## コンテキストと課題

**IADR-0171 は、自分が埋められない穴を明記して残した。**

> 本テストは本リポジトリ内しか見ない。基盤側の許可リストへ**基盤側の PR で**追加された場合、
> **AST の CI は緑のまま統制が破れる**。

待ち先であった MSP#445（基盤 MCP の再実装）は**完了している**。基盤に
`src/platform/backend/Services/McpServer/` が実装され、宣言的公開構成
`Configuration/mcp-publication.json` が 6 ツール（`retrieval.search_documents` /
`document.get_document` / `document.list_documents` / `graph.get_backlinks` /
`graph.get_links` / `graph.traverse`）を宣言し、ローカル k3s で稼働している（実測 2026-09-02）。

**相手が存在するようになった。** したがって IADR-0171 決定5 が留保した結合確認と、
§結果 が残した限界の両方に手が届く。

課題は 2 つある。

1. **本リポジトリは基盤リポジトリに依存しない。** 参照手段は GitHub 上の URL か隣接クローンであり、
   いずれも**読み取り専用・pin 固定なし**である（ADR-0029 決定2 と同じ思想）。
   **CI に隣接クローンは無い。** 検査は「相手が居ないこと」を前提に設計しなければならない。
2. **相手が居ないときに黙って緑になってはならない**（IADR-0166 の規律）。
   「違反 0 件」と「1 件も読んでいない」が区別できない検査は、検査が無いより悪い。

## 検討した選択肢

| 論点 | 案 | 評価 |
| --- | --- | --- |
| 何を読むか | A: 稼働中の `mcp-service` の `tools/list` を叩く | **棄却** |
| | B: 基盤の構成情報 API（`/internal/introspection`）を読む | **棄却** |
| | **C: 基盤リポジトリの `mcp-publication.json` を読む** | **採用** |
| 相手が居ないとき | D: 常に緑（何もしない） | **棄却** |
| | E: 常に赤（fail-loud） | **棄却** |
| | **F: 理由つきの `Assert.Skip`＋照合器は実ファイル非依存で常に検査** | **採用** |
| 明示指定が外れているとき | G: 同じく skip | **棄却** |
| | **H: 失敗させる** | **採用** |
| 置き場所 | I: 新しいテストファイル | **棄却** |
| | **J: `McpExposureNotDeclaredTests.cs` の中** | **採用** |

### A（稼働中の MCP を叩く）の棄却理由

**単体テストが実クラスタに依存すると、クラスタが落ちている日に統制の検査も落ちる。**
しかも `tools/list` は**呼び出し主体で結果が変わる**（未登録クライアントには空を返す＝存在秘匿）。
実測ではサービスアカウントに対して `{"tools":[]}` が返った —— **公開されているものが 0 件に見える**。
「公開されていない」ことの証拠として使えば、**登録簿が空であるという別の理由による 0 件**を
公開統制の成果と読み違える。実測は本作業で別途行い、記録は作業仕様書に残した。

### B（構成情報 API）の棄却理由

ADR-0012 §結果 が挙げた手段だが、**実測で `mcp-service` の `/internal/introspection` は
`{"service":"mcp-server","steps":[],"ports":[],"connectors":[]}` を返す** ——
実効ツール一覧を申告していない（基盤 ADR-0024 §5 が求める形にまだ届いていない）。
**読んでも公開ツールが分からない。** 相手の実装を待つ必要があり、A と同じ実環境依存も抱える。

### D（常に緑）の棄却理由

これは IADR-0171 の現状と同じであり、**本 ADR が埋めようとしている穴そのもの**である。

### E（常に赤 / fail-loud）の棄却理由

**隣接クローンが無いのは異常ではない。** 本リポジトリは基盤リポジトリに依存しない設計であり、
CI に基盤を clone させれば**それは依存の再導入**である。恒久的に赤いテストは、
やがて「無視してよい赤」として扱われ、**本物の赤を隠す**。

### I（新しいテストファイル）の棄却理由

`McpExposureNotDeclaredTests` は `backend/` と `deploy/` を走査して `mcp` の出現を違反とする。
**新しいファイルを作れば、そのファイルを走査除外に加えることになる。**
IADR-0171 決定2 は「除外が育ったぶんだけ検査は弱くなる」と書き、除外を意図的に 1 件へ抑えている。
**除外を 2 件に増やしてまで、ファイルを分ける理由が無い。**

## 決定

### 決定1: 読むのは**基盤リポジトリの `mcp-publication.json` そのもの**とする

`McpPublicationAllowlistDriftTests`（`McpExposureNotDeclaredTests.cs` 内）が
`src/platform/backend/Services/McpServer/Configuration/mcp-publication.json` を読み、
本ユニットのサービスが公開対象に含まれていれば落ちる。

**この 1 ファイルが決定点である。** 基盤の `ToolCatalog.Refresh` は**公開構成を起点に**
各サービスの自己申告を探す向きで書かれており（申告を起点にすると構成の書き漏れが「公開されてしまう」側へ倒れるため）、
**構成に載っていないツールは、申告があっても公開されない。**

### 決定2: 位置は **明示（環境変数）＞ 隣接クローン ＞ 見つからない** の順で決める

- `MSP_MCP_PUBLICATION_PATH` があればそれを使う。
- 無ければ**リポジトリルートの祖先を遡って** `microservices-platform/src/platform/.../mcp-publication.json` を探す。
  **git worktree ではリポジトリルート自身が `.claude/worktrees/...` の下にある**ため、
  「ルートの兄弟」を 1 段だけ見る実装では見つからない（実測でそうなる）。祖先を遡れば、
  通常のクローンでも worktree でも同じ 1 つの隣接クローンに当たる。

### 決定3: 見つからなければ **理由つきで `Assert.Skip`** する

`Assert.Skip` は runner 上で **Skipped（理由つき）** として報告される —— **Passed にはならない。**
理由には**探索した場所の一覧**を書く。「黙って 0 件検査へ落ちない」ための最小限である。

### 決定4: **明示したのに存在しなければ失敗**させる

`MSP_MCP_PUBLICATION_PATH` を設定するのは「そこを見ろ」という意思表示である。
そこに無いのは**設定ミス**であり、不在ではない。skip に倒すと、
**パスを間違えたまま「検査したつもり」で緑になる。**

### 決定5: **照合器そのものは実ファイルに依存せず常に検査する**

実データは常に 0 件であるため、**照合器が空を返すよう壊れても実データ検査は緑のまま**である。
したがって次を別テストで固定する（IADR-0171 決定3 と同じ構図）。

1. **陽性**: 本ユニットのサービス（`report-service` / `trade-decision-service` / `information-collection-service` /
   `ai-stock-trading-*` / `AiStockTrading.ReportService.*`）を**実際に検出する**
2. **陰性**: 2026-09-02 実測の 6 ツールを**違反としない**（「常に違反」向きの壊れ方を排除する）
3. **母集合**: 照合語が `backend/Services` の**実ツリーから導かれ**、痩せていない（下限 10・実測 11）
4. **skip の境界**: 明示されたパスが無いときは失敗する（決定4 の回帰テスト）

**隣接クローンの有無に関わらず、照合器は必ず検査される。**

### 決定6: 照合は **粗い部分一致** で行う（IADR-0171 決定2 と同じ）

本ユニットのサービス名を `backend/Services` のディレクトリ名から導き、
ケバブケース（`report-service`）と小文字連結（`reportservice`。名前空間 `AiStockTrading.ReportService` 用）へ展開し、
リポジトリ名（`ai-stock-trading` / `aistocktrading`）を加えた語の**部分一致**で判定する。

**公開名がどう綴られるかは基盤側の裁量である。** 厳密一致にすると、想定と違う綴りが黙って素通りする。

## 理由

- **決定1〜2 は「依存を作らずに相手を見る」ための最小構成である。** ファイルを読むだけなので、
  ビルドにも CI にも基盤リポジトリを要求しない。
- **決定3〜5 は同じことを 3 方向から言っている** —— 「この検査が緑であることが何を意味するか」を、
  緑のときに確かめられる形にする。skip は「見なかった」と言い、
  照合器の対照は「見たなら検出できた」と言う。**片方だけでは足りない。**
- **決定4 は「設定したのに効いていない」という、最も気づきにくい失敗を潰す。**

## 結果

- **基盤側の PR で本ユニットのサービスが公開対象へ追加されたら、隣接クローンを持つ開発環境で赤くなる。**
  IADR-0171 §結果 が記録した穴のうち、**本リポジトリ側から塞げる部分が塞がった。**
- **結合確認（IADR-0171 決定5・`docs/blocked-tasks.md` A-10）が実測で済んだ。**
  ツール一覧・検索・文書取得のいずれの経路でも本ユニットの文書は返らない（作業仕様書に 3 経路 × 主体の表を残した）。

### 悪い影響・残余リスク（記録する）

- 🔴 **本検査は「本ユニット自身のツールが公開されていないこと」しか担保しない。**
  ADR-0012 §結果 は「本ユニットの**文書コレクション・retrieval スコープ**が含まれないこと」を求めているが、
  **基盤の公開許可リストにその粒度は存在しない**（エントリは `{ name, service }` の 2 項目のみ）。
  公開済みの `document.*` / `retrieval.*` は**基盤の共有ナレッジベース全体**を対象とし、
  本ユニットが FR-08 で保存する文書も同じ `document-service` に入る。
  **「許可リストに本ユニットを載せない」だけでは ADR-0012 の決定は守れない。**
  現在の非公開は、以下の**別の理由**によって成立している（実測）:
  MCP クライアント登録簿が空 ／ 下流のツール実行口（`/internal/mcp/*`）が 404 ／
  本ユニットの KB 保存が realm 不整合で全件失敗しており文書が 1 件も存在しない。
  **いずれも統制ではなく、実装途上の状態である。** 計画・基盤への環流は #500 に記録し、利用者の裁定に委ねた。
- 🔴 **`NotificationService` は基盤にも同名のサービスがある。** 基盤自身の `notification-service` が
  公開対象に入ると、本検査は**誤検出で落ちる**。誤検出は安全側であり
  （IADR-0171 決定2 の「テストが落ちたので人が読む」と同じ）、失敗メッセージにその可能性を明記した。
  **除外は足していない** —— 足せば、本ユニットの `NotificationService` の公開も同時に見逃す。
- **CI では skip になる。** 隣接クローンは CI に無い。**skip は Passed ではない**が、
  「skip が並んでいるのが普通」になると気づかなくなる。**恒久的に緑にする手段（基盤の clone）は
  依存の再導入であり採らない。** 定期棚卸しで skip 件数を見ること。
- **`Assert.Skip` の実測はローカルでは行えなかった** —— 隣接クローンが実在するため常に本走行する。
  skip 経路は CI（隣接クローン無し）で確認する。
