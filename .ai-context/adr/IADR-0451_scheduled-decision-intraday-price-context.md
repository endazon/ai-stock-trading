# IADR-0451: 定時の判断へ日中文脈（前日比・当日始値比・日中高安）を渡し、出来高は「未提供」と明示する

- 状態: Accepted
- 日付: 2026-09-29
- 決定者: claude（起票 [#1035](https://github.com/endazon/ai-stock-trading/issues/1035)。#1015 のやること 2 の切り出し。利用者レビューは PR で受ける）

- 対象 Issue: #1035（起点 #1015・IADR-0435）。出来高の供給は planning#702（裁定中）
- 関連する実装仕様書: [20260929_1035_scheduled-decision-price-context](../specs/20260929_1035_scheduled-decision-price-context.md)

## コンテキスト

2026-09-26 の稼働 PoC で、新しい監視銘柄の一次スクリーニング・定時の本判断はすべて「上昇の勢い（価格上昇・出来高増加）や
好材料の具体的な情報が提示されていない」として Hold に倒れ、注文が 1 件も出なかった。

- 定時の判断へ渡る市況は、定時の節の「- 現在値」1 行だけだった（IADR-0099 決定 2）。値動きの材料は、急変
  （PriceMovementDetected）が起きたときの「基準値・変動率」にしか無い。
- 共有 `FinnhubQuoteClient` は `/quote` の `c/h/l/pc/t` を読み `FinnhubQuoteSnapshot` が高値・安値・前日終値を持っていたが、
  `FinnhubMarketDataSource` が `Quote(Symbol, Market, Price, AsOf)` へ詰め替えて捨てていた。始値 `o` は読んでいなかった。
- IADR-0435 で情報収集は同じ値を KB へ保存するようになったが、判断が RAG で拾えるかは検索次第であり、構造化した材料ではない。

### 計画上の位置づけ（裁定を要しない理由）

前日終値・当日始値・日中高安は、**現在値と同じ Finnhub `/quote` 応答の別項目**である。計画 ADR-0044 決定 1 は
「価格変動トリガーの現在値は、収集情報（市況）に含まれる。外部由来であり、既存の列挙の内側である」「新しい外部の情報源を
判断へ加えるときは、引き続き ADR-0003 の改定を要する」と定める。同じ応答の別項目は**同じ情報源・同じ分類（市況）**であり、
新しい外部の情報源ではない。したがって計画の裁定を要さず、本 IADR で足りる。

**出来高は `/quote` に無い**（別のエンドポイント・別の情報源が要る）。これは新しい情報源の追加に当たり得るため、
planning#702 で裁定中である。本 IADR は出来高を供給しない。

## 決定

### 決定 1: `Quote` は日中文脈を省略可能な値として運ぶ。0 は「不明」（null）

- 共有契約 `Quote` の末尾に `PreviousClose? / Open? / High? / Low?`（既定 null）を足す。既存の 4 引数の構築は不変である。
- `FinnhubQuoteClient` は応答の `o`（当日始値）も読み、`FinnhubQuoteSnapshot` に `Open` を足す（応答に無ければ 0）。
- `FinnhubMarketDataSource` は 4 項目を `Quote` へ写す。🔴 **0 以下は null（不明）へ倒す** —— Finnhub は場前の始値・高安、
  未知の銘柄の全項目を 0 で返す。0 を値として通すと前日比が -100%、始値比が 0 除算になる（現在値 0 を取得不可とした既存の扱いと同じ考え方）。
- 情報収集側の写像（`FinnhubInformationSource`）は変えない（IADR-0068 決定 2）。市場監視は追加項目を読まない（挙動は不変）。

### 決定 2: 価格供給は現在値と日中文脈をまとめたレコードを返す

- 取引判断サービスに `IntradayPriceContext(PreviousClose?, Open?, High?, Low?)` と `CurrentPriceReading(Price, Intraday)` を置き、
  `ICurrentPriceProvider.GetCurrentPriceAsync` の戻り値を `CurrentPriceReading?` にする（NoOp・テストダブルも追随）。
- 取得不可・鮮度切れ・無効化は従来どおりレコードごと null である。見送りゲート（IADR-0099 決定 3）と参照価格のアンカリング
  （同決定 2）は `reading?.Price` を見るため**従来と同値**である。
- 日中文脈の鮮度は現在値と同じ `AsOf` で判定済みとみなす（同じ応答だから）。`IntradayPriceContext.Of` が 0 以下を null へ倒す
  （`Quote` を作る情報源が決定 1 の正規化をしない場合の保険）。

### 決定 3: 値動きの行をコードで計算して、定時の節・急変の節・一次に出す

プロンプトに次の 5 行を出す（`TradeDecisionPromptBuilder.PriceContextLines`。本判断・一次で共用）:

```text
- 前日終値: 100 / 前日比: +2.00%
- 当日始値: 103 / 当日始値比: -0.97%
- 日中高値: 104 / 日中安値: 99.5
- 出来高: 未提供（出来高の取得経路が未整備のため渡していません。「出来高が無い」「出来高が少ない」とは扱いません）
- 前日比・当日始値比は、上の現在値からシステムが計算した値です（あなたは計算しません）。「不明」は値を取得できなかったことを表し、変化が無いことではありません。
```

- **変化率はコードで計算する**（ADR-0003・FR-16 の趣旨。LLM に計算させない）。符号つき・小数 2 桁の百分率（四捨五入）。
- 🔴 **変化率は「同じ節に出した現在値」から計算する** —— 急変の節は `trigger.Price`、定時の節と一次は供給の現在値。
  節の中で現在値と変化率が食い違わないようにする（保有状況節の評価価格と同じ規則。IADR-0351）。
- 🔴 **値が無い項目は「不明」と書き、0 や 0.00% を書かない**（0 は「変化なし」と読まれる。IADR-0351 決定 2 の作法）。
  供給が日中文脈を持たない（`intraday` が null）ときは 3 行とも「不明」である。
- 🔴 **出来高は無言で省かず「未提供」と明示する**（ADR-0020 の欠測の明示）。planning#702 の裁定後にこの行を差し替える。
- 行を出すのは**現在値を出す節だけ**である。定時で現在値が無い（既定 NoOp＝IsEnabled=false）ときは出さない
  （比べる現在値が無い。IADR-0099 決定 1 の「既定は現行動作」を保つ）。有効化した構成で現在値が取れなければ判断そのものを見送るため
  （IADR-0099 決定 3）、稼働の構成で「現在値はあるが値動きの行が無い」プロンプトは生じない。
- 急変の節では、価格供給が無効でも値動きの行を出す（現在値＝トリガーの価格があるため）。その場合 3 行は「不明」になる。

### 決定 4: 値動きの行は縮退の保護分（市況）に入れる。銘柄ごとの保護分を 400 → 700 文字へ

- 一次は門である（Hold で本判断が走らない）。値動きの行を削ると、実測と同じく一次が「勢いの情報が無い」で落とす。
  したがって市況として**保護分**に入れる（IADR-0247 の分類。削減の対象ではない）。
- `ScreeningContextAssembler` の銘柄ごとの保護分を `400 + PriceContextReserveChars（300）` にする。値動きの行の最悪長
  （桁の多い価格・通貨表記・全項目あり）は 278 文字（実測）で、試験が「予約を超えない」ことを固定する。
  既定の予算 150,000 文字（IADR-0313）に対し 1 銘柄 +300 文字であり、縮退の発生はほぼ変わらない。
- 縮退の試験の予算は同幅（+300）ずらした（削る件数・残る材料は従来と同じ）。

### 決定 5: Stage 0 では前日比だけを日足の前日終値から出し、当日の変化率は「不明」とする

- `AsOfDecisionInput` に省略可能な `previousClose`（`DatedPrice`。判断時点より前の最後の終値）を足す。
  🔴 **日付が AsOf 以降なら例外**（当日以降の終値は前日終値ではない＝未来の値で判断させない。ADR-0033 決定 2 と同じく型の側で守る）。
- 前日比は `ReferencePrice`（AsOf 時点の参照価格）と前日終値から計算する。
- 🔴 **当日の始値・日中高安は渡さない（常に「不明」）** —— 本番の定時の判断は場中に走る。日足の当日の値は
  その日の全体であり、判断時点では得られない情報（その後の高値・安値）を含む。始値は判断時点で既知だが、参照価格が日足の終値である
  Stage 0 では「終値の始値比」になり本番の「場中の現在値の始値比」と意味が変わるため、渡さない。
- 前日終値が渡されなければ前日比も「不明」である。既定の as-of 入力の供給口は常に null（IADR-0318）であり、実供給は残件である。
- 前日終値を渡さないことを as-of 入力の再構成可否（IADR-0387 の 4 種）には数えない —— 値動きの行は本番でも「不明」になり得る材料であり、
  判定母集団から外すほどの痩せではない（本番の判断も値動きの行が「不明」の入力で動くことがある）。ただし経路 B の本番は通常、当日始値比・日中高安を値つきで出すため、本番と Stage 0 の記録では入力が一致しない。記録と本番の比較（再現性）はこの差を含む前提で読む（残る制約を参照）。

## 却下した案

| 案 | 却下の理由 |
| --- | --- |
| 情報収集の KB（IADR-0435 で保存される /quote の値）を RAG で拾わせる | 検索次第で渡らないことがあり、構造化した材料ではない。縮退で削られ得る（ニュースと同じ扱い） |
| 変化率を LLM に計算させる（前日終値と現在値だけを渡す） | ADR-0003・FR-16 の趣旨（数値はコードで計算する）に反する。計算の誤りが判断根拠に混ざる |
| 出来高の行を省く | ADR-0020 の欠測の明示に反する（無言の空データ）。LLM は「出来高増加の情報が無い」を理由に Hold に倒れ続け、原因が読めない |
| 市況の取得を別途（判断サービスから /quote を直接）呼ぶ | 価格供給と同じ応答を 2 回取ることになり、Finnhub の自制レート（ADR-0043）を無駄に使う |
| 0 を値として渡す | 前日比 -100%・始値比の 0 除算を作る。「不明」と書く |
| Stage 0 に日足の当日の始値・高安を渡す | 判断時点では得られない当日の全体の値を含む（ルックアヘッド） |

## 結果

- 定時の本判断・一次・急変の本判断のプロンプトに、前日比・当日始値比・日中高安が構造化して載る。出来高は「未提供」と明示される。
- `Quote` の既存の利用者（市場監視・報告書・リスク管理）の挙動は変わらない（追加項目を読まない）。
- 1 銘柄の一次スクリーニングの保護分の見積りが 300 文字増える。

## 残る制約

- **出来高**: planning#702 の裁定待ち。裁定で供給が決まれば、`VolumeNotProvidedLine` を値の行へ差し替える別 PR を起こす。
- **#1035 のやること 3（経路 B のニュース源の有効化）**: 本 IADR の射程外。
- **日本株**: Finnhub の現在値は米国株のみ（IADR-0068 決定 5）。日本株は現在値が取れないため値動きの行も出ない（従来どおり）。
- **Stage 0 の実供給**: 既定の供給口は null を返す（IADR-0318）。日足からの前日終値の供給は as-of 入力の実供給とともに残件。
- **本番と Stage 0 の入力の差**: 本番（経路 B）は当日始値比・日中高安を通常は値つきで出し、Stage 0 は常に「不明」とする（決定 5）。記録と本番の判断の比較はこの差を含む。また急変の節では、変化率はトリガーの価格から計算し、前日終値・始値・高値・安値は判断時に取得した /quote の値を使うため、検知から判断までの間に日中の高値・安値が動くと、現在値が高安の範囲外に見えることがある（表示上のずれに留まる）。
- **プロンプト上の材料であってコードの統制ではない**: 値動きをどう判断に使うかは LLM に委ねる（方針・リスク制約の範囲内。ADR-0003）。

## ［2026-09-30 追記 / #1118］出来高の供給が決まり、値の行を足した（既定は無効で「未提供」の行は変わらない）

（前営業日の出来高・20 日平均比）とされた。経路と表示は [IADR-0467](IADR-0467_decision-volume-from-daily-kline-via-order-execution.md) が決めた。

- 🔴 **残る制約の「`VolumeNotProvidedLine` を値の行へ差し替える」は、差し替えではなく切り替えにした。** 判断の出来高が無効（`DecisionVolume:Enabled=false`。
  既定）なら `VolumeNotProvidedLine` を従来どおり出す（1 字も変えない）。有効化した構成では値の行、取得できないときは別の文 `VolumeUnavailableLine`（「未提供」）を出す。
- 決定 4 の予約 `PriceContextReserveChars` は 300 → 450 に広げた（出来高の値の行の最悪長。IADR-0467 決定 4）。
- 決定 5（Stage 0）は変えていない。Stage 0 の記録の出来高は「未提供」のまま（残件）。
