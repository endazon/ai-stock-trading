# IADR-0242: 通知テンプレートは全文ゴールデンで、統制の「しないこと」は否定形で固定する

- 状態: Accepted
- 日付: 2026-08-28
- 決定者: claude（起票 #341。利用者レビューは PR で受ける）

## 起点・関連

- 関連する計画書 ID: FR-09（通知）・FR-14（設定変更は Discord からは参照のみ）・NFR（セキュリティ：秘密情報）
- 関連する実装仕様書: [`20260828_341_discord-bot-and-notification.md`](../specs/20260828_341_discord-bot-and-notification.md)

## コンテキストと課題

#341 の受け入れ基準には、**「起きること」ではなく「起きないこと」を担保するテスト**が 3 つある。

- 通知テンプレートの**ゴールデンテスト（必須項目の欠落検知）**
- **設定変更が参照のみである**こと（否定形）
- **秘密情報がログ・トレースへ出力されない**こと（否定形）

実測すると、いずれも**部分的にしか担保されていない**。

- `NotificationFormatterTests` は個別項目の部分一致（`Should().Contain(...)`）であり、
  **テンプレートを 1 本足しても検査は 1 件も増えない**。「必須項目の欠落検知」になっていない。
- 「設定変更は参照のみ」は parser が未知コマンドを `Unknown` に倒すことで**実装上は満たされている**が、
  **それを固定するテストが 1 つも無い**。将来 `/config` を足しても CI は緑のままである。
- 秘密の非出力は Webhook URL について `DiscordWebhookHttpClientTests` があるが、
  **Bot トークンと kill switch 確認フレーズについては無い**。

## 検討した選択肢

1. **既存の部分一致テストを増やす** — 足し忘れを止められない（母集合が手書きの列挙のままである）。**却下**。
2. **スナップショットファイルを外部に置く**（`*.approved.txt`） — 承認ファイルの更新運用と CI の
   差分表示が要り、依存も増える。テンプレートは 20 本弱であり見合わない。**却下**。
3. **テスト内にゴールデン文字列を持ち、母集合はリフレクションで引く**（採用）

## 決定

1. **通知テンプレートは全文ゴールデンで固定する。** 期待値は `Title` / `Content` / `Severity` の
   **完全一致**（`Should().Be(...)`）とし、部分一致にしない。**必須項目の欠落は差分として必ず現れる。**
2. **母集合はリフレクションで引く。** `NotificationFormatter` の `public static ... From(<イベント型>)`
   オーバーロードを列挙し、**ゴールデン表に載っていない型があれば落とす。**
   **数を書かない**（`NotificationConsumerCoverageTests` と同じ規律——維持されない数は、あるだけ有害である）。
3. **「設定変更は参照のみ」を否定形で固定する。** 現実に打たれ得る設定変更コマンド
   （`/config` `/set` `/settings` `/watchlist` `/risk` `/assumptions` `/limit` ほか）が
   **1 つ残らず `Unknown` へ倒れ、どのコントローラも呼ばれない**ことを、parser とすべてのコマンドハンドラで固定する。
   **kill switch と pause/resume だけが例外である**ことも同じテストで示す（例外の範囲が広がったら落ちる）。
4. **秘密情報の非出力を否定形で固定する。** Bot トークン・kill switch 確認フレーズ・Webhook URL の
   いずれもが、**通る経路のログ本文（メッセージ・引数・例外）に現れない**ことを、記録ロガーで実測して固定する。
5. **ゴールデンは決定論的でなければならない。** 入力の日時・数量は固定値のみを使い、
   `DateTimeOffset.UtcNow` 等を期待値に混ぜない。文化依存の書式（`P1` 等）は既に排除済みであり、これを維持する。

## 理由

決定 2 が本決定の要である。**ゴールデンテストは、書いた分しか守らない。**
母集合を手書きの列挙にすると、**テンプレートを足した人がゴールデンを足し忘れても緑**になり、
「ゴールデンテストがある」という記録だけが残る。これは本プロジェクトが繰り返している
「**緑だが検査されていない**」の型そのものである（`NotificationConsumerCoverageTests` の冒頭コメントが
同じ事故を記録している）。**母集合をコードから引けば、足し忘れは赤になる。**

決定 3 は、**統制の「例外の範囲」こそが守るべきもの**だからである。「参照のみ」という規約は
**破壊的コマンドを足したときに破れる**。破れた瞬間に落ちるテストを、規約と同じ場所ではなく
**コードの側**に置く。

## 結果

- 良い影響: テンプレートの追加が必ずゴールデンの追加を伴う。統制の例外範囲の拡大が CI で止まる。
- 悪い影響・トレードオフ: 文言を直すたびにゴールデンの更新が要る（**意図した摩擦**である。
  通知文言は利用者が唯一読む出力であり、無自覚な変更を通さない）。
- フォローアップ: なし。
