## コンテキストと課題

**実装は完成しており、構成だけが計画に反していた。** `FxRateSourceFactory` は `Fx:Provider: "boj"` を
受け付け、FRED のキーがあれば `FallbackFxRateSource` を後段に積む。日銀アダプタは系列コードの落とし穴
（データコード `FM08'FXERD04` との取り違え・中心相場 `FXERD05` との取り違え）まで否定形テストで固定済みで、
フォールバック切替の可視化（`FxRateSourceFellBack` → 監査・通知・報告書）も結線済みである。

にもかかわらず、`Fx__Provider` の **6 箇所（2 ファイル × 3 サービス）** が日銀を指していなかった。

| サービス | 用途 | `values.yaml`（本番） | `values-local.yaml`（経路B） |
| --- | --- | --- | --- |
| `report` | 為替差損益の**期末レート** | `""`（no-op） | `"fred"` |
| `risk-management` | 承認記録時の**認識時レート** | `""`（no-op） | `"fred"` |
| `trade-decision` | 統制上限判定の**換算レート** | `""`（no-op） | `"fred"` |

- **経路B はフォールバック側だけで動いていた。** FRED `DEXJPUS` は系列こそ営業日次だが公表は H.10 週次で、
  最新観測の齢は最大 12.84 日まで積み上がる（#271 / IADR-0112 の実測）。鮮度**警告**は 5 日であるため
  **平常運用でも警告域に常駐しうる**状態だった。
- **FRED は API キーを要する。** 鍵の未設定は「日本株だけが全件見送りになる」という分かりにくい形で効く
  （#262 / IADR-0109。#364 で基準通貨が USD へ移り、必須の市場が US 株から日本株へ入れ替わっていた）。
- **本番は 3 箇所とも no-op**＝外貨建ての判断・記録・報告のすべてが供給されない。

🔴 **1 箇所だけ直すと 3 サービスで挙動が食い違う。** これが本設定点の事故の形である
（#643 の本文は「各 1 箇所」と書いていた）。

## 決定

### 決定1: `values-local.yaml`（経路B）の 3 箇所を `"fred"` → `"boj"` にする

計画 ADR-0022 決定1（日銀を第一）への単純な追随である。**FRED の鍵（`ast-secrets/fred-api-key`）は残す**ため、
経路B は初めて **日銀第一 → FRED フォールバック**の 2 段になる（決定2 の冗長化を実際に満たす）。

### 決定2: **本番 `values.yaml` の 3 箇所も `""` → `"boj"` にする**

空既定の根拠は「**実接続には鍵が要る／鍵が無ければどのみち no-op**」であった。**日銀は認証不要**であり、
この根拠が消える。空のまま残すと、本番を起動した瞬間に「外貨建ての判断・記録・報告が黙って供給されない」
という**既知の沈黙**を計画に反して温存する。

**反論（採らなかった側の言い分を残す）**: chart の `values.yaml` 冒頭は「実接続は Secret `ast-secrets`
（空既定）を明示設定したときのみ有効化する」と述べており、**外部連携の活性化は秘匿値で門を作る**のが
本 chart の姿勢である。日銀は鍵を持たないためこの門を作れず、**本設定点だけがその姿勢の例外**になる。
実際、本番の既定描画では他の外部連携（実 LLM・市況・Discord・収集ソース）がすべて空であり、
**為替だけが外部へ出る**という非対称が生まれる。

**それでも採った理由**:

1. 計画 ADR-0022 決定1 は「第一の情報源は日銀」と定めており、**どの環境でも日銀を指していない**現状は
   計画からの逸脱である（逸脱を続けるなら新しい IADR で根拠が要る側である）。
2. 外部へ出るのは**公開統計 API への GET のみ**（認証なし・1 回/分の自制・6 時間キャッシュ）。
   費用も資格情報も伴わず、失敗しても `null`（レート無し）へ縮退して発注を増やす方向へは倒れない。
3. **切り戻しは 3 行を `""` へ戻すだけ**である。
4. 本番は他の外部連携が空であり、レートを要求する経路自体がほとんど動かない。
   すなわち**実際の挙動の変化は小さく、計画適合と沈黙の解消という利得が大きい**。

**姿勢の例外は隠さず、`values.yaml` 冒頭へ明記した**（「例外は為替レート源だけである」）。

### 決定3: FRED のフォールバックは残す（外さない）

`FxRateSourceFactory.Create` の `case Boj` を実測で確認した:

- `options.Fred.ApiKey` が非空 → `FallbackFxRateSource`（`boj` → `fred` の順位つき）。
- 空 → **日銀単独**＋「フォールバックがありません」の警告 1 回（`Create` が明示的に出す）。
- `ResolveProvider` は `boj` 指定なら鍵の有無に関わらず `boj` を申告する（日銀は認証不要のため
  no-op へ倒れる経路が無い）。

したがって本番（鍵なし）は `boj` 単独＋起動時警告、経路B（鍵あり）は 2 段になる。
**「鍵が無いと FRED が積まれない」ことをもってフォールバックの設定点を消さない** ——
消すと、鍵を投入しても冗長化が戻らなくなる。

### 決定4: 鮮度の受容窓（`MaxRateAgeDays` / `StaleRateWarningDays`）は変えない

既定は **30 日 / 5 日**であり、これは #381 / IADR-0174 が**計画 ADR-0022 決定5・決定4 の値へ揃えたもの**である
（#271 / IADR-0112 の 14 日は FRED の週次公表からの逆算であり、根拠は既に計画側へ移っている）。
日銀は日次公表なので 30 日は緩いが、

- **狭めるのは計画値からの逸脱**であり、実装だけを厳しくすると計画と実装が別の値を持つ。
- **狭めると止まりやすくなる**: 休場明け・取得失敗、そして**FRED へフォールバック中は最大 12.84 日**に
  達するため、10 日程度へ下げるだけでフォールバックが「積まれているのに採用されない」状態を作りうる。

**警告（5 日）が「気づくための段」を受け持っている**ため、上限を下げなくても劣化は可視化される。

### 決定5: CI の描画ゲートは**緩めず、件数で数える形へ強める**

- `values-local` の検査を `Fx__Provider=fred`（1 件でも一致すれば緑）から
  **`boj` が 3 件そろっていること**へ変更した。**1 箇所だけ直した状態は緑にならない。**
- **本番既定にも同じ検査を新設した**（`Assert FX rate source is BOJ-first in prod default`）。
  併せて「既定描画に `fred` が第一として現れない」否定形も置いた。
- 既存の**経路B 漏出ゲート**（`Assert prod default excludes route-B activations`）は**触っていない**。
  同ゲートの禁止語は列挙（`value: "finnhub"` / `value: "DEXJPUS"` / `value: "discord-webhook"` ほか）であり、
  `value: "boj"` は含まれない。**本値は `values.yaml` 自身が持つのであって、経路B からの漏出ではない** ——
  ゲートの意図（経路B 限定設定の漏出防止）と本変更（計画準拠の既定変更）は別物であるため、
  **ゲートを緩める必要が無いことを実測で確認した**。

### 決定6: 記述面（chart README・運用仕様書・デプロイスクリプト）の「必須前提」を実体へ合わせる

「**`FRED_API_KEY` は日本株取引の必須前提**」という記述が 3 面に残っていた。日銀が第一になった今、
**必須ではなくフォールバック用**である（無くても換算できるが冗長化が失われる）。切り分け手順の期待値も
`fx-rate` の申告が `fred` → **`boj`** へ変わる。**実体と食い違う手順書は、事故のときに読まれる。**

## 対象外（やらないこと）

- **収集ソースの日銀（`Collection__Source__Boj__*`）**。`InformationSourceFactory` は
  `Collection:Source:Boj:Db` と `SeriesCodes`（**複数形**）を要求するが、これは**為替とは別枠**の
  「情報収集としてどの統計を集めるか」であり、系列の選定は本 issue の一次確認とは別の判断である
  （`FxOptions` のコメントも「情報収集の `Collection:Source:Boj` とは別枠」と明記）。
  `values-local.yaml` の「boj は統計分類/系列コードの一次確認が要るため列挙しない（#279 残置）」は
  **収集側の注記であり、本作業では解消しない**。
- **C# の実装コード**（アダプタ・ファクトリ・フォールバック・可視化）。すべて実装・テスト済み。
  `FxOptions.Provider` の XML ドキュメントが「現在の実装は "fred"」と**古くなっていた**ので是正しただけである。
- **実 API を叩くテストの追加**（IADR-0194 の「外部依存で CI を落とさない」を踏襲。本 IADR の実測は
  point-in-time の記録として本文に残す）。

## 実測（変更の影響範囲）

`helm template` の描画差分は **`Fx__Provider` の値 3 行ずつのみ**である。

| 描画 | env 名の件数（変更前 → 変更後） | 描画全体の差分 |
| --- | --- | --- |
| 既定（本番・`values.yaml`） | **169 → 169**（増減なし） | 3 行（`value: "" → "boj"`） |
| 経路B（`-f values-local.yaml`） | **203 → 203**（増減なし） | 3 行（`value: "fred" → "boj"`） |

**Helm はリストを置換する**ため、`extraEnv` を触る変更では env が黙って消える事故が起きる
（#279 / IADR-0114 決定4）。件数を数え、`comm -23` で「本番にあって経路B に無い env」が 0 件であることも確認した。

**新しいゲートが飾りでないことを変異で確かめた**（決定5 の裏取り）: `values.yaml` の
`Fx__Provider` を **1 箇所だけ** `""` へ戻すと、既定描画の `boj` は **3 → 2 件**になり
新設した検査は赤くなる。**まさにこの「1 箇所だけ直す／戻す」が #686 の事故の形**であり、
変更前の検査（`values-local` で `fred` が 1 件でも一致すれば緑）はこれを緑のまま通していた。
変異は検証後に戻し、作業ツリーがバイト同一であることを確認した。

## 残余リスク

- **本番の冗長化は 1 段しかない**（鍵が無いため FRED が積まれない）。起動時警告で可視化されるが、
  ADR-0022 決定2 を本番で満たすには `ast-secrets/fred-api-key` の投入が要る（chart README へ手順を書いた）。
- **本番既定が外部へ 1 リクエストも出さない状態ではなくなった**（決定2 の意図した逸脱）。
  chart の「秘匿値で門を作る」姿勢の**唯一の例外**であり、`values.yaml` 冒頭へ明記した。
- **実クラスタでの `fx-rate` 申告の確認は未実施**（本 PR は構成と描画までで、クラスタ実走は伴わない）。
  次回のデプロイ時に `GET /internal/introspection` の `fx-rate` が `boj` を申告することを確認する。
- **日銀 API の応答形式の変更は CI で捕まらない**（IADR-0194 と同じ残余リスク）。第一が落ちても
  FRED フォールバック（鍵があれば）と 3 段縮退が働き、最終的にはレート無し＝見送りへ倒れる。
