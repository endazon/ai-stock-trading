# IADR-0576: 決済の建玉ゲートを組み立てに依らず効かせ、ガードは取消を確かめてから保護記録を完了させる

> 実装リポジトリ内の意思決定記録（Implementation ADR）。1 ファイル = 1 意思決定。

- 状態: **Accepted**
- 日付: 2026-10-23
- 決定者: Claude Code（#1449 の求めに沿う実装の形。計画の規則は変えない）

## 起点・関連

- 起点: #1449（親 #1423 の L-1「決済の建玉ゲートの有効判定がコンストラクタ引数を直接見ており、フィールド `_positions` と不一致」、
  L-2「ガードは残存逆指値の取消を確認せずに記録を完了させ、保護記録の `Save` が無条件上書き」）。
- 計画: 業務フロー 02（建玉なき逆指値を残さない）、ADR-0016（実建玉との突合）、ADR-0050 決定 1。規則は変えない。
- 前提（覆さない）: IADR-0355（決済は実建玉と突き合わせる）、IADR-0461（処理中の決済の差し引き）、IADR-0396（保護記録の楽観並行と `Update`）、
  IADR-0406 決定3（レグの追跡の起点）、IADR-0569（未受理時のエントリーの取消は照会で確かめる）、IADR-0575（決済の直列化）。
- 改める: IADR-0396 の「残る制約」（常駐ガードは無条件の `Save` のまま）。

## コンテキスト

1. `OrderExecutionAppService` は `_positions = brokerPositions ?? broker as IBrokerPositionSource` を持つが、決済の建玉ゲートと処理中の決済の差し引きの入口は
   引数 `brokerPositions` を見ていた。本番の配線は両方に同じ値を渡すので実害は無い。アダプタだけを渡す組み立てではゲートが外れ、保有 0 からの売りが出る
   （実アダプタを `brokerPositions` なしで組む既存の試験が、是正後にゲートで止まることで確かめた）。
2. ガードは建玉の消えた逆指値に `CancelOrderAsync` を送った直後に記録を完了させていた。取消の要求が返ったことは取り消せたことではない。
   完了した記録の逆指値は巡回に載らず、発火すれば反対建玉になる。処理中の決済の除外も Active の記録のレグに限るので、生きている逆指値が判断の決済を縮める。
   取消の窓で約定すると、ポートの契約により取消は InvalidOperationException になり、その 1 件は巡回の失敗になっていた。
3. ガードの保護記録の書き込み 5 箇所は無条件の `Save` で、評価の間に並行に進んだ状態（レグの置き換え・残保護数量の確定・通知の印）を古い写しで巻き戻し得た。
   IADR-0396 は「ブローカーへの操作の後に書く経路で保存を落とすと、実在する注文と記録が食い違う」としてガードを無条件のまま残していた。

## 決定

### 決定 1: 決済の建玉ゲートはフィールド `_positions` で判定する

- 有効判定（`if`）と照会を `_positions` に揃える。明示の `brokerPositions` があればそれ、無ければ建玉照会の能力を持つアダプタそのもの（S1 の武装と同じ）。
- 能力の無い発注先（内蔵 paper）は `_positions` が null のまま。この分岐は起きない（従来どおり）。

### 決定 2: 残存逆指値の取消は照会で終端を確かめてから完了させる

- 取消の後に `GetOrderAsync` で照会する。
  - `Cancelled` / `Rejected` / `Expired` → 取消の直前までの部分約定を約定追跡に拾わせ（IADR-0406 決定3）、完了する。
  - `Filled`（取消の窓で約定）→ 約定として扱う。約定追跡の起点を進めて台帳へ届けさせ、完了する。反対建玉が生じ得るので Error を残す（手当ては帰属不明の建玉の検知が次の巡回で行う）。
  - null・非終端（取消待ち）→ **完了させない**（`Unknown`）。次の巡回は同じ評価に入り、まだ生きていれば取り消し直し、終端なら既存の失効・約定の分岐が閉じる。
- 取消の InvalidOperationException（契約の「約定済み・未知の ID」）は照会へ回す。他の例外は従来どおり巡回の 1 件の失敗とする（届いたか分からない取消を「取り消せた」と読まない）。
- 選ばなかった案: 取消待ちの間は通知（Critical）を出す。取消待ちは数秒で解ける平常の遷移であり、巡回ごとに鳴らすと誤報になる。ログ（Warning）だけを残す。

### 決定 3: ガードの保護記録の書き込みを読み直して当て直す形へ移す

- **完了**（`MarkCompleted`）: `ProtectiveStopStoreUpdates.Update` で最新の行へ当てる。当てるのは、最新が `Active` で、観測した写しと**同じレグ**
  （`StopDecisionId`・`StopOrderId`・`Attempt`）のときだけである。S1 の未到達の完了は、最新の残保護数量が 0 以下で未確定の外部要因が無いときだけ当てる。
  最新が既に閉じていれば完了として扱う。条件を満たさなければ書かずに `false` を返し、呼び出し側は `Unknown` で次の巡回へ回す（古い観測で新しいレグを閉じない）。
- **ブローカーへの操作の後**（張り直しの成功・送信結果待ちの採用・送信結果待ちへの移行・拒否された成行の試行の前進）: 変えた列だけを**条件なしに**最新の行へ当て直す。
  他の列は巻き戻さない。行が無ければ Error を残す（ストアは行を消さないので平常では起きない）。
  🔴 **当て直しの衝突が `MaxAttempts`（5）回続いたら、この経路に限り、最後に読んだ最新の行へ列を当てて無条件に保存する**（Warning を残す）。
  実在する注文と記録の食い違いを作らない（IADR-0396 が無条件を残した理由を保つ）。並行に書かれた列を 1 回巻き戻し得るが、注文を記録から落とすより害が小さい。
- 完了（`MarkCompleted`）の衝突が続いたときは `ProtectiveStopConcurrencyException` を上げ、巡回の 1 件の失敗とする（記録は Active のまま。閉じない側は次の巡回で評価し直せる）。
- 成行で手仕舞えた（記録あり）のに完了を当てられなかった巡回では、事実（`PositionClosed`）を**出さない**（`Unknown`）。次の巡回は同じ試行の記録から閉じ直し、
  閉じられた巡回で 1 回だけ出す（成行は重ねない）。
- `IProtectiveStopOrderStore.Save`（無条件）は新しい行を作る経路（発注執行のエントリー時の記録）のために残す。

## 結果

- 試験: T-10-3012（取消が未確認なら完了しない。一部約定のまま取消待ちを含む）、T-10-3013（取消の窓の約定）、T-10-3014（並行更新で巻き戻さない）、
  T-10-3015（アダプタだけの組み立てでゲートが効く）、T-10-3016（衝突が尽きても張り直しの注文 ID を落とさない）、T-10-3017（手仕舞いの事実は閉じた巡回で 1 回だけ）。
  変異 CC1〜CC7 はすべて赤（作業仕様書）。
- 既存の試験の偽物の取消は、照会で取消済みに見えるように直した（本物の証券会社と同じ）。

## 残余リスク

- 取消を確かめられない状態が続く間、巡回ごと（既定 30 秒）に取消を送り直す。
- ブローカーへの操作の後の記録で当て直しの衝突が尽きると、無条件の保存が並行に書かれた列を 1 回巻き戻し得る（注文を落とさない方を取った）。
- 手仕舞いを閉じられない巡回が続く間は、保護喪失（手仕舞い済み）の通知が遅れる（閉じられた巡回で出る）。
- 取消の窓の約定による反対建玉は本 IADR では手当てしない（帰属不明の建玉の検知に委ねる）。
- ガードの成行が板に残る判断の決済を取り消さない件は #1448 で扱う（本 IADR の対象外）。
