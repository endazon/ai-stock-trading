# IADR-0125: 方針文は「方針の実体」だけを持ち、状態・レビュー指示を本文へ書かない

- 状態: Accepted（[IADR-0115](./IADR-0115_report-auto-generation-scheduler.md) 決定4 の一部を改訂する）
- 日付: 2026-08-01
- 決定者: claude（実装）／利用者（issue #310 の指定＝継続時は実体のみを引き継ぎ、前置き・状態文言を除去する）

## 起点・関連

- 起点 issue: [#310](https://github.com/endazon/ai-stock-trading/issues/310)
  （日報方針の自動生成が前置き文ごと継承し世代累積する／確定後も「未確定」文言が残る）。
- 傘 issue: [#279](https://github.com/endazon/ai-stock-trading/issues/279)（経路B SIMULATE の本番パリティ未達）。
- 前提: [IADR-0115](./IADR-0115_report-auto-generation-scheduler.md)（自動生成・決定4 が方針文の作り方を決めた）、
  [IADR-0120](./IADR-0120_report-kind-purpose-and-parent-policy-feedforward.md)（上位方針の feed-forward）、
  [IADR-0116](./IADR-0116_report-draft-discord-notification.md)（提示通知）、
  [IADR-0028](./IADR-0028_daily-policy-sync-api.md)（確定済み日報方針の同期照会）。
- 作業仕様書: [20260801_310_report-policy-carryover-substance](../specs/20260801_310_report-policy-carryover-substance.md)

## コンテキストと課題

### 実測（2026-07-31 の経路B live 検証）

`daily-2026-07-31` を確定した直後の `GET /reports/daily-policy` が返した本文:

```
（自動生成ドラフト・未確定）

直近の確定済み日報方針（daily-2026-07-29）を継続する案です。確定前に内容を見直してください。

（自動生成ドラフト・未確定）                                    ← 2 世代目の前置きが入れ子で残存

直近の確定済み日報方針（daily-2026-07-27）を継続する案です。確定前に内容を見直してください。

本日の方針: 米国株 AAPL を積極的に買い増す（buy 寄り）…      ← 実体はここ
```

### 原因

`ReportPolicyDraft.CarryOver` が、**前世代の `PolicySummary` を丸ごと**新しい前置きの後ろへ連結していた。
`previousPolicy` は同種別の直近**確定済み** `PolicySummary` であり、それ自体が前回の自動生成物（＝前置きを含む）
であるため、継続のたびに前置きが 1 組ずつ積み上がる。

構造的な原因は、`PolicySummary` に **「方針の実体」と「生成物の状態・レビュー手順の指示」が混在**していたこと。
後者はレコードの状態（`ReportState` / `ReviewState`）と提示通知（IADR-0116）が既に持つ情報であり、
本文へ埋め込むと**確定によって嘘になる**。

### 実害

1. 継続が続くほど方針の実体が末尾へ押しやられ、プロンプトの大半が定型文になる。
2. `State=Confirmed` になっても本文が「（自動生成ドラフト・未確定）」「確定前に内容を見直してください」を
   含むため、**確定済み方針として LLM へ渡るテキストが自己矛盾**する。
3. 取引判断（`TradeDecisionService`）は `GET /reports/daily-policy`（IADR-0028）で得た `PolicySummary` を
   G4 の確定方針としてプロンプトへ載せるため、AI が「未確定なので取引しない」と誤読しうる。

## 検討した選択肢

| 案 | 内容 | 評価 |
| --- | --- | --- |
| A | 継続時に「前置きの直後 1 ブロックだけ」を実体とみなして切り出す | ✗ 位置に依存する。手で編集された本文・複数段落の方針で崩れる |
| B | 生成時に前置きを付けたまま、**読み出し時**（`GetConfirmedDailyPolicy`）に除去する | ✗ 保存済みの本文と取引が見る本文が食い違う。確定 UI では「未確定」が見え続ける |
| **C** | **方針文には実体だけを持たせ、状態はレコードの状態と通知に委ねる** | ✅ 採用。累積が構造的に起こらず、確定後の自己矛盾も消える |
| D | `TradingReport` に「前置き」列を足して本文と分離する | ✗ スキーマ変更を伴う。状態は既に `State` / `ReviewState` が持っており、二重管理になる |

## 決定

### 決定 1: 継続は「方針の実体」だけを引き継ぐ

`ReportPolicyDraft.Substance(policy)`（Domain・純関数）を新設し、本クラスが生成した前置き・状態文言・注記の行を
除去して実体だけを返す。`CarryOver` はこれを引き継ぎ、前置きを付け直さない。
除去は**全出現**に対して行うため、既に世代累積したレコードを継承しても 1 回で畳まれる。

自分自身の出力を継承元にしても不変（不動点）であり、何世代継続しても本文は伸びない。

### 決定 2: 除去対象には**本 PR 以前の文言**も含める

live の DB には累積済みのレコードが実在し、それが是正後の初回生成の継承元になる。
旧文言（`（自動生成ドラフト・未確定）` / `…継続する案です。確定前に内容を見直してください。` /
`…方針を記入したうえで確定してください。` / `上位方針（…）は未確定のため参照していません。`）を
畳めなければ、過去の累積をそのまま引き継いでしまう。
**既存レコード自体は書き換えない**（履歴として不変・issue #310 の指定）。読み出し時のサニタイズも行わない
（保存済みの本文と取引が見る本文を食い違わせない）。

### 決定 3: 状態・レビュー手順の文言は方針文へ書かない

`（自動生成ドラフト・未確定）` と「確定前に内容を見直してください」は本文から外す。
状態は `ReportState` / `ReviewState`（生成物は `Draft` / `PendingApproval` で止まる・IADR-0115 決定1）と
提示通知（IADR-0116。「承認待ちに並んだものだけを確認依頼する」）が持つ。

**IADR-0115 決定4 の「未確定である旨を明記する」を本決定が置き換える**。当時の意図（機械が書いた方針を
利用者が承認するだけの運用に退化させない）は、①自動生成が新方針を提案しないこと ②確定が OwnerOnly の
対話経路にしかないこと、で担保され続ける——本文の文言はその担保ではなかった。

参照できない上位方針の注記（03_reporting-cycle「上位方針の欠落」）は残すが、**確定後も残るテキストである**
ため「未確定のため」ではなく「確定済みのものがないため」という事実文に改める。継続元が無い場合も同様に、
事実（`参照できる確定済みの日報方針がありません。`）だけを置きレビュー指示は書かない。

### 決定 4: 上位方針の feed-forward にも実体だけを渡す

`ReportAutoGenerator` が `ParentPolicySummary`（IADR-0120 決定3）へ渡す上位方針にも `Substance` を適用する。
累積済みの環境では上位方針の本文が定型文で膨らんでおり、そのまま渡すとプロンプトが前置きで埋まる。
上位方針を `PolicySummary` へ混ぜない（IADR-0120 決定3）は不変。

### 決定 5: 利用者が書いた本文は改変しない

`Substance` が落とすのは生成器が書いた行のパターンに一致する行だけで、それ以外は 1 文字も変えない
（継承で方針が痩せない）。適用箇所は継承（`CarryOver`）と feed-forward のみで、利用者が手で作った
ドラフトの保存経路には適用しない。

**残存リスク（受容）**: 判別は行単位の**完全一致**であるため、利用者が手で書いた行がたまたま生成器の定型文
（例: `上位方針（週報）は確定済みのものがないため参照していません。`）と一字一句一致すると、次回の継承で
その行が落ちる。判別を厳密にする手（生成器のマーカー文字を本文へ埋め込む等）は、本 IADR が解こうとした問題
（状態・メタ情報を本文へ書かない）に逆行するため採らない。落ちうるのは**生成器が同じ文脈で書くはずの 1 行**に
限られ、方針の実体である文は残る。

## 理由

- 累積は「本文へ状態を書いた」ことの必然的な帰結であり、**状態を本文から外す**のが根治である
  （案 A・B は毎回の除去に頼るため、経路が増えるたびに漏れる）。
- 確定後の本文が「未確定」を名乗る状態は、取引方針の唯一の文字列表現（IADR-0028）が自己矛盾するという
  一点で害が大きい。ADR-0003 のガードレールは**状態と経路**で守るものであり、本文の定型文で守るものではない。
- 旧文言まで畳む（決定2）ことで、**是正のデプロイだけで live の累積が次回生成時に解消**する。
  移行スクリプトも手作業も要らない。

## 結果

- 継続が何世代続いても方針文は伸びない（実体のみ）。
- 確定した方針文に「未確定」は現れない＝ G4 の確定方針が自己矛盾しない。
- 累積済みの既存レコードは履歴として残るが、次回の自動生成が継承する時点で畳まれる。
- 「これは継続案である」という**出所の説明が方針文から消える**。継続元は同種別の直近確定済みという規則が
  一定であり、`BasedOn`（上位）・`PeriodKey`（自種別の並び）から追跡できる。承認待ちであること自体は
  `ReviewState` と提示通知が伝える。
- DB スキーマ・イベント・Helm/values・認可は不変。SIMULATE / 実弾 OFF に差分なし。
