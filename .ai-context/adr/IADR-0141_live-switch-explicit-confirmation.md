# IADR-0141: 実弾（moomoo `REAL`）への切替に明示的な確認操作をサーバ側でも強制する

- 状態: Accepted
- 日付: 2026-08-05
- 決定者: 実装（Claude Code）／ 起点 issue [#334](https://github.com/endazon/ai-stock-trading/issues/334)
- 作業仕様書: [20260805_334_broker-provider-axis](../specs/20260805_334_broker-provider-axis.md)

## コンテキストと課題

計画（FR-20（計画リポ） (1)・
05_screens（計画リポ） SC-02）は実弾への切替に 4 点の提示と
明示的な確認操作を義務づけ、**「既定の『OK』ボタン 1 押しで切り替えられてはならない」**と明記する。

これは「止める」統制である。ところが計画の記述はすべて**画面（SC-02）に対するもの**であり、
サーバ側で何を要求するかは述べていない。画面だけに置くと、統制は次の 3 つの経路で消える。

1. API を直接叩けば確認は存在しない（Discord Bot・スクリプト・将来の別クライアント）。
2. 画面の実装が「保存ボタンの `disabled` を外す」1 行の退行で失われる。`disabled` の欠落は目視で気づけない。
3. 4 点の提示と確認の**結び付き**が画面の状態管理にしか無いため、テストが通っていても実行時に外れうる。

## 検討した選択肢

1. **画面だけで強制する（計画の字面どおり）** — 実装は小さいが、上記 3 経路で失われる。統制の強度が
   「画面の実装品質」に等しくなる。
2. **サーバ側でも要求する（採用）** — 画面が壊れても、確認の無い切替は 400 で止まる。
3. サーバ側だけで要求し画面はそのまま送る — 利用者が理由を理解しないまま 400 を受け取るだけで、
   「4 点を読ませる」という統制の目的（無自覚な実弾投入の防止）を果たさない。画面の提示は必須である。

## 決定

### 決定1: 明示確認は画面とサーバの二重で要求する

`PUT /risk-controls/settings/broker-provider` は、切替先が `MoomooReal` の場合に限り次の**両方**を要求する。
どちらか一方でも欠ければ 400 を返し、設定は変わらない。

| 要素 | 由来 | 検証 |
| --- | --- | --- |
| `AcknowledgedLiveTrading`（同意） | 計画「チェックボックスの同意」 | `true` であること |
| `Acknowledgement`（文字入力） | 計画「『REAL』の文字入力」 | 後述の照合に合格すること |

`MoomooReal` **以外**への切替（内蔵 `paper` / moomoo `SIMULATE`）には要求しない。安全な方向の変更に摩擦を
足すと、危険なときだけ止まるという統制の意味が薄れる（[IADR-0086](IADR-0086_frontend-guard-edit-ui.md)
の「厳格化は確認不要」と同じ非対称）。

### 決定2: 文字入力の照合は「前後空白を除いた完全一致（大文字小文字を区別する）」とする

**計画は照合規則を述べていない**（「『REAL』の文字入力」とだけある）。実装は次を選んだ。

- 前後の空白は除く——コピー＆ペーストで末尾に空白が入るのは利用者の意図とは無関係である。
- **大文字小文字は区別する**——`real` を受理すると「`REAL` の文字入力」という計画の字面から外れる。
  また、この入力は「打つ手間」そのものが統制であり、区別を捨てると手間が減る方向にしか働かない。

照合文字列は `BrokerProviderChange.LiveAcknowledgementPhrase` の 1 か所に置く。画面・サーバ・テストが
同じ定数を参照し、片方だけが変わることを防ぐ。

### 決定3: 判定は純関数（`BrokerProviderChange`）に置き、画面とサーバの両方が同じ規則を使う

「実弾への切替か」「段階ゲートを飛ばしているか」「確認は足りているか」をドメインの純関数に集約する。
サーバの検証と画面の表示が別々の条件式を持つと、**画面が警告を出さないのにサーバは通す**（またはその逆）
という食い違いが生じる。

### 決定4: 段階との組み合わせは保存を妨げず、警告として提示する

計画は「運用段階との組み合わせは**保存を妨げない**が、段階が想定する発注先と異なる場合は**警告を表示する**」
と定める。よって `SkipsStageGate`（段階の既定が実弾でないのに実弾へ切り替えようとしている）は
**拒否理由ではなく警告**として応答に載せ、画面はモーダルの②として描く。

## 結果

- 「OK」1 押しで実弾へ切り替わる経路が、画面・API のどちらからも存在しなくなった。
- 退行防止テストは否定形を主にする（確認が欠けたとき**切り替わらない**こと）。
  4 点の提示は画面テスト（vitest）と E2E（Playwright）で、確認の強制はサーバのテストで固定する。

### 残余リスク

- **本 ADR が守るのは「設定値の変更」であって「実弾の発注」ではない。** 設定値はまだ発注経路へ結線されておらず
  （[IADR-0140](IADR-0140_broker-provider-axis.md) 残余リスク）、実弾そのものは
  [IADR-0111](IADR-0111_broker-tier-selection.md) の閂 0 が別途止めている。結線の際は、
  本確認が実弾解禁の唯一の関門にならないよう（閂を減らさないよう）注意すること。
- 4 点のうち③（equity と統制値の実額）は `GET /risk-controls/status` の取得に依存する。取得できない場合、
  画面は**実弾への切替を許さない**（提示できない項目がある状態で確認を取らない）。
