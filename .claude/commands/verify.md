---
description: ビルド・テスト・lint を実行し、作業仕様書の受け入れ基準と突き合わせて合否を報告する
argument-hint: （省略可）対象の作業仕様書パス or 起点 ID
allowed-tools: Read, Grep, Glob, Bash
---

引数 `$ARGUMENTS`: 検証対象の作業仕様書（`docs/specs/...`）または起点 ID（省略時は直近の変更・作業仕様書）。

目的: 実装が「動く」かつ「受け入れ基準を満たす」ことを機械的・客観的に確認する（AI 自身による完了前検証）。

手順:

1. `CLAUDE.md` 末尾の「技術スタック別ルール」から、ビルド/テスト/フォーマット・lint のコマンドを把握する（例 C#: `dotnet build` / `dotnet test` / `dotnet format --verify-no-changes`）。未定義なら使用中のスタックから推定し、不明なら人間に確認する。
2. 次を順に実行し、各結果（成功/失敗・要点）を記録する。
   - ビルド
   - テスト（可能ならカバレッジも）
   - フォーマット/lint チェック
3. 対象の作業仕様書を読み、受け入れ基準（チェックボックス）の各項目が、テストまたは実装で満たされているか突き合わせる。
4. `docs/DEFINITION_OF_DONE.md` の各項目を確認する。
5. 結果を「合格 / 不合格」で報告する。不合格項目は `ファイル:行` または失敗ログとともに、是正アクションを示す。
6. すべて合格なら、PR 作成・レビュー依頼へ進んでよい旨を伝える。

注意: 破壊的コマンド・本番環境への接続は行わない。テストはローカル/CI 相当の範囲に留める。
